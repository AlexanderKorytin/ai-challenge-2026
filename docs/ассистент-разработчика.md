# Дизайн: ассистент разработчика (день 31)

## Задача и видение

Условие дня 31 просит ассистента, который понимает проект. У ассистента три части:

- RAG (поиск по документам перед ответом) по `README`, `docs` и описаниям API;
- MCP даёт ассистенту текущую ветку git, по желанию — список файлов и `diff`;
- команда `/help` отвечает на вопрос о проекте.

Проект ассистента — этот репозиторий. Решение пользователя от 2026-10-12: `/help` целиком
отходит ассистенту, прежняя справка разделами переезжает в `/info`.

## Что решили и почему

```
/help <вопрос>
   ▼ помощник: отдельный агент, свой контекст
   ▼ поиск: сервер `rag`, индекс помощника (README + docs + openspec/specs)
   ▼ запрос к модели: инструкция + найденные куски + вопрос
   ▼ модель зовёт инструменты сервера `git`, если вопрос о состоянии проекта
   ▼ ответ с источниками печатается в главный экран
```

1. **`/help <вопрос>` запускает отдельного агента «помощник».** У помощника свой контекст.
   Вопрос и ответ не попадают в память текущего разговора и не зависят от его профиля.
   Образец — Claude Code: там на вопросы о самом инструменте отвечает отдельный помощник
   `claude-code-guide`, и основной разговор получает только его ответ.
   Отвергнуто: послать вопрос в текущий разговор. Тогда ответ зависит от активного профиля,
   и справочный вопрос засоряет память задачи.

2. **Помощника описывает обычный профиль `помощник`** — пара файлов `.json` и `.md`.
   Профиль лежит в данных пакета, порядок поиска профилей прежний, и своя пара файлов его
   перекрывает. Поле `rag` профиля называет сервер поиска. Новых полей и настроек нет: всё
   несут действующие поле `rag`, файл `.mcp.json` и список `permissions.allow`.
   Отвергнуто: своя настройка «сервер помощника» в `config.json`. Это второй канал рядом
   с работающим полем `rag`.

3. **Индекс помощника — отдельный файл.** `rag/cli.py index` получает набор корпуса
   `README.md` + `docs` + `openspec/specs` и пишет его в свой файл индекса. Сервер поиска
   читает его через `RAG_INDEX`. Требования `openspec/specs` — это наши описания API
   и схемы данных.
   Контрольный индекс `rag/index.sqlite` не меняется. Решение пользователя от 2026-10-07
   остаётся в силе: контрольные вопросы недели 5 в `docs` есть, и замеры по этому индексу
   с `docs` стали бы нечестными.
   `CLAUDE.md` в индекс помощника не входит: это рабочий договор среды разработки,
   а не документация проекта.

4. **Ветку git даёт официальный сервер MCP `git`** (подключён в дне 16). Модель сама зовёт
   `git_status`, `git_branch`, `git_diff_unstaged`, `git_log` через действующий мост
   `mcp_tools`. Разрешает их список `permissions.allow` в `.claude/settings.json` рабочего
   каталога, правила вида `mcp__git__git_status`. Разрешены только
   инструменты чтения.
   Отвергнуто: программа сама вписывает ветку в каждый запрос. Это проще, но тогда MCP
   модели не нужен, а `diff` и журнал всё равно требуют вызова инструмента.
   Отвергнуто: свой сервер git. Официальный уже закрывает условие.

5. **Список и чтение файлов даёт официальный сервер MCP `filesystem`** (день 20), только
   чтение. Решение пользователя от 2026-10-12 по лекции недели 7: она называет чтение файлов
   третьим родом инструментов ассистента. Нового кода нет — сервер стоит в `.mcp.json`.
   Первый вариант дизайна этот пункт вычёркивал: у сервера `git` такого инструмента
   нет. Структуру проекта описывают `README.md` и `docs/структура-репозитория.md` — они
   в индексе. Условие называет список файлов необязательным.

6. **`/help` без вопроса** особой подсказки не имеет (решение пользователя от 2026-10-12).
   Команда сообщает, что вопрос не задан, как любая команда без обязательного довода.

9. **Модель помощника — модель сеанса**, выбранная командой `/model`. С моделью `ollama/<имя>`
   помощник работает без облака (решение пользователя от 2026-10-12). Инструменты MCP
   местная модель зовёт сама — замер 2026-10-06.

7. **`/info`** получает всё поведение прежней `/help` без изменений: меню разделов,
   `/info <слово>`, подстановку слов при наборе. Ссылки `/help <раздел>` в текстах справки
   и в сообщениях об ошибках меняются на `/info <раздел>`.

8. **Ответ помощника** называет источники: путь и раздел найденного куска. Если поиск
   ничего не нашёл и инструменты не помогли — помощник отвечает «в документации этого нет».
   Строгую сверку цитат дня 24 не подключаем: условие её не просит.

## Затронутые способности

- `openspec/specs/commands/` — `/help` меняет смысл, появляется `/info`; подстановка слов
  переходит на `/info`.
- `openspec/specs/profiles/` — встроенный профиль `помощник` в данных пакета (если порядок
  поиска профилей этого места ещё не знает).
- `openspec/specs/agent/` — разовый агент со своим контекстом без записи в память разговора.
- `openspec/specs/memory/`, `interface/` — только замена упоминаний `/help <раздел>`.
- `rag/` — набор корпуса помощника в `rag/cli.py`. Требований OpenSpec у `rag/` нет.

## Границы: что делаем и чего НЕ делаем

Делаем:

- `/help <вопрос>`, `/info`, профиль `помощник`, индекс помощника;
- папку дня `week_7/day_1/` и ветку `w7d1`: постановка, песочница с `.mcp.json`
  (серверы `rag` и `git`), проверочные вопросы, видеоотчёт;
- живой прогон: 5–6 вопросов. Из них три о структуре проекта, один о ветке, один о `diff`,
  один далёкий (ждём отказ).

Не делаем:

- замер качества на контрольном наборе и сравнение режимов — условие просит работающего
  ассистента, а не исследование;
- правку контрольного индекса и контрольных наборов недели 5;
- инструменты записи в git;
- индексацию исходного кода.

## Риски и чем расплачиваемся

- **Привычка.** `/help` перестаёт быть справкой. Пользователь риск принял: инструмент
  в эксплуатацию не выпущен.
- **Содержимое `diff` уходит той модели, что выбрана в сеансе.** С DeepSeek это облако,
  с местной моделью данные компьютер не покидают.
- **Местная модель слабее держит источники** (замеры дней 26–28). Живой прогон идёт на
  обеих моделях.
- **Устаревание индекса.** Индекс помощника не обновляется сам. Навык `/отчет` уже
  пересобирает `rag/index.sqlite`; добавляем туда же пересборку индекса помощника.
- **Шум в `docs`.** Файлы `план-*.md` и `состояние-*.md` — рабочие записи, они могут
  вытеснять документацию в выдаче. Живой прогон покажет; если мешают — исключаем их из
  набора и называем это в отчёте.
- **Вне рабочей копии проекта** серверов `rag` и `git` в `.mcp.json` нет. Тогда `/help`
  отвечает строкой причины, а не падает.
