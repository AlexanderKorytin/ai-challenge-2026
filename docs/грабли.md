# Грабли рабочего окружения (проверено на своей шкуре)

- **Окружения в облачной папке.** iCloud помечает служебные `.pth`-файлы скрытыми, а Python
  начиная с 3.11 скрытые `.pth` игнорирует — установка пакета «editable» молча перестаёт
  работать, импорт падает с `ModuleNotFoundError`. Признак: файл на месте, путь верный, а
  `site.addsitedir` его не подхватывает (`ls -lO` покажет флаг `hidden`). Лечение на месте —
  `chflags nohidden`, правильное лечение — держать `.venv` вне облачной папки. Ещё iCloud
  плодит копии вида `myharness 2.pth` при конфликте синхронизации.
  **Итог 2026-09-07: репозиторий выведен из iCloud в `~/challenge/`** — грабли закрыты у
  корня, а не заплаткой. В облаке репозиторий больше не держим.
- **Проверки не должны трогать настоящие настройки.** Тесты harness писали в
  `~/.config/myharness/config.json` и затёрли рабочий ключ DeepSeek. Теперь каталог настроек
  берётся из `$MYHARNESS_CONFIG_DIR`, и проверки уводят его во временный каталог. Правило общее:
  всё, что пишет в домашний каталог, обязано иметь переопределение пути для проверок.
- **Установленная команда может смотреть в старый каталог.** После переезда проекта в iCloud
  команда `myharness` продолжала запускать код из прежней копии — правки шли мимо. Проверять,
  куда указывает установка: `cat ~/.local/share/uv/tools/<имя>/lib/python*/site-packages/*.pth`.
- **Автоматизация ввода в терминал и раскладка.** `System Events keystroke` шлёт коды клавиш, а
  не символы: при русской раскладке латиница превращается в кириллицу (`/profile` → `/ффффффф`).
  Для записи демонстраций текст надо класть в буфер обмена и вставлять Cmd+V.
