## Договоры модулей

### `ollama.py`
**Владеет**: адресом службы и именем модели. Адрес — `OLLAMA_HOST`, умолчание
`http://127.0.0.1:11434`. Модель — `КАЛОРИИ_МОДЕЛЬ`, умолчание `qwen3.5:9b-q4_K_M-32k`.
**Отдаёт**:
```python
def спросить(система: str, вопрос: str, схема: dict, *, клиент: httpx.Client | None = None) -> dict
class СлужбаНедоступна(Exception)   # нет соединения
class МоделиНет(Exception)          # служба ответила 404 на имя модели
class ОтветНегоден(Exception)       # ответ не разбирается как JSON по схеме
```
**Обещает**: шлёт `POST /api/chat` с `stream: false`, `think: false`, `format: схема`,
`options.temperature: 0`; возвращает разобранный словарь из `message.content`. Других адресов
не знает. Предел ожидания ответа не ставит (`httpx.Timeout(None)`).
**Не делает**: на диск не пишет, ничего не печатает, чисел не проверяет.

### `core.py`
**Отдаёт**:
```python
@dataclass(frozen=True)
class Блюдо:
    название: str
    ккал_100: float     # ккал на 100 г
    порция_г: float     # вес обычной порции
    ги: float
    @property
    def ккал_порции(self) -> float      # ккал_100 * порция_г / 100
    @property
    def разряд(self) -> str             # «низкий» до 55, «средний» 56–69, «высокий» от 70

def оценить(название: str, **kw) -> Блюдо | None      # None — модель сказала «не еда»
def подобрать(ккал: float, число: int, **kw) -> list[Блюдо]   # отсортирован по |ккал_порции − ккал|
```
`**kw` уходит в `ollama.спросить` (довод `клиент` для проверок).
**Обещает**: каждое возвращённое `Блюдо` прошло проверку: `0 < ккал_100 ≤ 900`, `порция_г > 0`,
`ги ≥ 0`. Иначе — `ОтветНегоден` с причиной. В `подобрать` негодное блюдо из списка даёт
`ОтветНегоден` на весь ответ: молча список не укорачивается.
**Не делает**: ничего не печатает; исключения `ollama.py` пропускает наверх.

## Шаг 1. Функция `оценить` отвечает на название блюда числами от живой модели

**Файлы**: `pyproject.toml`, `src/calories/__init__.py`, `src/calories/ollama.py`,
`src/calories/core.py`, `tests/test_ollama.py`, `tests/test_core.py`
**Зависит от**: ничего
**Ход**: быстрый
**Требование**: не про `myharness`
**Содержание**: `ollama.спросить` по договору. В `core.py` — `Блюдо`, проверка чисел, `оценить`.
Схема прямого направления: `{еда: boolean, ккал_100: number, порция_г: number, ги: number}`, все
поля обязательны. Системная инструкция: «Ты справочник по питанию. Назови калорийность блюда на
100 г, вес обычной порции в граммах и гликемический индекс. Если это не еда, поставь еда=false».
Проверки с `MockTransport`: тело запроса несёт `think: false` и схему; ответ разбирается;
отказ соединения → `СлужбаНедоступна`; 404 → `МоделиНет`; `ккал_100 = 950` → `ОтветНегоден`,
парная `900` проходит; `еда: false` → `None`; `разряд` на 55, 56, 69, 70.
**Проверка** (живой прогон, первый обмен с моделью): из `week_6/day_2/`
`uv run python -c "from calories.core import оценить; print(оценить('гречка отварная')); print(оценить('табуретка'))"`
— первое печатает `Блюдо` с числами, второе `None`.

## Шаг 2. Функция `подобрать` отвечает на число килокалорий списком блюд

**Файлы**: `src/calories/core.py`, `tests/test_core.py`
**Зависит от**: шаг 1
**Ход**: быстрый
**Требование**: не про `myharness`
**Содержание**: схема обратного направления: `{блюда: [{название, ккал_100, порция_г, ги}]}`,
`minItems` и `maxItems` равны доводу `число`. Инструкция: «Назови блюда, обычная порция которых
даёт около N ккал. Блюда разные: суп, второе, выпечка, фрукты. Для каждого — калорийность на
100 г, вес порции, гликемический индекс». Калорийность порции модель не называет: её считает
`Блюдо.ккал_порции`. Проверки: сортировка по отклонению; негодное блюдо в списке →
`ОтветНегоден`.
**Проверка** (живой прогон): `uv run python -c "from calories.core import подобрать; [print(б, б.ккал_порции) for б in подобрать(450, 5)]"`
— пять блюд, отклонение растёт сверху вниз. Число попаданий в ±20 % записать в README как
наблюдение, не как порог.

## Шаг 3. Команда `калории` печатает ответ, ведёт разговор и объясняет отказы

**Файлы**: `src/calories/cli.py`, `tests/test_cli.py`
**Зависит от**: шаги 1, 2
**Ход**: быстрый
**Требование**: не про `myharness`
**Содержание**: `main(argv=None) -> int` на `argparse`. Позиционный довод `запрос`
(необязателен), ключ `--блюд` (умолчание 5), ключ `--замер` (шаг 4). Функция
`ответить(строка: str, блюд: int) -> str`: строка разбирается как число (запятая и точка) →
`подобрать`, иначе → `оценить`. Вид прямого ответа:

```
Борщ со свининой — оценка модели
  калорийность   65 ккал на 100 г
  порция         300 г → 195 ккал
  гликемический индекс  45 (низкий)
Числа назвала местная модель. Не для врачебных решений.
```

Обратный ответ — таблица: блюдо, порция, ккал порции, отклонение со знаком, ГИ и разряд; та же
нижняя строка. `None` → «Не знаю такого блюда: <ввод>». Без довода `запрос` — разговор:
приглашение `> `, пустая строка и конец ввода завершают. Отказы: `СлужбаНедоступна` → «Служба
Ollama не отвечает по адресу <адрес>. Запусти: `ollama serve`», код 1; `МоделиНет` → «Модели
<имя> нет в службе. Загрузи: `ollama pull <основа>`», код 1; `ОтветНегоден` → причина, код 1; в
разговоре отказ ответа печатается, и разговор продолжается.
Проверки: выбор направления по строке («450», «450,5», «борщ», «7 злаков» — блюдо); код
возврата 1 на каждый отказ; текст отказа называет адрес и модель.
**Проверка** (ручной сценарий): `uv run калории "борщ со свининой"`; `uv run калории 450`;
`uv run калории табуретка`; `uv run калории` с тремя строками ввода;
`OLLAMA_HOST=http://127.0.0.1:1 uv run калории борщ` — сообщение и код 1.

**После шага 3 — один независимый просмотр шва**: `ollama.py`, `core.py`, `cli.py` и проверки
разом (`general-purpose` на `opus`). Вопросы просмотру: держатся ли договоры; теряется ли
ошибка молча; уходит ли запрос куда-либо, кроме местной службы.

## Шаг 4. Команда `калории --замер` печатает ошибку модели на контрольном наборе

**Файлы**: `контроль.jsonl`, `src/calories/measure.py`, `tests/test_measure.py`
**Зависит от**: шаг 1
**Ход**: быстрый
**Требование**: не про `myharness`
**Содержание**: строка набора: `{"блюдо", "ккал_100", "ги", "источник_ккал", "источник_ги"}`.
25 блюд: по 8–9 каждого разряда ГИ, простые продукты и готовые блюда. ГИ — из международных
таблиц (Atkinson и др., 2021, Am J Clin Nutr), калорийность — из таблиц Скурихина либо USDA
FoodData Central; источник назван в строке. Блюдо без опубликованного ГИ в набор не идёт.
Отступление от дизайна: дизайн называл для калорий только Скурихина; USDA добавлен, потому что
его таблицы открыты для сверки по сети.
`замерить(путь, **kw) -> Итог` с полями: `блюд`, `ошибка_ккал` (средняя относительная, %),
`ошибка_ги` (средняя абсолютная, единиц), `разряд_верен` (доля), `строки` (по блюду: справка,
оценка, отклонения). Печать — таблица по блюдам и три итоговых числа. Блюдо, на которое модель
сказала «не еда», считается отдельной строкой итога, в средние не входит.
Проверки: счёт трёх чисел на поддельных ответах; строка «не еда» не ломает средние.
**Проверка** (живой прогон): `uv run калории --замер` — таблица 25 строк и итог. Вывод
сохранить в `test/замер.txt`.
