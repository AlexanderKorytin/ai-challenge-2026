## Договоры

### `chunking` — его куски читают `store` и `compare`, завтра — поиск агента

**Отдаёт**:
```python
@dataclass(frozen=True)
class Кусок:
    chunk_id: str      # f"{strategy}:{source}:{n}", n — порядковый номер в файле с 0
    strategy: str      # "structure" | "fixed"
    source: str        # путь от корня репозитория, разделитель "/"
    title: str         # текст первого заголовка "# " файла; нет его — имя файла без .md
    section: str       # цепочка заголовков уровней 2–4 на позиции start, через " › "; "" до первого
    start: int         # смещение в символах внутри файла, включительно
    end: int           # исключительно; text == файл[start:end]
    text: str

def корпус(корень: Path) -> list[tuple[str, str]]          # [(source, текст)], отсортирован по source
def разделы(текст: str) -> list[tuple[int, int]]            # границы разделов стратегии structure
def нарезать_structure(source: str, текст: str) -> list[Кусок]
def нарезать_fixed(source: str, текст: str, размер: int) -> list[Кусок]
def размер_fixed(куски_structure: list[Кусок]) -> int       # медиана len(text), округление вниз
```
**Обещает**: `text == файл[start:end]` всегда; куски одного файла в одной стратегии идут по
возрастанию `start`; у `structure` куски покрывают файл без пропусков и наложений; строки,
начинающиеся с `#` внутри ограждения ``` ``` ```, заголовками не считаются; пустых кусков
(только пробельные символы) не бывает — они выбрасываются.
**Не делает**: сети не знает, на диск не пишет.

### `store` — схема файла индекса читается завтрашним поиском

**Отдаёт**:
```python
def записать(путь: Path, strategy: str, куски: list[Кусок], векторы: np.ndarray, сведения: dict) -> None
def стратегии(путь: Path) -> dict[str, dict]                 # strategy -> сведения сборки
def куски(путь: Path, strategy: str) -> tuple[list[Кусок], np.ndarray]  # все куски по (source, start) и их векторы
def найти(путь: Path, strategy: str, вектор: np.ndarray, k: int) -> list[tuple[float, Кусок]]
```
Схема SQLite:
```sql
CREATE TABLE IF NOT EXISTS сборки (strategy TEXT PRIMARY KEY, model TEXT, dim INTEGER,
  commit_hash TEXT, dirty INTEGER, built_at TEXT, seconds REAL, chunks INTEGER, fixed_size INTEGER);
CREATE TABLE IF NOT EXISTS куски (chunk_id TEXT PRIMARY KEY, strategy TEXT, source TEXT,
  title TEXT, section TEXT, start INTEGER, "end" INTEGER, text TEXT, vector BLOB);
```
**Обещает**: `записать` заменяет сборку своей стратегии целиком одной транзакцией (удаление
прежних кусков стратегии + вставка), чужую стратегию не трогает; вектор хранится `float32`,
нормированным до длины 1; `найти` возвращает `k` лучших по косинусу, по убыванию.
**Не делает**: эмбеддингов не считает, сети не знает.

### `embedder`

**Отдаёт**: `def эмбеддинги(тексты: list[str], *, модель="bge-m3", клиент: httpx2.Client | None = None) -> np.ndarray`
— `POST {OLLAMA_HOST или http://127.0.0.1:11434}/api/embed` с
`{"model", "input": тексты, "truncate": false, "options": {"num_ctx": 8192, "num_batch": 8192}}`.
`truncate: false` — Ollama по умолчанию молча обрезает длинный вход, и кусок проиндексировался бы
своим началом. `num_ctx: 8192` — окно `bge-m3`; без него Ollama берёт своё умолчание. `num_batch: 8192` — живой замер 2026-09-28 (Ollama 0.34.4): при умолчании 2048 вход длиннее ~2000 токенов отвергается «input length exceeds the context length» даже с `num_ctx: 8192`; самый длинный раздел корпуса — 4774 токена.
Ошибка ответа — исключение `ОшибкаЭмбеддера` с кодом и текстом Ollama.

## Шаг 1. Нарезка корпуса двумя стратегиями с метаданными
**Файлы**: `rag/pyproject.toml`, `rag/chunking.py`, `rag/check_rag.py`
**Зависит от**: ничего
**Ход**: быстрый — `Кусок` читают следующие шаги, но их пишет тот же ведущий; договор выписан выше.
**Требование**: не про myharness
**Проверка**: `uv run --project rag rag/check_rag.py` на малом тексте: заголовки `##`/`###`/`####`,
ограждение с `# комментарий` внутри, текст до первого заголовка. `structure`: разделов ровно по
заголовкам уровней 1–3, `####` остаётся внутри своего `###`, `# комментарий` в ограждении раздела
не открывает; куски покрывают файл встык. `fixed` с размером 10 на тексте длиной 25: куски
`[0,10) [8,18) [16,25)` (шаг 8 = 10 − 20 %); парная проверка — размер 11 даёт шаг 9
(`11 − floor(11·0,2)`). `section` куска `fixed`, начатого внутри `#### Scenario`, — полная
цепочка. На настоящем корпусе: `text == файл[start:end]` у каждого куска обеих стратегий.
**Содержание**:
- `корпус`: `openspec/specs/*/spec.md`, `docs/**/*.md`, `CLAUDE.md`; чтение `utf-8`.
- Заголовок: строка `^(#{1,6}) (.+)$` вне ограждения; ограждение переключается строкой,
  начинающейся с `` ``` ``.
- `structure`: граница раздела — начало строки заголовка уровня 1–3; кусок — от границы до
  следующей границы. `####` и глубже остаются внутри (сценарии при требовании).
- `fixed`: окно `размер` символов, шаг `размер - размер // 5` (перекрытие 20 %, по умолчаниям
  LangChain 1000/200 и LlamaIndex 1024/200); последний кусок кончается концом файла; файлы не
  склеиваются.
- Раздел `structure`, не влезающий в окно эмбеддера, делится в шаге 3 по отказу Ollama, а не
  здесь: число токенов знает только модель.

## Шаг 3. Эмбеддинги в Ollama и индекс SQLite; поиск из командной строки
**Файлы**: `rag/embedder.py`, `rag/store.py`, `rag/cli.py`, `rag/check_rag.py`, `.gitignore`
**Зависит от**: шаг 1
**Ход**: быстрый — схема файла индекса имеет завтрашнего читателя, она выписана договором выше.
**Требование**: не про myharness
**Проверка**: без Ollama — подставной эмбеддер (`httpx2.MockTransport`: вектор из счётчиков
букв): запрос уходит с `truncate: false`, `num_ctx: 8192` и `num_batch: 8192`; индекс во временном файле;
повторная `записать` той же стратегии заменяет куски, другой стратегии — не трогает; `найти`
возвращает по убыванию косинуса; ответ 400 с «context length» у куска `structure` — кусок делится
по абзацам надвое и индексируется частями с тем же `section`. **Живой прогон** (первый живой
обмен, от интерфейса не зависит): `brew install ollama`, `brew services start ollama`,
`ollama pull bge-m3`; `cli.py index --strategy all` на настоящем корпусе; `cli.py search
"куда пишется ключ API"` выдаёт кусок из `openspec/specs/config/spec.md`.
**Содержание**:
- `cli.py index --strategy structure|fixed|all [--index PATH]`, по умолчанию
  `rag/index.sqlite`. Порядок `all`: сначала `structure`, из него `размер_fixed`, затем `fixed`.
- Эмбеддинги — одной просьбой на файл (все куски файла). Отказ по длине — только тогда
  просьбы по одному куску, переполнивший кусок делится по ближайшему к середине `\n\n`
  (нет его — по `\n`) и повторяется рекурсивно; `chunk_id` частей — `…:<n>.<m>`.
- `сведения`: `model`, `dim`, `commit_hash` (`git rev-parse HEAD`), `dirty` (`git status
  --porcelain` по путям корпуса непуст), `built_at` ISO, `seconds`, `chunks`, `fixed_size`.
- `cli.py search "<вопрос>" [--strategy structure] [-k 5]` печатает место, косинус, `source`,
  `section`, первые строки текста.
- Вопрос эмбеддится как есть: у `bge-m3` нет приставок `query:`/`passage:`, в отличие от `e5`.

## Шаг 4. Сравнение стратегий на контрольном наборе
**Файлы**: `rag/compare.py`, `rag/cli.py` (команда `compare`), `rag/check_rag.py`
**Зависит от**: шаги 2 и 3
**Ход**: быстрый — читает индекс по договору `store`, пишет только свой отчёт.
**Требование**: не про myharness
**Проверка**: `check_rag.py` на подставном индексе из трёх кусков: место находки, `hit@1`,
`hit@5`, MRR считаются по известному ответу; фрагмент, разрезанный между двумя кусками, — не
попадание ни в одном. Живой: `cli.py compare --out week_5/day_1/сравнение.md`.
**Содержание**: попадание — фрагмент (пробелы свёрнуты) содержится в тексте куска (пробелы
свёрнуты). Место — номер первого попадания во **всей** выдаче: полный перебор и так упорядочивает
все куски, поэтому глубину выдачи выдумывать не нужно (`найти` с `k` = числу кусков стратегии).
Фрагмент, не лежащий целиком ни в одном куске, — место «разрезан», вклад в MRR 0. Отчёт: таблица сведений сборки; число кусков, длина наименьшая/медиана/наибольшая;
число кусков `fixed`, внутри которых лежит граница раздела `structure`; число фрагментов
набора, разрезанных нарезкой `fixed` (не лежат целиком ни в одном куске); `hit@1`, `hit@5`,
MRR; таблица по вопросам: вопрос, источник, место в каждой стратегии; выводы — абзацем,
пишет ведущий после замера.
