# План: местная модель как служба (день 30)

Дизайн — `docs/местная-служба.md`, состояние — `docs/состояние-местная-служба.md`.

## Изменения требований

Термин во всех требованиях — **«токен службы Ollama»**. Слово «ключ» остаётся за ключом DeepSeek.

- **`api`**, требование «Поставщика называет имя модели»:
  - определение одной фразой: местная модель — модель службы Ollama по адресу `OLLAMA_HOST`,
    где бы служба ни стояла; слово «местная» в приветствии и в `/model` значит «поставщик
    Ollama», показ не меняется;
  - при заданной непустой переменной окружения `OLLAMA_API_KEY` клиент Ollama SHALL слать её
    значение (токен службы Ollama) заголовком `Authorization: Bearer <значение>` во всех
    запросах к службе (`/v1` и `/api`). Переменная не задана либо пуста — прежняя
    строка-заглушка. Ключ DeepSeek в Ollama по-прежнему не уходит;
  - токен SHALL NOT уходить по открытому `http://` на непетлевой адрес: обмен кончается ошибкой,
    которая называет причину и адрес. Петлевые адреса — `127.0.0.1`, `localhost`, `::1`;
  - токен SHALL NOT попадать в журнал, профили и на экран;
  - новые сценарии: «служба за шлюзом с токеном», «токен и открытый адрес чужой машины».
- **`api`**, требование «Неудавшаяся установка соединения повторяется» (строки 77–79): запрет
  повтора для клиента Ollama остаётся. Меняется обоснование: служба Ollama отвечает сразу либо
  не запущена; для службы на чужом адресе повтор не заводится, пока нет замера обрывов на этом
  пути.
- **`api`**, требование «Словарь местной модели» (строки 183–185), и **`tokens`** (строки
  238–239, окно): ответ с кодом ошибки HTTP от шлюза перед службой (401, 429, 503) — это отказ
  службы, а не молчание. Словарь и окно за сеанс повторно не спрашиваются, счёт остаётся
  оценкой до перезапуска программы. Поведение кода не меняется, дописывается одна фраза.
- **`config`**, строка 6 и требование «Секрет не покидает файл настроек» (строки 81–83):
  уточнить «ключ DeepSeek API»; рядом с тайнами MCP назвать токен службы Ollama, который
  берётся из окружения.
- Обоснования со словами «на этой машине» (`api:57-58`, `tokens:154-155`, `batch:298-299`,
  `interface:396-399`, `commands:135`) остаются: они верны для умолчания `OLLAMA_HOST`, а
  определение в `api` называет случай чужого адреса. Приветствие адрес службы не называет —
  это отмечается в отчёте как известное упрощение.
- Соседние способности: `batch` («Наряду с местной моделью ключ DeepSeek не нужен»),
  `commands`, `tokens`, `config`, `interface`, `mcp` (приём для тайн из окружения).
- Шлюз — не часть `myharness`: требований в `openspec/specs/` у него нет.

## Договоры

### Заголовок токена (пишет `myharness`, читает шлюз)
**Отдаёт**: `providers.ollama_token() -> str` — значение `OLLAMA_API_KEY` без пробелов по краям
либо `"ollama"` (прежняя заглушка). Токен задан, а корень службы — `http://` на непетлевой адрес:
`ValueError` с причиной и адресом; `OllamaClient` отдаёт её как ошибку обмена без трассировки.
**Обещает**: каждый запрос `OllamaClient` несёт `Authorization: Bearer <ollama_token()>` — и
клиент `/v1`, и клиент `_native`.
**Не делает**: значение не пишет в журнал и исключения.

### Шлюз `llm_gateway/gateway.py` (читают Caddy, `проверка.py`, `myharness`)
**Владеет**: вёдрами частоты в памяти процесса (после перезапуска полные); журналом
`$LLM_GATEWAY_LOG` (JSONL, дописывание).
**Отдаёт**: `build_app(settings: Settings, transport: httpx2.AsyncBaseTransport | None = None)
-> Starlette`; `Settings.from_env(environ: Mapping[str, str]) -> Settings`.
**Настройки окружением**:

| Переменная | Значение на сервере |
|---|---|
| `LLM_UPSTREAM` | `http://127.0.0.1:11435` |
| `LLM_MODELS` | `qwen3.5:9b-q4_K_M-32k` (имена через запятую) |
| `LLM_RATE_PER_MINUTE` | `12` |
| `LLM_TOKEN_<имя>` | токен клиента `<имя>`; хотя бы один, иначе шлюз не стартует |
| `LLM_GATEWAY_LOG` | `/var/lib/llm-gateway/журнал.jsonl` |

**Обещает** — порядок проверок и коды:

```
нет токена или чужой токен            → 401
путь вне списка                       → 404
модель вне LLM_MODELS                 → 404  (чат и /api/show)
ведро клиента пусто                   → 429 + Retry-After: <секунд до жетона, вверх до целого>
вход + max_tokens > окна              → 400, error.code = "context_length_exceeded"
служба не принимает соединение        → 503, «узел модели недоступен»
иначе                                 → ответ службы как есть, поток без накопления
```

Тело отказа — вид OpenAI: `{"error": {"message": …, "type": …, "code": …}}`.
Разрешённые пути: `POST /v1/chat/completions`, `GET /v1/models`, `GET /api/tags`,
`POST /api/show`, `GET /api/ps`. Ответы `/v1/models`, `/api/tags` и `/api/ps` шлюз сужает до
моделей из `LLM_MODELS`. Жетон частоты тратит только `POST /v1/chat/completions`.
Токен клиента шлюз службе не передаёт. Сравнение токенов — `hmac.compare_digest`.
**Не делает**: текст запросов и ответов в журнал не пишет; своих пределов ожидания и своей
очереди не заводит; запрос не повторяет.

## Шаг 1. `myharness` шлёт токен службе Ollama

**Файлы**: `myharness/src/myharness/providers.py`, `myharness/src/myharness/api.py`,
`myharness/tests/check_units.py`, `openspec/specs/api/spec.md`,
`openspec/specs/tokens/spec.md`, `openspec/specs/config/spec.md`
**Зависит от**: ничего
**Ход**: быстрый. Читатель за границей файлов есть (шлюз), но договор — стандартный заголовок
Bearer из одной строки; отдельный исполнитель на три строки кода несоразмерен.
**Требование**: `openspec/specs/api/spec.md` → «Поставщика называет имя модели»
**Проверка**: в `check_units.py` рядом с проверками `OLLAMA_HOST` (строка ≈16553): подменный
транспорт запоминает заголовки. С `OLLAMA_API_KEY=тайна` оба клиента шлют `Bearer тайна`; без
переменной — `Bearer ollama` (парное значение). Отдельно: `OLLAMA_HOST=https://188.120.230.58:443`
даёт корень `https://188.120.230.58:443` без дописанного порта. Токен с
`OLLAMA_HOST=http://10.0.0.5:11434` даёт ошибку, с `http://127.0.0.1:11434` — уходит (пара).
**Содержание**: `providers.ollama_token()`; в `OllamaClient.__init__` вместо строки `"ollama"` —
`providers.ollama_token()`, клиенту `_native` — `headers={"Authorization": f"Bearer {ключ}"}`.
Правка абзаца требования и новый сценарий по разделу «Изменения требований».

## Шаг 2. Шлюз пропускает чат по токену и отсекает чужие пути и модели

**Файлы**: `llm_gateway/gateway.py`, `llm_gateway/tests/check_gateway.py`,
`llm_gateway/pyproject.toml`, `llm_gateway/uv.lock`
**Зависит от**: ничего
**Ход**: быстрый; шлюз в пределах шага сам пишет и сам читает, внешний договор выписан выше.
**Требование**: не про `myharness`
**Проверка**: `uv run python tests/check_gateway.py` — приложение через `httpx2.ASGITransport`,
служба — подставной транспорт. Сценарии: без токена 401 и с верным токеном 200 (пара); чужой
токен 401; `POST /api/pull` 404; модель вне списка 404; поток из трёх кусков доходит тремя
кусками; подставная служба бросает `ConnectError` → 503; токен клиента до службы не доходит;
строка журнала несёт клиента, модель, код и токены и не несёт текста реплики; `/api/tags`
сужен до разрешённых моделей. Журнал проверок — во временном каталоге через `LLM_GATEWAY_LOG`.
**Содержание**: `Settings` (неизменяемый класс данных: `upstream`, `models: frozenset[str]`,
`rate_per_minute: int`, `tokens: dict[str, str]` «токен → имя клиента», `log_path: Path`);
`Settings.from_env` бросает `SystemExit` с причиной, если нет ни одного `LLM_TOKEN_*` либо
пуст `LLM_MODELS`. Один обработчик на все пути. Клиент к службе — `httpx2.AsyncClient`
с `timeout=None`: модель думает долго, предел ожидания держит клиент шлюза. Поток:
`client.send(request, stream=True)` и `StreamingResponse(aiter_raw())`, закрытие ответа службы —
в фоновой задаче ответа. Токены входа и выхода для журнала шлюз берёт из поля `usage`
последнего куска потока либо тела ответа; поля нет — в журнале `null`.
Запуск: `python gateway.py --host 127.0.0.1 --port 8780`.

## Шаг 3. Шлюз держит частоту и окно

**Файлы**: те же, что у шага 2
**Зависит от**: шаг 2
**Ход**: быстрый; тот же шов, что у шага 2, один просмотр на оба шага — с узким поручением о
рисках безопасности (обход токена, обход списка путей и моделей, утечка токена и текста).
**Требование**: не про `myharness`
**Проверка**: в `check_gateway.py`, часы подменены доводом `clock` у `build_app`. Частота: при
`rate_per_minute=2` третий запрос подряд даёт 429 с `Retry-After: 30`, после сдвига часов на
30 с запрос проходит; ведро другого клиента при этом полно; `GET /v1/models` жетон не тратит.
Окно: подставная служба отдаёт `num_ctx 64` и словарь из `myharness/tests`; запрос в 10 токенов
проходит, запрос с текстом длиннее окна даёт 400 `context_length_exceeded`, короткий запрос с
`max_tokens: 100` даёт 400 (пара к первому).
**Содержание**: ведро токенов на клиента: вместимость `rate_per_minute`, пополнение
`rate_per_minute / 60` жетонов в секунду, время — `clock()` (умолчание `time.monotonic`).
Окно и словарь шлюз берёт у службы при первом запросе к модели и запоминает на время жизни
процесса: `OllamaClient.window(name)`, `OllamaClient.vocabulary(name)`,
`tokens.build_vocabulary`, `tokens.remember_vocabulary`. Вес входа —
`tokens.count_messages(messages, "ollama/"+name)` плюс `tokens.count_tools`. Выход — поле
`max_tokens` либо `max_completion_tokens` запроса, иначе 0. Служба окна либо словаря не дала —
проверка окна пропускается, в журнале `"окно": null`: отказывать по догадке шлюз не должен.
Фиксация шагов 2 и 3 — одна, с вердиктом просмотра.

## Шаг 4. Служба доступна из сети: туннель, systemd, Caddy

**Файлы**: `llm_gateway/deploy/llm-gateway.service`,
`llm_gateway/deploy/com.challenge.llm-tunnel.plist`, `mcp_servers/cbr/deploy/Caddyfile`,
`llm_gateway/README.md`, `docs/vps.md`
**Зависит от**: шаги 1 и 3
**Ход**: быстрый; настройка сервера, читатель — сам сервер. Файлы выкладки входят в просмотр
шва шагов 2–3, если готовы к нему; иначе их смотрит итоговый просмотр `Validation`.
**Требование**: не про `myharness`
**Проверка** (она же первый живой обмен; от интерфейса не зависит):
1. перед выкладкой — память: на сервере `python -c` строит словарь модели, `ps -o rss` меньше
   свободных 612 МБ с запасом под `cbr-mcp`; иначе стоп и возврат в `Research`;
2. `curl https://188.120.230.58/v1/models` без токена — 401;
3. `curl` чата с токеном с Мака — ответ модели;
4. тот же `curl` с сервера `challenge` — ответ модели;
5. `OLLAMA_HOST=https://188.120.230.58:443 OLLAMA_API_KEY=… uv run myharness --batch` с моделью
   `ollama/qwen3.5:9b-q4_K_M-32k` — ответ и точный счёт токенов;
6. `launchctl kill TERM` агенту туннеля — шлюз отвечает 503, затем туннель встаёт сам и чат
   отвечает; `https://188.120.230.58/mcp` по-прежнему отвечает 401 без токена.
**Содержание**:
- VPS: пользователь `llm-tunnel` (`useradd --system --shell /usr/sbin/nologin`), ключ
  `~/.ssh/llm_tunnel` на Маке (ed25519, без пароля). Ограничение — двумя слоями (находка
  просмотра шва: `port-forwarding` после `restrict` возвращает и прямую переадресацию `-L`):
  - `/etc/ssh/sshd_config.d/20-llm-tunnel.conf`: `Match User llm-tunnel` → `AllowTcpForwarding
    remote`, `PermitListen 127.0.0.1:11435`, `AllowStreamLocalForwarding no`,
    `AllowAgentForwarding no`, `X11Forwarding no`, `PermitTTY no`;
  - строка `authorized_keys`:
    `restrict,port-forwarding,permitlisten="127.0.0.1:11435",permitopen="127.0.0.1:1" ssh-ed25519 …`.
- Агент launchd: `ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30
  -o ServerAliveCountMax=3 -o IdentitiesOnly=yes -i ~/.ssh/llm_tunnel
  -R 127.0.0.1:11435:127.0.0.1:11434 llm-tunnel@188.120.230.58`, `KeepAlive` и `RunAtLoad`.
  Числа 30 и 3 — признак живого соединения ssh: обрыв замечается за 90 с.
- Служба: образец `mcp_servers/cbr/deploy/cbr-mcp.service` — `DynamicUser`, `StateDirectory=
  llm-gateway`, `EnvironmentFile=/opt/challenge/.env`, прочие настройки строками `Environment=`.
- Токены: `openssl rand -hex 32` на сервере, строки `LLM_TOKEN_mac` и `LLM_TOKEN_challenge` в
  `/opt/challenge/.env`. В репозиторий не попадают.
- Caddy: в блок узла добавить `@llm path /v1/* /api/*` → `reverse_proxy 127.0.0.1:8780` с
  `flush_interval -1`; `caddy validate`, затем `systemctl reload caddy`.
- Доставка: `rsync` каталогов `myharness/` и `llm_gateway/` по образцу `cbr-digest`
  (`docs/vps.md`), `uv sync --frozen --reinstall-package myharness`.
