## Договоры

### `support/store.py`
**Владеет**: файлом данных `SUPPORT_DATA` (умолчание `support/данные.json`). Пишут в него процессы
сервера `support` всех сеансов и веб-приложение при входе.
**Отдаёт**:
- `путь() -> Path`;
- `прочитать() -> dict` — без блокировки, как сейчас (`ToolError` при отсутствии и порче);
- `изменить(правка: Callable[[dict], T]) -> T` — блокировка `fcntl.flock` на файле `<данные>.lock`,
  чтение, `правка(данные)`, запись во временный файл рядом, `os.replace`;
- `войти(имя: str) -> dict` — пользователь по имени без учёта регистра и крайних пробелов; если его
  нет, заводит `{"user_id": "U-NN", "name": имя, "email": "", "registered": <сегодня ISO>, "os": "",
  "provider": "", "model": "", "env": {}, "mcp_servers": []}`, номер — наибольший плюс один.
**Обещает**: файл на диске всегда целый JSON; две одновременные записи не теряют ни одной; пустое
имя — `ValueError`.
**Не делает**: о вошедшем пользователе не знает — это дело `server.py`.

### Инструменты записи (`support/server.py`)
- `create_ticket(subject: str, text: str, error: str = "") -> Ticket` — номер `T-NNNN` наибольший
  плюс один, `created` — сейчас (`YYYY-MM-DDTHH:MM`), статус «открыт», `user_id` вошедшего.
- `add_message(ticket_id: str, text: str) -> Ticket` — сообщение `{"author": "ассистент", "at":
  сейчас, "text"}` в конец `messages`.
- `set_status(ticket_id: str, status: str, resolution: str = "") -> Ticket` — статус из
  {«открыт», «ждёт специалиста», «закрыт»}; «закрыт» без `resolution` — ошибка; другие статусы
  очищают `resolution`.

Чужой тикет — ошибка «тикет … не ваш», нет такого — «тикет … не найден», без входа — «вход не
выполнен», как у `get_ticket`. Пустые `subject`, `text` у `create_ticket` и `text` у `add_message` —
ошибка.

### `web/app.py`
**Владеет**: словарём сеансов в памяти `{номер куки: Сеанс}`; `Сеанс` держит пользователя, агента,
`mcp_tools.Соединения`, замок обмена. Каталоги `web/сеансы/<U-NN>/` и `web/state/` пишет только он.
**Отдаёт** (HTTP):
- `GET /` — `index.html`;
- `POST /api/login {"name"}` → `{"user", "history": [[вопрос, ответ], …], "models": [...]}` и кука
  `sid` (`HttpOnly`, `SameSite=Strict`);
- `POST /api/ask {"text", "model"}` → поток NDJSON: `{"kind": "content", "text"}`, `{"kind":
  "tool", "name", "args"}`, `{"kind": "tool_result", "name", "ok"}`, итог `{"kind": "done",
  "status", "error"}`;
- `GET /api/tickets` → тикеты вошедшего, новые первыми;
- `POST /api/new` — новый разговор;
- `POST /api/logout` — закрыть соединения MCP, забыть сеанс.

Без куки или с чужой — 401. Второй `/api/ask`, пока идёт первый, — 409.
**Обещает**: процессы серверов MCP сеанса закрываются на выходе, при новом входе того же
пользователя (прежний сеанс заменяется) и при остановке приложения — под замком обмена сеанса,
то есть после конца идущего ответа. Входы идут по одному. Остановка ждёт задач обменов.
**Не делает**: о тикетах в обмене ничего не пишет сам — пишет только модель инструментами.

## Шаг 1. Сервер `support` пишет в CRM
**Файлы**: `support/store.py`, `support/server.py`, `support/check_server.py`, `support/pyproject.toml` (описание)
**Зависит от**: ничего
**Ход**: быстрый. Чужой читатель — веб-приложение шага 2 — зовёт только `store.войти`, договор
выписан выше; запись на диск смотрит независимый просмотр шва шагов 1–2.
**Требование**: не про `myharness`
**Проверка**: `uv run python check_server.py` в `support/` на копии данных во временном каталоге
(`SUPPORT_DATA`); настоящий `данные.json` не меняется (`git status` чист).
**Содержание**:
- `server.py` читает через `store.прочитать`, пишет через `store.изменить`. Вошедший берётся внутри
  правки — из тех же данных, что правятся.
- Проверки — парами: `add_message` в свой T-1001 под U-01 проходит, в T-1002 под U-01 — «не ваш»;
  `set_status` «закрыт» без `resolution` — ошибка, с ней — проходит; `create_ticket` под U-03 даёт
  `T-1006`, второй — `T-1007`; неизвестный статус — ошибка; `store.войти("анна смирнова")` даёт U-01,
  `войти("Ирина")` — U-06, повторный `войти("ирина")` — тот же U-06. Одновременность: 20 потоков
  `store.изменить` дописывают по сообщению, в итоге 20 сообщений.
- Предусловие каждой проверки записи: файл данных — копия во временном каталоге.

## Шаг 2. Веб-приложение отвечает потоком
**Файлы**: `web/pyproject.toml`, `web/app.py`, `web/check_web.py`, `web/запуск.sh`, `.gitignore`
**Зависит от**: шаг 1
**Ход**: быстрый. Читателей за границей шага нет: каталоги сеансов пишет и читает только
приложение. Просмотр — вместе со швом шага 1.
**Требование**: не про `myharness`
**Проверка**: `check_web.py` (Starlette `TestClient`, без модели); живой обмен —
`curl` вход под «Борис Петров», вопрос «Тикет T-1002. Почему не работает авторизация?» на
`deepseek-v4-flash`: в потоке есть вызов `support__get_ticket` и `rag__search`, ответ про службу
Ollama. Это первый живой обмен; он не зависит от страницы (шаг 4).
**Содержание**:
- `pyproject.toml`: `myharness` путём `../../../myharness`, `starlette>=0.40`, `uvicorn>=0.30`.
  `store` берётся из `../support` путём в `sys.path`: сервер `support` пакетом не собирается.
- Окружение процесса задаёт `app.py` умолчаниями (`os.environ.setdefault`), окружение их перекрывает:
  `MYHARNESS_PROFILES=<день>/profiles`, `MYHARNESS_STATE_DIR=<web>/state`,
  `MYHARNESS_JOURNAL=<web>/журнал.jsonl`, `SUPPORT_DATA=<web>/данные.json`; каталог сеансов —
  `SUPPORT_WEB_SESSIONS`, умолчание `<web>/сеансы`.
  Нет `данные.json` — приложение копирует `support/данные.json` при старте.
- Каталог сеанса `web/сеансы/<U-NN>/`: `.mcp.json` — те же записи `rag` и `support`, что в
  `test/.mcp.json`, но `SUPPORT_USER` — значение номера, `SUPPORT_DATA` — путь рабочих данных;
  `.claude/settings.json` — `allow` из `test/.claude/settings.json` плюс
  `mcp__support__create_ticket`, `mcp__support__add_message`, `mcp__support__set_status`.
  Пишутся при каждом входе заново.
- Агент: `Agent("поддержка", profiles.load("поддержка")[0], инструменты=lambda:
  соединения.набор(каталог))`. История: `memory.latest_session(каталог, "поддержка")` →
  `memory.read_session(путь, window=0, system_fp=memory.fingerprint(profile.system))` →
  `agent.restore(pairs, приложения)`; затем `agent.set_store(memory.SessionStore(путь))`. Нет
  разговора — `memory.new_session(каталог, "поддержка")`. `/api/new` — новый путь и новый агент.
- Обмен: `agent.exchange(client, model, text, on_event=…)` — события кладутся в `asyncio.Queue`,
  ответ — `StreamingResponse` из очереди. `client` — один `api.Clients(config.load().api_key)` на
  приложение; `await client.prepare(model)` перед обменом.
- Модели: `deepseek-v4-flash` (умолчание) и `ollama/qwen3.5:9b-q4_K_M-32k`; другая — 400.
- `check_web.py`: вход «Анна Смирнова» → U-01; вход «Ирина» → U-06 и пользователь в рабочих данных;
  `/api/tickets` без куки — 401; кука Анны видит T-1001 и не видит T-1002; `.mcp.json` сеанса
  Бориса несёт `SUPPORT_USER` = `U-02`; модель вне списка — 400. Все данные — во временном каталоге.

**Зависит от**: шаги 1–2
**Ход**: быстрый: одна инструкция, читатель — модель.
**Требование**: не про `myharness`
**Проверка**: живьём через `curl` на `deepseek-v4-flash`, новый пользователь «Ирина»:
1. «У меня myharness пишет "Ollama не отвечает по адресу http://127.0.0.1:11434"» — ответ по FAQ,
   предложение завести тикет;
2. «Да, заведите» — в данных появился тикет Ирины со статусом «открыт», в переписке ответ;
3. «Запустил службу, всё заработало» — тикет «закрыт» с причиной;
4. «Как подключить myharness к Telegram?» — «В документации этого нет», после согласия тикет «ждёт
   специалиста».
Терминальный сценарий дня 33 не перегоняется: строки о записи срабатывают только при наличии
инструментов, а в песочнице `test/` их нет.
**Содержание**: раздел «Тикеты» инструкции:
- инструменты записи есть не всегда; нет их — этот раздел не действует;
- проблема без тикета — после ответа предложи завести тикет; заводи только с согласия;
- ответил по своему тикету — допиши ответ `add_message` коротко: причина и шаги;
- в документации нет ответа — с согласия заведи тикет и поставь «ждёт специалиста»;
- «закрыт» ставь, только когда человек сказал, что всё работает; `resolution` — что помогло;
- что записал, скажи человеку одной строкой с номером тикета.

под входом строка «Учебный вход без пароля». Текст ответа выводится как текст, не как HTML.
