# Дизайн: игровой агент (день 35)

## Задача и видение

Условие дня: «Видео + Код», при сдаче назвать решённую задачу. Задачу выбрал пользователь:
автоматизировать подбор компьютерных игр.

Видение пользователя:

- DeepSeek опрашивает человека о любимых играх, находит общее и формирует критерии вкуса.
- Местная модель раз в неделю смотрит будущие выпуски Steam и отмечает подходящие в календаре.
- Каждый день агент ищет вышедшие игры Steam и предлагает добавить их в список желаемых.
- При скидке на игру из списка желаемых агент уведомляет человека.
- Всё в веб-интерфейсе. Каждое предложение человек оценивает.
- Плюс — игра в список желаемых и под наблюдение скидок.
- Минус — игра в запреты (инварианты), DeepSeek пересматривает приоритеты.

Ответы пользователя 2026-10-16:

- игры человека агент узнаёт только опросом, ключ Steam не нужен;
- список желаемых — свой, в хранилище приложения, не в Steam;
- календарь — свой: страница-месяц в вебе и файл `.ics` для подписки;
- о скидке — лента уведомлений в вебе и системное уведомление macOS;
- код — в `main`, папка и ветка дня `w7d5` — под отчёт;
- **агент строится на `myharness` и это настоящий рабочий агент**, а не учебный показ.

Последнее решение меняет требования к устройству. Агент живёт месяцами. Значит, данные
переживают перезапуск и обновление, задания идут без человека, сбой виден, а не тих.

## Что решили и почему

### Устройство

```
человек ──► веб (Starlette, 127.0.0.1:8791, служба launchd)
              │ разговор, оценка, показ
              ▼
        Agent myharness (DeepSeek, профиль «игровой-советник»)
              │ инструменты MCP                    │ память myharness
              ▼                                    ▼
        сервер MCP `steam` ◄──────────┐     карточка папки агента:
        (магазин + хранилище SQLite)  │       «Любимые игры», «Общее», «Критерии», «Нежелательное»
              ▲                       │       «Ограничения» ← только плюс/минус человека
              │                       │
        задания launchd: неделя, день ┘
        (программа ведёт ход, местная модель судит через api.Clients myharness)
```

Рабочий каталог агента — `~/.local/share/games-agent/`. У `myharness` память привязана к
папке: разговор живёт по паре «каталог и профиль», карточка — по каталогу. Своя папка даёт агенту
свою память, отдельную от рабочих папок челленджа.

### Что берём из `myharness` как есть

| Способность `myharness` | Как служит агенту |
|---|---|
| `agent` — сущность `Agent` | веб-разговор; приём веб-чата дня 33 и `agents/digest` |
| `profiles` — пара `.json` и `.md` | профиль `игровой-советник`: инструкция опроса и пересмотра |
| `memory` — разговор | опрос переживает перезапуск службы |
| `memory` — карточка папки | профиль вкуса: разделы пишет модель |
| `memory` + `invariants` — «Ограничения» | запреты: строки пишет только человек, они уходят блоком «Инварианты» в каждый запрос |
| `mcp`, мост `mcp_tools` | инструменты магазина и хранилища модели, `permissions.allow` |
| `api` — `api.Clients`, приставка `ollama/` | местная модель в заданиях |
| `journal` | каждый обмен заданий и разговора записан |
| `tokens` | счёт расхода DeepSeek |

Агент работает только через веб. Терминал `myharness` для него не нужен (решение пользователя
2026-10-16).

### Опрос — один раз

Опрос идёт, пока в карточке нет «Критериев». Первый вход открывает разговор опроса. Когда
DeepSeek записал «Критерии», веб открывает главную страницу: предложения, желаемое, календарь,
лента. Повторный запуск службы опрос не начинает. Пройти его заново человек может кнопкой
«Пересобрать вкус» — она нужна, если вкус сильно поменялся.

### Профиль вкуса — карточка папки

У карточки нет перечня разделов: их называет тот, кто заполняет. Агент заполняет четыре раздела:
«Любимые игры», «Общее», «Критерии», «Нежелательное». Пишет их модель естественной записью
(способность `memory`), человек видит и правит их в вебе.

Критерии нужны поиску Steam, а он ищет по номерам меток (`search/results?tags=…`). Поэтому строка
«Критериев» имеет один вид: `<метка> (<номер>) — <вес>`, например `Ролевая игра (122) — 3`.
Инструмент `steam_tags` даёт модели список меток магазина. Программа заданий читает строки
«Критериев» и отвергает номер, которого в списке нет. Строку другого вида она пропускает и пишет
об этом в ленту, а не молчит.

Прежняя карточка при замене сохраняется запасной копией (`memory`). Отдельной истории версий
вкуса нет: её не просит видение, а второй список правок разошёлся бы с карточкой.

### Запреты — раздел «Ограничения»

По требованию `memory` раздел «Ограничения» пишет только человек: адрес записи называет он сам.
Оценка игры — слово человека: он сам и записал запрет (решение пользователя 2026-10-16).
Кнопка «минус» называет адрес записи. Программа пишет строку
`Не предлагать: <Игра> (<номер Steam>)` с источником «человек». Модель адреса не выбирает.

Запрет работает в двух местах:

1. Программа выбрасывает запрещённый номер до вопроса модели. Это гарантия.
2. Строка уходит блоком «Инварианты» в запрос DeepSeek (`П…`). Модель не предложит игру и в
   разговоре.

Человек снимает запрет кнопкой в вебе.

### Оценка

- **Плюс.** Игра идёт в список желаемых и под наблюдение скидок.
- **Минус.** Человек может назвать причину одной строкой, может и не называть.
  1. Программа пишет запрет в «Ограничения».
  2. Агент получает метки отвергнутой игры и причину. DeepSeek правит «Критерии» и
     «Нежелательное».
  3. Инструкция профиля: один минус не снимает жанр целиком. Иначе случайный минус сузит вкус.

### Сервер MCP `steam`

Местный сервер stdio в `mcp_servers/steam`, как `pipeline` в дне 19. Хранилище SQLite в
`~/.local/share/games-agent/games.sqlite`, путь переопределяет `GAMES_DATA_DIR`.

| Инструмент | Что делает | Модели |
|---|---|---|
| `steam_tags` | метки магазина | да |
| `steam_search` | поиск по меткам: вышедшие либо будущие | да |
| `steam_find` | поиск игры по названию: номер и точное имя | да |
| `steam_game` | описание, жанры, метки, дата, цена, оценка пользователей Steam | да |
| `list_suggestions` | предложения и их оценки | да |
| `list_wishlist` | желаемое с текущей ценой | да |
| `list_calendar` | будущие выпуски | да |
| `list_feed` | лента уведомлений | да |

Писать желаемое, оценки и календарь модели не дано: это делают кнопки человека и задания.
Так плюс и минус остаются словом человека, а не модели.

### Оценка пользователей Steam

Карточка предложения показывает оценку пользователей Steam: словесную сводку магазина и долю
положительных отзывов, например «Крайне положительные, 97 % из 862 216». Источник —
`appreviews/<номер>?json=1&language=all&num_per_page=0`, поле `query_summary`. Местная модель
видит ту же сводку в запросе отбора. Отзывов нет — так и пишется: «отзывов нет».

### Задания по расписанию

Два задания `launchd` на Маке — тот же приём, что таймер `systemd` в дне 18. Веб-служба — третий
файл `launchd` с автоперезапуском. Задание можно запустить кнопкой «Запустить сейчас».

Ход заданий ведёт программа, а не круг вызовов модели. Причина — замер дня 31: местная модель
зовёт инструменты не каждый раз. Пропущенный вызов в задании без человека — тихая потеря недели.

**Неделя — будущие выпуски.**

1. Программа читает «Критерии» и «Ограничения» из карточки.
2. Программа ищет `filter=comingsoon` по каждой метке критериев.
3. Программа выбрасывает запреты и уже показанные игры.
4. По каждой оставшейся игре программа берёт описание, метки и дату (`api/appdetails`).
5. Местная модель получает профиль вкуса и игру. Она отвечает по схеме JSON: «подходит» или «не
   подходит», и причину одной фразой.
6. Подходящая игра встаёт в календарь. Дата неточная («I кв. 2027») — игра идёт в список «дата
   не объявлена».

**День — вышедшие игры и скидки.**

1. Программа ищет вышедшие игры по меткам, порядок — по отзывам. Отбор — как в неделе.
2. Подходящие игры становятся предложениями в вебе.
3. Программа проверяет цену каждой игры из списка желаемых. Новая скидка — запись в ленте и
   уведомление macOS. Одну скидку по одной цене программа сообщает один раз.

Сбой задания (магазин не ответил, служба Ollama не поднята) — запись в ленте с причиной и
уведомление macOS. Рабочий агент не молчит неделю.

Числового порога «годности» нет: модель отвечает словом, а не баллом.

**Предел, названный вслух.** Поиск берёт одну страницу выдачи Steam на метку — 50 игр, это
умолчание магазина. Местная модель тратит около 2 с на игру (замер дня 27). Пять меток — около
250 игр и 8 минут на задание. Больше страниц — дольше задание. Менять — по слову пользователя.

### Отвергнутые подходы

- **Приложение мимо `myharness`.** Пользователь хочет рабочего агента на `myharness`. Свой
  клиент, своя память и свои запреты были бы вторым каналом рядом с работающим.
- **Отдельный файл профиля вкуса.** Карточка папки уже хранит знание с правами, запасной копией и
  показом. Второй файл разошёлся бы с ней.
- **Задания как свободный круг местной модели с инструментами.** См. замер дня 31 выше.
- **Настоящий список желаемых Steam.** Открытый API его не пишет, нужен пароль от учётной записи.
- **Google Календарь.** Нужен вход OAuth и тайна. Файл `.ics` подписывается из любого календаря.
- **Балл от 0 до 10 с порогом.** Порог — магическое число, подбирать его нечем.

### Автозапуск после первого запуска и карточки вкуса

```
«Игровой агент.app» (~/Applications) ── первый запуск ──► значок в строке меню ──► веб (дочерний процесс)
                                                              │ опрос в вебе
                                                              ▼
                                                 в карточке появились «Критерии»
                                                              │
                                                              ▼
                                   установка четырёх служб launchd: веб, значок, неделя, день
                                   дочерний веб и сам значок уступают место службам
```

- До карточки вкуса в автозапуске нет ничего: так сказал пользователь. Задания без «Критериев»
  всё равно упали бы.
- Карточка готова — значок ставит службы (`deploy/установить.sh`). После этого агент поднимается
  при входе в систему: веб, значок, задания по расписанию.
- Повторный запуск `.app` при установленных службах только открывает веб.

### Значок в строке меню

- Значок 🎮 со счётчиком: новые предложения плюс непрочитанные скидки, например «🎮 3».
- Нажатие открывает веб в браузере.
- Значок — отдельный процесс на PyObjC (`NSStatusItem`): строке меню нужен главный поток своего
  процесса, а веб занят Starlette. Счётчик значок берёт из `/api/state` раз в минуту — так часто
  новое появиться не может: задания идут раз в день и раз в неделю.
- У `.app` свой значок 🎮, его программа установки рисует из символа.

### Исправление ошибок в названиях игр

Поиск магазина прощает лёгкие опечатки, но не все (замер 2026-10-16: «baldurs gat 3» найден,
«stardew valey» и «Disco Elisium» — нет). Поэтому исправляет DeepSeek, а магазин подтверждает:

1. Новый инструмент сервера `steam_find(название)` — поиск магазина по названию (`api/storesearch`),
   номер и точное имя.
2. Инструкция советника: каждую названную игру проверить `steam_find`. Не нашлась — исправить
   написание самому и искать снова.
3. Имя в магазине отличается от написанного — переспросить: «Вы имели в виду Disco Elysium?».
4. В «Любимые игры» пишется точное имя Steam с номером.

### Находки живого прогона задания дня

Замер 2026-10-16 на пробной карточке из двух меток: 7 мин 30 с, найдено 89, судимо 76, подошли 44.

- **Порядок выдачи.** `sort_by=Reviews_DESC` давал малоизвестные игры с высокой долей отзывов.
  Порядок магазина по умолчанию — по соответствию метке — даёт заметные игры (Baldur's Gate 3,
  Age of Wonders 4, Rogue Trader). Берём его.
- **Свежесть выдачи.** Первая страница метки почти не меняется: через несколько дней все её игры
  станут показанными, и предложения иссякнут. Задание берёт **первую страницу метки, где есть
  непоказанные игры**, идя по страницам по 50. Своего числа страниц нет: предел — конец выдачи.
- **Ранжирование по оценкам** (вопрос пользователя 2026-10-16). Магазин сортирует «по отзывам» по
  одной доле положительных, и 100 % из 20 отзывов встаёт выше 97 % из 862 тысяч. Ранжируем сами
  оценкой SteamDB: `доля − (доля − 0,5) · 2^(−log10(всего + 1))` — малое число отзывов тянет к
  50 %, порога нет. По ней задание судит кандидатов (лучшие первыми), веб показывает предложения
  и календарь, карточка игры называет её числом. Будущие игры без отзывов идут в порядке
  желанности магазина.
- **Мягкий отбор.** 58 % «подходит». Инструкция отбора ужесточается: «подходит» — только при
  совпадении с критериями большого веса. Замер — на настоящей карточке после правки.

### Находки просмотра шва 2, меняющие решение

- **Календарь обновляется.** Задание недели заново берёт из магазина каждую игру календаря: дата
  уточнилась — событие появляется в `.ics`, выход перенесён — переносится. Игра вышла — она
  уходит из календаря в предложения, если человек её ещё не оценил.
- **Отказ модели запоминается вместе с отпечатком вкуса.** Отпечаток — хеш «Критериев» и
  «Нежелательного» карточки. Игра с отказом при том же отпечатке не судится снова. Вкус поменялся
  (минус, пересборка) — прежние отказы снова открыты для суда. Срока переспроса нет: повод
  переспросить один — вкус стал другим.
- **Минус убирает игру отовсюду.** Календарь, предложения и `.ics` не показывают игру с минусом
  и игру из «Ограничений».

### Десять игр (решение пользователя 2026-10-16)

«Во все не переиграть» — число 10 задал пользователь.

- Задание дня доливает **открытые** предложения (ещё без оценки) до 10. Десять неоценённых уже
  лежат — новых не ищет.
- Кандидаты судятся по убыванию оценки SteamDB; отбор останавливается на нужном числе подошедших.
- Календарь: за неделю — не больше 10 новых выпусков.

Предел «одна страница на метку, 50 игр» уходит: страницы берутся, пока не набрано нужное число
или не кончилась выдача.

### Вход в Steam — как принято у сторонних сайтов

Замер 2026-10-16:

- OpenID 2.0 Steam (`steamcommunity.com/openid`) отвечает. Это кнопка «Войти через Steam».
- `IPlayerService/GetOwnedGames` без ключа отвечает 401.
- Страница библиотеки `…/games?xml=1` требует входа.

Значит, вход идёт в два шага:

1. **«Войти через Steam».** Веб уводит на `steamcommunity.com/openid/login`, человек входит там, и
   Steam возвращает его на `127.0.0.1:8791/auth/steam`. Веб проверяет ответ у самого Steam
   (`check_authentication`) и берёт SteamID из `claimed_id`. Пароль агент не видит никогда.
2. **Ключ Steam Web API.** Человек заводит его сам на `steamcommunity.com/dev/apikey`, домен —
   `localhost`, и вставляет в веб один раз. Веб сразу проверяет ключ вызовом `GetOwnedGames`.
   Ключ лежит в `~/.config/games-agent/config.json` с правами 600, путь переопределяет
   `GAMES_CONFIG_DIR`. Ключ не попадает ни в журнал, ни на страницу, ни в запрос модели.

Отвергнуто: вход паролем и токен сеанса Steam. Токен даёт полный доступ к учётной записи, а
агенту нужно только чтение. Запись в настоящий список желаемых Steam поэтому по-прежнему нет.

Не замерено, проверю на ключе пользователя: отдаёт ли `GetOwnedGames` библиотеку закрытого
профиля владельцу ключа и читается ли закрытый список желаемых. Не отдаёт — веб скажет, какую
настройку приватности открыть.

### Мастер первого запуска — для любого человека

Вопрос пользователя 2026-10-16: агента можно отдать другому человеку. Тогда после входа в Steam
появляется страница настройки:

1. «Войти через Steam» → SteamID.
2. Три поля ключей, у каждого — пошаговая инструкция со ссылкой и проверка при сохранении:
   - **Steam Web API** — обязателен: библиотека и список желаемого;
   - **DeepSeek** — обязателен: опрос и пересмотр. Агент — отдельная программа, у другого человека
     `myharness` нет (поправка пользователя 2026-10-16). Поэтому ключ лежит в своём файле агента
     вместе с другими ключами и передаётся клиенту доводом `api.Clients(ключ)`; настройки
     `myharness` агент не читает. Каталоги `myharness` (`MYHARNESS_CONFIG_DIR`,
     `MYHARNESS_STATE_DIR`) веб и службы уводят внутрь каталогов агента;
   - **IsThereAnyDeal** — по желанию: исторический минимум.
3. Проверка местной модели: служба Ollama, `qwen3.5:9b-q4_K_M-32k`, `bge-m3`. Нет — страница
   называет команду установки.
4. Опрос вкуса с библиотеки.

Ключи меняются позже на странице «Настройки». За границей задачи — упаковка для чужого Мака
(подписанное приложение без репозитория и `uv`): другой человек клонирует репозиторий и
запускает `установить.sh приложение`.

### Библиотека и часы игры

- Задание дня берёт библиотеку: номер, имя, часы всего, часы за две недели, последний запуск.
- Купленная игра уходит из предложений, желаемого и календаря. Кнопка «Купил» не нужна.
- **Опрос начинается с библиотеки.** DeepSeek видит игры по убыванию часов и предлагает:
  «В Hades 120 ч — добавить в любимые?». Затем спрашивает про игры вне Steam.
- **Часы — довод вкуса.** Порогов в часах нет: модель видит часы рядом с играми и судит сама.
  «Купил и не играл» — повод спросить, а не вывод.

### Список желаемого Steam

Задание дня читает настоящий список желаемых (`IWishlistService/GetWishlist`). Его игры
наблюдаются на скидки наравне со своим списком желаемого. Ещё они довод вкуса: человек сам
хотел их. Писать в него нельзя — см. выше.

### Плашка игры и кнопки

- Нажатие на плашку открывает игру в клиенте Steam: `steam://store/<номер>` (решение
  пользователя). Рядом мелкая ссылка «в браузере».
- Кнопки плашки: «👍 Хочу», «👎 Нет», **«Уже играл»**. Последняя — для игр вне Steam: игра уходит
  из выдачи, агент спрашивает «понравилась?». «Да» — DeepSeek добавляет её в «Любимые игры»,
  «нет» — как минус.

### Скидки: исторический минимум

Уведомление о скидке называет исторический минимум цены по IsThereAnyDeal: «−50 %, 999 руб.;
минимум был 749 руб. в июне 2026». Нужен бесплатный ключ IsThereAnyDeal, он хранится там же, где
ключ Steam. Нет ключа — уведомление без минимума и одна строка в ленте об этом. Вид ответа
IsThereAnyDeal проверю на ключе.

### Выход игры из календаря

Задание дня видит игру календаря с датой «сегодня» — уведомление «Сегодня выходит …» один раз.

### RAG: похожие игры из вашей истории

Запрос местной модели сейчас несёт вкус и одну игру. Но вкус — обобщение, а точнее всего
говорят ваши решения по похожим играм. RAG переносит их на новую игру.

- **База знаний** — игры вашей истории: библиотека с часами, список желаемого, плюсы, минусы с
  причинами, «уже играл». Документ игры — имя, жанры, описание магазина и ваша отметка.
- **Индекс** — векторы местной `bge-m3` в Ollama, SQLite. Полная пересборка — раз в неделю, в
  задании недели (так сказал пользователь). Новая оценка дописывается в индекс сразу: иначе минус
  неделю не влиял бы на отбор.
- **Перед судом над кандидатом** — поиск самых похожих игр вашей истории. В запрос отбора они
  идут с отметкой: «похожа на Hades — 120 ч; на Outlast — минус: скучно».
- **Число похожих** — 5, по замеру поиска дня 23 (K₂ = 5). Своё число здесь не подбирается.
- **Цена.** Несколько сотен описаний `bge-m3` индексирует за минуты (день 32: 1296 кусков за
  158 с на этом Маке).
- **Выигрыш не замерен.** Замер — после первых 20 оценок человека: отбор с RAG и без него на тех
  же играх, совпадение вердикта модели с оценкой человека.
- Код поиска берётся из проекта `rag/` (векторы `bge-m3`, SQLite), а не пишется заново.

### Сверка вкуса раз в полгода

Число — пользователя. Задание недели видит, что последняя сверка была полгода назад и раньше.
Тогда оно пишет строку в ленту и шлёт уведомление, а веб показывает плашку «Пора сверить вкус».
Страница сверки показывает список любимых игр: убрать, добавить (название проверяется
`steam_find`), и DeepSeek пересобирает вкус. Игры, где часы сильно выросли с прошлой сверки,
модель предлагает добавить сама.

## Четвёртый заход Research (2026-10-16): местная модель на выбор, облако по желанию

Вопрос пользователя: хватит ли одной местной модели. Замер — тот же опрос на
`qwen3.5:9b-q4_K_M-32k` в песочнице:

| | DeepSeek | местная |
|---|---|---|
| инструменты | верно | верно (`list_library`, `steam_find` ×5, `steam_tags`, `save_taste`) |
| опечатки | исправлены, обе игры в любимых | найдены, в любимые не записаны |
| карточка | 4 игры, 10 критериев | 2 игры из 4, критерии годного вида |
| первая реплика | вопрос по часам | пустой ответ |
| язык | чистый | «роликовые игры», «казуалаки» |
| время ответа | секунды | 31, 152, 221 с |

Решение пользователя:

- **При установке мастер предлагает местную модель на выбор** и качает её из веба (Ollama
  `/api/pull`, ход загрузки на странице). `bge-m3` — всегда.
- **Облачная модель — по желанию, при входе.** Поле «облачная модель» с выбором поставщика;
  сейчас в выборе DeepSeek. Claude и OpenAI — отложенная задача 19 (поставщики `myharness`):
  у Claude свой протокол (SDK `anthropic`), у OpenAI свои словарь токенов, параметры и цены.
- **Без облачного ключа — только местная модель**, с предупреждением о последствиях по замеру
  выше. Советник тогда идёт на местной модели; для разговора с инструментами агент собирает себе
  вариант выбранной модели с окном 32 768 (Ollama `/api/create`, `num_ctx`), как файл модели дня
  26. Отбору хватает окна по умолчанию.

## Затронутые способности

Код `myharness` по замыслу не меняется. Требования `openspec/specs/` не затронуты. Если разведка
плана найдёт, что карточку чужой папки нельзя прочесть из программы без правки, правка пойдёт в
`main` своим шагом с требованием `memory`.

Новое в `main`:

| Часть | Что делает |
|---|---|
| `mcp_servers/steam/` | сервер MCP: магазин и хранилище SQLite |
| `agents/games/taste.py` | чтение «Критериев» и «Ограничений» карточки, запись запрета |
| `agents/games/judge.py` | местная модель: «подходит» или «не подходит» по схеме JSON |
| `agents/games/jobs.py` | задания недели и дня, уведомление macOS |
| `agents/games/web.py`, `index.html` | разговор с `Agent`, предложения, желаемое, календарь, `.ics`, лента |
| `agents/games/profiles/игровой-советник.{json,md}` | профиль агента |
| `agents/games/deploy/` | три файла `launchd` |
| `tests/` | разбор ответов магазина, строки критериев, фильтр запретов, учёт скидок — без сети и ключа |

## Границы

Делаем:

- опрос один раз, профиль вкуса в карточке, задания недели и дня, оценку с пересмотром, календарь с
  `.ics`, оценку пользователей Steam, список желаемых, скидки с уведомлением, ленту сбоев;
- службу веба и задания под `launchd`;
- проверки без сети;
- живой прогон и видео; папка и ветка дня `w7d5` — под отчёт.

Не делаем:

- вход в Steam, библиотеку и настоящий список желаемых Steam;
- терминальный вход в агента;
- несколько пользователей и вход по паролю: агент одного человека на `127.0.0.1`;
- магазины кроме Steam.

## Риски и чем расплачиваемся

- **Поиск Steam — не открытый API.** Номера игр программа достаёт из HTML-ответа поиска
  (`data-ds-appid`). Магазин сменит разметку — поиск сломается. Сбой виден в ленте.
- **Магазин ограничивает частоту.** `api/appdetails` отказывает примерно после 200 запросов за 5
  минут (по опыту сообщества, сам не замерял). Задание повторяет запрос после паузы.
- **Местная модель ошибается в отборе.** Мера — минус человека правит профиль.
- **Строки «Критериев» пишет модель.** Строка не того вида выпадет из поиска. Мера — запись в
  ленте и показ карточки в вебе.
- **Уведомление macOS из `launchd`.** Система может спросить разрешение при первом показе. Проверю
  живым прогоном.
- **Скидки на видео.** Настоящей скидки на игру из списка может не быть в день съёмки. Подделывать
  скидку не буду.
