## Изменения требований

- **`files` (новая способность).** Требования: пять инструментов и их доводы; корень —
  рабочий каталог, `realpath`, отказ наружу; `Read` — 2000 строк, 25 000 токенов,
  `PARTIAL view`, 256 КБ, `allow_large`; `Grep` — три режима, `head_limit`/`offset`,
  `.gitignore`; `Glob` — 100 путей по времени; запись только после полного `Read`, запрет
  `.git/`, `.claude/`, `.mcp.json`; запись по умолчанию только в хранилище `git`; правила
  `Read`, `Edit` и точные имена в `allow`/`deny`. Ссылается на `mcp` («Разрешение модели» —
  тот же файл правил).
- **`mcp`, «Разрешение модели».** Файл правил несёт и правила встроенных инструментов; правила
  `mcp__` действуют как прежде. Новое требование «Большой результат инструмента»: длиннее
  50 000 знаков или 25 000 токенов — в файл каталога состояния, модели путь и первые
  2000 знаков; ошибка длиннее 11 000 знаков — первые и последние 5000. Действует для MCP
  главного агента, помощника и для файловых инструментов. Соседи: `files`, `commands`
  (`/help` — помощник).
- **`batch`.** Агент наряда получает файловые инструменты; инструментов MCP по-прежнему нет
  (отложенная задача 17). Сосед: `files`.
- **`interface`.** Вызов файлового инструмента показывается путём, результат `Edit`/`Write` —
  многострочным `diff` с цветом строк. Сосед: `files`.
- **`agent`.** Агент по-прежнему не знает диска, выгрузку делает обёртка набора. Сценарий
  «агент без хранилища — в каталоге состояния ни одного файла» уточняется: «ни одного файла
  разговора»; выгрузка большого результата помощника — исключение со ссылкой на `mcp`.
  Агент отдаёт вес запроса (см. «Решения первого рубежа», п. 8).
- **`tokens`.** Перечень «обмена без инструментов» дополняется файловыми инструментами
  ссылкой на `files`.
- **`commands`.** Помощник `/help` не получает файловых инструментов — строка в перечне того,
  что он SHALL NOT получать.
- **`config`.** Ключ не попадает к модели: файловые инструменты не читают каталог настроек
  (ссылка на `files`).

## Решения первого рубежа `Spec` (2026-10-15)

Проверяющий нашёл семь противоречий. Каждое закрыто решением ниже; требования пишутся по нему.

1. **`mcp` «Разрешение модели» сужается.** «Только разрешённые `allow`» и «неразрешённый не
   предлагается» относятся к инструментам MCP. У встроенных своё умолчание: чтение — всегда,
   запись — в хранилище `git`. Довод — Codex (недоверенный каталог только на чтение) и отмена
   через `git`, а не Claude Code: тот без человека запись не даёт.
2. **Правило с путём у встроенного инструмента.** `deny` с путём (`Read(./.env)`,
   `Edit(src/**)`) снимает инструменты своего рода целиком: `Read(…)` — `Read`, `Glob`,
   `Grep`; `Edit(…)` — `Edit`, `Write`. Набор несёт жалобу «правило с путём не поддержано,
   инструменты сняты». Безопасная сторона: запрет не пропадает молча. `allow` с путём
   пропускается, как прежде `Bash(...)`.
3. **Испорченный файл правил** снимает все файловые инструменты, жалоба с путём; фраза
   `mcp` «SHALL NOT давать ни одного правила» ссылается на `files`. Иначе
   пропавший `deny` давал бы запись по умолчанию.
4. **Каталог настроек закрыт.** `Read`, `Glob`, `Grep` отказывают в путях внутри
   `config.config_dir()`. Из каталога состояния читается только каталог выгрузки этого
   рабочего каталога. Ключ остаётся только в файле настроек (`config`).
5. **Наряд выгружает во временный каталог** на время наряда, по концу наряда каталог
   удаляется. Требование `batch` «ни одного файла в каталоге состояния» не меняется.
6. **`mcp` «успешный результат — как есть»** правится: до предела — как есть; сверх — модели и в
   `звенья` журнала уходит сокращённый текст, целый результат лежит в файле выгрузки.
7. **`tokens`** — см. «Изменения требований».
8. **`allow_large`.** Свободное место = `tokens.window(модель)` − вес текущего запроса вместе
   со звеньями идущего круга и местом под ответ (`Agent.с_местом_под_ответ`). Агент хранит
   последний посчитанный вес в свойстве `Agent.вес_запроса: int | None`, обновляет его перед
   каждым потоком круга. `None` — отказ `allow_large`.
9. **Разрешение на миг вызова.** `исполнить` встроенного инструмента перечитывает правила, как
   MCP: снятое посреди круга правило отказывает следующему вызову.
10. **Ошибка MCP с `isError`** — исключение `RuntimeError` (`mcp_tools.py:338-384`), поэтому
    идёт веткой ошибки выгрузки: сокращение до 5000 + 5000, а не файл.
11. **Где действуют.** Главный агент и наряд. Не получают: помощник `/help`, ветви Branching,
    экраны стратегий, исполнители группы, шаги способов, служебные агенты.
12. **Права выгрузки.** Каталоги `700`, файлы `600`, как разговоры (`memory`).
13. **Выгрузка не чистится**, как у Claude Code. Решение записывается в `mcp` «Большой
    результат инструмента».
14. **Старшинство имён** между наборами в требования не идёт: приставка `mcp__` исключает
    совпадение со встроенными именами.
15. **Ограничение, а не правка:** запретные признаки инвариантов и судья смотрят ответ, а не
    `content`/`new_string` записи. Правило «не Go» обходится записью файла. Записывается в
    `files` как известное ограничение; правка — отдельной задачей.

## Договоры модулей

### `files_tools`
**Владеет**: учётом прочитанного `Учёт` — словарь «путь → (время изменения, полное ли чтение)»
на одного агента. Доступ только у набора этого агента.
**Отдаёт**:
- `class Учёт` — пустой при создании.
- `def набор(корень: Path, модель: Callable[[], str], свободно: Callable[[], int | None], учёт: Учёт, выгрузка: Path) -> Инструменты`
  — `корень` берётся на миг вызова поставщиком набора; `модель` — имя модели для счёта токенов;
  `свободно` — свободное место окна для `allow_large`, `None` — неизвестно; `выгрузка` —
  каталог больших результатов, `Read` его читает.
- `ИМЕНА = ("Read", "Write", "Edit", "Glob", "Grep")`.
**Обещает**: исполнитель не пишет вне `корень`, не пишет в `.git/`, `.claude/`, `.mcp.json` на
любой глубине; схемы `Write` и `Edit` есть в наборе, только если запись разрешена: правило
`allow` либо `корень` внутри хранилища `git` (поиск `.git` вверх по дереву) и нет `deny`.
Отказ — исключение `ValueError` с текстом для модели; агент сделает из него «ошибка
инструмента: …».
**Не делает**: сети не знает, процессов не запускает, кроме `git ls-files` в `Grep`; не читает
`config.config_dir()`; из каталога состояния читает только `выгрузка`. Правила перечитывает
на каждом вызове (`mcp_tools.прочитать_разрешения(корень)`).

### `tool_output`
**Отдаёт**: `def с_выгрузкой(набор: Инструменты | None, каталог: Path, модель: Callable[[], str]) -> Инструменты | None`;
`def каталог_выгрузки(cwd: Path) -> Path` — `memory.state_dir() / "tool-results" / memory.project_key(cwd)`.
**Обещает**: схемы и жалоба набора не меняются; успешный результат длиннее 50 000 знаков или
25 000 токенов (`MYHARNESS_MAX_TOOL_OUTPUT_TOKENS`) пишется в `<каталог>/<uuid>.txt`, модели
уходит путь и первые 2000 знаков; ошибка (исключение) длиннее 11 000 знаков сокращается до
первых и последних 5000 знаков и выпускается тем же исключением.
**Не делает**: файлов не удаляет — как Claude Code, он хранит их рядом с сеансом.

## Шаг 1. Модель читает и ищет файлы рабочего каталога
**Файлы**: `files_tools.py`, `openspec/specs/files/spec.md`, раздел проверок в `check_units.py`
**Зависит от**: ничего
**Ход**: быстрый — новый модуль, читателей за границей шага пока нет
**Требование**: `openspec/specs/files/spec.md` → требования о корне, `Read`, `Glob`, `Grep`
**Проверка**: на временном каталоге `набор(...).исполнить("Read", ...)` отдаёт строки с
номерами; файл в 3000 строк — 2000 строк и `PARTIAL view`; `../x` и символическая ссылка
наружу — отказ; `Grep` пропускает файл из `.gitignore`, `Glob` отдаёт новые первыми и метит
обрезку на 101-м файле.
**Содержание**:
- `_путь(корень, выгрузка, сырое, запись: bool) -> Path`: относительный путь — от корня;
  `Path.resolve()`; внутри `корень.resolve()` либо (только чтение) внутри `выгрузка.resolve()`;
  иначе `ValueError("путь вне рабочего каталога: …")`.
- `Read`: `offset` с 1, `limit` по умолчанию 2000; формат `f"{номер:>6}\t{строка}"`; файл
  больше 262 144 байт без `offset`/`limit` и без `allow_large` — отказ; счёт `tokens.count_text`
  моделью `модель()`; целый файл сверх 25 000 (`MYHARNESS_FILE_READ_MAX_OUTPUT_TOKENS`) —
  строки, пока влезают, и пометка `[PARTIAL view: показаны строки 1–N из M; читай дальше
  offset и limit]`; часть сверх предела — отказ с советом; `allow_large` — предел
  `свободно()`, `None` — отказ «свободное место окна неизвестно»; пустой файл и `offset` за
  концом — пометка с числом строк; нулевой байт в первых 8 КБ или не UTF-8 — отказ.
- `Glob`: `pattern`, `path`; обход `Path.glob`, без `.git`; сортировка по `st_mtime` убыванием;
  101-й путь отсекается, строка `(показаны 100 из M; уточни шаблон или path)`.
- `Grep`: `pattern` (Python `re`), `path`, `glob`, `output_mode`, `-i`, `head_limit`, `offset`;
  список файлов — `git ls-files -co --exclude-standard` внутри хранилища, иначе обход без
  `.git`; двоичные пропускаются; `content` — `путь:номер:строка`; `count` — `путь:число` и итог;
  `offset` за концом — `No entries at this offset`.
- Описания схем по-русски, с правилами из дизайна.

## Шаг 2. Модель правит и создаёт файлы с `diff` в ответе
**Файлы**: `files_tools.py`, `mcp_tools.py` (`прочитать_разрешения`, `Разрешения`),
`openspec/specs/files/spec.md`, `openspec/specs/mcp/spec.md` («Разрешение модели»), проверки
**Зависит от**: шаг 1
**Ход**: быстрый — `прочитать_разрешения` читает и сервер MCP, но вид правил `mcp__` не
меняется, и это ловит прежняя проверка
**Требование**: `files` → запись, запреты, разрешение; `mcp` → «Разрешение модели»
**Проверка**: `Edit` без `Read` — отказ; после `Read` — правка и `diff` с `---`/`+++`; два
вхождения без `replace_all` — отказ; `Write` в `.git/config` и `sub/.claude/settings.json` —
отказ; каталог без `.git` — схем `Edit`/`Write` нет, с `allow: ["Edit"]` — есть; `deny:
["Edit"]` в хранилище — нет; `Read` с `PARTIAL view` не открывает `Edit`.
**Содержание**:
- `Разрешения` получает `встроенный(имя) -> bool | None`: `True` — разрешён правилом, `False`
  — запрещён, `None` — правила нет. Правило `Read` покрывает `Read`, `Glob`, `Grep`; `Edit` —
  `Edit`, `Write`; точные имена тоже годны. Правила со скобками пропускаются.
- `прочитать_разрешения` оставляет строки `mcp__…` и строки из `ИМЕНА ∪ {"Read","Edit"}`.
- Чтение разрешено, пока нет `deny`. Запись: `deny` → нет; `allow` → да; иначе — есть ли
  `.git` (файл или каталог) в корне или выше.
- `Edit`: файл есть в `Учёт` с полным чтением; `old_string` ≠ `new_string`; вхождений ровно 1
  либо `replace_all`; запись UTF-8; ответ — `difflib.unified_diff` с путём от корня.
- `Write`: новый файл — без чтения, каталоги создаются; поверх — полное чтение и прежнее
  `st_mtime`, иначе «файл изменился после чтения»; ответ — `diff`.
- После записи `Учёт` обновляет время изменения файла.

## Просмотр

Один просмотр на шов: шаги 1–3 (ядро инструментов и выгрузка) — после шага 3; шаги 4–5 —
после шага 5. Разбор рисков безопасности входит в первый просмотр узким поручением: выход
из корня, запись в настройки прав, `git ls-files`.

## Шаг 7. Доверие папке при первом запуске (поправка дизайна 2026-10-15)
**Файлы**: `trust.py` (новый), `config.py`, `cli.py`, `files_tools.py` (`права`),
`openspec/specs/files/spec.md`, `openspec/specs/config/spec.md`, проверки `check_files.py`
**Зависит от**: шаги 1–6
**Ход**: быстрый — `trust` читает `files_tools.права` и `cli.main`, оба меняются в этом же шаге
**Требование**: `files` → «Доверие папке» (новое) и «Разрешение файловых инструментов» (правило
`git` заменено доверием); `config` → поле `trusted_dirs`
**Проверка**: во временном каталоге настроек: папка вне `git` без доверия — три схемы чтения;
`trust.доверить` — пять схем, запись в `config.json` с правами `600`; подпапка доверенной папки —
пять схем; домашний каталог (`HOME` во временный) — доверие на сеанс, в файл не пишется. Живой
запуск `myharness` в новой папке: вопрос, «2» — выход без окна, «1» — окно и запись в настройках.
**Содержание**:
- `config.Config.trusted_dirs: list[str]`, `load` берёт список строк, прочее — пустой список.
- `trust.ключ(cwd) -> Path` — корень `git` (`.git` вверх по дереву), вне `git` — `cwd`.
- `trust.доверена(cwd) -> bool` — `cwd` и предки до корня `git` (вне `git` — до корня
  файловой системы) против `trusted_dirs` и доверия сеанса.
- `trust.доверить(cwd)` — домашний каталог: в доверие сеанса; иначе `ключ(cwd)` в `trusted_dirs`,
  `config.save`.
- `trust.спросить(cwd, ввод=input, вывод=print) -> bool` — текст вопроса из дизайна; «1» —
  доверить, «2», конец ввода, `Ctrl+C` — `False`.
- `cli.main`: до `asyncio.run` — `if not trust.доверена(cwd) and not trust.спросить(cwd): return`.
- `files_tools.права`: `в_git(корень)` заменяется на `trust.доверена(корень)`. `в_git` остаётся
  для `Grep` (список файлов `git ls-files`).
