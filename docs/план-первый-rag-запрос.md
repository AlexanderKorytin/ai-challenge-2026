## Договоры модулей

### `rag/server.py` — инструмент `search`
**Отдаёт**: инструмент MCP `search(query: str, k: int = 5) -> str`; функция
`найти_текст(вопрос: str, k: int, индекс: Path, считать=эм.эмбеддинги) -> str`.
**Обещает**: текст ответа — куски по убыванию близости, каждый так:
```
[1] openspec/specs/config/spec.md › Requirement: Права файла настроек (0.712)
<текст куска>
```
пустая строка между кусками. Строка-заголовок куска всегда начинается с `[n] <путь> ›` —
по ней `rag/eval.py` узнаёт найденные источники. Стратегия — `structure`, индекс —
`$RAG_INDEX` либо `rag/index.sqlite`. `k` < 1 — ошибка инструмента.
**Не делает**: не пишет на диск, ключей не знает; Ollama недоступна — ошибка инструмента с
причиной (`isError`), а не падение процесса.

### `mcp_tools.Поиск`
**Владеет**: своими `_Держатель` по имени сервера; `Соединения` о них не знает и их не закрывает.
**Отдаёт**: `async найти(каталог: Path, сервер: str, вопрос: str) -> str`,
`async закрыть() -> None`.
**Обещает**: сервер берётся из `.mcp.json` каталога по имени **без** правил `permissions` —
вызывает программа по указанию профиля, а не модель; соединение одно на сервер на весь сеанс;
перед вызовом запись сверяется с `.mcp.json` (изменилась — закрыть и открыть) и живость —
`отвечает(срок)`, умершее открывается заново; сверка и переоткрытие — под `asyncio.Lock`,
сам вызов — вне замка (одновременные вызовы наряда); вызов идёт с
доводами `{"query": вопрос}`; результат — текст `_текст_результата`.
**Не делает**: исключений, кроме `RuntimeError` с причиной (нет сервера в файле, не поднялся за
`MCP_TIMEOUT`, `isError`, обрыв), не выпускает; тайны в причине вычищены как у `Соединения`.

### `Agent` — поставщик поиска
**Отдаёт**: доводом конструктора `поиск: Callable[[str], Awaitable[str]] | None = None`;
`build_messages(..., найденное: str = "")`.
**Обещает**: поставщик зовётся один раз за `exchange`, до сборки, с вопросом человека
(`content`); непустой результат идёт в хвост последнего сообщения блоком
```
Найдено в базе знаний по вопросу:

<текст поставщика>
```
перед рабочим состоянием и вопросом; в память (`remember`, история) не попадает; сбой —
жалоба `не удалось найти в базе знаний: <причина>` в `store_error`, обмен идёт без блока.
Без поставщика запрос байт в байт прежний.

## Изменения требований

Первый рубеж `Spec` (2026-09-29) вернул четыре находки и жалобу поиска; ниже — исправленный
раздел.

- **profiles**: новое «Режим RAG задаётся полем rag» — строка, имя сервера из `.mcp.json`;
  пусто или нет поля — режим выключен; не строка — предупреждение, поле отброшено; поле входит в
  слепок профиля (требование «Слепок профиля для журнала» дополняется).
- **agent**: новое «Найденное в базе знаний идёт в хвост запроса»:
  - при поставщике поиска агент до сборки ищет по вопросу человека; блок стоит в последнем
    сообщении перед рабочим состоянием и вопросом;
  - **хвост** — место в последнем сообщении, общее для блока рабочего состояния и блока
    найденного; найденное — **не слой памяти**: в `/memory`, `/forget` не входит, в память и
    историю не оседает;
  - блок входит в вес обрезки, в признак «сверх предела» и в предупреждение перед каждым
    следующим потоком круга вызовов ровно тем текстом, что уходит (по образцу «вес считается вместе с
    инвариантами»); требование о составе веса обрезки (`agent`, перечень частей запроса)
    дополняется;
  - сбой поиска — жалоба тем же путём, что жалоба набора инструментов (рядом с результатом
    обмена, в выводе наряда); обмен идёт без блока; в журнале его отсутствие видно по
    отправленному сообщению — нового поля нет.
- **memory**: «хвост» в требовании о рабочей памяти уточняется — несёт рабочее состояние наряду
  с найденным; `/system` печатает системную часть и хвост рабочего состояния, а блок найденного
  собирается по вопросу и **в показ не входит** — `/system` говорит строкой «режим RAG: сервер
  <имя>, найденное подставляется по вопросу», отправленный блок лежит в журнале. Обоснование
  «наряд воспроизводим, слои меняются» не задевается: найденное не слой; воспроизводимость
  наряда с `rag` держится снимком индекса (фиксация в сведениях сборки) и журналом.
- **tokens**: вне обмена (полоска, предупреждение до отправки) блок найденного **не
  учитывается** — он неизвестен до вопроса и меняется от вопроса к вопросу, в отличие от
  описаний инструментов; внутри обмена обрезка меряет его точно. Переполнение окна из-за найденного до отправки
  первого потока **не предупреждается** — названо прямо (пять кусков против окна в миллион
  токенов). Оговорка дописывается рядом с
  «вес описаний берётся по последнему обмену».
- **mcp**:
  - «Разрешение модели»: запрет запуска сервера без разрешённых инструментов касается
    соединения ради инструментов модели; сценарий «правил нет» — «…если сервер не назван
    полем `rag` профиля»;
  - `Purpose`: второй потребитель — поиск программы, у главного собеседника и в наряде;
  - новое «Поиск программы»: сервер, названный полем `rag`, запускается без правил
    `permissions`, его `search` зовёт программа; соединение на сеанс, перед вызовом запись
    сервера сверяется с `.mcp.json` (изменилась или исчезла — закрыть, открыть заново) и
    живость — `ping`; тот же сервер, разрешённый ещё и модели, живёт вторым процессом — это
    допустимо; «Кто получает инструменты MCP» не меняется.
- **batch**: новое «Наряд ведёт режим RAG профиля» — задание с `rag` ищет перед обменом;
  соединение одно на наряд, одновременные вызовы по нему допустимы, переоткрытие умершего —
  одно на всех (под замком), закрыто по концу наряда; жалоба поиска печатается строкой задания.

Соседи: `journal` (отправленные сообщения несут блок; перечень слепка дополняется `rag`),
`commands` — без правки (`/system` описан в `memory`).

## Шаг 1. Сервер `rag` отвечает на `search` найденными кусками
**Файлы**: `rag/server.py`, `rag/pyproject.toml`, `rag/uv.lock`, `rag/check_rag.py`
**Зависит от**: ничего
**Ход**: быстрый — читатели формата (шаги 3 и 5) пишутся по договору этого плана.
**Требование**: не про myharness
**Проверка**: `uv run --project rag rag/check_rag.py` — новая проверка: `найти_текст` на
подставном индексе даёт `[1] <путь> ›` и порядок по близости, `k=0` — ошибка; живой вызов:
учебный клиент `mcp` по stdio зовёт `search("права файла настроек")` на настоящем индексе —
в ответе `openspec/specs/config/spec.md`.
**Содержание**: `MCPServer("rag")`, `@сервер.tool()` `search`, описание доводов подписью, как у
`pipeline`; `найти_текст` через `store.найти(индекс, "structure", вектор, k)`; `ОшибкаЭмбеддера`
→ `ToolError`. Запуск: `uv run --project rag rag/server.py`.

## Шаг 2. Профиль с полем `rag` кладёт найденное в запрос агента
**Файлы**: `profiles.py`, `agent.py`, `tests/check_units.py`
**Зависит от**: ничего
**Ход**: быстрый — код пишет ведущий, независимый просмотр шва; читатели хвоста (обрезка,
журнал, `/system`) меряют `payload`, и договор сохраняет его единственной склейкой.
**Требование**: profiles → «Режим RAG задаётся полем rag»; agent → «Найденное в базе знаний
идёт в хвост запроса»
**Проверка**: проверки в `check_units.py` — (а) агент с подставным поставщиком: последнее
сообщение запроса начинается с блока, память после обмена содержит только вопрос; парная — без
поставщика запрос прежний; (б) поставщик бросает — `store_error` с «не удалось найти», ответ
получен; (в) профиль `"rag": 5` — предупреждение, режим выключен; слепок несёт `rag`.
**Содержание**: `Profile.rag: str = ""`, разбор `_rag(raw, warnings)`; в `exchange` до
`build_messages`: `найденное, жалоба_поиска = await self._найти(content)`; жалоба дописывается в
`store_error` **после** сборки, как жалоба набора, иначе сборка её затрёт; `_с_хвостом(content,
найденное)` склеивает `блок найденного`, `хвост работы`, `content` через `\n\n`, пустые части
пропускаются.

## Шаг 3. Главный собеседник и наряд ищут через сервер из `.mcp.json`
**Файлы**: `mcp_tools.py`, `state.py`, `cli.py`, `batch.py`, `tests/mcp_учебный_сервер.py`,
`tests/check_units.py`
**Зависит от**: шаг 2 (довод `поиск`)
**Ход**: быстрый — провод и обёртка по образцу `Соединения`; просмотр шва вместе с шагом 2.
**Требование**: mcp → «Поиск программы»; batch → «Наряд ведёт режим RAG профиля»
**Проверка**: `check_units.py` — `Поиск.найти` на учебном сервере возвращает текст `search`;
второй вызов — тот же процесс; сервер без правил `permissions` всё равно запускается; имени нет
в `.mcp.json` — `RuntimeError` с именем; `закрыть` не оставляет процесса. **Живой обмен**
(первый, не зависит от интерфейса): `myharness --batch` из песочницы шага 5 на одно задание
профилем с `rag` — в журнале последнее сообщение начинается с «Найдено в базе знаний».
**Содержание**: `class Поиск` рядом с `Соединения` (переиспользует `_Держатель`,
`mcp_client.прочитать`, `предел`, `описать_сбой`); `State.поиск: mcp_tools.Поиск`; в провод
главного: `поиск=(lambda q: state.поиск.найти(Path.cwd(), profile.rag, q)) if profile.rag
else None`; `cli.py` рядом с `state.mcp.закрыть()` — `state.поиск.закрыть()`; `run_order`
заводит `Поиск()` на наряд, отдаёт агенту задания с `rag`, закрывает в `finally`; после обмена
печатает `turn.store_error` строкой задания, как `journal_error`. `/system` (где он собирается —
найти по `work_block`) дописывает строку «режим RAG: сервер <имя>, найденное подставляется по
вопросу» при `profile.rag`.
