# План: местная модель в `myharness`

Дизайн — `docs/местная-модель.md`, состояние — `docs/состояние-местная-модель.md`.
Шаги 1–3 — общая задача в `main`. Шаг 4 — день 26 в ветке `w6d1`.

## Отступление от дизайна: ключ остаётся обязательным

Дизайн обещал работу с местной моделью без `/auth`. План это снимает. Признак
`config.is_authorized` держат девять мест интерфейса: приветствие, ввод, список команд, панель
агентов, наряд. Архивариус, судья и распознаватель всё равно идут в DeepSeek и требуют ключа. Сжиматель
идёт моделью разговора, как велит `agent` → «Модель сжимателя»: это требование не меняется. Ключ у пользователя
есть. Правка девяти мест ради случая, которого нет, несоразмерна задаче дня.

Что остаётся обязательным: **ключ DeepSeek в Ollama не уходит**. Местный клиент получает
строку-заглушку `ollama`.

## Договоры модулей

### `providers`
**Владеет**: ничем, состояния нет.
**Отдаёт**:
- `OLLAMA_PREFIX = "ollama/"`;
- `is_local(model: str) -> bool` — имя начинается с приставки;
- `local_name(model: str) -> str` — имя без приставки, как его знает Ollama;
- `ollama_root() -> str` — адрес службы без `/v1`: из `OLLAMA_HOST`, иначе
  `http://127.0.0.1:11434`. Значение без схемы получает `http://`.

**Не делает**: в сеть не ходит.

### `api.Clients` — читатели: `Agent.exchange`, служебные агенты, наряд, `/model`, `/auth`
**Владеет**: клиентом DeepSeek и клиентом Ollama.
**Отдаёт**:
- `Clients(api_key: str)`;
- `async stream_chat(model, messages, params=None, tools=None) -> AsyncIterator[StreamEvent]` —
  подпись прежняя;
- `async list_models() -> list[str]` — модели DeepSeek; сбой пробрасывается, как прежде;
- `async local_models() -> list[str]` — местные модели с приставкой; служба молчит — пустой
  список без сбоя. Два метода, а не один: без сети список DeepSeek не отдаётся, а местная
  модель нужна как раз тогда;
- `async validate() -> bool` — проверяет ключ DeepSeek, как прежде;
- `async prepare(model: str) -> None` — для местной модели узнаёт окно и кладёт его в
  `tokens.remember_window`. Для модели DeepSeek ничего не делает. После удачи повторный вызов
  в сеть не ходит;
- `async aclose() -> None`.

**Обещает**:
- модель с приставкой уходит в Ollama под именем без приставки, остальные — в DeepSeek;
- ключ DeepSeek в Ollama не уходит;
- запрос к DeepSeek остаётся байт в байт прежним;
- `stream_chat` местной модели сначала зовёт `prepare`;
- окно неизвестно только пока Ollama не ответила про модель: служба молчит или модели нет.
  Обмен в таком положении не проходит, поэтому у каждого состоявшегося обмена окно известно;
- сбой `prepare` запрос не останавливает: сбой назовёт сам запрос;
- местный клиент на петлевой адрес (`127.0.0.1`, `localhost`, `::1`) идёт мимо посредника из
  окружения; на прочие адреса — по тем же правилам, что клиент DeepSeek;
- события потока те же четыре рода; рассуждения Ollama из `delta.reasoning` приходят событием
  `reasoning`.

**Не делает**: модели не скачивает и не удаляет. В память службы модель загружает только
`prepare`, когда файл модели не задал окна.

### `tokens` — читатели окна: `agent.py`, `output.py`, `ui.py`
**Отдаёт**:
- `window(model: str) -> int | None` — `CONTEXT_WINDOW` для модели DeepSeek; для местной —
  запомненное число или `None`;
- `remember_window(model: str, size: int) -> None`;
- `price(usage, model, moment=None)` — для местной модели `0.0`.

**Обещает**: `window` в сеть не ходит и не ждёт.

**Правило для читателей при `None`**: предупреждение о переполнении молчит, сжатие не
запускается, полоска занятости рисуется только по прочим ограничителям, строка `/tokens` пишет
«окно неизвестно» без доли, `/compact` и `/context` называют причину — окно, а не `compact_at`.
Состояние длится, пока Ollama не ответила про модель; после первого состоявшегося обмена его
не бывает.

## Изменения требований

- **`api`**. «Назначение» называет двух поставщиков. Новое требование «Поставщика называет имя
  модели»: приставка `ollama/`, адрес из `OLLAMA_HOST`, ключ DeepSeek в Ollama не уходит.
  Требование о повторе соединения уточняется: повтор действует только для DeepSeek, местный
  клиент соединение не повторяет; на петлевой адрес он идёт мимо посредника. Обоснование
  предела чтения «окно — миллион токенов» получает оговорку «у моделей DeepSeek». «Список
  моделей» — два списка, местный пуст при молчащей службе. «Потоковый ответ» — рассуждения
  читаются из `reasoning_content` и из `reasoning`. Ссылаются: `commands`, `batch`, `agent`.
- **`params`**. Требование о дополнительном теле получает исключение: для местной модели поле
  `thinking` не уходит, выключенные рассуждения уходят как `reasoning_effort: "none"`.
  Требование о пометке «игнорируется API, пока включены рассуждения» получает исключение: у
  местной модели пометки нет, Ollama применяет `temperature` и `top_p`. Семь ручек те же.
  Ссылается: `profiles`, `commands` (`/params`).
- **`tokens`**. Окно — свойство модели: константа для DeepSeek, для местной — число от Ollama.
  Пока Ollama не ответила про модель, окно неизвестно. Предупреждение до отправки и порог
  сжатия считаются от окна модели. Требование о тарифе разделяет «местную» и «незнакомую»
  модель: местная стоит 0, незнакомая по-прежнему даёт «тариф неизвестен». Живой счёт местной
  модели приблизителен. Ссылаются: `agent`, `interface`, `commands`, `profiles`.
- **`commands`**. `/model` показывает модели обоих поставщиков; модели Ollama без способности
  `completion` не показывает. `/tokens` при неизвестном окне пишет «окно неизвестно» без доли.
- **`interface`**. НОВОЕ требование: приветствие называет поставщика текущей модели.
  Требование о полоске занятости получает исключение: при неизвестном окне полоски нет.
- **`agent`**. Требование о пороге сжатия получает оговорку: при неизвестном окне сжатие не
  запускается. «Модель сжимателя» не меняется: сжиматель идёт моделью разговора, и местной тоже.
- **`profiles`**. Обоснование числа 0,8 получает оговорку: расчёт дан на примере DeepSeek;
  число для местной модели то же.
- **`config`, `batch`** — не меняются: ключ остаётся обязательным, новых полей файла нет.

## Шаг 1. Модель `ollama/<имя>` отвечает через `myharness`

**Файлы**: `providers.py`, `api.py`, `cli.py`, `batch.py`, `commands_model.py` (`do_auth`),
`state.py`, `params.py`, `commands_params.py`, `tests/check_units.py`,
`openspec/specs/api/spec.md`, `openspec/specs/params/spec.md`
**Зависит от**: ничего
**Ход**: быстрый. Читатели `stream_chat` есть, но подпись и события не меняются.
**Требование**: `api` → «Поставщика называет имя модели», «Неудавшаяся установка соединения
повторяется», «Потоковый ответ разделяет рассуждения и ответ»; `params` → новое требование о
переводе `thinking`
**Проверка**: живой наряд из одного вопроса с `"model": "ollama/qwen3.5:9b-q4_K_M"` через
`uv run myharness --batch`: ответ получен, рассуждения и расход в журнале. Это первый живой
обмен; от шагов интерфейса он не зависит. Перед ним — `ollama pull qwen3.5:9b-q4_K_M`.
**Содержание**:

- `providers.py` — по договору выше.
- `api.py`:
  - класс `_ChatClient(base_url, api_key, retries)` — прежнее тело `DeepSeekClient`. Поток читает
    `getattr(delta, "reasoning_content", None) or getattr(delta, "reasoning", None)`;
  - `DeepSeekClient(api_key)` — `_ChatClient(BASE_URL, api_key, CONNECT_RETRIES)`, поведение
    прежнее;
  - `OllamaClient()` — `_ChatClient(providers.ollama_root() + "/v1", "ollama", 0)`. Свой
    `split_params`: при `thinking == {"type": "disabled"}` кладёт `reasoning_effort: "none"`;
    поле `thinking` убирает всегда. Ошибку соединения заменяет сообщением «Ollama не отвечает
    по адресу <адрес> — запустите службу»;
  - `OllamaClient.models() -> list[tuple[str, int | None]]` — `GET /api/tags`, затем
    `POST /api/show` на каждую модель; берёт модели со способностью `completion`; окно — число
    из строки `num_ctx` поля `parameters`;
  - `OllamaClient.window(name) -> int | None` — `num_ctx` из `/api/show`. Его нет — клиент
    загружает модель пустым `POST /api/generate` и читает `context_length` её записи в
    `GET /api/ps`: так окно точное и при умолчании службы. Служба молчит или модели нет —
    `None`;
  - `Clients` — по договору выше.
- `cli.py:137`, `batch.py:446`, `commands_model.do_auth`, `state.py:103` — `Clients` вместо
  `DeepSeekClient`.
- `params.py`: функция пометки ручки получает имя модели; для местной модели пометки об
  игнорировании `temperature` и `top_p` нет. `commands_params.py` передаёт текущую модель.
- Проверки без сети (подменный транспорт `httpx2`): модель с приставкой уходит на адрес Ollama
  без приставки и с ключом `ollama`; модель без приставки — на DeepSeek с настоящим ключом;
  перевод `thinking`; событие `reasoning` из поля `reasoning`; сообщение при отвергнутом
  соединении.

## Шаг 2. Окно и цена считаются от модели

- Проверки: `window` для трёх случаев; цена местной модели 0, цена `deepseek-v4-flash` прежняя
