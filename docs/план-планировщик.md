## Договоры модулей

### `store.py`

**Владеет**: одним соединением `sqlite3` с файлом по пути из конструктора. Больше к файлу никто
не ходит.
**Отдаёт**:
```python
@dataclass(frozen=True)
class Job:            # id, currencies (list[str], верхний регистр), cron, created_at,
                      # next_run (datetime с поясом), runs_ok, runs_failed,
                      # last_run_at (datetime | None), last_error (str | None)
@dataclass(frozen=True)
class Observed:       # code, name, rate_date (date), nominal, value, unit_rate
@dataclass(frozen=True)
class Summary:        # code, name, count, first: Observed, last: Observed,
                      # change, change_pct, min: Observed, max: Observed, mean,
                      # last_seen_at (datetime)

class Store:
    def __init__(self, путь: Path) -> None          # создаёт каталог и таблицы, если их нет
    def add_job(self, currencies: list[str], cron: str, next_run: datetime, now: datetime) -> Job
    def jobs(self) -> list[Job]                      # по id
    def delete_job(self, job_id: int) -> bool        # False — такого нет
    def set_next_run(self, job_id: int, next_run: datetime) -> None
    def record_run(self, job_id: int, at: datetime, error: str | None, new: int) -> None
    def add_rates(self, rates: list[Observed], seen_at: datetime, job_id: int) -> int  # число новых
    def summary(self, code: str, date_from: date | None, date_to: date | None) -> Summary | None
```
**Обещает**: курс `(code, rate_date)` хранится один раз — повторная запись не меняет строку и не
считается новой (`INSERT OR IGNORE`, первичный ключ `(code, rate_date)`). Время хранится
строкой ISO с поясом и возвращается `datetime` с поясом. Сводка сравнивает `unit_rate` (курс за
единицу), а не `value`: у валюты номинал может смениться. `change_pct` — от первого курса.
Снятое задание не удаляет ни курсов, ни запусков. `summary` возвращает `None`, если в отборе нет
ни одного курса.
**Не делает**: сети не знает, cron не разбирает, исключений `ToolError` не выпускает.

### `scheduler.py`

**Отдаёт**:
```python
def next_run(cron: str, after: datetime) -> datetime   # ValueError на негодном выражении
async def run_job(store: Store, job: Job, now: datetime) -> None
class Scheduler:
    def __init__(self, store: Store, clock: Callable[[], datetime]) -> None
    def wake(self) -> None           # задания изменились — пересчитать сон
    async def tick(self) -> None     # выполнить все задания со сроком <= clock(), сдвинуть сроки
    async def run_forever(self) -> None
```
**Обещает**: `run_job` никогда не выпускает исключение: любой сбой (ЦБ, разбор) — строка
`runs` с текстом ошибки. После запуска срок задания = `next_run(cron, now)` от **текущего**
времени, а не от старого срока — поэтому сколько бы сроков ни было пропущено, выполняется один
запуск. `run_forever` спит до ближайшего срока либо до `wake()`, своего шага опроса нет.
**Не делает**: доводов инструментов не проверяет — это `server.py`.

## Шаг 1. Сервер собирает курсы по расписанию и отвечает, как идут задания

**Файлы**: `mcp_servers/cbr/store.py`, `mcp_servers/cbr/scheduler.py`,
`mcp_servers/cbr/server.py`, `mcp_servers/cbr/check_server.py`, `pyproject.toml`, `uv.lock`
**Зависит от**: ничего
**Ход**: быстрый — все читатели хранилища внутри `mcp_servers/cbr` и связаны договором выше;
прежней версии файла базы нет.
**Требование**: не про `myharness`
**Проверка**: `uv run python check_server.py` — ниже названные случаи «ок», прежние не упали.
**Содержание**:
- `store.py` по договору. Таблицы:
  `jobs(id INTEGER PRIMARY KEY, currencies TEXT, cron TEXT, created_at TEXT, next_run TEXT)`,
  `runs(job_id INTEGER, at TEXT, error TEXT, new INTEGER)`,
  `rates(code TEXT, rate_date TEXT, name TEXT, nominal INTEGER, value REAL, unit_rate REAL,
  seen_at TEXT, job_id INTEGER, PRIMARY KEY(code, rate_date))`. Валюты задания — через запятую.
  `jobs()` собирает `runs_ok/runs_failed/last_run_at/last_error` одним запросом к `runs`.
- `scheduler.py` по договору. `next_run` — `croniter(cron, after).get_next(datetime)`, `after`
  в поясе `Europe/Moscow`. `run_job`: `server._ежедневные(завтра по Москве)` — вызывается через
  модуль `server` в момент запуска, чтобы проверки подменяли `server._получить` одним местом;
  валюты задания из ответа → `Observed` (дата — атрибут `Date` ответа) → `add_rates`;
  отсутствующий в ответе код — ошибка запуска с его именем, прочие валюты всё равно пишутся.
  `run_forever`: `asyncio.wait_for(событие.wait(), timeout=до ближайшего срока)`; нет заданий —
  ждёт только события.
- `server.py`: общий `Store` и `Scheduler` создаются в `main()` (путь — `CBR_MCP_DB`, по
  умолчанию `./cbr.sqlite3` рядом с сервером); для инструментов — модульные `_хранилище`,
  `_планировщик`, которые подставляют и `main()`, и проверки. Инструменты:
  - `schedule_collect(currencies: list[str], cron: str) -> ScheduledJob` — коды приводятся к
    верхнему регистру и сверяются со списком ЦБ на сегодня (неизвестный — `_не_найдена`), cron
    — через `next_run` (`ValueError` → `ToolError("cron: …")`), пустой список — `ToolError`;
    после записи `_планировщик.wake()`.
  - `list_schedules() -> Schedules` (поле `jobs: list[ScheduledJob]`).
  - `delete_schedule(job_id: int) -> Deleted` — нет такого — `ToolError`; `wake()`.
  `ScheduledJob`: `id, currencies, cron, next_run, runs_ok, runs_failed, last_run_at, last_error`
  — времена строкой ISO с поясом. Описания доводов — `Annotated[..., Field(description=…)]`.
  `main()`: `asyncio.run` поверх `asyncio.gather(uvicorn.Server(config).serve(), планировщик.run_forever())`.
- `check_server.py`: база во временном каталоге; часы подменяются. Случаи: завести задание →
  срок следующей минуты по cron; негодный cron и неизвестная валюта — ошибка (парная: годные
  проходят); `tick` в срок пишет курсы и запуск «успех»; второй `tick` в тот же день — новых 0
  (идемпотентность); пропуск трёх сроков → один запуск и срок после «сейчас»; сбой ЦБ → запуск
  с ошибкой, задание живо; снятое задание не выполняется, курсы остались. Протокол: список
  инструментов — шесть имён; `schedule_collect` через клиент возвращает `structuredContent`.

(инструмент), `mcp_servers/cbr/check_server.py`
**Зависит от**: шаг 1
**Ход**: быстрый — читает только таблицу `rates` своего же модуля по договору выше.
**Требование**: не про `myharness`
**Проверка**: `uv run python check_server.py`: сводка по трём курсам с известными числами.
**Содержание**:
- `Store.summary`: строки `rates` по коду и датам, упорядоченные по `rate_date`; `first/last` —
  края, `min/max` — по `unit_rate` (при равенстве — более ранняя дата), `mean` — среднее
  `unit_rate`, `change = last.unit_rate − first.unit_rate`, `change_pct = change / first.unit_rate × 100`,
  `last_seen_at` — наибольший `seen_at`.
- `get_summary(currency: str, date_from: str | None = None, date_to: str | None = None) -> RateSummary`
  — даты через `_дата`, начало позже конца — `ToolError`; `None` из хранилища — `ToolError`
  «нет собранных курсов {код} …; заведите сбор schedule_collect». Числа в ответе — как есть, без
  округления (округляет модель при пересказе).
- Проверка: три курса вручную через `add_rates` — числа сводки совпадают с посчитанными руками;
  отбор по периоду отсекает крайний курс (парная: без отбора он есть); пустой отбор — ошибка.
