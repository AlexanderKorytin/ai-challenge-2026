## Шаг 1. Сервер `support` отдаёт пользователя, его тикеты и тикет по номеру

**Файлы**: `week_7/day_3/support/*`
**Зависит от**: шаг 0
**Ход**: быстрый. Читатель за границей — модель через `myharness`, но договор у неё — схема
инструментов MCP, её проверяет `check_server.py` настоящим клиентом.
**Требование**: не про myharness
**Проверка**: `uv run --project week_7/day_3/support python week_7/day_3/support/check_server.py`
печатает «ок» на каждой проверке:
- `get_ticket("T-1001")` отдаёт тикет с `error` и `user_id` = `U-01`; `"T-1002"` отдаёт другой
  `error` (парная проверка соседнего значения);
- `get_ticket("T-9999")` даёт ошибку инструмента «тикет T-9999 не найден»;
- `find_user(email="vera@example.com")` и `find_user(user_id="U-03")` отдают одного человека;
- `find_user()` без доводов даёт ошибку «нужен user_id или email»;
- `list_tickets("U-03")` отдаёт закрытый тикет `T-1003`;
- в списке инструментов ровно три имени, ни одно не пишет.

**Содержание**:

Образец устройства — `mcp_servers/pipeline/server.py`: `MCPServer`, `@srv.tool()`, выход —
модели `pydantic`, ошибки — `ToolError`, запуск `srv.run()` по stdio под `if __name__`.
Путь к данным — `SUPPORT_DATA`, умолчание — `данные.json` рядом с `server.py`. Файл читается
при каждом вызове: правка данных видна без перезапуска сеанса. Сервер на диск не пишет.

Инструменты, имена полей латиницей, описания по-русски:

```python
@srv.tool()
def get_ticket(ticket_id: str) -> Ticket          # T-1001 … ; регистр букв не важен
@srv.tool()
def find_user(user_id: str = "", email: str = "") -> User   # один из двух обязателен
@srv.tool()
def list_tickets(user_id: str) -> TicketList      # все тикеты пользователя, новые первыми
```

```python
class User(BaseModel):
    user_id: str; name: str; email: str; registered: str      # дата ISO
    os: str                 # «macOS 15.6», «Ubuntu 24.04»
    provider: str           # «deepseek» | «ollama»
    model: str              # имя модели в myharness
    env: dict[str, str]     # значимые переменные: OLLAMA_HOST, OLLAMA_API_KEY = «задан»|«не задан», MCP_TIMEOUT
    mcp_servers: list[str]  # имена серверов в .mcp.json пользователя

class Message(BaseModel):
    author: str; at: str; text: str     # author: «клиент» | «поддержка»

class Ticket(BaseModel):
    ticket_id: str; user_id: str; created: str
    status: str             # «открыт» | «закрыт»
    subject: str; text: str
    error: str              # текст ошибки с экрана myharness, дословно; пусто, если нет
    resolution: str         # чем закрыт; пусто у открытого
    messages: list[Message]

class TicketList(BaseModel):
    user_id: str; tickets: list[Ticket]
```

`данные.json` — `{"users": [...], "tickets": [...]}`. Тексты ошибок в поле `error` берутся
дословно из кода `myharness` (`myharness/src/myharness/api.py` и соседние модули), не
выдумываются. Состав:

| Тикет | Пользователь | Окружение | Суть |
|---|---|---|---|
| T-1001 открыт | U-01 Анна, `anna@example.com` | `deepseek`, `deepseek-v4-flash` | «не работает авторизация»; ошибка отказа ключа (401) |
| T-1002 открыт | U-02 Борис, `boris@example.com` | `ollama`, `ollama/qwen3.5:9b-q4_K_M-32k`, `OLLAMA_HOST` не задан | «не работает авторизация»; «Ollama не отвечает по адресу …» |
| T-1003 закрыт | U-03 Вера, `vera@example.com` | `ollama` через шлюз, `OLLAMA_HOST=http://192.168.1.20:8780`, `OLLAMA_API_KEY` не задан | «шлюз не пускает»; закрыт без решения: «клиент не ответил» |
| T-1004 открыт | U-04 Глеб, `gleb@example.com` | `deepseek`, серверы `git`, `cbr` | сервер MCP не отвечает за отведённое время |
| T-1005 открыт | U-05 Дина, `dina@example.com` | `deepseek` | предупреждение о переполнении окна до отправки |

У Веры (U-03) открытого тикета нет: сценарий спрашивает её почтой, без номера.
