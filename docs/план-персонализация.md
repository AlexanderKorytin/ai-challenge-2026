# План: персонализация ассистента (день 12)

Дизайн: `docs/персонализация.md`. Состояние работы: `docs/состояние-персонализация.md`.
Код правится в `main`; папка `week_3/day_2/` и ветка `w3d2` заводятся шагом 8 под видеоотчёт.

Читатель плана — инженер без контекста проекта, а также ведущий после рубежа очистки.

## Договоры модулей

### profiles
**Владеет**: разбором файлов профиля и записью их на диск. Доступ имеют `commands_model`
(`/profile save`, `/profile new`), `strategies.switch_profile`, `agent` (читает поля), `journal`
(через `snapshot`).
**Отдаёт**:
- `def target_dir(cwd: Path) -> Path` — куда писать новый профиль: первый существующий каталог из
  `search_dirs()`, кроме `$MYHARNESS_PROFILES`-каталога, если его нет на диске; при отсутствии
  всех — `user_profiles_dir()`, который создаётся.
- `def проверить_имя(name: str) -> str | None` — жалоба словами либо `None`. Отвергает пустое,
  одни пробелы, имя с `/`, `\`, ведущей точкой и `..`.
- `def save_pair(profile: Profile, directory: Path) -> tuple[Path, Path | None]` — пишет
  `<имя>.json` и, если `profile.system` непуст, `<имя>.md`; в JSON тогда стоит `system_file`.
  Возвращает пути. Существующие файлы НЕ затирает: при их наличии возбуждает `FileExistsError`.
- поле `Profile.overrides: list[str]`.
**Обещает**: `save_pair` пишет оба файла или ни одного (сначала `.md`, при ошибке `.json` —
`.md` убирается); имя в возвращённых путях совпадает с `profile.name`.
**Не делает**: сети не знает, в настройки не пишет, исключений, кроме `OSError` и
`FileExistsError`, не выпускает.

### memory (в части блока записей)
**Владеет**: текстом блока записей о человеке. Читатели: `agent._система`, `agent.блок_фактов`
(вес и ограничители), `/system`.
**Отдаёт**: `def facts_block(facts: list[str], *, перекрытые: Sequence[str] = ()) -> str`.
**Обещает**: запись из `перекрытые`, дословно совпавшая с записью списка (сравнение
`casefold()` после `_нормализовать`), печатается с пометкой `ПОМЕТКА_ПЕРЕКРЫТИЯ` и остаётся в
блоке; несовпавшая строка `перекрытые` на текст блока не влияет; пустой список записей по-прежнему
даёт пустую строку.
**Не делает**: на диск не ходит, профиля не знает — перекрытые приходят доводом.

### profile_maker
**Владеет**: текстами запросов мастера и разбором его ответов. Читатель — `interview` (ход обряда)
и `commands_model` (запуск).
**Отдаёт**:
- `ИМЯ_МАСТЕРА: str` — имя агента для журнала и копилки выбывших.
- `def questions_profile() -> Profile` и
  `def questions_request(описание: str, записи: list[str], доступные: list[str], пары: list[tuple[str, str]]) -> str`
  — шаг опроса: один следующий вопрос либо признак «готово».
- `def parse_step(raw: str) -> str | None` — вопрос либо `None` («готово»); `ValueError` на мусор.
- `def draft_profile() -> Profile` и
  `def draft_request(описание: str, записи: list[str], доступные: list[str], пары: list[tuple[str, str]]) -> str`
  — сборка: итоговый профиль объектом JSON.
- `def parse_draft(raw: str) -> Черновик` — `ValueError` на мусор. `Черновик` — датакласс с полями
  `имя: str`, `заголовок: str`, `описание: str`, `разделы: list[tuple[str, list[str]]]`,
  `агенты: list[str]`, `перекрывает: list[str]`.
- `def собрать(черновик: Черновик, *, доступные: list[str], записи: list[str]) -> tuple[Profile, list[str]]`
  — `Profile` с `system`, собранным из разделов, и список жалоб на отброшенное.
**Обещает**: `собрать` отбрасывает имена агентов не из `доступные` и строки `перекрывает`, не
совпавшие ни с одной записью, — каждое отбрасывание попадает в список жалоб; `Profile.system`
непуст, если в черновике был хоть один раздел.
**Не делает**: на диск не ходит, к сети не обращается, состояния сеанса не трогает.

### interview (обобщённый обряд)
**Владеет**: ходом обряда «вопрос за ход» и полем `state.интервью`. Читатели — `commands_project`
(`/project new`, `/project отмена`), `commands_model` (`/profile new`), общая развилка ввода
`cli`/`commands`.
**Отдаёт**: прежние `идёт`, `принять_ответ`, `отменить` без изменения подписей;
`def начать(state: State, тема: str = "", *, род: Род = РОД_КАРТОЧКИ) -> None`;
датакласс `Род` с полями `имя`, `команда_заново`, `шаг`, `разбор_шага`, `итог`, `записать`.
**Обещает**: при `род=РОД_КАРТОЧКИ` поведение, сообщения и число обращений к модели те же, что до
правки (страховка — проверки дня 11 проходят без изменений); одновременно идёт не больше одного
обряда любого рода.
**Не делает**: о содержании карточки и профиля не знает — всё это приходит через `Род`.

## Шаг 1. Профиль записывается парой файлов в ближний каталог

**Файлы**: `myharness/src/myharness/profiles.py`
**Зависит от**: ничего
**Ход**: полный, потому что читатель за границей файла — команда `/profile save`
(`commands_model.cmd_profile`) и файлы профилей, записанные прежней версией кода.
**Требование**: `openspec/specs/profiles/spec.md` → «Профиль хранится парой файлов» (дополняется
записью), новое «Новый профиль пишется в ближний каталог»
**Проверка**: в `check_units` — `save_pair` кладёт `.json` и `.md`, `load` поднимает из них
профиль с той же инструкцией; повторная запись тем же именем даёт `FileExistsError` и не трогает
лежащие файлы; `target_dir` при существующем `profiles/` в каталоге запуска выбирает его, иначе
`user_profiles_dir()`.
**Содержание**: добавить `target_dir`, `проверить_имя`, `save_pair` по договору выше. Прежнюю
`save(profile)` оставить как есть — её зовёт `/profile save` без имени каталога — и выразить через
`save_pair(profile, user_profiles_dir())` с предварительным удалением существующих файлов (у
`/profile save` перезапись своим именем — законное поведение, и менять его эта работа не должна).
Запись `.md` — через `write_private` (права 600), как это делает память. Порядок: сначала `.md`,
затем `.json`; при ошибке записи `.json` убрать только что созданный `.md`.
**Проверки пишут в свой каталог**: новый путь записи закрыт уже существующей переменной
`MYHARNESS_PROFILES`, которую `check_units` ставит во временный каталог в шапке файла; шаг обязан
сверить, что `target_dir` этот каталог уважает.

дословное, после `_нормализовать` и `casefold`. В `agent.блок_фактов` и в путях сборки системной
части передавать `self.profile.overrides`.
