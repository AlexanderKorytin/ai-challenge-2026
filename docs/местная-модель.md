# Дизайн: местная модель в `myharness`

## Задача и видение

Условие дня 26 (неделя 6, день 1): местная языковая модель запущена на своей машине. К ней
можно обратиться через командную строку или HTTP API. Модель отвечает на простой запрос. Нужно
минимум три запроса разной сложности.

Видение пользователя: работать с местной моделью через `myharness`. Выбор модели пересмотреть:
стоит `Qwen3.8-27B` в сжатии `IQ3_XXS`, но для этого Мака она может быть не лучшей.

Машина: Apple M3 Pro, 18 ГБ общей памяти, свободно 178 ГБ диска. Ollama 0.34.4 работает службой
`launchd` на `127.0.0.1:11434`.

## Что замерено до дизайна (2026-10-05)

| Вопрос | Ответ живого запроса |
|---|---|
| Говорит ли Ollama в формате OpenAI | да: `/v1/models`, `/v1/chat/completions`, поток, `usage` последним куском |
| В каком поле идут рассуждения | `delta.reasoning`. `myharness` читает `reasoning_content` и рассуждения теряет |
| Как отключить рассуждения | `reasoning_effort: "none"`. Поле DeepSeek `thinking: {"type":"disabled"}` Ollama молча пропускает |
| Что при переполнении окна | отказ 400: «request (19926 tokens) exceeds the available context size (4096 tokens)», поле `n_ctx` |
| Окно загруженной 27B | 4096 токенов (`ollama ps`), хотя модель обучена на 262 144 |
| Скорость 27B | около 8 токенов/с (замер 2026-09-29) |
| Посредник из окружения | для `localhost` не задан, запрос идёт напрямую |
| Служба не запущена | соединение отвергается сразу |

## Что решили и почему

### 1. Поставщика называет имя модели: `ollama/<имя>`

Модель `ollama/qwen3.5:9b` уходит в Ollama. Модель без приставки уходит в DeepSeek, как сейчас.

Причина: поле `model` уже есть у настроек, профиля, агента группы, наряда и довода `--model`.
Второе поле «поставщик» рядом с ним было бы вторым каналом. Одна группа сможет держать агента
на DeepSeek и агента на местной модели рядом — это сравнение понадобится на этой неделе.

Образец: Codex держит встроенного поставщика `ollama` с адресом `localhost:11434/v1`. Запись
`поставщик/модель` принята в Hermes и OpenCode.

Адрес службы — `http://127.0.0.1:11434/v1`. Переменная `OLLAMA_HOST` его переопределяет: это
переменная самой Ollama, своей не заводим.

### 2. Один класс клиента, выбор по модели

`api.py` получает общий клиент формата OpenAI с адресом и ключом. Над ним стоит распределитель
с прежним договором: `stream_chat(model, …)`, `list_models()`, `aclose()`. Распределитель
смотрит на приставку и отдаёт запрос нужному клиенту. Вызывающий код (`Agent`, наряд, служебные
агенты) договор не меняет.

Параллель с JVM: один интерфейс и две реализации, выбор реализации по ключу — как
`Map<String, Provider>` за фасадом.

Отличия местного клиента от клиента DeepSeek:

- ключ не нужен. Запрос к местной модели работает без `/auth`;
- повтора установки соединения нет. Служба либо слушает, либо нет. Десять повторов DeepSeek дали
  бы минуты ожидания вместо сообщения «Ollama не отвечает по адресу …»;
- рассуждения читаются из `delta.reasoning`;
- ручка `thinking` переводится в `reasoning_effort: "none"` при выключенных рассуждениях.

Семь ручек остаются теми же. Новых ручек не заводим.

### 3. Окно называет Ollama, а не константа

Сейчас окно — константа `tokens.CONTEXT_WINDOW` = 1 048 576. Для местной модели она ложна в
256 раз. Окно становится свойством модели:

- модель DeepSeek — прежняя константа;
- местная модель — `num_ctx` из `/api/show`, иначе `context_length` загруженной модели из
  `/api/ps`;
- окно узнать не удалось — полоска пишет «окно неизвестно», предупреждение до отправки молчит.
  Отказ Ollama при переполнении явный, молчаливой потери нет.

Окно задаёт файл модели Ollama (`Modelfile`, строка `PARAMETER num_ctx`): `/v1` поля `num_ctx`
не принимает. Файл модели лежит в папке дня и фиксируется в git.

Живой счёт токенов идёт словарём DeepSeek и для местной модели приблизителен. Точный расход
приходит в `usage` ответа.

> Пересмотрено 2026-10-06: счёт местной модели идёт её словарём от службы Ollama и точен для
> словарей вида `gpt2`. Дизайн — `docs/счёт-токенов-местной-модели.md`.

### 4. Цена местной модели — ноль

`tokens.price` для модели с приставкой `ollama/` возвращает 0. Сейчас она вернула бы «тариф
неизвестен», что неверно: тариф известен, он нулевой.

### 5. Служебные агенты остаются на DeepSeek

Архивариус, судья, распознаватель и разворот запроса поиска названы моделью
`deepseek-v4-flash`. Распределитель отправит их в DeepSeek. Ключа нет — они молчат, как сейчас
без клиента. Сжиматель и опросы идут моделью разговора, то есть местной.

### 6. `/model` показывает оба списка

Список `/model` — модели DeepSeek и модели Ollama с приставкой. Модели без способности
`completion` (например, `bge-m3`) в список не входят. Служба не отвечает — местных строк нет,
список DeepSeek показан.

### 7. Модель — `qwen3.5:9b`, решение пользователя

Берём `qwen3.5:9b-q4_K_M` (6,6 ГБ по странице Ollama). Решение пользователя 2026-10-05: задача
дня простая, сравнение кандидатов в неё не входит.

Довод против действующей 27B: при 11 ГБ весов на окно остаётся 4096 токенов и скорость
8 токенов/с. Разговор `myharness` с памятью в 4096 токенов не поместится. 9B оставляет память
под окно в десятки тысяч токенов; точный размер окна подберём при загрузке по `ollama ps`.

### Отвергнутые подходы

- **Только `curl` и `ollama run` в папке дня.** Условие закрывает, видение пользователя — нет.
- **Переменная с адресом вместо поставщика** (подменить `BASE_URL`). Дёшево, но окно, цена,
  ключ, повторы и поле рассуждений остались бы от DeepSeek и врали бы молча.
- **Родной `/api/chat` Ollama вместо `/v1`.** Даёт `num_ctx` в запросе, но требует второго
  разборщика потока и вызовов инструментов. Цена не окупается: окно задаёт файл модели.
- **Поле `provider` в профиле и настройках.** Второй канал рядом с полем `model`.

## Затронутые способности

- `openspec/specs/api/` — два поставщика, распределение по имени модели, местный клиент без
  ключа и без повтора соединения, поле `reasoning`.
- `openspec/specs/params/` — перевод `thinking` для местной модели.
- `openspec/specs/tokens/` — окно по модели, нулевая цена, приблизительный живой счёт.
- `openspec/specs/commands/` — `/model` с двумя списками; обмен с местной моделью без `/auth`.
- `openspec/specs/batch/` — наряд с местной моделью идёт без ключа.
- `openspec/specs/config/` — переменная `OLLAMA_HOST`; новых полей файла нет.
- `openspec/specs/interface/` — заголовок «DeepSeek API» и строка окна.

## Границы: что делаем и чего НЕ делаем

Делаем двумя проходами:

1. **Общая задача в `main`**: пункты 1–6, требования, проверки без сети и без Ollama.
2. **День 26 в ветке `w6d1`**, папка `week_6/day_1/`: файл модели, три запроса разной
   сложности через `myharness`, `README.md`, видеоотчёт. Условие говорит «CLI или HTTP API»;
   пользователь выбрал один путь — `myharness`, он ходит к модели по HTTP API.

Не делаем:

- сравнение нескольких моделей и запросы через `ollama run` и `curl`;
- других поставщиков (LM Studio, llama.cpp, OpenAI). Отложенная задача 6 остаётся отложенной;
  её решение «один поставщик» эта работа меняет — запись в `docs/отложенное/` поправим;
- загрузку и удаление моделей из `myharness`;
- ручку `num_ctx` и прочие ручки Ollama;
- перевод служебных агентов на местную модель;
- свой словарь токенов для местных моделей (сделано 2026-10-06 отдельной задачей:
  `docs/счёт-токенов-местной-модели.md`).

## Риски и чем расплачиваемся

- **Малое окно.** Системная часть `myharness` (память, инварианты, карточка) может не войти в
  окно местной модели. Отказ явный, но работа встанет. Лечение — `num_ctx` в файле модели;
  размер настоящего запроса замерим первым живым прогоном.
- **Память Мака.** Веса и окно делят 18 ГБ с системой. Большое окно при большой модели уводит
  часть слоёв на процессор, скорость падает в разы. Замер покажет по `ollama ps`.
- **Инструменты.** Автомат задачи и MCP зовут инструменты модели. Малые модели зовут их хуже.
  В этой работе проверяем только, что вызов проходит по формату; качество не меряем.
- **Приблизительный счёт.** Полоска занятости для местной модели считает чужим словарём.
  Ошибку покажет сравнение с `usage` в прогоне дня. Закрыто 2026-10-06 словарём модели.
- **Служебные агенты без сети.** Без ключа или без сети архивариус и судья молчат. Полностью
  автономной работы эта задача не даёт.
