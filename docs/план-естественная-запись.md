# План: естественная запись в слои памяти

Вход — утверждённый дизайн `docs/естественная-запись.md`. Состояние работы —
`docs/состояние-естественная-запись.md`.

## Карта файлов

| Файл | За что отвечает |
|---|---|
| `myharness/src/myharness/recognizer.py` | **новый**: зачин, инструкция и профиль распознавателя, запрос, разбор ответа, запись в слой и строка показа |
| `myharness/src/myharness/commands.py` | одно звено в `handle_submit`: реплика с зачином уходит распознавателю |
| `myharness/src/myharness/workspace.py` | точное совпадение строки в разделе задачи не дописывается второй раз |
| `myharness/src/myharness/project_card.py` | то же для раздела карточки |
| `myharness/src/myharness/ui.py` | справка `/help` печатает список зачинов |
| `myharness/tests/check_units.py` | логика: зачин, разбор ответа, запись в слои, замок, профиль запроса |
| `myharness/tests/check_layers.py` | живой сценарий в поднятом приложении: реплика человека → запись → показ → отмена |
| `openspec/specs/memory/spec.md` | требование «Естественная запись в слои памяти» и правка замка «Ограничений» |

## Договор модуля `recognizer`

За границей его файлов читают двое: `commands.handle_submit` зовёт распознавание, `ui.help_fragments`
печатает список зачинов.

**Владеет**: ничем на диске. Состояния между вызовами не держит; записи кладёт чужими руками —
`memory.add_fact`, `workspace.add_line`, `project_card.add_line`/`create`.

**Отдаёт**:

```python
ЗАЧИНЫ: tuple[str, ...]                     # «запиши», «запомни», «добавь в», «отметь», «вот тебе факт»
СЛОИ: tuple[str, ...]                       # «человек», «задача», «папка»
ИМЯ_РАСПОЗНАВАТЕЛЯ: str                     # «распознаватель» — под этим именем он виден журналу прогонов
МОДЕЛЬ_РАСПОЗНАВАТЕЛЯ: str                  # «deepseek-v4-flash»

@dataclass
class Адрес:
    слой: str          # один из СЛОИ
    раздел: str        # «» для слоя «человек»
    текст: str         # строка, которая ляжет в хранилище

def есть_зачин(текст: str) -> bool
def разобрать(raw: str) -> tuple[Адрес | None, str]      # (адрес, "") либо (None, причина)
def профиль() -> Profile
def вход(state: State, реплика: str) -> str
async def спросить(state: State, реплика: str) -> tuple[Адрес | None, str]
def записать(state: State, адрес: Адрес) -> bool          # True — строка легла в хранилище
```

**Обещает**: `разобрать` НЕ выпускает исключений ни на каком вводе — мусор это `(None, причина)`.
`записать` не пишет в раздел «Ограничения» карточки НИКОГДА, при любом написании имени. `спросить`
всегда учитывает расход обмена в состоянии сеанса, даже когда обмен оборвался.

**Не делает**: окна не знает — всё, что говорит человеку, уходит через `output.append_log`; в
`ui` ввозится поздно, внутри функций, чтобы `ui.help_fragments` мог ввезти `ЗАЧИНЫ` и круга ввоза
не возникло.

## Шаг 1. Зачин узнаётся в строке, ответ распознавателя разбирается

**Файлы**: `myharness/src/myharness/recognizer.py` (новый), `myharness/tests/check_units.py`
**Зависит от**: ничего
**Ход**: быстрый — модуль новый, за границей его файлов в этом шаге читателей нет; ни диска, ни сети
**Требование**: `openspec/specs/memory/spec.md` → «Естественная запись в слои памяти» (пишется шагом 6)
**Проверка**: `uv run python tests/check_units.py` — блок проверок зачина и разбора

**Содержание**:

- `ЗАЧИНЫ = ("запиши", "запомни", "добавь в", "отметь", "вот тебе факт")` — один список на
  инструмент, из него же печатает справка.
- `есть_зачин(текст)`: сравнение по НАЧАЛУ строки, `casefold`, с границей слова — следом должен
  идти конец строки или знак, не являющийся буквой или цифрой. «Запиши,» и «ЗАПОМНИ:» — зачин,
  «запишите» и «дозаписи» — нет. Краевые пробелы сняты.
- `Адрес` — `dataclass` с полями `слой`, `раздел`, `текст`.
- `разобрать(raw)`: `json.loads`, затем по очереди — не объект, нет поля `слой`, слой не из
  `СЛОИ` и не `"нет"`, текст пуст после схлопывания пробелов. Слой `"нет"` → `(None, "")`: это не
  сбой, а честный ответ «не запись», и причина пуста именно поэтому. Для слоя `задача` раздел
  сверяется с пятью разделами `workspace`, приводится к каноническому виду, неизвестный —
  причина «раздел задачи не узнан». Для слоя `папка` пустой раздел — причина; для слоя `человек`
  раздел затирается в `""`.
- Проверки: зачин в любом регистре и с любым знаком следом; «запишите» не зачин; зачин
  посреди строки не считается; не JSON, не объект, нет поля, слой незнаком, текст из пробелов,
  слой «нет», раздел задачи «План» и «план» и «ПЛАН» дают один канон, раздел задачи «Стек» —
  причина.

## Шаг 2. Адрес ложится в слой, и человеку сказано, чем это убрать

**Файлы**: `myharness/src/myharness/recognizer.py`, `myharness/src/myharness/workspace.py`,
`myharness/src/myharness/project_card.py`, `myharness/tests/check_units.py`
**Зависит от**: шаг 1
**Ход**: **полный** — читатель за границей файлов шага есть, и не один: файлы хранилищ на диске,
которые пишут и читают `commands_task`, `commands_project`, `interview` и прежние версии кода.
Здесь же стоит замок на разделе «Ограничения» — по этим строкам программа будет судить ответы
модели, и обойдённый замок не заметен ничем, кроме просмотра.
**Требование**: `openspec/specs/memory/spec.md` → «Естественная запись в слои памяти»,
«Раздел „Ограничения“ карточки пишет только человек»
**Проверка**: `uv run python tests/check_units.py` — блок записи в три слоя: строка легла в файл,
номер в строке показа совпадает с номером в `/memory`, `/task`, `/project`; «ограничения»,
«Ограничения» и «ОГРАНИЧЕНИЯ» отклонены и файл карточки побайтно не изменился

**Содержание**:

- `записать(state, адрес)`:
  - слой `человек` → `memory.add_fact(адрес.текст)`; строка показа
    `записано о вас: «<текст>» — убрать: /forget <номер>`, где номер — позиция строки в
    `memory.load_facts()` после записи;
  - слой `задача` → активной задачи нет (`state.слаг_задачи` пуст либо файл не поднялся) →
    отказ строкой `естественная запись в задачу: рабочей задачи нет` и подсказка
    `/task new <название>`; задача есть → `workspace.add_line`; показ
    `<раздел строчными> задачи «<название>»: «<текст>» — убрать: /task забыть <слово> <номер>`,
    где `<слово>` берётся из `commands_task.РАЗДЕЛ_ПО_СЛОВУ` обратным отображением, а номер —
    длина раздела после записи;
  - слой `папка` → имя раздела через `project_card.нормализовать_раздел`; совпало с
    `project_card.РАЗДЕЛ_ОГРАНИЧЕНИЙ` → **отказ ДО всякой записи**, строка
    `раздел «Ограничения» пишете только вы: адрес выбрала модель` и подсказка
    `/project Ограничения: <текст>`; иначе карточки нет → `project_card.create(каталог,
    {имя: [текст]}, источник="человек")`, карточка есть → `project_card.add_line(..., источник="человек")`;
    показ `карточка, <Раздел>: «<текст>» — убрать: /project забыть <Раздел> <номер>`;
  - после удачной записи — `conversation.забыть_счёт_занятости(state)`: новая строка утяжеляет
    следующий запрос, и полоска занятости обязана это заметить;
  - отказ хранилища («уже записано», нет прав, память полна) уходит в ленту строкой ошибки как
    есть, без своих слов поверх.
- `workspace.add_line` и `project_card.add_line`: перед дописыванием сверить строку с уже
  лежащими в ЭТОМ разделе — совпадение без учёта регистра и лишних пробелов даёт
  `(False, "уже записано")`. Правило общее для команды и для естественной записи: два входа в
  одно хранилище не имеют права вести себя по-разному.

## Шаг 3. Один дешёвый запрос называет адрес

**Файлы**: `myharness/src/myharness/recognizer.py`, `myharness/tests/check_units.py`
**Зависит от**: шаг 1
**Ход**: **полный** — названное исключение «деньги с итоговым числом»: обмен распознавателя
оплачен человеком, и не попади он в `state.retire` и `state.session_cost`, `/tokens` показывал бы
число, которое врёт вниз, — молча и всегда.
**Требование**: `openspec/specs/memory/spec.md` → «Естественная запись в слои памяти»
**Проверка**: `uv run python tests/check_units.py` — подставной клиент: профиль без предела на
выход и с `json_object`, вход несёт разделы карточки и пять разделов задачи, расход обмена лёг в
состояние сеанса, обрыв по длине и отказ дают причину, а не адрес

**Содержание**:

- `ИНСТРУКЦИЯ` — признак слоя объективный, формулировка взята из назначения спецификации
  `memory`: «перестаёт быть правдой в другой папке» → папка; «умирает вместе с задачей» → задача;
  «правда всегда и везде» → человек; сиюминутное и содержание самой задачи — не запись. Слово
  `json` и пример ответа стоят внутри инструкции: без них DeepSeek отклоняет запрос с
  `response_format`.
- `профиль()`: `keep_history=False`, `temperature` 0.2, `thinking: disabled`,
  `response_format: {"type": "json_object"}`, **предела на выход нет** (день 9: предел рвёт ответ
  и съедает заход целиком). Профиль собирается заново на каждый вызов.
- `вход(state, реплика)`: сама реплика дословно; список слоёв; имена разделов карточки этой
  папки, если карточка есть; название активной задачи и её пять разделов либо слово «задачи нет».
  Разговор на вход не идёт.
- `спросить(state, реплика)`: одноразовый `Agent(ИМЯ_РАСПОЗНАВАТЕЛЯ, профиль())`,
  `agent=ИМЯ_РАСПОЗНАВАТЕЛЯ` в `exchange`; `state.retire([агент])` и учёт денег через
  `output.turn_price` в `finally` — оборвавшийся обмен тоже мог быть оплачен; `finish_reason ==
  "length"` → причина «ответ оборван по длине»; `обмен.ok` ложь → причина от сервера; иначе
  `разобрать(обмен.text)`.

**Живой прогон несёт этот шаг**, и он не зависит ни от одного шага интерфейса: `спросить`
зовётся из короткого скрипта с настоящим клиентом, без окна и без клавиатуры. Ведущий прогоняет
три реплики настоящей моделью — «запиши в задачи проекта: вынести команды памяти», «запомни, что
меня зовут Александр», «запиши функцию на Python, которая складывает два числа» — и смотрит, какой
адрес назван у каждой.

## Шаг 4. Реплика с зачином идёт в память, всё прочее — собеседнику

**Файлы**: `myharness/src/myharness/commands.py`, `myharness/tests/check_layers.py`
**Зависит от**: шаги 2 и 3
**Ход**: **полный** — читатель за границей файлов шага это весь ввод инструмента: через
`handle_submit` проходят команды, ответы интервью, вопросы исполнителям и ответ о ключе. Ошибка
в этом звене съедает строку человека молча — ровно та беда, от которой в этом же месте уже стоят
две оговорки про интервью.
**Требование**: `openspec/specs/memory/spec.md` → «Естественная запись в слои памяти»
**Проверка**: `uv run python tests/check_layers.py` — в поднятом приложении: реплика с зачином
кладёт строку в слой и печатает, чем её убрать; названная команда отмены действительно убирает
её; реплика «запиши функцию на Python» уходит обычным вопросом и ответ модели виден в ленте;
реплика с зачином на экране способов уходит вопросом, а не в память

**Содержание**:

- Звено встаёт в `handle_submit` ПОСЛЕ проверки авторизации и ДО постановки вопроса в очередь;
  условие: адресат — главный экран, строка не команда, интервью не идёт, `есть_зачин(text)`.
- Эхо реплики печатается ЗДЕСЬ, один раз (`ui.user_fragments`), и дальше по обоим путям строка
  повторно не печатается: путь вопроса вызывается с уже напечатанным эхом.
- Пока идёт запрос распознавателя, в ленте стоит строка `разбираю, куда это положить`; вторая
  реплика с зачином, пришедшая в это время, распознавание не заводит — уходит обычным вопросом,
  как при ответе «не запись». Признак «идёт распознавание» живёт полем в `State`.
- Ответ `(None, "")` — не запись → строка уходит обычным вопросом молча.
  Ответ `(None, причина)` — оплаченный сбой → строка ошибки с причиной, и реплика всё равно
  уходит обычным вопросом: терять набранное человеком нельзя ни на каком пути.
- В `check_layers.FakeClient` добавляется ответ распознавателя: запрос с
  `params["response_format"]` отдаёт заранее заданный объект JSON, обычный запрос — прежний
  «ответ модели». Очередь заготовленных ответов лежит полем клиента, чтобы сценарий проверял и
  запись, и «не запись».

## Шаг 5. Справка называет зачины

**Файлы**: `myharness/src/myharness/ui.py`, `myharness/tests/check_layers.py`
**Зависит от**: шаг 4 — справка описывает работающее поведение, а не обещанное
**Ход**: быстрый — читателя за границей нет, `help_fragments` печатает текст и ничего не
возвращает наружу
**Требование**: `openspec/specs/memory/spec.md` → «Естественная запись в слои памяти»
**Проверка**: `uv run python tests/check_layers.py` — `/help` в ленте содержит все зачины
из `recognizer.ЗАЧИНЫ` и слово о том, что адрес называет модель и запись можно убрать

**Содержание**: абзац в разделе справки «Память — четыре слоя», сразу под таблицей
«слой — записать — прочитать — убрать». Список зачинов печатается ИЗ `recognizer.ЗАЧИНЫ`
(поздний ввоз внутри `help_fragments` — иначе круг ввоза `ui` ↔ `recognizer`), а не переписан
словами рядом. Текст говорит три вещи: с каких слов начинается естественная запись, что адрес
называет модель и запись показывается строкой, и что команды никуда не делись.

## Шаг 6. Требование в спецификации

**Файлы**: `openspec/specs/memory/spec.md`
**Зависит от**: шаги 1–5 — требование описывает то, что уже работает
**Ход**: быстрый — текст требований, читатель у него человек
**Требование**: этот шаг его и пишет
**Проверка**: `openspec validate --specs --strict` проходит; `openspec show memory` показывает
новое требование

**Содержание**:

- Новое требование «Естественная запись в слои памяти» со сценариями: зачин узнан и строка легла
  в названный слой; ответ «не запись» — реплика ушла вопросом; распознаватель не ответил —
  реплика всё равно ушла вопросом; адрес «Ограничения» карточки отклонён при любом написании;
  слой «задача» без активной задачи — отказ и подсказка; повтор строки в разделе не дописан;
  реплика с зачином вне главного экрана распознавание не заводит.
- Правка требования «Раздел „Ограничения“ карточки пишет только человек»: в него не принимается
  запись, АДРЕС которой выбрала модель, — даже когда слова в строке сказаны человеком и
  источник записи «человек».

## Проверка самого плана

1. **Покрытие**: зачин — шаг 1; один дешёвый запрос и объект ответа — шаги 1 и 3; показ, запись и
   способ отменить — шаг 2; ложный зачин — шаг 4; замок «Ограничений» — шаг 2; повтор строки —
   шаг 2; справка — шаг 5; спецификация — шаг 6. Лишних шагов нет.
2. **Заглушек нет**: «TBD», «позже», «при необходимости» в плане не встречаются.
3. **Имена** `Адрес`, `ЗАЧИНЫ`, `есть_зачин`, `разобрать`, `спросить`, `записать`,
   `ИМЯ_РАСПОЗНАВАТЕЛЯ` совпадают во всех шагах и в договоре.
4. **Ход с причиной** у каждого шага; у трёх полных читатель за границей назван поимённо.
5. **Живой прогон** несёт шаг 3 и зависит только от шага 1; интерфейс ему не нужен.
6. **Работу стадии `Validation` ни один шаг не повторяет**: полного прохода всех наборов
   проверок в шагах нет, каждый шаг называет свой целевой сценарий.
7. **Новых путей записи на диск нет** — пишем в существующие хранилища, которые проверки уже
   уводят во временный каталог через `MYHARNESS_STATE_DIR`.
