## Находка стадии Plan

Поле журнала `elapsed_ms` считает только обмен с моделью: отсчёт стартует в
`myharness/src/myharness/agent.py:2219`, а поиск идёт раньше, в строке 2159. Время поиска вместе с
переписыванием запроса в журнал не попадает. Для местного режима это заметная доля ожидания:
переписывание — отдельная генерация. Поэтому появился шаг 3: запись журнала получает поле
`search_ms`. Существующее поле `elapsed_ms` смысла не меняет — его читают итог наряда и прежние
отчёты.

## Изменения требований

- **`batch`, новое требование** «Наряду с местной моделью ключ DeepSeek не нужен». Наряд,
  модель которого названа с приставкой `ollama/`, SHALL стартовать при файле настроек без
  ключа. Служебные запросы задания идут моделью задания.
- **`batch`, правка** требования «Внятные отказы вместо трассировки» (строки 235–253): отказ
  по отсутствию ключа относится к наряду с моделью DeepSeek. Сценарий «ключ API не задан»
  получает условие «модель наряда без приставки `ollama/`». Текст отказа прежний.
- **`batch`, одна фраза** в требование о сводке наряда (строки 133–136): время задания в
  сводке — время обмена с моделью, поиск в него не входит.
- **`api`, правка** строк 21–24: ключ DeepSeek обязателен диалоговому режиму и наряду с моделью
  DeepSeek; наряд с местной моделью стартует без ключа (ссылка на новое требование `batch`).
- **`journal`, отдельный абзац** в требовании о составе записи, по образцу полей `звенья` и
  `инварианты`: `search_ms` — время поиска программы перед обменом, миллисекунды, целое. Поле
  есть у обмена, где агент звал поставщика поиска, в том числе при жалобе поиска и при отмене
  после поиска. `elapsed_ms` считает только обмен с моделью, поиск в него не входит.
- Соседи: `config` (строка 44 — о диалоговом режиме, не меняется), `agent` («Найденное в базе
  знаний идёт в хвост запроса»; счётчик времени агента остаётся без поиска и не правится),
  `mcp` («Поиск программы»).
- `rag/` требований в OpenSpec не имеет.

## Договоры

### `rag/rewrite.py`

**Владеет**: выбором поставщика для одного запроса. Состояния не держит.
**Отдаёт**:

- `модель_переписывания() -> str` — значение `RAG_REWRITE_MODEL`, иначе `МОДЕЛЬ`
  (`deepseek-v4-flash`). Читает окружение при каждом вызове.
- `спросить(тело: dict, *, клиент=None) -> str` — подпись прежняя. Поставщика называет
  `тело["model"]`: приставка `ollama/` — местная служба, иначе DeepSeek.
- `переписать` и `развернуть` — подписи прежние, модель берут из `модель_переписывания()`.

**Обещает**:

- При модели `ollama/<имя>` запрос идёт на `http://<OLLAMA_HOST>/v1/chat/completions`
  (умолчание `127.0.0.1:11434`, как в `embedder.py`). В теле: `model` без приставки,
  `reasoning_effort: "none"` вместо поля `thinking` (так рассуждения Ollama выключает
  `myharness.api`), остальное как есть. Файл настроек не читается, заголовка с ключом нет,
  посредник из окружения не применяется.
- При модели без приставки поведение прежнее байт в байт. Судья `cite_eval.py` и `chat_eval.py`
  не задеты.
- Сбой местной службы — `ОшибкаПереписывания` со словом «Ollama», а не «DeepSeek».

**Не делает**: на диск не пишет; модель в службу не загружает и не проверяет её наличие.

### Запись журнала (читает `rag/eval.py`)

`search_ms` — целое, миллисекунды от входа в `Agent._найти` до выхода. Поле есть у обмена, где агент
звал поставщика поиска, в том числе при жалобе поиска. `elapsed_ms` — как прежде, только обмен с моделью.

## Шаг 1. Сервер поиска переписывает запрос местной моделью

**Файлы**: `rag/rewrite.py`, `rag/server.py` (только шапка), `rag/check_rag.py`
**Зависит от**: ничего
**Ход**: быстрый
**Требование**: не про `myharness`
**Проверка**: живой вызов без ключа. Команда из `rag/`:
`MYHARNESS_CONFIG_DIR=<пустой каталог> RAG_REWRITE_MODEL=ollama/qwen3.5:9b-q4_K_M-32k uv run python -c "import rewrite; print(rewrite.переписать('Почему в дне 19 отказались от MCP sampling?'))"`
печатает одну строку запроса. Без `RAG_REWRITE_MODEL` та же команда кончается ошибкой «нет
ключа DeepSeek» — парная проверка.
**Содержание**: по договору выше. В `check_rag.py` рядом с проверками строк 413–444, тем же
подставным транспортом: тело местного запроса (адрес, `model` без приставки,
`reasoning_effort`, нет `thinking`, нет заголовка `Authorization`); файл настроек не тронут;
парная — без переменной запрос идёт на адрес DeepSeek с прежним телом.

## Шаг 2. Наряд с местной моделью стартует без ключа

**Файлы**: `myharness/src/myharness/batch.py`, `openspec/specs/batch/spec.md`,
`openspec/specs/api/spec.md`, `myharness/tests/check_units.py`
**Зависит от**: ничего
**Ход**: быстрый
**Требование**: `openspec/specs/batch/spec.md` → «Наряду с местной моделью ключ DeepSeek не нужен»
**Проверка**: живой наряд из одного вопроса с `--model ollama/qwen3.5:9b-q4_K_M-32k` и
`MYHARNESS_CONFIG_DIR` на пустой каталог даёт ответ и код 0. Тот же наряд с
`--model deepseek-v4-flash` печатает прежний отказ (ключа нет, сам режим его не спрашивает,
где задать) и код 1.
**Содержание**: в `batch.main` условие отказа становится
`not settings.is_authorized and not providers.is_local(order.model)`. Проверка условия стоит
после применения `--model`. `api.Clients` получает пустой ключ; клиент DeepSeek строится, но не
вызывается. Если построение клиента с пустым ключом падает — `Clients` строит клиента DeepSeek
при первой надобности, так же как уже строит клиента Ollama (`api.py`, свойство `_ollama`).
Обращение к DeepSeek без ключа кончается обычной ошибкой обмена, не трассировкой.

## Шаг 4. Отчёт считает скорость и стабильность

**Файлы**: `rag/eval.py`, `rag/check_rag.py`
**Зависит от**: шаг 3 (имя поля)
**Ход**: быстрый
**Требование**: не про `myharness`
**Проверка**: `eval.py` на журнале дня 23 без новых ключей даёт прежние меры качества;
на журнале шага 5 с одним `--repeat` печатает таблицу стабильности.
**Содержание**:

- Сводная таблица получает три столбца. «время, с (медиана / наибольшее)» — по заданиям
  режима сумма `search_ms` и `elapsed_ms`. «поиск, с (медиана)» — `search_ms`; прочерк, если
  поля нет. «токенов выхода в секунду (медиана)» — `usage.completion_tokens` на `elapsed_ms`.
- Новый довод `--repeat <run_id>`, можно несколько раз. Каждый называет полный повтор наряда.
  Прогон 1 — записи доводов `--run` (их смысл прежний), прогоны 2 и далее — по `--repeat`.
- С `--repeat` отчёт получает раздел «Стабильность»: по режиму — число прогонов; сколько
  вопросов дали одну и ту же пару «доля фактов, отказ» во всех прогонах; сколько ответов
  совпали дословно; наименьшая и наибольшая доля фактов режима по прогонам; сколько заданий
  остались без удачной записи. Ниже — таблица по вопросам: доля фактов в каждом прогоне.
- Сводная таблица качества с `--repeat` считается по прогону 1. Без `--repeat` раздела нет.
- Шапка модуля описывает новые столбцы и довод.

Местное переписывание запроса выигрыша поиску не дало. «Источник найден» на 10 вопросах, режим
`heuristic`: без переписывания 8, местная модель с уточнённой инструкцией 8, DeepSeek 9. Цена

`RAG_REWRITE_MODEL` остаётся в коде.
