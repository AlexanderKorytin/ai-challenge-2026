# Дизайн: свой MCP-сервер и вызов его инструментов моделью (день 17)

## Задача и видение

Условие: свой MCP-сервер вокруг любого API — регистрация инструмента, описание входных
параметров, возврат результата; подключить к своему агенту, вызвать из приложения, получить и
использовать результат. Итог: агент вызывает инструмент MCP и получает результат.

Видение пользователя: git и GitHub уже подключены в дне 16 — нужен другой API. Выбран
**API курсов Центрального банка РФ** (`cbr.ru/scripts/`, без ключа).

Разрыв с днём 16: `myharness` инструменты MCP только перечисляет (`/mcp`), модель их не видит —
в требовании `mcp` это прямо названо «следующей работой». Значит, день состоит из двух частей:
сервер и мост «инструмент MCP → вызов инструмента DeepSeek».

## Что решили и почему

### Сервер `cbr` — наш, на VPS

- Пишем сами поверх голого XML-API ЦБ: `mcp_servers/cbr/` в `main` — свой uv-проект
  (`pyproject.toml`, `mcp>=2.2,<3`), не зависящий от пакета `myharness`: клиент и сервер —
  разные программы, в этом смысл протокола. Параллель с JVM: отдельный сервис со своей сборкой,
  а не класс внутри клиента.
- Каркас — `MCPServer` из `mcp` 2.2: декоратор `@tool` регистрирует инструмент, описание доводов
  берётся из подписи (`Annotated[..., Field(description=…)]`), возврат — модель данных, из
  которой библиотека строит и текст, и `structuredContent` со схемой выхода. Три пункта условия
  закрыты штатными средствами, без ручной сборки JSON-схем.
- Два инструмента:
  - `get_rate(currency, date?)` — курс по коду (`USD`, `EUR`, `CNY`…) на дату: код, название,
    номинал, курс за номинал и за единицу и **дата, на которую ЦБ установил курс** (на выходной
    ЦБ отдаёт курс последнего рабочего дня — модель должна это видеть).
  - `get_rate_dynamics(currency, date_from, date_to)` — курс по дням за период.
  Неизвестный код — ошибка инструмента со списком известных кодов на эту дату.
- Источник — официальный `www.cbr.ru` (XML в windows-1251), не зеркало `cbr-xml-daily.ru`.

### Размещение: VPS (в итоге `38.180.117.69` за Caddy; ниже исходный замысел для `83.136.235.149`)

Решения пользователя 2026-09-22: сервер на VPS; VPS новый, с панелью ispmanager, работаем через
панель (рекомендовалась чистая Ubuntu — риски ниже).

- **Способ связи — Streamable HTTP** (сетевой способ MCP, как у сервера GitHub в дне 16). stdio
  через ssh отвергнут: работает только с одного Мака, это не сетевая служба.
- Служба слушает **только `127.0.0.1:8770`**, служба systemd с перезапуском, код в
  `/opt/challenge/services/cbr-mcp/`, доставка из `main` через `rsync`, фиксация на сервере в git.
- **Наружу — только HTTPS.** Изменено при исполнении (решения пользователя 2026-09-22): на сервере
  FirstVDS сертификат на имя дважды упёрся в общий недельный предел `fvds.ru`, и после проверки
  служба переехала на прежний VPS `38.180.117.69` (чистая Ubuntu): вход
  `https://38.180.117.69/mcp` через Caddy, который сам получает и продлевает сертификат Let's
  Encrypt на IP. Ниже — исходный замысел для сервера с панелью, в работе не остался: сайт `koritin84.fvds.ru` и сертификат
  Let's Encrypt заводятся самой панелью (`mgrctl`), пересылка `/mcp` на `127.0.0.1:8770` —
  штатным включением панели (`vhosts-includes`), чтобы панель её не переписала. Голый HTTP с
  токеном отвергнут: токен шёл бы по сети открытым текстом.
- **Доступ — по токену** `Authorization: Bearer …`. Проверка — в самой службе (сравнение без
  утечки по времени), а не в nginx: тайна не должна лежать в конфигурации, которую ведёт панель.
  На сервере токен в `/opt/challenge/.env` (права 600, `EnvironmentFile` службы), у клиента — в
  переменной окружения `CBR_MCP_TOKEN`; в `.mcp.json` — `Bearer ${CBR_MCP_TOKEN}`, дословно как
  GitHub в дне 16, и `/mcp add` уже отказывает в буквальном токене. Нет токена или он неверен —
  `401`, и клиент дня 16 уже показывает «HTTP 401 Unauthorized».
- Без собственного сервера на Маке: в песочнице дня `.mcp.json` указывает на адрес VPS. Для
  проверок без сети сервер поднимается в процессе.

### Мост в `myharness`

- **Разрешение — как у Claude Code.** Модели предлагаются только инструменты, разрешённые
  правилами `permissions.allow` в `.claude/settings.json` и `.claude/settings.local.json`
  рабочего каталога: тот же файл и тот же вид правил (`mcp__cbr` — весь сервер, `mcp__cbr__*`,
  `mcp__cbr__get_rate` — один инструмент). `permissions.deny` старше `allow`: правило запрета,
  написанное для Claude Code, обязано запрещать и здесь. Неразрешённые инструменты не
  предлагаются вовсе — так Claude Code ведёт себя в пакетном режиме, где спросить некого.
  Решение пользователя 2026-09-22. Отвергнуто: «все инструменты без разрешения» — запись в
  GitHub уходила бы модели молча; «вопрос человеку посреди ответа» — верно образцу, но это новое
  окно вопроса в терминале, вдвое больше работы дня; остаётся возможным продолжением.
- **Один набор, а не второй круг.** Агент уже умеет круг «вызовы → результаты → поток»
  (`agent.Инструменты`, день 13), поставщик один — автомат задачи. Инструменты MCP
  **дописываются в тот же набор**: схемы — рядом, исполнитель — по имени
  `mcp__<сервер>__<инструмент>` уходит в MCP, прочие имена — автомату. Показ вызова, запись
  звеньев в журнал, отмена `Ctrl+C` и `/clear` посреди круга, предупреждение об окне — всё уже
  есть и не дублируется.
- **Соединение живёт весь сеанс**, как у Claude Code: соединение (и процесс местного сервера) не открывается заново на
  каждый вызов. Открывается лениво — перед первым обменом, где есть разрешённый сервер (запуск
  терминала не ждёт серверов, а без разрешённых серверов ничего не запускается). Список
  инструментов снимается при соединении. Перед каждым обменом сверяются `.mcp.json` и правила:
  сервер исчез или потерял разрешение — соединение закрывается, появился — открывается, умер —
  переоткрывается. Для этого поставщик набора у агента может быть асинхронным.
- **Библиотечная ловушка**: вход и выход из контекста соединения (и stdio, и HTTP) обязаны идти в одной
  задаче `asyncio` (области отмены `anyio`). Поэтому у каждого сервера своя долгоживущая задача,
  держащая соединение до сигнала остановки, а вызовы идут через её сессию из задачи обмена.
  Закрытие всех — при выходе из терминала.
- **Пределы — только чужие.** Соединение — под `MCP_TIMEOUT` (как в дне 16). Вызов инструмента
  — под `MCP_TOOL_TIMEOUT`, если задан (имя и единицы Claude Code); не задан — предела нет, круг
  останавливает человек, как и сейчас. Своих потолков на размер результата нет.
- **Результат модели**: текстовые части ответа сервера; `isError` и обрыв соединения — исключение,
  которое агент уже превращает в «ошибка инструмента: …», и круг продолжается. Нетекстовые
  части — строкой-пометкой вида `[изображение image/png]`.
- **Сбои — в существующий канал.** Сервер не поднялся — жалоба набора (`store_error`), как у
  сбоя поставщика автомата сегодня; своего поля и своей строки не заводим.
- **`/mcp` дополняется, а не дублируется**: у каждого инструмента в показе пометка, разрешён ли он
  модели. Новой команды нет.
- Инструменты получает только собеседник главного экрана — то же правило, что у автомата задачи.
  Пакетный режим, группа, способы и служебные агенты их не получают.

## Затронутые способности

- `openspec/specs/mcp/` — снять «передача модели — следующая работа»; новые требования:
  разрешение моделью (`allow`/`deny`), соединение на сеанс, вызов и его результат, пометка в `/mcp`.
- `openspec/specs/agent/` — поставщик набора инструментов может быть асинхронным (если требование
  о поставщике там есть; иначе — `task-machine`, где набор описан сейчас).
- `openspec/specs/commands/` — пометка разрешения в показе `/mcp`.

## Риски и чем расплачиваемся

- **Панель ispmanager** (решение пользователя вопреки рекомендации): может переписать ручные
  настройки nginx и сетевого экрана — поэтому только её штатные места; её службы уже заняли
  687 из 956 МБ памяти; часть устройства (сайт, сертификат) живёт в панели, а не в git —
  записывается в `docs/vps.md` командами `mgrctl`.
- Сетевой экран сервера сейчас открыт (политика «принимать», правила только у панели): снаружи
  видны 22, 53, 80, 1500, 1501. Сервер MCP это не расширяет (слушает `127.0.0.1`); закрытие
  прочего — отдельная задача, в этот день не входит.
- VPN на Маке (Happ) режет исходящий порт 22 у любого адреса: новый адрес добавлен в его
  исключения. В `docs/грабли.md`.

- Долгоживущие соединения — первый асинхронный ресурс, живущий дольше обмена; ошибка в закрытии
  оставит висящий процесс сервера. Проверка: выход из терминала и `/clear` не оставляют процессов.
- Первый обмен с разрешённым сервером дольше на время запуска (`uv run` — около секунды).
- Правила разрешений читаются урезанно: только `mcp__…`; правила прочих видов (`Bash(...)`)
  пропускаются молча — к `myharness` они не относятся.
- ЦБ может сменить формат XML — сломается разбор; ошибка дойдёт до модели текстом, а не падением.
