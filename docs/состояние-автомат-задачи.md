## Решения ведущего внутри шагов

- Шаг 4, просмотр: неизвестный профиль консилиума при загрузке НЕ отбрасывается (отступ от Р3
  дизайна) — остаётся с предупреждением, проверяется при созыве (шаг 6). Причина: `available()`
  зависит от каталога запуска, и `/profile save` стёр бы имя с диска.
- Шаг 4, просмотр: стадия, у которой были переходы, но ни один не годен, делает негодной всю
  карту — иначе она молча становилась конечной.
- Имя стадии приводится одной функцией `machine.имя_стадии`, её зовёт и `workspace.set_stage`.
- `machine` не импортирует на верхнем уровне `profiles`, `state`, `team`, `agent`, `output`.
- Шаг 2, просмотр: вес памяти всегда считается по ПОЛНОМУ раскрытию (с звеньями и
  рассуждениями), а в запрос пара уходит по факту инструментов. Признак «как собран прошлый
  запрос» отвергнут: он устаревает между сборками, и первый запрос с инструментами после
  запуска или снятия паузы выбрасывал бы пары дословно. Перевес при паузе — безопасная сторона;
  у профилей без карты приложений нет, и вес не меняется.
- Шаг 3, просмотр: круг сверяет поколение памяти перед каждым вызовом и потоком (`/clear`
  останавливает круг), не проглатывает отмену из исполнителя; перед каждым следующим кругом
  оценивает окно и при превышении ОТПРАВЛЯЕТ запрос с предупреждением (отказ сами отвергнут:
  противоречит требованию tokens «отказывать самим нельзя», отвергнутый сервером запрос не
  оплачивается); вес описаний инструментов агент запоминает с прошлого обмена для полоски и
  предупреждения (отставание на один обмен принято).
- Шаг 3, открыто для живого прогона: служебная обёртка сервера вокруг `tools` не мерена — снять
  числом (`prompt_tokens` с инструментами минус без них минус `count_tools`).
