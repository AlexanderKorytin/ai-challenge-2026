# Отложенная задача 6: переход myharness с DeepSeek на OpenAI

Вынесено из `CLAUDE.md` 2026-09-12: подробный план отложенной работы не нужен
в каждом запросе. Состояние — ОТЛОЖЕНО, ничего не переключаем.

**Состояние: ОТЛОЖЕНО.** Ни код, ни требования, ни настройки не менялись. До отдельного решения
пользователя `myharness` продолжает работать только с DeepSeek. Работа общая: ведётся в `main`,
ветка и папка дня для неё не создаются.

**Решение на входе.** Переход чистый: после него действующим поставщиком становится OpenAI.
Одновременная поддержка DeepSeek и OpenAI в объём не входит. Разговор и долговременная память
остаются под управлением `myharness`; серверное состояние OpenAI не становится вторым источником
истины. Для Responses API запросы уходят с `store=false`.

**Перед началом.** Повторно прочитать текущую документацию OpenAI по моделям, Responses API,
параметрам, потоковым событиям, подсчёту токенов, хранению данных и ценам. Имена моделей, размеры
окон, тарифы и допустимые значения рассуждений из разбора 2026-09-11 — исходные сведения, а не
вечные константы. Выбрать модели по ролям только после этой сверки: основная работа, сложная
проверка, архивариус и сжиматель, дешёвая механическая работа.

**Зависимости и порядок относительно других отложенных задач.**

- Задачу 5 про смысловые повторы архивариуса желательно закрыть раньше: после перехода каждый
  повтор продолжит ездить в системной инструкции, но уже по тарифу OpenAI.
- Конвейер из задачи 3 переход не блокирует. Если переход выполнится первым, старый план
  конвейера всё равно пересматривается целиком: в нём зашиты модели и параметры DeepSeek.
- Инструменты агентов и усечение их вывода из задачи 2 в этот переход не входят.

**План работы.**

1. Пройти стадию `Research`: сверить действующий код и `openspec/specs/`, исследовать актуальные
   договоры OpenAI, сравнить чистый переход с многопоставочным устройством и заново утвердить
   дизайн. Без нового утверждения этот план не исполнять.
2. Создать через OpenSpec отдельное изменение для перехода. Описать наблюдаемое поведение в
   затронутых способностях `api`, `params`, `tokens`, `config`, `commands`, `agent`, `team`,
   `batch`, `profiles` и при необходимости `memory`; не смешивать его с изменением `конвейер`.
3. Выписать в стадии `Plan` договоры затронутых модулей и разбить каждый широкий договор по
   границам состояния и поведения. Полный ход обязателен для шагов, которые сохраняют или
   восстанавливают ключ и память пользователя, считают деньги либо обрезают его контекст:
   ошибки там стоят денег или теряют данные молча.
4. Заменить `DeepSeekClient` клиентом OpenAI на Responses API. Сохранить внутренний договор
   потока приложения, но преобразовывать типизированные события OpenAI: текст ответа,
   доступную сводку рассуждений, завершение, отказ и расход. Не называть сводку внутренней
   цепочкой рассуждений: OpenAI её не раскрывает.
5. Оставить историю разговора локальной и передавать её запросом из `Agent`. Не применять
   `previous_response_id` и Conversations API: иначе состояние разделится между диском
   `myharness` и сервером поставщика, а восстановление по паре «рабочий каталог + профиль»
   перестанет быть единственным правилом.
6. Заменить общие константы модели описанием каждой разрешённой текстовой модели: размер окна,
   предел входа и выхода, поддерживаемые усилия рассуждений, наличие сводки рассуждений,
   тарифы обычного и длинного контекста. `/model` должен показывать только пригодные модели,
   а не весь ответ `/models` с моделями изображений, речи и векторных представлений.
7. Пересобрать закрытый набор параметров по действующему договору Responses API. В частности,
   перевести предел ответа в `max_output_tokens`, усилие — в `reasoning.effort`, структурированный
   ответ — в `text.format`; удалить `thinking` DeepSeek. Значения показывать только моделям,
   которые их действительно принимают, и не переносить прежние семь ручек механически.
8. Заменить словарь DeepSeek и расчёт одной общей модели. Живая полоска должна считаться
   локально без сетевого запроса на каждую клавишу; перед отправкой для дорогого или близкого
   к окну запроса использовать точный счёт Responses Input Tokens, если действующий API его
   предоставляет; окончательный расход брать только из ответа сервера.
9. Переработать расчёт денег: нормализовать входные, повторно использованные, выходные и
   внутренние токены рассуждений; учитывать разные тарифы моделей и длинного контекста.
   Не переносить часы пик DeepSeek. В журнал по-прежнему писать токены, а не вычисленную цену,
   чтобы изменение тарифа не превращало старую запись в недоказуемое число.
10. Версионировать формат настроек и провести ключ безопасно. Старый ключ DeepSeek не отправлять
    в OpenAI и не принимать молча за новый: при первом запуске после перехода явно запросить
    ключ OpenAI через `/auth`. Секрет по-прежнему хранить только в защищённом
    `config.json` с правами `600`, не выводить и не писать в журнал или профиль.
11. Перевести все пути обмена: обычный интерфейс, пакетный режим, группы, способы, цепочки,
    архивариус и сжиматель. Убрать имена моделей DeepSeek, его тексты ошибок, запасной список,
    специальное тело запроса и старый токенизатор; совместимые названия без работающего
    поведения не оставлять.
12. Как только готова настоящая точка входа, провести через неё ранний живой обмен, не ожидая
    общего прохода проверок. Затем обновить проверки по способностям и по мере готовности путей
    выполнить остальные живые сценарии: обычный поток, структурированный ответ, сводка
    рассуждений, обрыв по пределу выхода, запрос у границы окна, архивариус, сжиматель,
    пакетный режим и одновременная группа. Отдельно сверить серверный расход с экраном и
    расчётом стоимости.
13. На `Validation` сначала провести независимый просмотр связности всех изменений и снять
    замечания, затем на неподвижном дереве одним полным проходом выполнить оба набора проверок,
    ручные сценарии интерфейса и `openspec validate --specs --strict`. После
    подтверждения пользователя обновить `README.md`, карту способностей и рабочий контекст,
    затем завершить общую задачу сводкой без видео.

**Критерии готовности будущего перехода.**

- Ни один рабочий путь не обращается к DeepSeek и не предлагает его параметры или модели.
- Все виды запуска дают ответ через OpenAI: обычный, пакетный, группа, способы и цепочки.
- Память между запусками, глобальные факты, сжатие и журнал сохраняют действующее поведение.
- Сводка рассуждений честно отличена от внутренней цепочки рассуждений.
- Предупреждение об окне и цена используют сведения выбранной модели, а не одну общую константу.
- Старый ключ не покидает файл настроек и никогда не отправляется другому поставщику.
- Код, проверки, OpenSpec и пользовательская документация описывают одно и то же поведение.
