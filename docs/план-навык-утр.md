# План: навык `/утр`

Дизайн — `docs/навык-утр.md`, утверждён 2026-10-05. Состояние — `docs/состояние-навык-утр.md`.

## Уточнение дизайна, найденное при планировании

Дизайн обещал: счётчик читает список запретной транслитерации из `CLAUDE.md`. Сделать это нельзя:
список там стоит прозой в скобках, кончается «и т.п.» и содержит слово «нет» (в значении «цепь»).
Программа, читающая такой список, пометит каждое русское «нет».

Решение плана: **список переезжает** из скобок `CLAUDE.md` в таблицу файла `правила.md`
(«запретное слово → русское»). Файл правил подключён к `CLAUDE.md`, поэтому список по-прежнему
попадает в каждый разговор и остаётся один. В `CLAUDE.md` правило о транслитерации сохраняется
и ссылается на таблицу. Слова «нет» и «виа» остаются в таблице с пометкой «программа не
проверяет»: по написанию их от русских слов не отличить.

## Изменения требований

Требований `myharness` задача не задевает: `openspec/specs/` не меняется.

## Карта файлов

| Файл | За что отвечает |
|---|---|
| `bin/утр.py` | счётчик: длинные предложения, длинные абзацы, запретные слова |
| `bin/проверка_утр.py` | проверки счётчика, запуск `python3 bin/проверка_утр.py` |
| `.claude/skills/утр/правила.md` | правила письма и таблица запретных слов; подключается к `CLAUDE.md` |
| `.claude/skills/утр/SKILL.md` | команда `/утр <файл>`: порядок правки, границы, пункты ГОСТа |
| `CLAUDE.md` | строка подключения; список запретных слов уходит в таблицу |
| память `кратко-в-чат.md` | ссылка на правила |

## Договор: таблица запретных слов

У таблицы два читателя: модель и `bin/утр.py`. Поэтому вид закреплён.

**Владеет**: `правила.md`, раздел с заголовком `## Запретные слова`.
**Отдаёт**: таблицу Markdown из трёх столбцов — `Слово`, `Писать`, `Программа`. В столбце
`Слово` — начало слова строчными буквами (`коммит`, `деплой`). В столбце `Программа` — `да`
либо `нет`.
**Обещает**: одна строка — одно начало слова; других таблиц в этом разделе нет.
**Не делает**: исключений и склонений не перечисляет — счётчик сам ищет начало слова.

## Шаг 1. Счётчик считает нарушения формы в файле Markdown

**Файлы**: `bin/утр.py`, `bin/проверка_утр.py`
**Зависит от**: ничего
**Ход**: быстрый
**Требование**: не про `myharness`
**Проверка**: `python3 bin/проверка_утр.py` — код 0; `python3 bin/утр.py docs/грабли.md` печатает
строки вида `docs/грабли.md:12: длина 27: <начало предложения>` и итог.

**Содержание**

Запуск: `python3 bin/утр.py <файл> [<файл> …] [--правила <путь>]`. Путь к правилам по умолчанию —
`.claude/skills/утр/правила.md` от корня репозитория (корень — родитель каталога `bin`).
Зависимостей нет. На диск программа не пишет.

Что пропускается целиком: заголовок YAML в начале файла, блоки кода между тройными обратными
кавычками, строки таблиц (начинаются с `|`), заголовки (`#`), строки подключения (`@…`).

Единица текста — абзац: подряд идущие непустые строки. Пункт списка — своя единица; строка
продолжения с отступом относится к своему пункту. Знак цитаты `>` в начале строки снимается.

Разбиение на предложения: конец — `.`, `!`, `?`, `…`, за которым идёт пробел и прописная буква,
цифра, обратная кавычка, «ёлочка» либо конец единицы. Двоеточие перед списком предложение не
кончает. Текст в круглых скобках вынимается и считается отдельным предложением (примечание
к п. 8.2.5.1).

Подсчёт слов в предложении (то же примечание):

- отрезок в обратных кавычках — одно слово;
- отрезок в «ёлочках» — одно слово (цитируемый текст);
- ссылка `[текст](адрес)` — считаются слова текста, адрес не считается;
- число, в том числе с запятой, точкой, знаком процента и единицей без пробела — одно слово;
- слово через дефис — одно слово;
- отрезок без букв и цифр (тире, стрелка) словом не считается.

Три правила и их имена в выводе:

| Имя | Условие |
|---|---|
| `длина N` | в предложении N слов, N > 20 (п. 8.2.5.1, 8.2.6.1) |
| `абзац N` | в абзаце N предложений, N > 6 (п. 8.2.6.2); пункты списка не проверяются |
| `слово <начало>` | слово текста начинается с запретного начала из таблицы, где `Программа` = `да`; регистр не важен; отрезки в обратных кавычках не проверяются |

Вывод: по строке на нарушение — `путь:строка: имя: первые 60 знаков предложения`. Номер строки —
строка, где предложение начинается. Последняя строка — итог: `длина: A, абзац: B, слово: C`.
Код возврата: 0 — нарушений нет, 1 — есть, 2 — файл или таблица правил не прочитаны.

Открытые функции (их зовут проверки):

```python
def слова(предложение: str) -> int
def предложения(единица: str) -> list[str]
def единицы(текст: str) -> list[tuple[int, str, bool]]   # строка начала, текст, пункт ли списка
def запретные(путь_правил: Path) -> list[str]
def нарушения(текст: str, запретные: list[str]) -> list[tuple[int, str, str]]  # строка, имя, отрывок
```

Проверки в `bin/проверка_утр.py` — парами «ровно на границе / за границей»:

- 20 слов не нарушение, 21 — нарушение;
- отрезок в обратных кавычках из пяти слов считается одним словом;
- отрезок в «ёлочках» считается одним словом;
- текст в скобках считается отдельно: 18 слов и скобки из 5 слов — не нарушение;
- блок кода и строка таблицы не дают ни одного нарушения;
- абзац из шести предложений — нет, из семи — да; список из семи пунктов — нет;
- «коммиты» найдено, `git commit` в обратных кавычках — нет, слово с `Программа` = `нет` — нет;
- `запретные` читает таблицу из временного файла правил, а не из настоящего.

Чего шаг сознательно не делает: сокращения с точкой («т. е.», «п. 8») отдельно не разбираются.
После такой точки идёт строчная буква либо цифра пункта; цифра даст лишний разрыв, то есть
предложение сочтётся короче. Программа из-за этого может пропустить длинное предложение, но
ложного нарушения не даст. Это названо в строке документации программы.

## Шаг 2. Правила действуют в чате, `/утр <файл>` правит файл

**Файлы**: `.claude/skills/утр/правила.md`, `.claude/skills/утр/SKILL.md`, `CLAUDE.md`,
память `кратко-в-чат.md`
**Зависит от**: шаг 1 (вид таблицы и запуск счётчика)
**Ход**: быстрый
**Требование**: не про `myharness`
**Проверка**: живой прогон — `/утр` на копии настоящего файла проекта во временном каталоге:
счёт `bin/утр.py` до и после, чтение правки глазами на предмет потери смысла и чисел.
`python3 bin/утр.py .claude/skills/утр/правила.md .claude/skills/утр/SKILL.md` — нарушений нет:
навык сам написан по своим правилам.

**Содержание**

`правила.md` — без заголовка YAML, только правила и по одному примеру «нет / да». Разделы:

1. `## Предложение` — одна мысль, до 20 слов, прямой порядок, действительный залог, глагол
   вместо отглагольного существительного, обороты, простые предложения вместо сложного.
2. `## Слова` — один термин на понятие, без метафор, русское слово вместо иностранного, имена в
   обратных кавычках как есть, новое понятие объяснять при первом упоминании, числа с единицей
   и источником, «не знаю» вместо домысла.
3. `## Ответ` — главное первым, абзац до шести предложений, список для перечисления, схема
   вместо абзаца о связях, предупреждение до действия, одна команда на предложение.
4. `## Когда правило уступает` — только там, где иначе теряется смысл или точность.
5. `## Запретные слова` — таблица по договору выше. В неё переходят все слова из скобок
   `CLAUDE.md` с их русскими заменами оттуда же, а также «скилл», «воркер», «линтер», «фича»,
   «баг», «фикс», «ревью», «релиз» — слова, которые образец считает допустимыми.

Примеры в правилах — из нашей работы, а не из образца.

`SKILL.md`: заголовок с `name: утр`, `description`, `user_invocable: true` — как у остальных
навыков проекта. Содержание:

- без довода — напечатать `правила.md`;
- с доводом-файлом: прочитать файл и `правила.md`; запустить `python3 bin/утр.py <файл>`;
  править; запустить ещё раз; показать три строки итога — было, стало, оставлено намеренно и
  почему;
- не трогать: блоки кода, отрезки в обратных кавычках, цитаты, строки ошибок, числа, таблицы
  замеров, слова `SHALL`/`MUST`/`WHEN`/`THEN` и заголовки в `openspec/specs/`;
- смысл не решать: место, где форма требует догадки о замысле автора, вынести в список вопросов;
- правку не фиксировать;
- раздел «Откуда правила»: ГОСТ Р 58049-2017, п. 8.2, с номером пункта у каждого правила, и
  образец с адресом.

`CLAUDE.md`, раздел «Общие»:

- пункт о транслитерации: перечень в скобках и пары замен заменяются ссылкой на таблицу
  «Запретные слова»; запрет и исключение для имён остаются словами на месте;
- новый пункт: «**Письмо — по правилам упрощённого технического русского**», одна фраза, и
  строка подключения `@.claude/skills/утр/правила.md`.

Память `кратко-в-чат.md`: в «How to apply» дописывается ссылка на правила; запись остаётся.

Замер постоянного расхода: размер `правила.md` в знаках и оценка в токенах называются
пользователю до фиксации.

## Живой прогон

Обмен `myharness` с моделью задача не трогает. Живой прогон несёт шаг 2: команда `/утр` на
настоящем тексте.

## Самопроверка

Покрытие дизайна: правила (п. 2, 3) — шаг 2; команда (п. 4) — шаг 2; счётчик (п. 5) — шаг 1;
строка в `CLAUDE.md` и память — шаг 2. Заглушек нет. Новых путей записи в домашний каталог нет:
счётчик не пишет, навык правит только названный файл. Шаги не повторяют полный проход
`Validation`: наборы `check_units`, `check_app`, `check_layers` здесь не запускаются.
