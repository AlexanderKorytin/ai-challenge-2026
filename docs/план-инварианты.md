## Изменения требований

- **`invariants` (новая способность).** Инвариант — строка, которую модель не может завести и
  снять: запись о человеке с пометкой `инвариант: да` (`Г`), строка «Ограничений» карточки (`П`),
  строка «Ограничений» задачи (`З`), правило карты стадий (`А`). Инварианты всех уровней действуют
  вместе; противоречие двух разрешает человек. Блок «Инварианты» стоит первым в системной части
  главного собеседника; модель начинает ответ строкой сверки и при нарушении отказывает с номером
  и текстом. Запретные признаки `[запрет: …]` ищутся программой в блоках кода ответа. Судья —
  отдельный запрос после ответа, вердикт строкой под ответом, в журнале и в сохранённой паре.
  `/invariants` показывает список, `/invariants global <текст>` заводит глобальный инвариант.
- **`memory`.** Меняются: «Раздел «Ограничения» карточки пишет только человек» — добавляется
  такой же замок раздела задачи (распознаватель отказывает с подсказкой `/task ограничение …`);
  запись о человеке получает необязательный ключ заголовка `инвариант: да`, который принимается
  только от человека; «Ограничения» карточки и задачи и записи-инварианты уходят из своих блоков в
  блок инвариантов; старшинство «задача > карточка > записи» остаётся для обычного содержимого.
  `/memory` помечает записи-инварианты. Ссылаются: `agent` (порядок системной части), `commands`.
- **`agent`.** Меняется порядок системной части: блок инвариантов первым, дальше записи,
  инструкция, карточка, выжимка (факты разговора). Добавляется проверка ответа до записи пары у
  агента с поставщиком проверки; служебные агенты её не получают. Ссылается: `tokens` (вес
  системной части считается по тому же блоку).
- **`task-machine`.** Добавляется: правила карты выводятся строками `А` в блок инвариантов при тех
  же условиях, при которых выдаются инструменты; инструменты и проверка перехода не меняются.
- **`commands`.** Добавляется `/invariants` и `/invariants global <текст>`; справка.
- **`journal`.** Запись прогона получает поле `инварианты` (сверка, признаки, судья).
- **`tokens`.** Не меняется по тексту: вес системной части уже считается по собранному блоку;
  расход судьи входит в итог сеанса тем же путём, что у распознавателя.

## Договоры модулей

### invariants
**Владеет**: ничем; читает слои через функции `memory`, `project_card`, `workspace`, `machine`.
**Отдаёт**:
```python
@dataclass(frozen=True)
class Инвариант:
    номер: str            # "Г1", "П2", "З1", "А1"
    текст: str            # строка без хвоста признаков
    признаки: tuple[str, ...]  # пусто у А и у строк без [запрет: …]

def разобрать_строку(строка: str) -> tuple[str, tuple[str, ...]]
def собрать(каталог: Path, слаг_задачи: str | None, профиль: Profile) -> tuple[list[Инвариант], list[str]]
def блок(список: list[Инвариант]) -> str          # "" для пустого
def найти_признаки(ответ: str, список: list[Инвариант]) -> list[tuple[str, str]]  # (номер, признак)
def профиль_судьи() -> Profile
def вход_судьи(список: list[Инвариант], вопрос: str, ответ: str) -> str
def разобрать_вердикт(текст: str) -> tuple[list[str], str] | None  # (номера, довод)
def строка_сверки(ответ: str) -> str | None       # первая строка, если начинается с «Инварианты:»
```
**Обещает**: порядок — `Г`, `П`, `З`, `А`, внутри уровня — порядок файла; номера сплошные внутри
уровня; `собрать` не бросает (жалобы вторым значением); `найти_признаки` смотрит только внутрь
ограждений из трёх обратных кавычек, сравнение без учёта регистра; судья видит только `Г/П/З`.
**Не делает**: не пишет на диск, не ходит в сеть (судью зовёт `state`).

### memory (изменение)
**Отдаёт**: `add_fact(text, *, source="человек", инвариант=False)`;
`load_invariant_facts() -> tuple[list[str], list[str]]`;
`load_records() -> tuple[list[tuple[str, bool]], list[str]]` (текст, инвариант) — в порядке `/memory`.
**Обещает**: `инвариант=True` при `source != "человек"` → `(False, "инвариант ставит только человек")`,
файл не пишется; `load_facts` отдаёт ВСЕ записи, как раньше (номера `/forget` не сдвигаются);
файл без ключа — не инвариант.

### Agent (изменение)
**Отдаёт**: новые доводы конструктора
`инварианты: Callable[[], str] | None = None`,
`проверка: Callable[[str, str], Awaitable[Проверка]] | None = None`;
`Turn.проверка: Проверка | None`.
```python
@dataclass
class Проверка:           # в agent.py, чтобы не тянуть state
    сверка: str | None    # строка сверки из ответа или None
    признаки: list[tuple[str, str]]
    судья: list[str]      # номера нарушенных
    довод: str
    жалоба: str | None    # судья не ответил / вердикт не разобран
    def пометка(self) -> str   # "" если нарушений нет; иначе строки «⚠ …»
```
**Обещает**: блок инвариантов входит и в `build_messages`, и в `блок_фактов` (значит — в
обрезку, полоску и заготовку выжимки); проверка зовётся только при `status == "ok"`, до
`remember`; непустая `пометка()` дописывается к сохраняемому тексту ответа через пустую строку;
исключение проверки → `Проверка(жалоба=…)`, обмен не падает; без поставщиков запрос байт в байт
прежний.

## Шаг 1. Инварианты четырёх уровней читаются, запираются и стоят первым блоком в запросе

**Файлы**: `invariants.py` (кроме судьи), `memory.py`, `project_card.py`, `workspace.py`,
`machine.py`, `recognizer.py`, `state.py`, `agent.py`
**Зависит от**: ничего
**Ход**: полный, потому что порядок системной части читают за границей шага — вес запроса в
`output._predict_outgoing`, полоска занятости и заготовка выжимки в `compact.py` берут его через
`Agent.блок_фактов`; ошибка там молча ломает обрезку.
**Требование**: `invariants` → «Инвариант», «Блок в запросе»; `memory` → замки и перенос строк;
`agent` → порядок системной части; `task-machine` → строки `А`.
**Проверка**: в `check_units.py` — карточка с «Ограничениями» `Стек: Kotlin и Ktor [запрет:
com.google.dagger; import dagger]`, задача с одной строкой, запись-инвариант и обычная запись,
профиль с картой и воротами: `/system`-текст главного агента начинается с «Инварианты», несёт
`Г1`, `П1`, `З1`, `А1`; раздела «Ограничения» нет ни в тексте карточки, ни в хвосте; обычная
запись — в блоке записей, запись-инвариант — нет. Парно: без инвариантов системная часть совпадает
с прежней побайтно. `add_fact(..., source="архивариус", инвариант=True)` отказывает и файла не
пишет. Распознаватель с адресом «задача / Ограничения» отказывает с подсказкой.
**Содержание**:
- `memory.py`: `_Факт.инвариант: bool`; `_разобрать_факт` читает ключ `инвариант` (`да` → True);
  `add_fact` пишет строку `инвариант: да` в заголовок при `инвариант=True`; замок первым делом.
- `invariants.разобрать_строку`: хвост `[запрет: a; b]` в конце строки (регулярное выражение
  `\s*\[запрет:\s*([^\]]*)\]\s*$`, без учёта регистра), признаки делятся по `;`, пустые
  отбрасываются; текст без хвоста.
- `invariants.собрать`: `Г` — `memory.load_invariant_facts()`; `П` — `project_card.load(каталог)`,
  раздел `РАЗДЕЛ_ОГРАНИЧЕНИЙ`; `З` — `workspace.load_task(каталог, слаг)`, раздел «Ограничения»;
  `А` — `machine.инварианты_автомата(задача, профиль)`.
- `machine.инварианты_автомата(задача, профиль) -> list[str]`: пусто, если нет карты,
  стратегия `branching` или `_не_годна(...)` непусто; иначе «Стадии меняются только вызовом
  move_stage и только по переходам карты» и по строке на каждую стадию с `approval`:
  «Из стадии X дальше — только после утверждения человеком командой /task утвердить».
- `invariants.блок`: заголовок «Инварианты — правила, которые ты не имеешь права нарушать», список
  `П1. текст`, затем `УПОТРЕБЛЕНИЕ` — четыре пункта дизайна (сверка до ответа; первая строка
  `Инварианты: нарушений нет` либо `Инварианты: запрос нарушает <номера>`; отказ с номером, текстом,
  объяснением, решением в рамках и словами «изменить инвариант может только человек командой»;
  противоречие двух — назвать оба и спросить). Признаки в блок не идут.
- `project_card.блок(карточка)` и `workspace.блок(задача, карта)` пропускают раздел «Ограничения»
  всегда (инварианты теперь идут своим блоком; второго места у них нет).
- `memory.УПОТРЕБЛЕНИЕ_ЗАПИСЕЙ` дополняется: «Блок «Инварианты» старше справки».
- `state.user_facts` возвращает записи без инвариантов (через `load_records`);
  `state.invariants_block(state) -> str` = `invariants.блок(invariants.собрать(Path.cwd(),
  state.слаг_задачи, state.profile)[0])`; жалобы — `RuntimeError`, как у `project_block`.
- `state.главный_агент` передаёт `инварианты=lambda: invariants_block(state)`.
- `agent.py`: `_блок_начала(жалобы: list[str] | None) -> str` склеивает блок инвариантов и
  `facts_block` через пустую строку; им пользуются `build_messages` (вместо нынешнего `block`) и
  `блок_фактов`. Жалоба: «не удалось собрать инварианты: …».
- `recognizer._в_рабочую_задачу`: адрес с разделом «Ограничения» → отказ по образцу
  `_в_карточку_папки` с подсказкой `/task ограничение <текст>`.

## Шаг 3. Признаки и судья проверяют ответ, вердикт виден и сохранён

**Файлы**: `invariants.py` (судья), `agent.py` (`Проверка`, вызов, `Turn`, журнал), `state.py`
(`проверить_ответ`), `output.py`, `ui.py`
**Зависит от**: шаг 1
**Ход**: полный, потому что меняется договор `Agent.exchange` и `Turn`, который читают `output`,
`team`, `methods`, `batch` и журнал; и потому что расход судьи входит в итог сеанса (деньги с
итоговым числом).
**Требование**: `invariants` → «Запретные признаки», «Судья»; `agent` → проверка до записи пары;
`journal` → поле `инварианты`.
**Проверка**: в `check_units.py` поддельным клиентом: ответ с блоком кода, содержащим
`implementation("com.google.dagger:dagger:2.51")`, при З1 с признаком → `Turn.проверка.признаки ==
[("З1", "com.google.dagger")]`, пометка в сохранённой паре и в журнале. Парно: то же слово в
прозе отказа — признаков нет. Судья вернул `{"нарушены": ["П3"], "довод": "…"}` → строка
`⚠ судья: ответ нарушает П3 — …`; судья вернул мусор → «судья не ответил: …», пара сохранена без
пометки нарушения. Без инвариантов `Г/П/З` судья не зовётся (счётчик запросов подделки).
Парно: исполнитель группы (агент без поставщика проверки) — запрос и сохранённая пара прежние.
**Содержание**:
- `invariants.профиль_судьи()`: `keep_history=False`, `temperature 0`, `json_object`, рассуждения
  выключены, инструкция: «Тебе даны инварианты, вопрос и ответ ассистента. Нарушение — только
  если ответ ПРЕДЛАГАЕТ, советует или показывает кодом решение, противоречащее инварианту.
  Упоминание запрещённого, чтобы отказать или объяснить отказ, нарушением не является. Верни
  JSON {"нарушены": [номера], "довод": "одна строка"}.» `МОДЕЛЬ_СУДЬИ = "deepseek-v4-flash"`,
  `ИМЯ_СУДЬИ = "судья"`.
- `state.проверить_ответ(state) -> Callable[[str, str], Awaitable[Проверка]]`: собирает список;
  `признаки = invariants.найти_признаки`; если есть `Г/П/З` и `state.client` — один обмен
  одноразового `Agent(ИМЯ_СУДЬИ, профиль_судьи())`, учёт расхода как в `recognizer.спросить`
  (`state.retire`, `turn_price`, `session_cost_known`).
- `state.главный_агент` передаёт `проверка=проверить_ответ(state)`.
- `agent.exchange`: при `status == "ok"` и `self._проверка` — `await`, результат в
  `turn.проверка`; `answer_text` для `remember` = ответ + `"\n\n" + пометка()` при непустой
  пометке; в запись журнала — `"инварианты": {"сверка", "признаки", "судья", "довод", "жалоба"}`.
- `output.run_turn`: при `turn.проверка` печатает под ответом: строку сверки выделенным стилем
  (`ui.invariant_check_fragments`); если инварианты есть, а строки сверки нет — подсказку
  «ответ без строки сверки инвариантов»; каждую `⚠`-строку (`ui.invariant_violation_fragments`);
  жалобу судьи (`ui.error_fragments`).
