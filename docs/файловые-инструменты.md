# Дизайн: ассистент с операциями над файлами (день 34)

## Задача и видение

Условие: ассистент сам читает и меняет файлы проекта. Человек ставит цель, а не называет файл.
Нужно минимум два сценария из пяти. Ассистент работает с 2–3 файлами и больше. Изменения
сохраняются на диск или выводятся как `diff`. Прогон можно повторить.

Видение пользователя:

- завести маленький проект с кодом и подключить к нему ассистента;
- `myharness` работает с файлами **по умолчанию**, без профиля и без `.mcp.json`, как Claude Code
  (ответ пользователя 2026-10-15).

## Что решили и почему

### Встроенные файловые инструменты в `myharness`

Новый модуль `files_tools.py` в `main` даёт набор `Инструменты` (`agent.py:268`) из пяти
инструментов. Имена и доводы взяты у Claude Code. Так правила `permissions` в
`.claude/settings.json` одинаково понимают обе программы.

| Инструмент | Что делает | Доводы |
|---|---|---|
| `Read` | читает файл, строки с номерами | `file_path`, `offset`, `limit` |
| `Write` | создаёт файл или пишет поверх, возвращает `diff` | `file_path`, `content` |
| `Edit` | заменяет кусок текста, возвращает `diff` | `file_path`, `old_string`, `new_string`, `replace_all` |
| `Glob` | ищет файлы по шаблону имени | `pattern`, `path` |
| `Grep` | ищет текст регулярным выражением | `pattern`, `path`, `glob`, `output_mode` |

Набор встаёт **первым** в `соединить(...)` у главного агента (`state.py:591`). При совпадении
имён побеждает первый набор, поэтому сервер MCP не подменит `Read`.

Правила работы, как у Claude Code:

- **Корень — рабочий каталог** (`Path.cwd()` на миг вызова, как у автомата задачи). Путь
  проходит `realpath`. Символическая ссылка наружу корня даёт отказ.
- **`Edit` и `Write` поверх файла требуют прежнего `Read` этого файла** в сеансе. Иначе отказ
  «сначала прочитай файл». Правило мешает модели переписать файл вслепую.
- **`Edit` требует единственного вхождения** `old_string`, если нет `replace_all`.
- **Запись запрещена** в `.git/`, `.claude/` и `.mcp.json`. Через эти файлы модель выдала бы
  себе права или запуск команды (беда дня 20: команда в `.git/config`).
- **`Glob` и `Grep` пропускают** то, что не входит в `git`: берут список `git ls-files
  --cached --others --exclude-standard`. Вне хранилища `git` обходят дерево без `.git`.
  `Grep` пропускает двоичные файлы.
### Большие файлы и большой вывод — как в Claude Code

Источник: `code.claude.com/docs/en/tools-reference.md`, `env-vars.md`, `mcp.md` и строки
программы Claude Code 2.1.300 (разведка 2026-10-15). Своих чисел нет: каждое взято оттуда.
Без пределов бывает беда дня 31: `search_files` вернул 3,8 МБ, и DeepSeek ответил ошибкой 400.

`Read`:

- По умолчанию отдаёт до 2000 строк в виде `cat -n`: номер, табуляция, текст.
- Предел одного вызова — 25 000 токенов. Переменная `MYHARNESS_FILE_READ_MAX_OUTPUT_TOKENS`
  меняет его, как `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` у Claude Code.
- Файл целиком больше предела токенов: модель получает первую часть и пометку `PARTIAL view`
  с подсказкой читать дальше доводами `offset` и `limit`.
- Файл больше 256 КБ целиком не читается. Чтение частью сверх предела токенов тоже даёт отказ.
  Отказ советует читать меньшими частями или искать через `Grep`.
- Довод `allow_large: true` снимает оба предела. Тогда меркой служит свободное место в окне
  контекста.
- Пустой файл и `offset` за концом файла дают пометку с числом строк, а не пустой ответ.
- Двоичный файл и файл не в UTF-8 дают отказ. Картинки и PDF не читаются: модели DeepSeek и
  `qwen3.5:9b` картинок не принимают.

`Grep`:

- Три режима `output_mode`: `files_with_matches` по умолчанию, `content`, `count`.
- Доводы `head_limit` и `offset` листают вывод. `offset` за концом даёт `No entries at this offset`.
- Учитывает `.gitignore`.

`Glob`:

- Отдаёт до 100 путей, новые по времени изменения первыми. Сверх 100 — пометка об обрезке.
- `.gitignore` не учитывает, как Claude Code. Каталог `.git` пропускает.

**Большой результат любого инструмента уходит в файл.** Это правило Claude Code для MCP.
Сейчас в `myharness` у результатов MCP предела нет совсем, поэтому правило закрывает весь класс
беды, а не только файловые инструменты:

- результат длиннее 50 000 знаков или 25 000 токенов программа пишет в файл каталога состояния
  сеанса;
- модель получает путь к файлу и первые 2000 знаков;
- `Read` читает этот каталог, хотя он лежит вне рабочего каталога; запись туда закрыта;
- `MYHARNESS_MAX_TOOL_OUTPUT_TOKENS` меняет предел токенов, как `MAX_MCP_OUTPUT_TOKENS`;
- результат-ошибку длиннее 11 000 знаков программа сокращает до первых и последних 5000 знаков.

Каталог состояния уже переопределяется для проверок. Новый путь записи в домашний каталог не
появляется.

`Edit` и `Write`:

- Чтение с пометкой `PARTIAL view` не считается чтением перед правкой.
- Файл изменился после `Read`: правка проходит, если `old_string` по-прежнему совпадает ровно
  один раз. Так у Claude Code с версии 2.1.208.
- Новый файл `Write` создаёт без чтения.

### Разрешения

Чтение разрешено всегда. Запись (`Edit`, `Write`) разрешена по умолчанию **внутри хранилища
`git`**. Вне `git` запись выключена, и модель не получает этих инструментов. Так поступает
Codex: недоверенный каталог работает только на чтение. В хранилище `git` любую правку можно
отменить командой `git checkout`.

Правило `deny` в `.claude/settings.json` снимает инструмент. Пример: `deny: ["Edit", "Write"]`.
Правило `allow` разрешает запись вне `git`. Сейчас `прочитать_разрешения` (`mcp_tools.py:93`)
берёт только правила `mcp__`. Он начнёт брать и пять имён выше. Правила с путём вида
`Edit(src/**)` пропускаются, как сейчас `Bash(...)`.

Вопроса человеку посреди ответа нет и не будет: его не заведено (требование «Разрешение
модели»).

### Показ и журнал

- `⚙ Edit: путь` вместо сырого JSON доводов.
- Результат `Edit` и `Write` выводится многострочным `diff` с цветом строк `+` и `−`. Сейчас
  результат сжимается в одну строку (`ui.py:392`).
- Журнал не меняется: вызовы и `diff` уже лежат в поле `звенья`.

### Где работает

- Главный агент — да.
- Пакетный режим — да. Наряд нужен для повтора прогона: тот же список целей на том же
  начальном состоянии проекта.
- Помощник `/help` — нет. Он отвечает на вопросы и файлы не правит.
- Местная модель Ollama получает инструменты без правки (`api.py:219`).

### Учебный проект и сценарии

Проект заводит ведущий в песочнице `week_7/day_4/test/проект/`: маленькая программа «учёт
задач» на Python — 4–5 модулей, `README.md`, файл правил `ПРАВИЛА.md`, своё хранилище `git`.
Причина: прогон повторяется только от известного начального состояния.

Три сценария, на один больше условия:

1. **Найти все места использования API.** Цель: «где используется хранилище задач». Ассистент
   пишет отчёт `ИСПОЛЬЗОВАНИЕ.md` со ссылками `файл:строка`.
2. **Проверить проект по правилам.** В проекте заложены 3–4 нарушения `ПРАВИЛА.md`. Цель:
   «проверь проект по правилам и исправь нарушения». Ассистент правит файлы через `Edit`.
3. **Обновить документацию по изменениям кода.** Ведущий заранее фиксирует новую команду.
   Цель: «обнови документацию под последнюю фиксацию». Ассистент правит `README.md` и
   заводит `CHANGELOG.md`.

В сценарии 3 модели нужен `git diff`. Встроенного инструмента для `git` нет. Новая команда
описана в файле `ЗАМЕТКА.md`, или модель сравнит код с `README.md` сама. Выбор — на `Plan`.

Повтор: `сброс.sh` возвращает проект к начальной фиксации, наряд прогоняет цели, `git diff`
пишет итог в `итог-<сценарий>.diff`. Каждый сценарий идёт дважды. Совпадение прогонов
сравнивается по задетым файлам и найденным нарушениям, а не по тексту.

### Отвергнуто

- **Серверы MCP `filesystem` и `git` в песочнице.** Работает без правки кода, но только в
  папке с `.mcp.json`. Пользователь хочет умения по умолчанию.
- **Запись по умолчанию в любом каталоге.** Запуск в домашнем каталоге дал бы модели запись по
  всему каталогу без отмены.
- **Вопрос человеку перед каждой записью**, как в Claude Code. Это новая способность окна: пауза
  ответа, ввод, продолжение. Объём — отдельный день.
- **Свой `Bash`.** Условие просит работу с файлами, а не исполнение команд. Риск несоразмерен.

## Границы

Делаем: модуль, правила, показ, наряд, требования, проверки в `myharness/tests/`; учебный
проект, наряд, два прогона трёх сценариев, `README.md` дня, видеоотчёт.

Не делаем: вопрос человеку перед записью, `Bash`, правила с путём `Edit(...)`, инструменты у
помощника `/help`, инструменты MCP в наряде (отложенная задача 17).

## Риски и чем расплачиваемся

- **Модель портит файл правкой.** Отмена — `git`, поэтому запись по умолчанию только в нём.
  Неотслеживаемый файл `git` не вернёт. Это остаётся.
- **Выход из корня.** Ловится `realpath` и сверкой приставки пути. Проверки — на `..`,
  символическую ссылку и абсолютный путь.
- **Запись в настройки прав.** Запрет `.git/`, `.claude/`, `.mcp.json` на любой глубине дерева.
- **Слабая модель не листает.** `qwen3.5:9b` может не дочитать файл по `offset` после пометки
  `PARTIAL view`. Это видно в живом прогоне.
- **Каталог результатов растёт.** Файлы больших результатов живут в каталоге состояния сеанса.
  Чистит их `/clear` сеанса — решение на `Plan`.
- **Наряд пишет без человека.** Запускается только в песочнице после сброса.

## Поправка 2026-10-15: доверие папке вместо правила `git`

Решение пользователя: «как в Claude Code — `cd` в проект, `myharness`, разрешение один раз при
первом запуске в папке, дальше работает с файлами». Правило «запись по умолчанию только в
хранилище `git`» снимается.

Устройство по Claude Code 2.1.300 (документация `security`, `permissions`, `headless` и программа):

- **Вопрос при запуске окна** в папке без доверия, до открытия окна:
  «Папка: <путь>. Это ваш проект или проект, которому вы доверяете? `myharness` сможет читать и
  править файлы здесь. 1 — да, доверяю; 2 — нет, выйти». «Нет» — выход, как «No, exit».
- **Ключ доверия** — корень хранилища `git`, вне `git` — сама папка. Доверие предка покрывает
  подпапки: поиск идёт вверх до корня `git`, вне `git` — до корня файловой системы.
- **Хранение** — список `trusted_dirs` в файле настроек `~/.config/myharness/config.json` (права
  `600`, `$MYHARNESS_CONFIG_DIR`). Claude Code хранит то же в `~/.claude.json`.
- **Домашний каталог** не запоминается: доверие на сеанс, вопрос при каждом запуске.
- **Что даёт доверие:** все пять файловых инструментов, чтение и запись. Правила `deny` в
  `.claude/settings.json` действуют по-прежнему.
- **Наряд (`--batch`)** вопроса не задаёт, как `claude -p`. В доверенной папке наряд получает
  все пять инструментов. В недоверенной — только чтение, запись открывает правило `allow: ["Edit"]`.

Сверка с Claude Code: доверие там само правку не открывает. В режиме по умолчанию человека
спрашивают на каждую правку, а в режимах `acceptEdits` и `auto` правка идёт без вопроса
(замечание пользователя). `myharness` ведёт себя как эти режимы: вопроса посреди ответа нет,
после доверия правка идёт без вопросов. Отмена правки — забота человека (`git`).

Попутно доверие закрывает серверы `.mcp.json` чужой папки в окне: окно не откроется без
доверия. Наряд вопроса не задаёт и, как `claude -p`, запускает сервер поиска `rag` из `.mcp.json`
без вопроса. «Только чтение» в недоверенной папке не гарантия: её собственный
`.claude/settings.json` с `allow: ["Edit"]` открывает запись наряду, как и у `claude -p`.
