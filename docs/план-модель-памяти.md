## Договоры модулей

### mddoc
**Владеет**: ничем; чистое преобразование текста.
**Отдаёт**:
```python
@dataclass(frozen=True)
class Документ:
    заголовок: dict[str, str]           # порядок ключей сохранён
    разделы: list[tuple[str, str]]      # (имя без «## », тело без хвостовых пустых строк)
    def раздел(self, имя: str) -> str   # «» если нет
def разобрать(текст: str) -> Документ
def собрать(заголовок: Mapping[str, str], разделы: Iterable[tuple[str, str]]) -> str
```
**Обещает**: `разобрать(собрать(з, р))` возвращает ровно `з` и непустые `р`; текст без заголовка
разбирается как документ с пустым заголовком; двоеточие внутри значения заголовка сохраняется.
**Не делает**: на диск не ходит, исключений не выпускает, порядка разделов не меняет.

### workspace
**Владеет**: каталогом `<состояние>/work/<ключ каталога>/` и файлами `<слаг>.md` в нём.
Читатель за границей — человек, правящий файл руками.
**Отдаёт**:
```python
РАЗДЕЛЫ = ("Ограничения", "План", "Сделано", "Сейчас", "Находки")
@dataclass
class Задача:
    слаг: str; название: str; этап: str
    создана: str; изменена: str
    разделы: dict[str, list[str]]   # ключи из РАЗДЕЛЫ, значения — строки-пункты
    путь: Path
def work_dir(cwd: Path) -> Path
def list_tasks(cwd: Path) -> tuple[list[Задача], list[str]]        # по «изменена» убыв.
def load_task(cwd: Path, слаг: str) -> tuple[Задача | None, list[str]]
def create_task(cwd: Path, название: str) -> tuple[Задача | None, str]
def add_line(задача: Задача, раздел: str, текст: str) -> tuple[bool, str]
def set_stage(задача: Задача, этап: str) -> tuple[bool, str]
def close_task(задача: Задача) -> tuple[bool, str]
def блок(задача: Задача) -> str     # текст эфемерного хвоста, с обрамлением
```
**Обещает**: неизвестный раздел отвергается сообщением, а не записью; повтор названия задачи
отдаёт прежнюю задачу, а не второй файл; каталоги 700, файлы 600; запись атомарна (черновик и
переименование), поэтому читатель видит либо целый файл, либо прежний.
**Не делает**: сети не знает, терминала не знает, исключений наружу не выпускает — ошибка
возвращается текстом.

### project_card
**Владеет**: каталогом `<состояние>/project/<ключ каталога>/` и файлом `проект.md` в нём.
**Отдаёт**:
```python
РАЗДЕЛЫ = ("Что это за проект", "Стек", "Ограничения", "Порядок работы", "Где что лежит")
РАЗДЕЛ_ОГРАНИЧЕНИЙ = "Ограничения"
@dataclass
class Карточка:
    проект: str; каталог: str; заполнена: str; источник: str
    разделы: dict[str, list[str]]
    путь: Path
def card_path(cwd: Path) -> Path
def load(cwd: Path) -> tuple[Карточка | None, list[str]]
def save(карточка: Карточка) -> str | None
def create(cwd: Path, разделы: Mapping[str, list[str]], *, источник: str) -> tuple[Карточка | None, str]
def add_line(карточка: Карточка, раздел: str, текст: str, *, источник: str = "человек") -> tuple[bool, str]
def блок(карточка: Карточка) -> str
# интервью — чистые функции, обмен ведёт вызывающий
def questions_profile() -> Profile
def questions_request(инструкция: str, папка: str) -> str
def parse_questions(raw: str) -> list[str]
def card_profile() -> Profile
def card_request(пары: list[tuple[str, str]]) -> str
def parse_card(raw: str) -> dict[str, list[str]]
```
**Обещает**: `add_line` с `источник != "человек"` в раздел «Ограничения» отвечает отказом и не
пишет ничего; `parse_questions` и `parse_card` при непригодном ответе поднимают `ValueError`, а не
отдают пустое (пустое неотличимо от «модель промолчала», а за запрос уже заплачено); разбор
принимает только разделы из `РАЗДЕЛЫ`, чужие отбрасывает.
**Не делает**: к API не ходит, терминала не знает.

### Agent (изменение существующего)
**Владеет**: прежним — памятью пар, выжимкой, счётчиками. Новое: два поставщика слоёв.
**Отдаёт** (добавляется к конструктору):
```python
Agent(..., project: Callable[[], str] | None = None, work: Callable[[], str] | None = None)
def work_block(self) -> str          # эфемерный хвост, «» если поставщика нет
```
**Обещает**: порядок системной части — записи о человеке, инструкция профиля, карточка проекта,
выжимка; блок рабочего состояния не попадает ни в `self._messages`, ни в файл сессии, ни в
выжимку; вес хвоста учтён обрезкой до сборки списка сообщений.
**Не делает**: на диск не ходит — слои приходят вызываемыми, как уже приходят записи о человеке.

### Шаг 4. Запрос собирается из четырёх слоёв в заданном порядке, рабочее состояние — хвостом
**Файлы**: `myharness/src/myharness/agent.py`, `myharness/src/myharness/memory.py`
**Зависит от**: шаги 2, 3
**Ход**: полный, потому что за границей файлов шага читают собранный запрос: `compact` (сборка
выжимки по тому же блоку записей), `layout` (полоска занятости зовёт `блок_фактов` и
`ограничители`), `batch` (создаёт `Agent` своими доводами), `tests/check_app.py` (сверяет
системную часть). Ошибка тут молча меняет цену каждого обмена.
**Требование**: `openspec/specs/memory/spec.md` → «Слои подаются в заданном порядке» и
«Рабочее состояние не оседает в разговоре»
**Проверка**: собрать `Agent` с тремя поставщиками, вызвать `build_messages("вопрос")` — в
системном сообщении блоки идут записи → инструкция → карточка → выжимка, а хвост стоит перед
текстом вопроса в последнем сообщении; после `remember` в `history()` нет ни одной строки хвоста.
**Содержание**: конструктор получает `project` и `work` — вызываемые, как уже сделано у `facts`,
и по той же причине. `_система(факты)` меняет порядок на `факты, profile.system, карточка,
выжимка`; тот же порядок в `system_text()` и в ветви стратегий. Записи стоят выше инструкции
намеренно: они одинаковы у всех персон, и верхнее положение даёт кэшу поставщика делиться ими
между персонами. В `build_messages` перед обрезкой собирается `payload = хвост + "\n\n" + content`
(при пустом хвосте — сам `content`), и дальше везде — `payload`: обрезка взвешивает ровно то, что
уйдёт в модель. В память (`remember`, `exchange`) уходит исходный `content` — иначе через три хода
в истории лежали бы три противоречивых состояния задачи. `memory.facts_block` получает первую
строку «Справка о собеседнике: сведения ниже верны всегда и везде. Использовать, только если
относится к вопросу; не упоминать без надобности.»

### Шаг 5. Главный разговор видит свои слои, активная задача живёт в состоянии сеанса
**Файлы**: `myharness/src/myharness/state.py`, `myharness/src/myharness/conversation.py`
**Зависит от**: шаг 4
**Ход**: полный, потому что `__post_init__` состояния зовут проверки напрямую и `cli` при
запуске: лишнее обращение к диску отсюда ударило бы по каждому запуску и по каждой проверке.
**Требование**: `openspec/specs/memory/spec.md` → «Слои принадлежат главному разговору»
**Проверка**: собрать `State` во временном каталоге состояния — `system_text()` главного агента
пуст сверх инструкции; завести задачу и карточку, собрать `State` заново — оба блока на месте;
в другом рабочем каталоге карточки нет, а записи о человеке есть.
**Содержание**: поле `активная_задача: Any = None` (тип — `workspace.Задача`; `Any`, чтобы
`state` не ввозил `workspace` ради подсказки). Функции `project_block(state)` и `work_block(state)`
рядом с `user_facts`; главному агенту они передаются замыканиями в `__post_init__`. Карточка
читается с диска на каждую сборку — как и записи, и по той же причине: человек правит файл руками
между двумя вопросами. Подъём при запуске: `restore_conversation` дополняется поднятием **последней
изменённой** задачи рабочего каталога и строкой отчёта в ленте. Выбор «последняя изменённая», а не
запомненная в настройках, сделан по образцу Claude Code: состояние берётся из того, что лежит на
диске, а не из второго списка, который разойдётся с ним.

### Шаг 8. Интервью заполняет карточку двумя запросами к модели
**Файлы**: `myharness/src/myharness/interview.py`, `myharness/src/myharness/commands_project.py`
**Зависит от**: шаги 3, 7
**Ход**: полный, потому что тут тратятся деньги за два обмена и сюда приходит ответ модели, из
которого рождается файл: непригодный ответ обязан отличаться от пустой карточки, а не молча стать ею
**Требование**: `openspec/specs/memory/spec.md` → «Карточку заводит интервью двумя запросами»
**Проверка**: живой прогон в инструменте — `/project new` в чистой папке задаёт по одному вопросу

втором запросе оставляет папку без карточки и говорит об этом строкой.
**Содержание**: состояние диалога интервью — в `State` (`интервью: Any`), ввод человека
перехватывается в `handle_submit` до общей развилки, как уже перехватывается ответ на вопрос о

### Шаг 14. Живой прогон: интервью и влияние слоёв на ответ
**Файлы**: `week_3/day_1/test/сравнение.py` (заводится вместе с папкой дня)
**Зависит от**: шаги 8, 13
**Ход**: полный, потому что тратятся деньги и итогом служат числа, по которым судят о работе дня
**Требование**: не про поведение инструмента
**Проверка**: три состава, каждый дважды: «с карточкой» и «без карточки» на вопросе «как мне
запустить проверки?» — с карточкой в ответе есть `uv` и запуск без ключа API; «с рабочим слоем» и
«без» на вопросе «что делаем дальше?» — со слоем назван этап и следующий пункт плана; удаление
одной записи о человеке убирает ровно одно свойство ответа. Расхождение двух прогонов одного
состава меньше, чем разница между составами, — иначе показ ничего не доказывает.
**Содержание**: скрипт поднимает `Agent` напрямую с нужным набором поставщиков и ходит к API;
`--batch` не трогаем — наряду слои не нужны, и заводить их там значило бы менять пакетный режим
ради одной демонстрации. Живой обмен доступен уже после шага 4: агента можно поднять без окна и
без клавиатуры, и ни один шаг интерфейса ему не предшествует.
