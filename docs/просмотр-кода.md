# Дизайн: автоматический просмотр кода (день 32)

## Задача и видение

Условие дня 32: конвейер запускается на запрос на слияние, ассистент получает изменения и
изменённые файлы, ищет по базе знаний (документация и код) и возвращает текст просмотра.
Текст называет возможные ошибки, архитектурные замечания и рекомендации.

Решение пользователя 2026-10-13: конвейер исполняет исполнитель GitHub. Мак и VPS в работе
конвейера не участвуют.

## Что решили и почему

```
запрос на слияние (opened, synchronize, reopened)
   ▼ GitHub Actions: .github/workflows/просмотр-кода.yml
   ▼ выгрузка двух копий: основа (main) и вершина запроса
   ▼ Ollama + bge-m3 на исполнителе (кэш моделей)
   ▼ индекс основы: документация (structure) + код (code), кэш по хэшу корпуса
   ▼ agents/review/review.py
        git diff основа...вершина → участки изменений
        участок → запрос поиска → куски документации и куски кода
        изменения + изменённые файлы + найденное → DeepSeek
   ▼ комментарий в запросе на слияние (один, обновляется при повторе)
```

1. **Программа просмотра — `agents/review/review.py`.** Образец — `agents/digest`: отдельный
   проект `uv`, DeepSeek зовёт через `myharness.api`, ключ берёт из `DEEPSEEK_API_KEY`.
   Программа работает и на Маке: `review.py --base main --head <ветка>` печатает текст в вывод.
   Конвейер только добывает две копии кода и публикует ответ. Так живой прогон не зависит от
   GitHub.

2. **Код в индексе — новая стратегия нарезки `code` в `rag/chunking.py`.** Модуль `ast` режет
   файл Python на функции, методы и остаток модуля. Раздел куска — «модуль › класс › функция».
   Параллель с JVM: так же PSI в IntelliJ делит файл Kotlin на объявления. Индекс просмотра
   `rag/review.sqlite` несёт две стратегии: `structure` для `README.md`, `docs` и
   `openspec/specs`, `code` для файлов `*.py`. Проверки (`tests/`) и папки дней в корпус кода
   не входят.

3. **Два поиска на участок изменений.** Запрос — имя функции из заголовка участка и добавленные
   строки. Первый поиск идёт по документации, второй по коду. Режим `heuristic`
   (косинус и BM25), числа дня 31: K₁ = 50, K₂ = 5, τ = 0,50. Для кода эти числа не замерены:
   контрольного набора по коду нет, и день его не заводит. Одинаковые куски разных участков
   в запрос идут один раз.

4. **Индекс строится по основе, а не по вершине.** Основа отвечает на вопрос «как устроено
   сейчас», изменения показывают «что меняется». Ключ кэша — хэш файлов корпуса основы:
   индекс пересобирается только после изменения `main`.

5. **Ответ — три обязательных раздела**: «Возможные ошибки», «Архитектурные замечания»,
   «Рекомендации». Каждый пункт называет файл и строку. Пункт, опирающийся на базу знаний,
   называет источник (путь › раздел). Пустой раздел пишется словом «нет». Ниже программа сама
   дописывает список найденных кусков: читатель видит, на что опирался ответ.

6. **Публикация — один комментарий с меткой `<!-- просмотр-кода -->`.** Повторный запуск
   обновляет его. Образец — действие Claude Code для GitHub: оно держит один закреплённый
   комментарий. Тот же текст идёт в сводку задания.

7. **Своих пределов нет.** Число участков и длину изменений программа не ограничивает. Если
   запрос не входит в окно модели (счёт `myharness.tokens`), программа завершается с ошибкой
   и называет размер. Молча она ничего не обрезает.

8. **Сборка индекса досчитывает только новое** (решение пользователя 2026-10-13 по замеру).
   Полная сборка на исполнителе GitHub заняла 57 мин 52 с при 158 с на Маке. Теперь команда
   `index` берёт вектор куска из прежней сборки той же стратегии и той же модели, если текст
   куска не изменился. Модель считает векторы только для новых и изменённых кусков. Образец —
   индекс кода в Cursor: он сверяет хэши и пересчитывает разницу. Схема индекса не меняется,
   отдельного ключа команды нет: вектор зависит только от текста и модели. Конвейер берёт
   ближайший прошлый индекс из кэша по приставке ключа.

Отвергнуто:

- **Свой исполнитель на Маке.** Репозиторий открытый: чужой запрос на слияние исполнил бы
  свой код на Маке.
- **Служба на VPS.** Нужны новая служба и открытый вход. Путь с Мака к VPS нестабилен
  (`docs/vps.md`).
- **Пакетный режим `myharness` вместо своей программы.** Наряд ищет по тексту вопроса целиком.
  Изменения как запрос поиска дают шум: нужен запрос на участок. Это правка способностей
  `batch` и `agent` ради одного дня.
- **Модель с инструментами (читает файлы сама).** Отложенная задача 17 не закрыта, а на
  исполнителе модель с инструментами и чужим текстом на входе — лишний риск.
- **Готовый индекс файлом выпуска с Мака.** Конвейер зависел бы от Мака: слияние через сайт
  GitHub оставило бы индекс устаревшим, и просмотр молча шёл бы по старому коду.
- **Хэш файла в индексе.** Нужна новая таблица, а сравнение текста куска даёт то же без неё.

## Затронутые способности

Требования `openspec/specs/` не меняются: код `myharness` не трогаем, у `rag/` своей
способности нет. Меняются `rag/chunking.py`, `rag/cli.py` (стратегия `code`), добавляются
`agents/review/` и `.github/workflows/просмотр-кода.yml` — всё в `main`.

## Границы: что делаем и чего НЕ делаем

Делаем:

- стратегию `code`, программу просмотра, конвейер, проверки нарезки и разбора изменений;
- ветку `w7d2` и папку `week_7/day_2` с `README.md` и сценарием показа;
- показательный запрос на слияние из отдельной ветки: в нём заложены ошибка в логике и
  нарушение требования (ключ API попадает в журнал). Запрос не сливается и закрывается
  после видео.

Не делаем:

- комментарии к отдельным строкам и блокировку слияния по итогу просмотра;
- просмотр запросов из чужих копий репозитория: тайны им GitHub не выдаёт, задание печатает
  причину и завершается успешно;
- нарезку кода не на Python;
- контрольный набор и подбор чисел поиска по коду.

## Риски и чем расплачиваемся

- **Время сборки индекса на исполнителе неизвестно.** У исполнителя 4 ядра без видеоядра,
  в корпусе около 54 тыс. строк Python вместе с проверками. Первый шаг плана — замер. Если
  сборка дольше 15 минут, решение о сужении корпуса принимает пользователь.
- **Ключ DeepSeek становится тайной репозитория GitHub.** Ключ покидает Мак. Событие
  `pull_request` чужим копиям тайну не выдаёт; событие `pull_request_target` не используем.
- **Подмена указаний через изменения.** Текст изменений — чужие данные. Инструкция называет
  их данными, инструментов у модели нет, права задания — `contents: read` и
  `pull-requests: write`. Худший исход — неверный текст комментария.
- **Автор запроса из своей ветки может изменить сам файл конвейера.** Право записи в
  репозиторий есть только у владельца, риск принят.
- **Просмотр не повторяется слово в слово**: ответы DeepSeek различаются между запусками
  (замер дня 24).

## Что нужно от пользователя

1. Выполнить `! gh auth refresh -s workflow`: токен `gh` не имеет права отправлять файлы
   конвейера.
2. Согласие записать ключ DeepSeek тайной репозитория (`gh secret set`, ведущий делает сам,
   ключ на экран не выводит).
