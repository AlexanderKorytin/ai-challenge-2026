# План: подключение MCP (день 16)

Дизайн: `docs/подключение-mcp.md`. Код — в `main`; ветка `w4d1` и папка `week_4/day_1/` —
после кода, под постановку, песочницу `test/` и видеоотчёт.

Факты библиотеки `mcp` 2.2.0, проверенные пробой 2026-09-21 (примеры в сети — версии 1.x и не
годятся):

- stdio: `mcp.client.stdio.stdio_client(StdioServerParameters(command, args, env))` →
  `(read, write)`;
- HTTP: `mcp.client.streamable_http.create_mcp_http_client(headers=…)` — асинхронный контекст
  клиента `httpx`, затем `streamable_http_client(url, http_client=клиент)` → кортеж, первые два
  члена `(read, write)`;
- `ClientSession(read, write)` — асинхронный контекст; `await s.initialize()` →
  `.server_info.name`, `.protocol_version`; `await s.list_tools(params=PaginatedRequestParams(cursor=…))` (первый запрос — `params=None`) → `.tools`
  (`.name`, `.description`, `.input_schema`), `.next_cursor`;
- учебный сервер: `from mcp.server.mcpserver import MCPServer`, `@srv.tool()`, `srv.run()`;
  имя инструмента — латиницей (SEP-986, иначе предупреждение в поток ошибок).

## Изменения требований

- **`mcp` (новая способность).** Файл серверов `.mcp.json` рабочего каталога в формате Claude
  Code (`mcpServers`; stdio — `command`/`args`/`env`, HTTP — `type: "http"`/`url`/`headers`);
  подстановка `${ИМЯ}` и `${ИМЯ:-умолчание}`, незаданная переменная — сбой этого сервера с её
  именем; соединение открывается, согласуется, список инструментов берётся целиком по всем
  страницам, соединение закрывается; сбой одного сервера не мешает остальным; имя инструмента
  для показа — `mcp__<сервер>__<инструмент>`; запись файла сохраняет прочие ключи и серверы и
  идёт через временный файл; тайны — отказ на буквальный `Authorization`, предупреждение на
  прочие буквальные значения; значения заголовков и переменных на экран и в журнал не выводятся.
  Имя `mcp__<сервер>__<инструмент>` в этот день — **только для показа**, модели не отдаётся;
  часть от инструмента берётся как её отдал сервер и не проверяется (SEP-986 допускает в ней `.`,
  а `task-machine` требует от имён функций модели `[A-Za-z0-9_-]`) — правило для имени функции у
  модели решает следующий день. Ограничение на имя сервера — задел под то же правило, дешёвый
  сейчас и дорогой после того, как записи уже заведены.
- **`commands`.** Новое требование «/mcp»: без доводов — список серверов и инструментов;
  `add` двух видов, `remove`; отказы (имя занято, имя вне `[A-Za-z0-9_-]`, неизвестное имя,
  нет ни адреса, ни `--`). Ссылка на способность `mcp`. `/mcp` ключа DeepSeek не требует и
  видна в меню до авторизации (сценарий). Подстановка при наборе — только слова `add`/`remove`;
  имена серверов после `/mcp remove` не подставляются.
  Правка «Состав команд»: `/mcp` в перечне команд; справка — **одиннадцать** разделов, слово
  `mcp` и заголовок «MCP» в перечнях, сценарий «меню разделов справки» — «одиннадцати».
- Соседи: `interface` (меню команд по «/» перечисляет команды — `/mcp` добавляется тем же
  порядком, что прочие, отдельного требования не нужно), `config` (правка Purpose: «единственный
  секрет приложения» → единственный секрет, который **хранит** сам `myharness`; тайны серверов MCP
  не хранятся, а подставляются из окружения — см. `mcp`), `journal` (не задет: `/mcp` в
  журнал не пишет).

## Договоры

### `mcp_client`

**Владеет**: ничем между вызовами — файл читается при каждом вызове, соединение живёт внутри
одного вызова.
**Отдаёт**:

```python
ИМЯ_ФАЙЛА = ".mcp.json"

@dataclass(frozen=True)
class Сервер:                      # запись файла, как она лежит (без подстановки)
    имя: str
    способ: Literal["stdio", "http"]
    команда: str | None            # stdio
    доводы: tuple[str, ...]        # stdio
    окружение: dict[str, str]      # stdio, env
    адрес: str | None              # http
    заголовки: dict[str, str]      # http

@dataclass(frozen=True)
class Инструмент:
    сервер: str
    имя: str                       # как отдал сервер
    описание: str                  # полностью, "" если нет
    схема: dict                    # input_schema как есть
    @property
    def полное_имя(self) -> str:   # f"mcp__{сервер}__{имя}"

@dataclass(frozen=True)
class Итог:                        # по одному серверу
    сервер: Сервер | НегоднаяЗапись
    имя_на_сервере: str | None     # server_info.name
    протокол: str | None           # protocol_version
    инструменты: tuple[Инструмент, ...]
    сбой: str | None               # причина одной строкой; при сбое инструменты пусты

@dataclass(frozen=True)
class НегоднаяЗапись:              # запись, которую не разобрать (SSE, нет command/url, …)
    имя: str
    причина: str

class ОшибкаФайла(Exception): ...  # порча всего файла (не JSON, не объект), имя занято/неизвестно

ПЕРЕМЕННАЯ_ПРЕДЕЛА = "MCP_TIMEOUT"  # мс, как у Claude Code; решение пользователя 2026-09-21
ПРЕДЕЛ_ПО_УМОЛЧАНИЮ_МС = 30_000

def прочитать(путь: Path) -> list[Сервер | НегоднаяЗапись]   # нет файла — []; порядок — как в файле
def подставить(текст: str, окружение: Mapping[str, str]) -> str   # KeyError(имя) на незаданной без умолчания
@asynccontextmanager
async def соединение(сервер: Сервер) -> AsyncIterator[tuple[ClientSession, InitializeResult]]
async def список(сервер: Сервер) -> Итог             # исключений не выпускает
async def список_всех(путь: Path) -> list[Итог]      # серверы одновременно, итоги в порядке файла
def добавить(путь: Path, сервер: Сервер) -> None     # ОшибкаФайла, если имя занято
def убрать(путь: Path, имя: str) -> None             # ОшибкаФайла со списком имён, если нет такого
```

**Обещает**: `список` ловит любое исключение соединения, включая группы исключений `anyio`, и
кладёт в `сбой` самую глубокую причину одной строкой; значения заголовков и переменных не
попадают в `сбой` никогда (подстановка ошибается именем переменной, а не значением);
`список_всех` не падает на одном сервере; `добавить`/`убрать` сохраняют прочие ключи верхнего
уровня и порядок прочих серверов, пишут `json.dumps(…, ensure_ascii=False, indent=2)` через
временный файл в том же каталоге и `os.replace`. Окружение stdio-сервера — `os.environ`,
дополненное его `env` после подстановки (как у Claude Code: без родительского окружения `uvx`
не найдёт `PATH`).
**Не делает**: не вызывает инструменты, не проверяет имя сервера и тайны (это разбор команды),
не пишет в журнал, не знает интерфейса, не ставит предела числа страниц.
**Предел ожидания**: у библиотеки пределы по умолчанию есть только у HTTP, у stdio — никакого; поэтому `список` целиком (запуск, `initialize`,
все страницы) идёт под пределом `MCP_TIMEOUT`, как запуск сервера у Claude Code. Истечение — сбой
«сервер не ответил за N с», процесс снят. Кривое `MCP_TIMEOUT` — сбой у каждого сервера.
Негодная запись не ломает файл: её `Итог` несёт причину в `сбой`. Код ответа HTTP ≥400
дописывается в сбой («HTTP 401 Unauthorized»). Вызов поверх `соединение()` (следующий день)
сам отфильтровывает `НегоднаяЗапись` и сам ставит свой предел: `соединение()` предела не несёт.

## Шаг 1. Модуль `mcp_client`: соединение и список инструментов по файлу серверов, его правка

**Файлы**: `myharness/pyproject.toml`, `myharness/uv.lock`, `myharness/src/myharness/mcp_client.py`,
`myharness/tests/mcp_учебный_сервер.py`, `myharness/tests/check_units.py` (новый раздел в конце)
**Зависит от**: ничего
**Ход**: полный, потому что у модуля есть читатели за границей файлов шага — команды шага 2 и
мост инструментов к DeepSeek на следующий день; ошибка границы (что выпускает `список`, что
лежит в `сбой`) разойдётся с ними молча.
**Требование**: `openspec/specs/mcp/spec.md` (пишется в шаге 3)
**Проверка**:
1. `check_units`, раздел MCP, без сети: учебный сервер с двумя инструментами (`add`, `echo`) —
   `список` даёт `протокол` непустой, имена `add`, `echo`, `полное_имя` вида
   `mcp__local__add` (запись названа `local`), схема с `required`; парная — сервер с несуществующей командой даёт `сбой`
   и пустые инструменты, а `список_всех` из двух записей (живая и битая) даёт оба итога в порядке
   файла; подстановка: `${A}`, `${A:-x}` при незаданной, `KeyError` с именем при незаданной без
   умолчания; `добавить`/`убрать` во временном каталоге: прочий ключ верхнего уровня сохранён,
   занятое имя — `ОшибкаФайла`, неизвестное — `ОшибкаФайла` с именами; нет файла — `[]`.
2. **Живой прогон** (несёт этот шаг; интерфейса не требует): в песочнице ведущего `.mcp.json`
   с `github` (HTTP, `Authorization: Bearer ${GITHUB_TOKEN}`) и `git` (`uvx mcp-server-git`),
   `GITHUB_TOKEN=$(gh auth token) uv run python -c "…список_всех…"` — оба сервера без сбоя,
   инструментов 45 и 12 (или сколько отдадут — записать); затем тот же прогон без
   `GITHUB_TOKEN` — у `github` сбой с именем переменной, `git` цел.

**Содержание**: соединение — `AsyncExitStack`: для stdio `stdio_client(StdioServerParameters(
command=подставленная, args=[подставленные], env={**os.environ, **подставленные}))`; для HTTP
`create_mcp_http_client(headers=подставленные)` и `streamable_http_client(адрес,
http_client=клиент)`; затем `ClientSession` и `initialize()`. `список` — цикл
`list_tools(cursor=…)` до `next_cursor is None`. Поток ошибок stdio-сервера (`errlog`)
отводится в `subprocess.DEVNULL`-подобный приёмник, а не в терминал: иначе чужие строки лягут
поверх экрана `prompt_toolkit`. Разбор записи файла: есть `url` (или `type` `http`) — HTTP,
есть `command` — stdio, иначе `ОшибкаФайла` с именем записи; `type` `sse` — `ОшибкаФайла`
«SSE не поддерживается». Сбой = `f"{type(e).__name__}: {e}"` самой глубокой причины группы.

## Шаг 2. Команды `/mcp`, `/mcp add`, `/mcp remove` в `myharness`

**Зависит от**: шаг 1
**Ход**: быстрый, потому что читатель — только человек за экраном.
**Требование**: `openspec/specs/commands/spec.md` → «/mcp»

`/mcp add git -- uvx mcp-server-git`, `/mcp add github https://api.githubcopilot.com/mcp/
--header "Authorization: Bearer ${GITHUB_TOKEN}"`, `/mcp` — два сервера со списками,
`/mcp add git …` — отказ «занято», `/mcp remove git`, `/mcp` — один сервер, `/help mcp`.
**Содержание**: `cmd_mcp` разбирает `arg` через `shlex.split`; `add`/`remove` — синхронная
запись и строка итога («сервер <имя> добавлен в <путь>; проверить — /mcp»); без доводов —
строка «подключаюсь к N серверам…», затем `await mcp_client.список_всех(Path.cwd() /
ИМЯ_ФАЙЛА)` и замена строки ожидания итогом: по серверу заголовок
`<имя> · <способ> · <имя_на_сервере> · протокол <версия> · инструментов N`, под ним по
инструменту `полное_имя — первая строка описания`; сбой — строка ошибки с причиной; нет файла —
подсказка `/mcp add`. Значения заголовков и `env` не печатаются нигде (у записи показываются
только имя и способ). Раздел справки `mcp` (одиннадцатый, заголовок «MCP»): зачем, три команды, где лежит файл, что
токен подставляется из переменной.
