## Договоры

### `rag/chunking.корпус_каталога`

**Отдаёт**: `корпус_каталога(каталог: Path) -> list[tuple[str, str]]` — пары «путь от каталога,
текст» для всех `*.md` каталога рекурсивно, по возрастанию пути.
**Обещает**: вид пар тот же, что у `корпус(корень)`; нарезка и запись в индекс не меняются.
**Не делает**: сети не знает, на диск не пишет.

### `rag/cli.py index --corpus <каталог>`

**Обещает**:

- без `--corpus` поведение прежнее байт в байт;
- с `--corpus` индекс собирается из `корпус_каталога`, поля сборки `commit_hash` и `dirty`
  равны `NULL`: корпус лежит вне git;
- `--corpus` без явного `--index` завершается ошибкой `rag: --corpus требует --index` и ничего
  не пишет. Иначе чужой корпус затёр бы базу знаний проекта `rag/index.sqlite`;
- каталог без файлов `*.md` — ошибка, индекс не трогается.

Читатель за границей шага — сервер `rag/server.py`: схема индекса для него не меняется.

### Имя задания наряда (пишет `наряд.py`, читает `оценка.py`)

`<настройка>.<прогон>-<задание>`. `<настройка>` — ключ из `настройки.json`, латиница, цифры и
дефис. `<прогон>` — целое с 1. `<задание>` — `q01`…`q25` для реплик набора и `party` для
сценария. Пример: `t07.1-q03`.

### `test/ресурсы.jsonl` (пишет `наряд.py`, читает `оценка.py`)

Строка на прогон: `{"настройка", "прогон", "run_id", "модель", "size", "size_vram",
"context_length", "файл_модели_байт", "ts"}`. `size`, `size_vram`, `context_length` — из ответа
службы `GET /api/ps` сразу после прогона. `run_id` — из последней записи журнала.

### `настройки.json`

```json
{"t07": {"основа": "qwen3.5:9b-q4_K_M", "окно": 8192, "инструкция": "хозяин.md",
         "params": {"temperature": 0.7, "thinking": {"type": "disabled"}, "max_tokens": 600}}}
```

`окно: null` — модель берётся как есть, окно задаёт служба. Иначе `наряд.py` создаёт модель
`tavern:<квант>-<окно>` файлом модели из двух строк `FROM` и `PARAMETER num_ctx`. Отсутствующий
ключ в `params` означает «не слать»: действует умолчание модели.

## Шаги

## Шаг 1. `rag/cli.py index --corpus <каталог>` собирает индекс из чужого каталога

**Файлы**: `rag/chunking.py`, `rag/cli.py`, `rag/check_rag.py`
**Зависит от**: ничего
**Ход**: быстрый. Читатель за границей есть — `rag/server.py`, но схема индекса не меняется;
шов просматривает независимый проверяющий один раз.
**Требование**: не про `myharness`
**Проверка**: во временном каталоге два файла `.md`; `uv run --project rag rag/cli.py --index
<временный>.sqlite index --corpus <каталог> --strategy structure` печатает число кусков;
`search` по этому индексу находит кусок. Вторая команда без `--index` выходит с ошибкой, а
отпечаток `sha256` файла `rag/index.sqlite` до и после совпадает.
**Содержание**:

- `chunking.корпус_каталога` по договору.
- `команда_index`: `корпус = ч.корпус_каталога(доводы.corpus) if доводы.corpus else ч.корпус(КОРЕНЬ)`.
- `собрать` получает довод `из_git: bool`; при `False` в сведения идут `commit_hash=None`,
  `dirty=None`, команда `git` не зовётся.
- Отказ без `--index`: довод `--index` получает умолчание `None`, прочие команды подставляют
  `ИНДЕКС` сами.
- `check_rag.py`: три проверки с поддельным счётом векторов — сборка из каталога, отказ без
  `--index`, пустой каталог. Парная проверка: без `--corpus` число кусков равно прежнему.

После шага — фиксация в `main`, затем `git worktree add ~/challenge/w6d4 -b w6d4 main` и папка
`week_6/day_4/` с `README.md` (постановка) и `.gitignore`.

## Шаг 2. Книга правил лежит в своём индексе, и поиск по нему отвечает

**Файлы**: `week_6/day_4/правила.py`, `week_6/day_4/.gitignore`, `week_6/day_4/test/.mcp.json`
**Зависит от**: шаг 1

**Требование**: не про `myharness`

разорванных слов и перепутанных колонок нет.
**Содержание**:

- Адрес: `https://media.wizards.com/2017/avalon_hill/BaBG_Rulebook.pdf`. Отпечаток `sha256`
  `0a08615fa1132a71bf28879ec693e59b99b0a75e9774471db54bc2a98e16a882` вписан в программу; другой
  отпечаток — ошибка с обоими значениями.
- Извлечение — `pymupdf`, построчно с размером и именем шрифта (замер 2026-10-08: текст чистый,
  слова не рвутся). Строка шрифта `TiamatCondensedSC` размером от 16 — заголовок `##`. Строка
  размера 10 шрифтов `TiamatText-Bold` и `CronosPro-BoldDisp` — заголовок `###`. Строки
  `RULES | <число>` и страницы 1, 22–24 (адреса, авторы, пустые заметки) выбрасываются.
- Выход: `test/правила/BaBG_Rulebook.pdf`, `test/правила/md/rulebook.md`. Затем программа зовёт
  `rag/cli.py --index test/правила/правила.sqlite index --corpus test/правила/md --strategy structure`.
- `test/.mcp.json`: сервер `rules` — `rag/server.py` из `~/challenge/main`, окружение
  `RAG_INDEX=<песочница>/правила/правила.sqlite`, `RAG_MODE=base`. Режим уточняет шаг 4.

## Шаг 6. Оценка: по журналу — таблица мер правила, фантазии, скорости и ресурсов

**Файлы**: `week_6/day_4/оценка.py`, `week_6/day_4/проверки.py`
**Зависит от**: шаг 5
**Ход**: быстрый, с одним независимым просмотром шва `наряд.py` + `оценка.py`: ошибка меры

**Требование**: не про `myharness`
**Проверка**: `uv run --project ~/challenge/main/rag оценка.py --настройка do` печатает строку

да», без одного — «нет»; ссылка `[2]` при двух найденных кусках — «да», `[7]` — «нет»; два
одинаковых текста — разнообразие 0, два текста без общих слов — 1.
**Содержание**:

- Меры программы по ответу: три раздела («Правило», «Сцена», «Что дальше») на месте; доля
  кириллицы среди букв вне скобок и кавычек; ссылка `[n]` раздела «Правило» ведёт на найденный
  кусок (заголовки найденного — из отправленного сообщения, как в `rag/eval.найденные_источники`);
  `finish_reason`; `usage.completion_tokens`; `elapsed_ms` + `search_ms`; токены в секунду.
- Разнообразие: `1 − |A∩B| / |A∪B|` по множествам слов раздела «Что дальше» (у ответа без
  разделов — всего ответа). Считается между прогонами одной реплики и между репликами прогона.
- Судья `deepseek-v4-pro` через `rag/rewrite.спросить`, ответ — JSON:
  `{"правило": "верно" | "частично" | "неверно" | "отказ", "продолжает": bool, "новое": bool,
  "выбор": bool, "вымысел_как_правило": bool, "довод": str}`. Вход судьи: реплика, ожидание,
  ответ. Для задания `party` — отдельный запрос на реплику с 3-й:
  `{"помнит": bool, "противоречит": bool, "довод": str}` по полю `связи`.
- Вердикты хранятся в `test/вердикты.json` по отпечатку входа, как `rag/cite_eval.Вердикты`:
  судья зовётся один раз на ответ.
- Выход: Markdown-таблица, строка на настройку: правило верно, отказ на чужих, форма, ссылка,
  русский, три признака фантазии, вымысел как правило, разнообразие, длина ответа (медиана и
  наибольшая), обрывов по длине, время (медиана), токенов в секунду, память, доля видеоядра,
  окно. Довод `--out` пишет файл, `--настройка` повторяется.
