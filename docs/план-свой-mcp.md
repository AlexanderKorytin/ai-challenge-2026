## Договоры модулей

### mcp_tools
**Владеет**: словарём держателей соединений `{имя сервера: _Держатель}` одного сеанса терминала;
кроме него никто к сессиям не обращается.
**Отдаёт**:
- `class Разрешения` (frozen): `allow: tuple[str, ...]`, `deny: tuple[str, ...]`;
  `разрешён(полное_имя: str) -> bool`; `сервер_возможен(имя_сервера: str) -> bool`.
- `def прочитать_разрешения(каталог: Path) -> tuple[Разрешения, str | None]` — правила из
  `.claude/settings.json` и `.claude/settings.local.json` (списки складываются), жалоба при
  порче файла (тогда правил из этого файла нет).
- `class Соединения`: `async def набор(self, каталог: Path) -> Инструменты | None`,
  `async def закрыть(self) -> None`.
**Обещает**: неразрешённый инструмент не попадает в схемы и не исполняется (исполнитель
отказывает по имени, даже если модель его выдумала); `deny` старше `allow`; сбой сервера не
выпускается исключением из `набор`, а ложится в `Инструменты.жалоба` без тайн; после `закрыть`
процессов местных серверов не остаётся; вход и выход из контекста соединения — в одной задаче.
**Не делает**: не пишет на диск; не показывает на экран; своих пределов не ставит (только
`MCP_TIMEOUT`, `MCP_TOOL_TIMEOUT`).

### agent (изменение договора)
- `инструменты: Callable[[], Инструменты | None | Awaitable[Инструменты | None]] | None`;
  `_набор_инструментов` становится `async`, результат-ожидаемое дожидается. Прочее — как было.
- `Инструменты` получает `жалоба: str | None = None`; непустая жалоба идёт в `store_error` тем же
  путём, что жалоба поставщика сегодня, и при непустом наборе.
- `def соединить(*наборы: Инструменты | None) -> Инструменты | None` — схемы подряд, исполнитель
  по имени отдаёт тому набору, чья схема это имя несёт; имени нет ни в одной схеме — результат
  «нет такого инструмента: <имя>» (текст автомата); жалобы через «; ». Все `None` — `None`.

## Изменения требований

Первый рубеж `Spec` (2026-09-22) вернул раздел с четырьмя находками; ниже — исправленный.

- **mcp**:
  - «Purpose»: снимается «передача модели — следующая работа».
  - «Соединение и список инструментов» сужается до опроса `/mcp`: открыть, список, закрыть —
    это про показ; соединение для модели живёт по новому требованию ниже.
  - Новое «Разрешение модели»: модели предлагаются только инструменты по правилам
    `permissions.allow` из `.claude/settings.json` и `.claude/settings.local.json` рабочего
    каталога, вид `mcp__<сервер>`, `mcp__<сервер>__*`, `mcp__<сервер>__<инструмент>`; `deny`
    старше `allow`; порча файла — жалоба и нет правил из него.
  - Новое «Кто получает»: только собеседник главного экрана и только при стратегии не
    `branching` (у неё звенья круга не хранятся — `memory` «Узел Branching»); пакетный режим,
    исполнители группы, шаги способов и служебные агенты — нет. От карты стадий, выбранной
    задачи и паузы инструменты MCP НЕ зависят.
  - Новое «Соединение на сеанс»: открывается перед первым обменом с разрешённым сервером,
    сверяется с файлами перед каждым обменом, умершее переоткрывается, закрывается при выходе.
  - Новое «Вызов инструмента»: имя функции `mcp__<сервер>__<имя>` с заменой знаков вне
    `[A-Za-z0-9_-]` на `_`; результат — текстовые части; `isError` и обрыв — «ошибка
    инструмента»; предел `MCP_TOOL_TIMEOUT` только если задан. «Тайны не показываются» —
    распространяется на жалобу набора.
  Соседи: `commands`, `agent`, `task-machine`, `invariants`, `tokens`, `memory`, `config`.
- **agent**, «Круг вызовов инструментов идёт внутри одного обмена»: поставщик MAY быть
  асинхронным; у набора MAY быть жалоба, она доходит до человека и при непустом наборе.
- **task-machine**: везде, где об отсутствии инструментов говорится как о следствии условий
  автомата, — «инструментов автомата»: требование «Инструменты автомата даются только задаче
  своего профиля» (`:29-35`, «запрос уходит без инструментов автомата; инструменты MCP — по
  способности `mcp`»), сценарии `:51`, `:56`, «Пауза снимает инструменты» `:237`, `:241-242`,
  строка `:17-18` («при которых выдаются инструменты автомата»). Имя вызова, которого нет ни в
  одном наборе, по-прежнему получает «нет такого инструмента: …» — один текст на весь набор.
- **invariants** `:198`: «условия, при которых не выдаются инструменты автомата».
- **tokens** `:54-55`: вес приложений и описаний растёт и у профиля без карты стадий, если
  разрешены инструменты MCP; `:163-164` — отставание на обмен и после правки `.mcp.json` и
  правил разрешений.
- **commands**, «/mcp»: у инструмента в показе — пометка «✓ модели»; жалоба на испорченный файл
  правил — строкой ошибки над списком. `:482` — «вернёт модели инструменты автомата».
- **memory** «Узел Branching» не меняется: инструментов у `branching` по-прежнему нет.

## Шаг 1. Сервер `cbr` отвечает инструментами на местном запросе
**Файлы**: `mcp_servers/cbr/*`
**Зависит от**: ничего
**Ход**: быстрый — читатель сервера за границей шага только клиент по протоколу, а протокол
держит библиотека.
**Требование**: не про myharness
**Проверка**: `uv run --directory mcp_servers/cbr python check_server.py` — все строки «ок»;
затем местный запуск `CBR_MCP_TOKEN=t uv run --directory mcp_servers/cbr python server.py
--port 8770` и `mcp_client.список` на `http://127.0.0.1:8770/mcp` с заголовком — два инструмента;
без заголовка — сбой с «HTTP 401 Unauthorized».
**Содержание**:
- `ИСТОЧНИК = "https://www.cbr.ru/scripts/"`; `async def _получить(путь: str, доводы: dict) ->
  bytes` через `httpx.AsyncClient` с его умолчательным пределом ожидания (5 с на соединение и
  чтение) — своего числа не заводим; истечение — ошибка инструмента «ЦБ не ответил»; декодирование `windows-1251`
  делает `xml.etree.ElementTree.fromstring` по заголовку XML.
- Модели выхода (`pydantic.BaseModel`): `Курс{code, name, nominal, value, unit_rate,
  rate_date, requested_date}`, `Точка{date, nominal, value, unit_rate}`,
  `Динамика{code, name, date_from, date_to, points: list[Точка]}`. Числа — `float` из «86,3793».
  Имена полей латиницей: схема уходит модели DeepSeek, а описания полей — по-русски.
- `@srv.tool() async def get_rate(currency: Annotated[str, Field(description="Код валюты по
  ISO 4217: USD, EUR, CNY…")], date: Annotated[str | None, Field(description="Дата ГГГГ-ММ-ДД;
  не задана — сегодня")] = None) -> Курс` — `XML_daily.asp?date_req=ДД/ММ/ГГГГ`, `rate_date`
  из `ValCurs/@Date`. Неизвестный код — `ValueError("нет курса XXX на ДД.ММ.ГГГГ; есть: …")`.
- `@srv.tool() async def get_rate_dynamics(currency, date_from, date_to) -> Динамика` — ID
  валюты из `XML_daily.asp` на `date_to`, затем `XML_dynamic.asp?date_req1&date_req2&VAL_NM_RQ`.
  `date_from > date_to` — `ValueError`.
- `srv = MCPServer("cbr", instructions="Официальные курсы валют ЦБ РФ к рублю.")`.
- `def приложение(токен: str, имена: list[str]) -> ASGIApp`: `srv.streamable_http_app(
  stateless_http=True, json_response=True, transport_security=TransportSecuritySettings(
  allowed_hosts=имена, allowed_origins=[]))`, обёрнутое своей прослойкой ASGI: заголовок
  `Authorization` ≠ `Bearer <токен>` (сравнение `hmac.compare_digest`) — ответ 401 с
  `WWW-Authenticate: Bearer`. Без сеансов на сервере: перезапуск службы не рвёт клиента.
- `__main__`: `--host 127.0.0.1 --port 8770 --allowed-host …` (повторяемый), токен из
  `CBR_MCP_TOKEN`; нет или пустой — выход с ошибкой, а не служба без замка.
- `check_server.py`: разбор образцов (`XML_daily`, `XML_dynamic`, выходной день) подменой
  `_получить`; ошибка неизвестного кода со списком; через `httpx.ASGITransport` — 401 без
  токена, 401 с чужим токеном, 200 на `initialize` с верным; `tools/list` отдаёт оба
  инструмента с описанием каждого довода и `outputSchema`; `tools/call get_rate` —
  `structuredContent` с `rate_date`. Парная проверка: тот же вызов с другим кодом даёт другой курс.

## Шаг 3. Модель вызывает разрешённый инструмент MCP и получает результат
**Файлы**: `mcp_tools.py`, `mcp_client.py`, `agent.py`, `state.py`, `cli.py`, `tests/check_units.py`
**Зависит от**: ничего (проверки — на учебном сервере stdio)
**Ход**: быстрый — изменённый договор агента (асинхронный поставщик, `жалоба`) читают только
файлы этого же шага; прочие агенты поставщика не получают.
**Требование**: `mcp` → «Разрешение модели», «Соединение на сеанс», «Вызов инструмента»;
`agent` → «Круг вызовов инструментов идёт внутри одного обмена»
**Проверка**: `uv run python tests/check_units.py` по строкам «MCP-мост»: учебный сервер в
`.mcp.json` временного каталога, `allow: ["mcp__local__add"]` — в схемах `mcp__local__add` есть,
`mcp__local__echo` нет (парная: `allow: ["mcp__local"]` — оба); поддельный клиент DeepSeek
вызывает `add` с `{"a":2,"b":3}` — результат круга «5»; вызов `echo` при разрешённом только `add`
— «нет такого инструмента: mcp__local__echo» (схемы у него нет); прямой вызов исполнителя MCP
с именем неразрешённого инструмента — «ошибка инструмента: … не разрешён»; `deny: ["mcp__local__add"]` поверх `allow` — нет `add`;
второй обмен не запускает второй процесс (номер процесса сервера тот же); убитый процесс —
следующий обмен переоткрывает; `закрыть()` — процесса нет; битый `settings.json` — жалоба с
путём, инструментов нет.
**Содержание**:
- `mcp_client`: `async def все_инструменты(сессия: ClientSession, сервер: str) ->
  tuple[Инструмент, ...]` — цикл по страницам из `список`, `список` зовёт её же;
  `_вычистить` → `вычистить` (открытое имя, читатель — `mcp_tools`).
- `mcp_tools._Держатель`: `сервер`, `задача: asyncio.Task`, `готово: asyncio.Event`,
  `стоп: asyncio.Event`, `сессия: ClientSession | None`, `инструменты`, `сбой: str | None`.
  Тело задачи: `async with mcp_client.соединение(сервер) as (сессия, _)` → `все_инструменты` →
  `готово.set()` → `await стоп.wait()`; исключение — `сбой = вычистить(...)`, `готово.set()`.
- `Соединения.набор(каталог)`: читает `.mcp.json` (`mcp_client.прочитать`) и разрешения;
  нужные серверы = годные записи с `сервер_возможен`; лишние держатели — `стоп.set()` и ожидание
  задачи; новые и умершие (`задача.done()`) — новый держатель; ожидание `готово` всех под
  `mcp_client._предел()` одновременно; не дождались — задача снимается, сбой «сервер не ответил
  за N с». Схема на инструмент: `{"type": "function", "function": {"name": имя_функции,
  "description": описание, "parameters": схема}}`, где `имя_функции = re.sub(r"[^A-Za-z0-9_-]",
  "_", полное_имя)`; имя длиннее 64 знаков — инструмент не предлагается, жалоба «имя длиннее 64
  знаков — API DeepSeek его не примет» (это предел API, а не наш). Исполнитель: имя функции →
  (держатель, исходное имя), разрешение проверяется ещё раз, `json.loads` доводов (не объект —
  `ValueError`), `сессия.call_tool` под `asyncio.timeout(MCP_TOOL_TIMEOUT/1000)` только если
  переменная задана; результат — текстовые части через перевод строки, прочие —
  `[<тип> <mimeType>]`, нет текстовых, но есть `structuredContent` — `json.dumps(...,
  ensure_ascii=False)`; `isError` — `RuntimeError(текст)`.
- `Соединения.закрыть()`: `стоп.set()` всем, `asyncio.gather` задач.
- `agent`: `_набор_инструментов` — `async`, `inspect.isawaitable`; жалоба набора
  складывается с жалобой поставщика; `соединить(...)`.
- `state`: поле `mcp: mcp_tools.Соединения` (заводится в `State`), поставщик главного
  собеседника — `async def _набор_главного(): return agent.соединить(machine.набор(state,
  profile), await state.mcp.набор(Path.cwd()) if profile.context_strategy != CONTEXT_BRANCHING
  else None)`. Проверка шага 3 дополняется: при `branching` инструментов MCP в схемах нет;
  задача на паузе — инструменты MCP есть, инструментов автомата нет.
- `cli.repl`: `await state.mcp.закрыть()` в `finally` до закрытия клиента.
