## Договоры

### `rag/server.py` — формат ответа `search`
**Отдаёт**: куски через пустую строку, у каждого первая строка
`[n] <source> › <раздел> · <chunk_id> (<счёт с тремя знаками>)`, дальше текст куска
(`text.strip()`). `<раздел>` сам может содержать ` › ` и ` · `; `<chunk_id>` пробелов не
содержит и стоит **последним** перед счётом.
Пустой итог — одна строка:
`В базе не нашлось достаточно близкого (режим <режим>, порог <порог>, лучшая близость <значение с тремя знаками>).`
**Обещает**: начало `[n] <source> ›` и конец `(<счёт>)` прежние — `eval.найденные_источники`
читает новые журналы без правки. «Лучшая близость» — то самое значение, которое сравнивалось с
порогом: косинус у `threshold`/`heuristic`, вероятность у `model`.
**Не делает**: на диск не пишет.

### `rag/cite.py`
**Отдаёт**:
```python
ПУСТО = "В базе не нашлось достаточно близкого"
ОТКАЗ = "не знаю"

@dataclass(frozen=True)
class Найденное:            # один кусок блока найденного
    номер: int; источник: str; раздел: str; chunk_id: str; текст: str

@dataclass(frozen=True)
class Ссылка:               # строка раздела «Источники»
    номер: int | None; chunk_id: str | None; строка: str

@dataclass(frozen=True)
class Цитата:               # строка раздела «Цитаты»
    номер: int | None; текст: str

@dataclass(frozen=True)
class Разбор:
    ответ: str              # текст раздела «Ответ»; у отказа — весь ответ
    источники: list[Ссылка]
    цитаты: list[Цитата]
    отказ: bool             # ответ начинается словами «Не знаю» (без регистра и знаков)
    уточнение: bool         # в ответе есть вопросительный знак

def найденное(отправленное: str, вопрос: str) -> list[Найденное] | None
def разобрать(ответ: str) -> Разбор
def источник_годен(ссылка: Ссылка, куски: list[Найденное]) -> bool
def цитата_дословна(цитата: Цитата, куски: list[Найденное]) -> bool
```
**Обещает**: `найденное` — `None`, если блока нет (поиск не состоялся), `[]` — если блок есть, а
кусков ноль (сработал порог). Текст последнего куска не захватывает вопрос: хвост
`"\n\n" + вопрос` срезается. `цитата_дословна` прощает только различие пробельных символов
(любая их последовательность равна одному пробелу) — ни кавычки, ни разметку, ни регистр.
`источник_годен` — номер в пределах найденного **и** `chunk_id` строки равен `chunk_id` куска с
этим номером.
**Не делает**: сети не знает, на диск не ходит, исключений на кривом ответе не выпускает —
кривой ответ даёт пустые разделы.

## Шаг 1. Сервер называет `chunk_id` куска и лучший счёт при пустом итоге
**Файлы**: `rag/rerank.py`, `rag/rerank_compare.py`, `rag/server.py`, `rag/check_rag.py`
**Зависит от**: ничего
**Ход**: быстрый. Читатель формата за границей шага — `rag/eval.py`, но начало и конец строки
не меняются, и это держит проверка в файлах шага.
**Требование**: не про myharness
**Проверка**: `uv run --project rag rag/check_rag.py` — код 0; живьём:
`RAG_MODE=heuristic RAG_K1=30 RAG_THRESHOLD=0.54` и вызов `server.найти_текст` на вопросе q01 —
в строках видны `· structure:…:<n>`.
**Содержание**:
- `rerank.Итог` получает поле `лучшее: float | None = None` — наибольшее значение, сравнивавшееся
  с порогом, по всем кандидатам (`None` у `base` и при нуле кандидатов). Считает `Поиск.отобрать`:
  `max(н.счёт if режим == "model" else н.косинус for н in найденные)`.
  `rerank_compare.py:153` собирает `Итог` тремя позиционными доводами — остаётся рабочим за счёт
  умолчания.
- `server.найти_текст`: строка куска
  `f"[{место}] {кусок.source} › {раздел} · {кусок.chunk_id} ({найденный.счёт:.3f})"`;
  пустой итог —
  `f"В базе не нашлось достаточно близкого (режим {режим}, порог {порог}, лучшая близость {итог.лучшее:.3f})."`
  (при `лучшее is None` хвост «лучшая близость» опускается).
- Описание модуля `server.py` — новый вид строки.
- Проверки: строка куска несёт `chunk_id` последним перед счётом; `eval.найденные_источники`
  на блоке нового вида возвращает те же пути (парная: на блоке старого вида — тоже); пустой итог
  называет лучшее значение, и оно ниже порога (парная: при пороге ниже лучшего итог непуст).

## Шаг 3. Программа сверяет источники и цитаты ответа с найденным
**Файлы**: `rag/cite.py`, `rag/check_rag.py`
**Зависит от**: шаг 1 (формат строки), шаг 2 (настоящие ответы пробы — образец для разбора)
**Ход**: быстрый. Читатель за границей — `cite_eval.py` шага 4, его пишет тот же ведущий сразу
следом; договор выписан выше.
**Требование**: не про myharness
**Проверка**: `check_rag.py` — код 0; `cite.разобрать` и сверка на четырёх записях журнала пробы
шага 2 дают то же, что видно глазами.
**Содержание**: договор `rag/cite.py` выше, плюс:
- `найденное`: блок начинается с `ЗАГОЛОВОК_НАЙДЕННОГО` (`"Найдено в базе знаний по вопросу:"`),
  заголовки кусков ищутся **по порядку номеров** после пустой строки (как в
  `eval.найденные_источники` — в тексте кусков бывают строки того же вида) выражением
  `(?:\A|\n\n)\[<n>\] (.+?) › (.*) · (\S+) \(-?\d+\.\d{3}\)$`; текст куска — от конца заголовка
  до начала следующего заголовка либо до конца сообщения без хвоста `"\n\n" + вопрос`.
- `разобрать`: разделы — по строкам `## Ответ`, `## Источники`, `## Цитаты` (решёток от одной
  до шести, регистр не важен). Строка источника — пункт списка `- [n] …`; `chunk_id` — последнее
  слово после ` · `. Строка цитаты — пункт `- [n] «…»`: снимается одна пара внешних кавычек
  `«»` либо `""`. Отказ — как `eval.отказ`: слова ответа без регистра и знаков начинаются с
  `ОТКАЗ`.
- Проверки (каждая с парной): цитата с переносом строки внутри засчитана, с заменённым словом —
  нет; цитата из куска 2 под номером 1 — нет; источник с чужим `chunk_id` — нет; номер вне
  найденного — нет; вопрос в хвосте сообщения цитатой не считается; ответ без разделов — пустые
  списки; «Не знаю, уточните…?» — отказ с уточнением, «Ответ: не знаю» — не отказ.

## Шаг 4. Отчёт дня: три пункта условия по 10 вопросам и режим «не знаю»
**Файлы**: `rag/cite_eval.py`, `rag/rewrite.py`, `rag/eval.py`, `rag/check_rag.py`
**Зависит от**: шаг 3
**Ход**: быстрый. Деньги есть (судья), но итогового денежного числа отчёт не несёт; читателя за
границей шага у отчёта нет.
**Требование**: не про myharness
**Проверка**: `check_rag.py` — код 0; отчёт по журналу пробы шага 2 (4 задания) собирается, судья
живьём выносит вердикты по `q01` и `q06`, повторный запуск с тем же `--verdicts` судью не зовёт.
**Содержание**:
- `rewrite.py`: из `переписать` выносится
  `спросить(тело: dict, *, клиент: httpx2.Client | None = None) -> str` — запрос к DeepSeek и
  текст ответа (`choices[0].message.content`), те же ошибки `ОшибкаПереписывания`, ключ читается
  внутри. `переписать` зовёт её; поведение прежнее, существующие проверки переписывания проходят
  без правки.
- `eval.загрузить`: имя задания `([qnf])(\d+)-([\w+]+)`.
- `cite_eval.py`:
  - `МОДЕЛЬ_СУДЬИ = "deepseek-v4-pro"`, рассуждения — умолчание API (включены),
    `response_format: json_object`.
  - `судить(вопрос: str, ответ: str, цитаты: list[str], спросить=пер.спросить) -> dict` —
    `{"вердикт": "следует" | "частично" | "не следует", "довод": str}`. Судье уходят вопрос,
    раздел «Ответ» и **только дословные** цитаты; инструкция: «следует» — каждое утверждение
    ответа подтверждено цитатами, «частично» — часть утверждений без опоры, «не следует» —
    ответ противоречит цитатам либо не опирается на них; в инструкции слово JSON и пример
    (без них DeepSeek отклоняет `json_object`). Вердикт вне трёх слов — `ValueError`.
  - Файл вердиктов (`--verdicts`): `{"<имя задания>": {"sha": <sha256 ответа>, "вердикт", "довод"}}`;
    вердикт берётся из файла при совпавшем `sha`, иначе судья зовётся и файл переписывается
    через временный файл и `os.replace` после каждого вердикта. Без дословных цитат судья не
    зовётся: вердикт «нет цитат».
  - Мера основного вопроса (`q`): поиск был; **источники есть** — раздел непуст и все строки
    годны; **цитаты есть** — раздел непуст и все цитаты дословны; **смысл** — вердикт судьи;
    доля фактов (`eval.доля_фактов`); ложный отказ.
  - Мера вопроса без ответа (`n`, `f`): начинается с «Не знаю»; есть уточнение; слой —
    «порог» (`найденное == []`) либо «модель».
  - Отчёт: сводка строками «источники есть: N из 10», «цитаты есть: N из 10», «все цитаты
    дословны: M из K цитат», «смысл совпадает: N из 10 (частично — P)», «ложных отказов»,
    «не знаю: N из 10, из них порогом — A, моделью — B; с просьбой уточнить — C»; таблица по
    вопросам; раздел ответов: вопрос, ответ целиком, под ним по каждой цитате `✓`/`✗` и вердикт
    судьи с доводом.
  - Запуск: `uv run --project rag rag/cite_eval.py --journal <журнал> --run <run_id> [--run …]
    --verdicts <файл.json> --out <файл.md>`; наборы — `--answers`, `--negative`, `--far` с
    умолчаниями `rag/answers.jsonl`, `rag/negative.jsonl`, `rag/far.jsonl`; из `n` и `f` в отчёт
    идут только задания, бывшие в наряде.
- Проверки: судья подменён функцией; вердикт из файла не зовёт судью, при другом ответе — зовёт
  (парная); файл вердиктов пишется во временный каталог; «источники есть» ложно при одной негодной
  строке (парная — при всех годных истинно); слой «порог» при пустом блоке и «модель» при
  непустом; `eval.загрузить` берёт `f01-cite`.

**После шага 4 — один независимый просмотр шва** шагов 1, 3, 4 (`general-purpose` на `opus`):
формат строки ↔ разбор ↔ отчёт. Находки закрываются пачкой.
