## Договор модуля

### `assistant`

**Владеет**: ничем. Состояния между вопросами нет.

**Отдаёт**:

```python
ИМЯ_ПОМОЩНИКА = "помощник"
def профиль() -> tuple[Profile, list[str]]          # профиль и предупреждения загрузки
async def спросить(state: State, вопрос: str, *, on_event=None) -> Turn
```

**Обещает**:

- каждый вызов `спросить` заводит нового `Agent` без хранилища: память разговора не меняется;
- поиск идёт через `state.поиск`, инструменты — через `state.mcp.набор(Path.cwd())`;
  инструментов автомата задачи у помощника нет;
- модель — модель сеанса, та же, что у обмена главного экрана;
- расход уходит в итог сеанса на любом пути (`state.retire`, `state.session_cost`) — по
  образцу `recognizer.спросить`.

- блока «Инварианты», судьи, карточки папки, рабочего состояния и записей о человеке у
  помощника нет: `Agent` заводится без поставщиков `facts`, `project`, `work`, `инварианты`,
  `проверка`.

**Не делает**: каталог состояния не трогает, на экран не печатает, исключения обмена не
глотает. Журнал прогонов пишет сам `Agent` под именем `помощник`.

**Имя профиля `помощник` не защищено намеренно.** Любая одноимённая пара файлов в каталогах
поиска перекрывает встроенный профиль, в том числе заведённая мастером `/profile new`. Это
обычное правило перекрытия профилей; предупреждения загрузки `/help` печатает.

## Изменения требований

Слово: агент команды `/help` во всех требованиях называется **«помощник по проекту»**. Слово
«помощник» в `commands` уже занято мастером профиля и группой. Помощник по проекту — отдельный
род агента, а не «служебный агент»: запреты служебным агентам на него не переносятся молча,
в каждом перечне получателей у него своя строка.

- **`commands`, «Состав команд»** — перечень получает `/info`. Текст о справке внутри него
  (меню, `<слово>`, неоднозначное и неизвестное слово) переходит под имя `/info`.
- **`commands`, «Команды памяти подсказывают следующим уровнем»** — подстановка слов идёт
  после `/info `, а не после `/help `.
- **`commands`, новое требование «Вопрос помощнику по проекту»** — `/help <вопрос>` SHALL
  отправлять вопрос помощнику по проекту: новый агент на каждый вопрос, память разговора не
  меняется, ответ печатается в главный экран. `/help` без вопроса SHALL сообщать, что вопрос
  не задан. `/help` не является запросом панели и очереди панели не ждёт. Модель — модель
  сеанса.
- **`commands`, видимость до авторизации** — `/info` видна до ключа, `/help` — после, как
  прочие команды, которым нужен клиент.
- **`commands`, `memory`, `interface`** — 14 упоминаний `/help <раздел>` меняются на
  `/info <раздел>`: `commands/spec.md` строки 10, 32, 34, 45, 50, 54, 58, 80, 109, 655, 673,
  846; `memory/spec.md:1128`; `interface/spec.md:65`.
- **`mcp`, Purpose и «Кто получает инструменты MCP»** — второй получатель: помощник по
  проекту. Он получает инструменты разрешённых серверов MCP без инструментов автомата задачи.
  Уточнение рядом: «сервер, названный полем `rag` профиля» — профиля того агента, который
  ведёт обмен.
- **`agent`, «Найденное в базе знаний идёт в хвост запроса»** — перечень получателей
  поставщика поиска получает помощника по проекту. Перечень повторяют `profiles/spec.md:494`,
  `batch/spec.md:277`, `mcp/spec.md:12` — правятся вместе.
- **`agent`, `invariants`, `memory`, `task-machine`** — помощник по проекту SHALL NOT получать
  блок «Инварианты», строку сверки, судью, карточку папки, рабочее состояние, записи
  о человеке и инструменты автомата. В перечни «кто не получает» дописывается его имя.
  Следствие принято: инвариант папки на ответ помощника не действует.
- **`tokens`, `journal`** — имя помощника по проекту в перечне агентов итога сеанса; прогон
  помощника пишется в журнал под именем `помощник`, номер обмена всегда 1.
- **`profiles`, `api`** — не меняются.
- У `rag/` требований OpenSpec нет.

## Шаг 4. `/help <вопрос>` отвечает по документации и состоянию git

**Файлы**: `assistant.py` (`спросить`), `commands.py` (ветка `/help`), `ui.py` (видимость
`/help` после авторизации), `myharness/tests/test_assistant.py`, требования `commands`, `mcp`,
`agent`, `profiles`, `batch`, `invariants`, `memory`, `task-machine`, `tokens`, `journal` — по
разделу «Изменения требований»
**Зависит от**: шаги 2, 3
**Ход**: быстрый. Шаг пользуется `state.поиск`, `state.mcp`, `state.retire` и не меняет их.
**Требование**: `openspec/specs/commands/spec.md` → новое требование «Вопрос помощнику по проекту»
**Содержание**:

- `спросить` — по договору выше. Агент:
  `Agent(ИМЯ_ПОМОЩНИКА, профиль, инструменты=lambda: state.mcp.набор(Path.cwd()), поиск=state_mod.поставщик_поиска(state, профиль))`.
- Ветка `/help`: пустой довод — `ui.error_fragments("вопрос не задан: /help <вопрос>")`.
  Иначе строка ожидания «ищу в документации» по образцу `ОЖИДАНИЕ_РАСПОЗНАВАНИЯ`, затем
  ответ в главный экран. Ошибка обмена, жалоба поиска и жалоба набора инструментов печатаются
  строкой причины. Нет клиента — строка «нет ключа и не выбрана местная модель».
- Предупреждения `профиль()` печатаются перед ответом.

**Проверка**: проверки с подставным клиентом. Первая: после `спросить` длина памяти
`state.main_agent` прежняя. Парная: обычный вопрос длину памяти меняет. Вторая: расход
помощника входит в `state.session_usage_total`. Ручной сценарий из песочницы с серверами
`rag` и `git` в `.mcp.json`: «в какой я ветке?» — в журнале есть вызов инструмента сервера
`git`, ответ называет ветку. То же на местной модели.
