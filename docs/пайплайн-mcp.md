# Дизайн: пайплайн MCP-инструментов (день 19)

## Задача и видение

Условие: несколько MCP-инструментов (`search`, `summarize`, `saveToFile`) в цепочке —
первый получает данные, второй обрабатывает, третий сохраняет. Проверить автоматическое
выполнение цепочки и корректность передачи данных между инструментами.

Видение пользователя: искать в интернете; поставщик — **Википедия** (решение 2026-09-24);
**всё на Маке, без VPS**; выжимку делает **сам сервер вызовом DeepSeek** со своим файлом ключа (решение
2026-09-24, заменило MCP sampling — см. ниже).

Сценарий: человек пишет в `myharness` «найди в Википедии про X и сохрани выжимку в файл».
DeepSeek сам вызывает `search` → `summarize` → `saveToFile`, человек получает путь к файлу.

## Что решили и почему

### Местный сервер `pipeline`, stdio

Новый сервер `mcp_servers/pipeline/` (в `main`, рядом с `cbr`), запускается `myharness` как
дочерний процесс по stdio из `.mcp.json` рабочего каталога. VPS не нужен; процесс живёт
столько же, сколько соединение сеанса `myharness` (`mcp_tools.Соединения`). Те же `mcp>=2.2,<3`,
`MCPServer`, `@srv.tool()`, модели данных со `structuredContent`, что у `cbr`.

### Три инструмента, данные передаются по ссылке

| Инструмент | Вход | Что делает | Выход |
|---|---|---|---|
| `search` | `query`, `lang` (по умолчанию `ru`) | MediaWiki API одним запросом: `generator=search` + `prop=extracts` (`exintro`, `explaintext`) + `info` (адрес). Сколько статей — умолчание MediaWiki (`gsrlimit` 10), своего числа не заводим | `search_id`, запрос, список «заголовок, адрес, длина вступления»; вступления статей остаются в сервере |
| `summarize` | `search_id`, `focus` (необязательный — на чём сосредоточиться) | берёт вступления **из хранилища сервера**, сам вызывает DeepSeek и сжимает с пометками источников `[n]` | `summary_id`, текст выжимки, источники, модель, `usage` |
| `saveToFile` | `summary_id`, `filename` | пишет Markdown: запрос, дата, выжимка, список источников | путь, размер, `sha256` |

**Почему по ссылке, а не по значению.** Передай модель найденный текст в `summarize` доводом, она
переписала бы его своими словами, обрезала или перепутала — и «корректность передачи» проверить
было бы нечем, а текст оплачивался бы дважды. По ссылке модель переносит только `search_id` /
`summary_id`, данные между инструментами идут внутри сервера и сверяются суммой. Модель при этом
видит всё нужное: заголовки после `search`, выжимку после `summarize`.

Хранилище — словарь в памяти процесса сервера. Переживать сеанс ему незачем: результат цепочки —
файл. Неизвестный id — ошибка инструмента с понятной причиной («сделайте search заново»).

**Автоматичность цепочки** обеспечивает модель: описание каждого инструмента называет, откуда
брать его вход («`search_id` из `search`»). Человек пишет одну просьбу — три вызова идут одним
кругом инструментов `myharness` без его участия.

### Выжимка — сервер сам вызывает DeepSeek

**Пересмотрено 2026-09-24.** Сначала была утверждена выжимка через MCP sampling (сервер просит
модель клиента). На первом рубеже `Spec` выяснилось: протокол 2026-07-28 объявил sampling
**устаревшим** (SEP-2577, вместе с roots и logging) — работает ещё не меньше 12 месяцев, затем
может быть снят; авторы протокола называют альтернативой вызов модели вне протокола. Новая
способность `myharness` на списанной возможности — сознательный техдолг, пользователь выбрал
замену.

`summarize` сам шлёт `POST https://api.deepseek.com/chat/completions` (`httpx2`, без SDK):
модель `deepseek-v4-flash` (умолчание `myharness`), рассуждения выключены (`thinking:
{"type": "disabled"}`) — выжимка это прочтение, а не сочинение, как у судьи; `max_tokens` не
задаётся — своих потолков нет, обрезанная выжимка неотличима от целой. Любой `finish_reason`,
кроме `stop`, — ошибка инструмента, а не молчаливо обрезанный текст.

**Ключ** — в собственном файле настроек сервера `~/.config/pipeline-mcp/config.json`
(`{"api_key": ..., "model": ...}`, `model` необязателен), права 600, каталог переопределяется
`$PIPELINE_CONFIG_DIR` (правило CLAUDE.md о путях для проверок). В окружение, `.mcp.json`,
журнал и ответы инструментов ключ не попадает; текст ошибок DeepSeek вычищается от ключа. Нет
файла или ключа — ошибка `summarize` с путём файла. Ключ переносится ведущим один раз трубой из
настроек `myharness`, не выводясь на экран. **`myharness` не меняется.**

Расход выжимки `myharness` не видит (это не его обмен): ответ `summarize` несёт `usage` модели,
и он виден в журнале как результат инструмента. В итог сеанса `myharness` он не входит —
названо в рисках.

### Файл результата

Каталог — `PIPELINE_OUT_DIR`, по умолчанию `результаты/` в рабочем каталоге (правило CLAUDE.md:
путь записи переопределяется для проверок). `filename` — только имя: пустое, с `/`, `\`, управляющими знаками или ведущей точкой —
отказ; расширение `.md` дописывается. **Существующий файл не перезаписывается** — отказ с
причиной: перезапись теряет прежний результат молча.

### Отвергнуто

- **Передача данных по значению через модель** — см. выше: искажение не ловится, текст дважды.
- **Один инструмент `run_pipeline`**, делающий всё внутри. Цепочку тогда исполняет не
  связка инструментов, а одна функция — условие проверяет именно передачу между инструментами.
- **Три отдельных сервера.** Ссылка `search_id` между процессами потребовала бы общего хранилища;
  выгоды никакой.
- **MCP sampling** — устарел в протоколе 2026-07-28 (SEP-2577), см. выше.
- **Ключ через окружение** или **чтение файла настроек `myharness`** — первое нарушает правило о
  ключе, второе привязывает сервер к чужому формату.
- **Выжимка без модели** — нарезка фраз, а не пересказ.
- **Tavily / DuckDuckGo / Brave** — выбор пользователя: Википедия, ключ не нужен.

## Затронутые способности

- `myharness` не меняется, требований OpenSpec задача не задевает. Сервер `pipeline` — вне `myharness`, требований OpenSpec не имеет (как `cbr`); его договор —
  описания инструментов и проверка `check_server.py`.

## Проверки

- `mcp_servers/pipeline/check_server.py` — без сети и модели: настоящая сессия MCP в памяти,
  MediaWiki и DeepSeek подменены; цепочка `search → summarize →
  saveToFile` — выжимка получила ровно сохранённые вступления, файл содержит ровно выжимку
  (`sha256`), отказы: неизвестный id, `..` в имени, существующий файл, нет ключа.
- Живой прогон из песочницы `week_4/day_4/test/`: одна просьба в `myharness` → три вызова в
  журнале по порядку, файл в `результаты/` на настоящих данных Википедии.

## Границы

Делаем: сервер `pipeline` из трёх инструментов, свой файл ключа сервера, проверки, песочница,
видео. `myharness` не трогаем.

Не делаем: поиск вне Википедии, полные тексты статей (только вступления), хранение результатов
между сеансами, MCP sampling (устарел, см. выше).

## Риски и чем расплачиваемся

- **Модель может не довести цепочку** (остановиться после `search`, спросить «сохранить?»). Лечится
  описаниями инструментов; живой прогон покажет. Жёстко навязывать порядок программой не будем —
  это отнимает у агента решение.
- **Расход выжимки вне счёта `myharness`**: живой счёт и итог сеанса его не покажут; виден в
  ответе `summarize` (`usage`) и в журнале. Цена — вторая точка расхода ключа.
- **Ключ в двух файлах**: при смене ключа менять оба.
- **Википедия требует `User-Agent` с контактом** — ставим имя сервера и адрес репозитория,
  без почты.
