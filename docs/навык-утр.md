# Дизайн: навык `/утр` — упрощённый технический русский

Род задачи по `/штурм`: точечная правка соглашений. Образец —
`https://github.com/tony-adamson/utr-skills` (фиксация `671ba00`).

## Задача и видение

Пользователь принёс образец и поставил задачу: написать свой навык, лучше образца и под наш
порядок работы. Решение пользователя 2026-10-05: **правила действуют в чате всегда, а названный
файл навык правит по команде.**

Упрощённый технический русский (УТР) — раздел 8.2 ГОСТ Р 58049-2017. Это набор правил письма,
при котором читатель понимает текст с первого прочтения и так же, как автор. Английский
прародитель — ASD-STE100.

## Что решили и почему

### 1. Один файл правил, два читателя

```
.claude/skills/утр/правила.md ◀── CLAUDE.md, строка подключения  (чат, каждый разговор)
            ▲
            └────────────────── .claude/skills/утр/SKILL.md      (/утр <файл>, по команде)
```

Правила лежат одним файлом `правила.md`. `CLAUDE.md` подключает его строкой
`@.claude/skills/утр/правила.md` в разделе «Общие»: Claude Code подставляет такой файл в начало
каждого разговора. Поэтому правила переживают рубеж очистки без единого действия. `SKILL.md`
читает тот же файл, когда правит текст по команде.

Причина: `CLAUDE.md` запрещает пересказывать навыки («два описания одного порядка неизбежно
разойдутся»). Строка подключения — не пересказ.

Цена: файл правил оплачивается в каждом обмене. Поэтому в нём только правила и по одному примеру
на правило, без истории и обоснований. Обоснования и номера пунктов ГОСТа лежат в `SKILL.md`,
который в разговор попадает только по команде.

### 2. Что берём из ГОСТа

Все правила сверены с текстом п. 8.2, у каждого назван пункт.

- Предложение — одна мысль, до 20 слов (8.2.5.1, 8.2.6.1). Подсчёт по примечанию ГОСТа: число,
  идентификатор, сокращение, имя в обратных кавычках — одно слово; текст в скобках — отдельное
  предложение.
- Прямой порядок слов (8.2.3.4). Действительный залог (8.2.3.3, 8.2.3.13).
- Глагол вместо отглагольного существительного; не больше двух существительных подряд (8.2.3.10).
- Причастные и деепричастные обороты — только там, где без них теряется смысл (8.2.3.11).
- Сложное предложение заменять простыми (8.2.3.14).
- Одно понятие — один термин, без синонимов (8.2.3.7).
- Без метафор, сравнений и жаргона (8.2.3.5).
- **Русское слово вместо иностранного, если оно есть (8.2.3.6).** Образец от этого пункта
  отступил и оставил «деплой» и «коммит». У нас транслитерация уже запрещена `CLAUDE.md`, и
  ГОСТ это правило подтверждает. Список запретных слов один. По уточнению плана он переехал из
  скобок `CLAUDE.md` в таблицу `правила.md`: прозу со словом «нет» программа прочитать не может.
- Перечисление — вертикальным списком (8.2.3.16).
- Абзац — одна тема, до шести предложений (8.2.6.2).
- Предупреждение стоит перед действием и начинается с условия или с команды (8.2.7).
- Инструкция: одна команда на предложение, конкретные файл, команда и значение (8.2.5.2, 8.2.5.4).

### 3. Что добавляем от себя — под наш порядок

- **Главное первым.** Ответ, вывод или вердикт — первым предложением. Это действующее правило
  «кратко в чат».
- **Новое понятие объяснять при первом упоминании** одной фразой, по возможности параллелью с
  Kotlin и JVM. Пользователя учат с нуля; сухость УТР объяснений не отменяет. В ГОСТе то же
  сказано о сокращениях (8.2.3.10).
- **Имена — как есть.** Команды, файлы, поля, выводы — в обратных кавычках, без перевода и
  склонения.
- **Числа с единицей и источником**: «89,3 млн токенов входа по `bin/расход.py`», а не «много».
- **Не знаю — так и писать**: «не проверял», «неизвестно». Домысел за факт не выдавать.
- **Схема вместо абзаца**, когда в ответе есть связи, порядок или состояния. Подписи узлов — те
  же термины, что в тексте.

### 4. Команда `/утр <файл>`

Навык читает названный файл и `правила.md`, запускает счётчик (см. п. 5), правит текст и
показывает итог тремя строками: сколько нарушений было, сколько осталось и какие оставлены
намеренно. Правка идёт в рабочее дерево, не фиксируется — её видно в `git diff`.

Что навык **не трогает никогда**: блоки кода, имена в обратных кавычках, цитаты, строки ошибок,
таблицы замеров, заголовки `SHALL`/`MUST`/`WHEN`/`THEN` в `openspec/specs/`. Смысл и числа
меняться не должны: навык правит форму. Если правка формы требует решить, что автор имел в
виду, навык не решает, а выносит место в список вопросов.

Команда без имени файла печатает правила — и только.

### 5. Счётчик `bin/утр.py`

Программа считает то, что считается точно и без словаря форм слов:

- предложения длиннее 20 слов — по правилам подсчёта ГОСТа;
- абзацы длиннее шести предложений;
- слова из таблицы «Запретные слова» файла `правила.md` — список читается из таблицы, а не
  переписывается в код.

Выход: строки `файл:строка: правило: отрывок` и код возврата. Зависимостей нет, только
стандартная библиотека Python.

Залог, обороты, цепочки существительных и синонимы программа **не считает**: это решает модель
по правилам. Причина в подходах ниже.

### 6. Подходы и отвергнутое

| Подход | Цена | Решение |
|---|---|---|
| **А. Правила + счётчик точного** | один файл правил и программа в 250 строк с проверками | **берём** |
| Б. Только правила, как в образце | проверка — самооценка: модель сама решает, что уложилась в 20 слов | отвергнут: счёт слов модели не доверяют |
| В. Полный проверяющий на `pymorphy3` (залог, причастия, цепочки) | зависимость, ложные срабатывания, свой набор проверок на проверяющего | отвергнут: цена ошибки — неловкая фраза, аппарат дороже самой работы |

Отвергнуто из образца:

- **Режим «до конца сессии» и его выключатель.** У нас правила — умолчание проекта. Разовое
  отступление пользователь просит словами.
- **`utr-poh`, словарь мата.** Не берём: в задаче один навык, и наши тексты ложатся в публичный
  репозиторий.
- **«Держи правила на 80 %».** Число не из ГОСТа. Вместо него правило: норму нарушают только
  там, где иначе теряется смысл или точность.
- **Ширина схемы 80 символов, «от 3 до 10 узлов».** Числа автора образца, из ГОСТа не следуют.
  Не заводим.
- **Страница HTML по просьбе.** У Claude Code для этого есть свой инструмент; навык письма им не
  управляет.
- **Обращение на «ты» как правило.** Навык обращение не предписывает. Процедуры в наших навыках
  написаны неопределённой формой («прочитать», «назвать») — так и остаётся.
- **Установщик `install.sh` и настройка для Codex.** Навык живёт в `.claude/skills/` проекта,
  как остальные.

## Затронутые способности

Требования `openspec/specs/` не затронуты: поведение `myharness` не меняется. Стадия `Spec`
поэтому сводится к одной сверке: `правила.md` не противоречит разделу «Общие» `CLAUDE.md`.

Затронутые файлы:

| Файл | Что |
|---|---|
| `.claude/skills/утр/правила.md` | новый: правила, по примеру на правило |
| `.claude/skills/утр/SKILL.md` | новый: команда `/утр <файл>`, пункты ГОСТа, границы |
| `bin/утр.py` | новый: счётчик |
| `myharness/tests/` либо проверка рядом с `bin/` | проверки счётчика: подсчёт слов по допущениям ГОСТа |
| `CLAUDE.md`, раздел «Общие» | строка подключения правил |
| память `кратко-в-чат` | ссылка на правила; запись остаётся |

## Границы: что делаем и чего НЕ делаем

Делаем: навык, файл правил, счётчик с проверками, строку в `CLAUDE.md`. Живой прогон: `/утр`
на одном настоящем файле проекта, с показом счёта до и после.

Не делаем:

- не переписываем существующие документы, навыки и спецификации под УТР;
- не встраиваем `/утр` в навыки стадий и в конвейер `/задание`;
- не трогаем общие навыки в `~/.claude/skills/`;
- не вводим проверку в фиксацию или в CI.

## Риски и чем расплачиваемся

- **Постоянный расход.** Файл правил оплачивается в каждом обмене каждого разговора проекта.
  Лечение — объём: только правила. Размер назову после написания, замером, до фиксации.
- **OMP.** Неизвестно, раскрывает ли OMP строку подключения `@…` в `CLAUDE.md`. Если нет —
  в OMP строка читается как указание «прочитать файл». Проверить можно только в самой OMP;
  в эту задачу проверка не входит.
- **Сухость.** УТР написан для инструкций к технике. В объяснении нового понятия он может дать
  текст рубленый и бедный. Лечение — правило об объяснении при первом упоминании и оговорка
  о потере смысла. Проверяется только чтением живых ответов.
- **Счётчик ловит форму, а не смысл.** Нулевой счёт не значит, что текст понятен.
