# Дизайн: оркестрация MCP (день 20)

## Задача и видение

Условие: зарегистрировать несколько MCP-серверов; агент выбирает нужный инструмент, корректно
маршрутизирует запросы и выполняет длинную цепочку. Проверить сценарий с инструментами разных
серверов и корректность выбора и порядка вызовов.

Видение пользователя: сценарий придумывает ведущий, с профильными помощниками.

## Что решили и почему

### Правка `myharness` не нужна — маршрутизация уже есть

Разведка и все трое помощников (`mcp-teacher`, `ai-agents-teacher`, `ai-security-teacher`)
сходятся: сервер входит в имя функции `mcp__<сервер>__<инструмент>`, вызов уходит держателю по
этому имени (`mcp_tools.py`, карта «имя → держатель»), вызовы одного круга исполняются по порядку
модели, ошибка сервера доходит до модели и круг продолжается, своего предела числа кругов нет.
Отсюда главное: **отдельной ошибки маршрутизации не бывает — маршрут выбран вместе с именем.**
Проверять надо выбор модели, а не программу. Значит, день — это сценарий, настройка серверов,
профиль и проверка следа; ветка дня заводится сразу, в `main` идёт только этот дизайн, план и
состояние.

### Сценарий — «справка по юаню», четыре сервера, одна просьба

Просьба человека одной репликой:

> Подготовь справку по китайскому юаню: курс ЦБ на сегодня и как он менялся за последний месяц,
> и что о юане пишет Википедия. Выжимку статей сохрани отдельным файлом, а сводную справку с
> цифрами ЦБ и выводами положи в `справки/`. Всё зафиксируй в git.

| Сервер | Где | Инструменты, разрешённые модели |
|---|---|---|
| `cbr` | наш, VPS `188.120.230.58`, HTTPS с токеном | `get_rate`, `get_rate_dynamics` |
| `pipeline` | наш, местный stdio | `search`, `summarize`, `saveToFile` |
| `filesystem` | официальный `@modelcontextprotocol/server-filesystem`, npx | `write_file`, `read_text_file`, `list_directory`, `list_allowed_directories` |
| `git` | официальный `mcp-server-git` не старше 2025.12.18, uvx, `--repository` | `git_status`, `git_add`, `git_commit`, `git_log` |

Ожидаемый след — около 10 вызовов. Зависимости (частичный порядок):

```
get_rate ─┐
get_rate_dynamics ─┼──────────────► write_file(справка) ─┐
search → summarize ┴► saveToFile(выжимка) ──────────────┴► git_add → git_commit
```

**Развилка выбора внутри сценария.** Файлы пишут два сервера: `saveToFile` принимает только
`summary_id` и пишет выжимку, `write_file` пишет произвольный текст. Сводную справку с цифрами ЦБ
записать `saveToFile` нельзя, а выжимку по ссылке `write_file` не умеет. Инструкция профиля ролей
этих инструментов **не называет** — модель различает их по описаниям. Так выбор проверяется
по-настоящему, а не подсказан (предложение `ai-agents-teacher`; `mcp-teacher` предлагал убрать
`saveToFile`, чтобы не было пересечения, — отвергнуто: пересечение и есть проверка выбора, а
случайным оно не будет, потому что каждый путь годится только для своих данных).

### Песочница — отдельный репозиторий

`week_4/day_5/test/справки/` — свой `git init`; корень `filesystem` и `--repository` у `git` —
этот каталог абсолютным путём, туда же `PIPELINE_OUT_DIR`. Вложенный `.git` внесён в `.gitignore`
ветки дня. Причина (`ai-security-teacher`): на репозитории челленджа `git_add` достал бы любой
файл, а фиксация легла бы на текущую ветку рядом с чужими рабочими копиями. Наш клиент не
объявляет roots — каталоги задаются доводами запуска, это обычный способ для такого клиента.

### Разрешения — точными именами

`permissions.allow` — ровно таблица выше. `deny` — необратимое и лишнее: `edit_file`,
`move_file`, `git_reset`, `git_checkout`, `git_create_branch`, `git_diff` (CVE-2025-68144 —
подстановка ключей командной строки). Так и шум выбора меньше: у модели около 13 инструментов, а
не 40.

### Профиль — общие правила, без подсказки маршрута

Системная инструкция профиля дня: запись и фиксация в этом каталоге разрешены человеком заранее —
не спрашивать; работа кончена, когда есть фиксация, и ответ называет её хэш; после «ошибки
инструмента» тот же вызов с теми же доводами не повторять — исправить доводы или сказать, что шаг
невозможен. Предела числа кругов нет — останавливает модель сама или человек отменой.

### Проверка выбора и порядка — скрипт по следу журнала

`week_4/day_5/test/след.py` читает запись обмена из `myharness-journal.jsonl` (последнюю или по
`run_id`), выписывает вызовы по порядку с сервером и доводами и сверяет:

1. **выбор** — все обязательные инструменты вызваны, неразрешённых и лишних серверов нет;
   справка записана `write_file`, выжимка — `saveToFile`;
2. **порядок** — только причинные рёбра графа выше, не точная последовательность: модель вправе
   поменять местами `get_rate` и `search` или вызвать их одним кругом;
3. **перенос данных** — `summarize` получил `search_id` из ответа `search`, `saveToFile` —
   `summary_id` из ответа `summarize`; `git_add` получил оба записанных файла; в тексте справки
   есть курс из ответа `get_rate`;
4. **итог** — `git_commit` успешен, хэш назван в ответе.

Выход скрипта — таблица следа и ненулевой код при нарушении. Это доказательство одного живого
прогона, а не устойчивости; на видео строки `⚙` идут показом, скрипт — доказательством.

Отвергнуто: проверки pytest с подставной моделью — они доказали бы только программу, а круг и
маршрут уже покрыты `myharness/tests/check_units.py`; ручная сверка строк `⚙` — не повторяема.

## Затронутые способности

- `openspec/specs/mcp/` — не меняется: поведение уже описано («Вызов инструмента», «Соединение
  на сеанс», «Разрешение модели»).
- `openspec/specs/journal/` — не меняется: поле `звенья` уже несёт след.

## Границы

Делаем: ветку `w4d5`, папку дня с `README.md`, песочницу `test/` (`.mcp.json`,
`.claude/settings.json`, профиль, репозиторий `справки/`), `след.py`, живой прогон, видеоотчёт.

Не делаем: поддержку roots и `tools/list_changed` в клиенте (сценарию не нужны); сервер GitHub
(необратимые действия на удалённой службе ради показа не оправданы, 45 инструментов шума);
вопрос человеку посреди круга; пределы числа кругов.

## Риски и чем расплачиваемся

- Модель остановится на полпути или спросит разрешения — лечится инструкцией профиля; если не
  лечится, это находка дня, а не повод заводить предел.
- Внедрение указаний через выжимку Википедии в контекст рядом с `write_file` и `git_commit` —
  ограничено песочницей и узкими разрешениями; остаточный риск — мусорная фиксация в песочнице,
  видна в `git log`.
- `write_file` молча перезаписывает файл — в песочнице приемлемо.
- Сервер `cbr` на VPS недоступен — цепочка упрётся в «ошибку инструмента»; перед записью видео
  проверить `/mcp`.
- `след.py` сверяет один прогон — устойчивость на нескольких прогонах не доказывается.
