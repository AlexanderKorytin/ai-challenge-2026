# config Specification

## Purpose
Хранение настроек harness между запусками: ключ DeepSeek API, выбранная модель, имя активного
профиля и выключатель сбора фактов. Здесь лежит единственный секрет приложения, поэтому у файла
отдельные правила доступа и отдельная точка переопределения для проверок.

Настройки — не то же самое, что состояние: разговоры и глобальные факты живут отдельно, в каталоге
состояния, со своим переопределением пути. Причина разделения — сохранность: удаление файла
настроек не должно уносить с собой переписку.

## Requirements

### Requirement: Каталог настроек переопределяется переменной окружения
Инструмент SHALL брать каталог настроек из `$MYHARNESS_CONFIG_DIR`, а при незаданной переменной —
из `~/.config/myharness`.

Требование не косметическое: проверки, писавшие в настоящий каталог, однажды затёрли рабочий ключ
пользователя. Всё, что пишет в домашний каталог, обязано иметь переопределение пути.

#### Scenario: проверки уводят настройки во временный каталог
- **WHEN** задана переменная `MYHARNESS_CONFIG_DIR`
- **THEN** чтение и запись настроек идут только внутри указанного каталога
- **AND** файл в `~/.config/myharness` не создаётся и не изменяется

#### Scenario: обычный запуск
- **WHEN** переменная не задана
- **THEN** настройки читаются из `~/.config/myharness/config.json`

### Requirement: Файл настроек защищён правами доступа
Инструмент SHALL выставлять файлу настроек права `600` при каждой записи и SHALL создавать
недостающие родительские каталоги.

#### Scenario: первая запись ключа
- **WHEN** пользователь проходит авторизацию, а каталога настроек ещё нет
- **THEN** каталог создаётся, файл записывается, права файла — `600`

### Requirement: Испорченный файл настроек не роняет запуск
Инструмент SHALL возвращать настройки по умолчанию, если файл отсутствует, нечитаем или содержит
неразбираемый JSON.

Молчаливый откат к умолчаниям здесь допустим: без ключа harness всё равно предложит `/auth`,
а падение на старте не оставляет пользователю выхода.

#### Scenario: файл повреждён
- **WHEN** `config.json` содержит неразбираемый JSON
- **THEN** harness запускается с умолчаниями: ключ отсутствует, модель `deepseek-v4-flash`,
  профиль `default`

### Requirement: Настройки хранят выключатель сбора фактов
Файл настроек SHALL хранить признак сбора глобальных фактов архивариусом. Умолчание SHALL быть
ВКЛЮЧЕНО. Признак SHALL меняться командой памяти и SHALL переживать перезапуск. Непригодное
значение в файле SHALL давать умолчание. Профилю управлять этим признаком SHALL NOT позволяться.

Умолчание включено потому, что память — свойство самого инструмента: разговор сохраняется при любом
профиле, включая встроенный, и сбор фактов идёт так же. Выключатель нужен человеку, который не
хочет, чтобы инструмент запоминал его в этом сеансе, а не как обряд включения перед работой.

Признак лежит именно здесь, а не в профиле, намеренно. Профиль отвечает на вопрос «кем сейчас
работает модель», а память — про пользователя и его рабочую папку, к личности модели отношения она
не имеет. Заведи мы поле профиля, сбор фактов пришлось бы включать в каждом профиле заново, и в
половине из них его бы забыли.

Непригодное значение даёт умолчание по общему правилу этого файла: падение на старте не оставляет
пользователю выхода.

#### Scenario: первый запуск
- **WHEN** признака в файле настроек нет
- **THEN** сбор фактов включён

#### Scenario: выключено и перезапущено
- **WHEN** сбор фактов выключен командой, а инструмент запущен заново
- **THEN** сбор по-прежнему выключен, архивариус не запускается ни разу

#### Scenario: мусор вместо признака
- **WHEN** в поле признака лежит не логическое значение
- **THEN** взято умолчание, запуск не прерван

### Requirement: Секрет не покидает файл настроек
Инструмент SHALL хранить ключ API только в файле настроек и SHALL NOT записывать его в журнал
прогонов, в профили и в вывод на экран.

#### Scenario: запись прогона
- **WHEN** ответ модели получен и записывается в журнал
- **THEN** в записи журнала нет ключа API ни в каком виде
