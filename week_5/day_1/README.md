# День 21. Индексация документов

Неделя 5 — RAG. Цели недели: научиться работать с эмбеддерами, искать по базе знаний,
включать это в работу агента и использовать в реальной работе.

## Постановка

Взять набор документов (≥20–30 страниц), реализовать пайплайн индексации: нарезка на куски,
эмбеддинги, сохранение индекса (FAISS / SQLite / JSON). Усиление: метаданные куска (`source`,
`title`, `section`, `chunk_id`) и две стратегии нарезки — фиксированным размером и по
структуре — со сравнением.

## Что сделано

- **Корпус — знания самого проекта**: требования `openspec/specs/` (18 способностей), дизайны и
  планы `docs/`, `CLAUDE.md` — 75 файлов, около миллиона символов русского текста (сотни
  страниц). Только на своём корпусе правильный ответ известен заранее, а к концу недели агент
  будет отвечать на вопросы о `myharness` по его же требованиям.
- **Эмбеддер** — `bge-m3` (1024 числа, окно 8192 токена, хорошо знает русский) в местной
  службе Ollama на Маке, по HTTP `POST /api/embed`.
- **Две стратегии**: `structure` режет по заголовкам Markdown уровней 1–3 (для требований —
  «требование со всеми сценариями»), `fixed` — окном с перекрытием 20 % (156 символов); размер окна равен
  медиане длины кусков `structure`, чтобы сравнение мерило границы, а не размер.
- **Индекс** — один файл SQLite: куски с метаданными (`chunk_id`, `strategy`, `source`,
  `title`, `section` — цепочка заголовков, `start`/`end`) и вектором, плюс сведения о сборке
  (модель, хеш фиксации корпуса, время). Поиск — косинус полным перебором.
- **Проверка** — 30 контрольных вопросов своими словами, у каждого дословный ключевой
  фрагмент ответа; набор зафиксирован в git до первого замера.

Код общий на неделю и живёт в `main`: [`rag/`](https://github.com/AlexanderKorytin/ai-challenge-2026/tree/main/rag).
Дизайн — `docs/индексация.md`, план — `docs/план-индексация.md` (в `main`).

## Что такое эмбеддинг — на пальцах

Эмбеддинг — вектор из 1024 чисел, который модель строит по смыслу текста. Похоже на
`hashCode` в Java, только наоборот: у `hashCode` похожие строки дают несвязанные числа, а здесь
близкие по смыслу тексты дают близкие векторы. Близость мерится косинусом угла между ними:
1 — «про одно и то же», около 0 — «ни при чём». Поиск — посчитать вектор вопроса и взять куски
с наибольшим косинусом.

## Как запустить (из корня `main`)

```bash
ollama pull bge-m3                                        # один раз, ~1,2 ГБ
uv run --project rag rag/cli.py index --strategy all      # ~3 минуты
uv run --project rag rag/cli.py search "куда пишется ключ API"
uv run --project rag rag/cli.py compare --out week_5/day_1/сравнение.md   # в ветке дня
uv run --project rag rag/check_rag.py                     # проверки без Ollama
```
