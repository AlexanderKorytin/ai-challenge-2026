# День 22. Первый RAG-запрос

**Стадия: Executing** (ход стадий — `docs/состояние-первый-rag-запрос.md` в `main`).

## Постановка

Реализовать функцию «вопрос → поиск релевантных кусков → объединение с вопросом → запрос к LLM».
Сравнить ответ модели без RAG и с RAG. Усиление: мини-набор из 10 контрольных вопросов по своей
базе; для каждого — ожидание (что должно быть в ответе) и источники, которые должны быть
использованы. Результат — агент с двумя режимами и сравнение качества.

## Что сделано

База — индекс дня 21: знания самого проекта (`openspec/specs`, `docs`, `CLAUDE.md`), нарезка
`structure`, эмбеддинги `bge-m3` в местной Ollama.

- **Поиск — MCP-сервером** `rag/server.py` (в `main`): один инструмент `search(query, k=5)`,
  ответ — куски строками `[n] <путь> › <раздел> (близость)` и текстом. Поиск живёт в одном месте, и
  тот же сервер подключается к любой среде, умеющей MCP.
- **Режим RAG в агенте `myharness`** — поле профиля `rag` с именем сервера из `.mcp.json`. Перед
  каждым обменом агент **сам** (не модель) зовёт `search` с вопросом человека и кладёт найденное
  блоком «Найдено в базе знаний по вопросу:» в эфемерный хвост последнего сообщения — туда же, где
  живёт рабочее состояние задачи. В память найденное не оседает. Сбой поиска — жалоба, а не
  молчаливый ответ без базы. Требования — `openspec/specs/{agent,profiles,mcp,batch,memory,tokens}`.
- **Два режима = два профиля** (`profiles/проект`, `profiles/проект-rag`): одна модель
  `deepseek-v4-flash`, `temperature` 0, рассуждения выключены, одна инструкция; у RAG — поле `rag`
  и просьба ссылаться на номера кусков.
- **10 контрольных вопросов** — `rag/answers.jsonl` в `main`, зафиксированы в git до первого
  прогона: вопрос, ожидание, факты (короткие строки, обязанные быть в ответе), источники.
  8 вопросов о проекте, 9-й — общее знание (контекст не должен портить ответ), 10-й — ловушка
  (веб-интерфейса у `myharness` нет, модель обязана не выдумать порт).
- **Сравнение** — наряд `test/наряд.json` (10 вопросов × 2 режима) через `myharness --batch`,
  затем `rag/eval.py` по журналу → `сравнение.md`.

| выдумок | 0 | 0 |
| токенов на наряд (10 ответов) | ~1,8 тыс. | ~32 тыс. |

Полные ответы обоих режимов — в `сравнение.md`.

## Вердикты ведущего

- **Без RAG модель не выдумывает.** На все восемь вопросов о проекте — «не знаю, дайте документ»;
  девятый (общее знание) — верно. Разница режимов — не «врёт против знает», а «не знает против
  знает».
- **Все провалы режима RAG — промахи поиска, не модели.** В вопросах 2 и 8 ответ лежит в
  `CLAUDE.md` и `openspec/specs/params`, но в пятёрку попали планы других дней со словами
  «требования» и «расход». В вопросах 1 и 6 нашлись соседние разделы нужного файла (`Purpose`
  спецификации настроек, заголовочный кусок дизайна дня 19) — и модель **честно сказала**, что
  прав файла и причины отказа от sampling в найденном нет, а не додумала.
- **Вопрос 3** засчитан по фактам, хотя «источник найден — нет»: верный ответ (`MCP_TIMEOUT`,
  30 000 мс) пришёл из плана дня 16, а не из спецификации `mcp`. Набор источников был уже, чем
  база; ответ верен.
- **Вопрос 8** — опасный случай: не найдя строки `CLAUDE.md` о десяти кругах, модель выдала за
  «расход дня 15» расход задачи «естественная запись» от **2026-09-15** (263 $, два круга
  итогового просмотра, `docs/состояние-естественная-запись.md`) — спутала день челленджа с числом
  месяца. Числа настоящие, задача не та. С RAG модель отвечает **по найденному**, и если найдено
  похожее, но не то, ответ уверенно не тот — со ссылкой на источник, что делает его правдоподобнее.
- **Вопрос 10 (ловушка)** — оба режима верно: «не знаю, `myharness` — терминальный клиент».
- **Вопрос 9** — оба режима верно; контекст ответ не испортил.

Вывод на следующие дни недели: качество упирается в поиск. Кандидаты — повторное упорядочивание
найденного, смешанный поиск по словам (для имён вроде `top_k`, `SEP-2577`) и порог близости.

## Как повторить

```bash
cd week_5/day_2/test
uv run --project ~/challenge/main/myharness myharness --batch наряд.json
uv run --project ~/challenge/main/rag ~/challenge/main/rag/eval.py \
    --journal myharness-journal.jsonl --run <run_id> --out ../сравнение.md
```

Для живого разговора: `myharness` из `test/`, `/profile проект-rag` против `/profile проект`.
