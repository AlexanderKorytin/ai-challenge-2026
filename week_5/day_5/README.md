# День 25. Мини-чат с RAG и памятью задачи

**Стадия: Executing** — контрольный прогон сделан один раз, числа ниже как есть (ход стадий —
`docs/состояние-чат-с-памятью.md` в `main`).

## Постановка

Мини-чат, который хранит историю диалога, при каждом новом вопросе ищет контекст в базе через
RAG, отвечает с учётом найденного и всегда выводит источники. Усиление — «память задачи»: что
пользователь уже уточнил, какие ограничения и термины зафиксированы, что является целью диалога.
Проверить на двух длинных сценариях по 10–15 сообщений: ассистент не теряет цель и продолжает
выдавать ответы с источниками.

## Что это

Мини-чат — `myharness` на экране Sticky Facts. Дизайн — `docs/чат-с-памятью.md`, план —
`docs/план-чат-с-памятью.md` (оба в `main`).

| пункт условия | чем закрыт |
|---|---|
| хранит историю | полная запись разговора на диске; в запрос уходят четыре последние пары (`strategy_window`) |
| ищет при каждом вопросе | поле профиля `rag`: программа зовёт `search` сервера `rag` перед каждым обменом; уточняющая реплика сперва разворачивается в самостоятельный вопрос по контексту разговора |
| отвечает по найденному, всегда с источниками | три раздела дня 24: «Ответ», «Источники» (путь › раздел · `chunk_id`), «Цитаты» |
| память задачи | словарь фактов разговора: извлекатель после каждой реплики человека кладёт `цель`, `термин:…`, `ограничение:…`, `уточнение:…`; словарь уходит в каждый запрос, переживает перезапуск, виден и правится командой `/facts` |

Правки общего инструмента (в `main`): контекст разговора в поиске (`rag/server.py`,
`rag/rewrite.py`, `myharness` — `agent`, `mcp_tools`), поиск на экранах `sliding` и `facts`,
задание наряда из нескольких реплик (`asks`), инструкция извлекателя, повтор установки
соединения с DeepSeek, отчёт `rag/chat_eval.py`.

## Что где лежит

- `profiles/чат.json`, `profiles/чат.md` — профиль чата: `rag`, `context_strategy: facts`,
  инструкция трёх разделов и памяти задачи;
- `test/.mcp.json` — сервер поиска `rag` в режиме `heuristic` с переписыванием (K₁ 30, K₂ 5,
  τ 0,54 — числа дня 23);
- `test/наряд.json` — два контрольных сценария по 12 реплик, каждая реплика несёт вопрос;
- `test/ожидания.json` — что ждём по каждой реплике и что обязано лежать в памяти задачи к концу;
- `test/запуск.sh` — живой чат из песочницы либо наряд;
- `проверка.md`, `вердикты.json` — отчёт контрольного прогона и вердикты судьи цели.

## Как запустить

```bash
cd week_5/day_5/test
./запуск.sh                      # живой чат: экран Sticky Facts, /facts показывает память задачи
./запуск.sh --batch наряд.json   # два сценария без человека
uv run --project ~/challenge/main/rag ~/challenge/main/rag/chat_eval.py \
  --journal myharness-journal.jsonl --run <run_id> --expect ожидания.json \
  --verdicts ../вердикты.json --commit <фиксация сценариев> --out ../проверка.md
```

Нужны: ключ DeepSeek в настройках `myharness`, Ollama с `bge-m3`, индекс `rag/index.sqlite`.
