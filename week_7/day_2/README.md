## Условие

Конвейер запускается на запрос на слияние. Ассистент:

- получает изменения и изменённые файлы;
- использует RAG (поиск по базе знаний перед ответом) по документации и коду;
- возвращает текст просмотра: возможные ошибки, архитектурные замечания, рекомендации.

## Что сделано

Код лежит в `main`. Код `myharness` и требования `openspec/specs` не менялись.

```
запрос на слияние (opened, synchronize, reopened)
   ▼ GitHub Actions: .github/workflows/review.yml, исполнитель ubuntu-24.04
   ▼ выгрузка основы (вершина main), вершина запроса — через git fetch
   ▼ Ollama 0.34.4 + bge-m3 (модель из кэша)
   ▼ индекс основы rag/review.sqlite: документация (structure) + код (code), из кэша
   ▼ agents/review/review.py
        git diff основа...вершина → участки изменений
        участок → задетое объявление + текст участка → поиск по документации и по коду
        найденное + изменённые файлы + изменения → DeepSeek (deepseek-v4-flash)
   ▼ один комментарий в запросе; повторный запуск обновляет его

отправка в main
   ▼ тот же конвейер досчитывает индекс и кладёт его в кэш основной ветки
```

| Часть | Файл | Что делает |
|---|---|---|
| Нарезка кода | `rag/chunking.py`, `нарезать_code` | режет файл Python модулем `ast` на функции, заголовки классов, методы и остаток модуля |
| Сборка индекса | `rag/cli.py`, `index --strategy code` | собирает файлы `*.py`; вектор куска с прежним текстом берёт из прежней сборки |
| Программа просмотра | `agents/review/review.py` | разбирает изменения, ищет, зовёт DeepSeek, проверяет три раздела ответа |
| Конвейер | `.github/workflows/review.yml` | запуск, кэш, публикация комментария |

Параллель с JVM: нарезка по `ast` — то же, что деление файла Kotlin на объявления через PSI
в IntelliJ. Кэш GitHub Actions — то же, что кэш зависимостей Gradle в CI.

## Запуск на своей машине

Нужны служба Ollama с моделью `bge-m3` и ключ в `DEEPSEEK_API_KEY`.

1. Собери индекс из корня репозитория (две команды — в описании `rag/cli.py`).
2. Запусти просмотр:

```
uv run --project agents/review agents/review/review.py --base main --head <ветка>
```

Программа печатает текст просмотра. Код выхода 1 означает сбой, причина идёт в поток ошибок.

## Что выяснили по ходу

- **Запрос поиска из изменённых строк не находит документацию.** Запрос из пути файла и
  строк правки не поднял требования задетой способности в первые пять ни на одном из трёх
  участков. Запрос из задетого объявления и текста участка поднял их на всех трёх.
- **Полная сборка индекса на исполнителе без видеоядра идёт 58 минут.** Сборка теперь берёт
  вектор неизменённого куска из прежнего индекса. Схема индекса не менялась: вектор зависит
  только от текста куска и модели.
- **Кэш запуска запроса на слияние другим запросам не виден.** Индекс собирает запуск на
  отправку в `main`: кэш основной ветки доступен всем запросам.

- **Поле `pull_request.base.sha` остаётся на фиксации, от которой запрос открыт.** Задание
  брало из неё старую программу. Основа теперь — вершина ветки назначения. Беду показал первый
  дубль ролика.

## Границы и остаточные риски

- Запрос из чужой копии репозитория просмотра не получает: GitHub не выдаёт ему тайну.
  Задание печатает причину и завершается успешно.
- Упоминания `@имя` и ссылки в тексте модели не обезвреживаются.
- Сценарий установки Ollama и модель `bge-m3` не закреплены хэшем.
- Автор с правом записи может изменить `review.yml` в своей ветке.
- Нарезка `code` понимает только Python. Числа поиска для кода не замерены: контрольного
  набора по коду нет.
- Ответы DeepSeek между запусками различаются словами; обе заложенные беды названы во всех
  прогонах дня.
