## Условие

Ассистент разработчика понимает проект:

- RAG (поиск по документам перед ответом) по `README`, `docs` и описаниям API;
- MCP даёт ассистенту текущую ветку git, по желанию — список файлов и `diff`;
- команда `/help` отвечает на вопрос о проекте.

## Что сделано

Проект ассистента — этот репозиторий. Код лежит в `main`, в инструменте `myharness`.

```
/help <вопрос>
   ▼ помощник по проекту: новый агент на каждый вопрос, свой контекст
   ▼ поиск: сервер MCP `rag`, индекс `rag/assistant.sqlite`
   ▼ запрос к модели сеанса: инструкция + найденные куски + вопрос
   ▼ модель сама зовёт инструменты серверов `git` и `filesystem`
   ▼ ответ с источниками печатается в главный экран
```

- **`/help <вопрос>`** отправляет вопрос помощнику по проекту. Память разговора не меняется.
  Активный профиль на ответ не влияет.
- **`/info`** — прежняя справка разделами. Раньше она называлась `/help`.
- **Индекс помощника** `rag/assistant.sqlite`: `README.md`, `docs` и требования
  `openspec/specs`. Планы `docs/план-*.md` и файлы `docs/состояние-*.md` в индекс не входят.
  В индексе 674 куска. Контрольный индекс `rag/index.sqlite` не менялся.
- **Ветку, изменения и журнал git** даёт официальный сервер MCP `git`.
- **Список и чтение файлов** даёт официальный сервер MCP `filesystem`. Разрешены два инструмента
  чтения: `list_directory` и `read_text_file`.
- **Модель** — модель сеанса: DeepSeek либо местная `ollama/qwen3.5:9b-q4_K_M-32k`.
- **Профиль помощника** встроен в код. Пара файлов `помощник.json` + `помощник.md` в каталоге
  профилей его перекрывает.

Требования: `openspec/specs/commands/spec.md`, требование «Вопрос помощнику по проекту».
Дизайн и план: `docs/ассистент-разработчика.md`, `docs/план-ассистент-разработчика.md`.

## Как запустить

Сначала собери индекс помощника из корня рабочей копии `main`:

    uv run --project rag rag/cli.py --index rag/assistant.sqlite index --strategy structure \
        --corpus . --include README.md docs openspec/specs \
        --exclude 'docs/план-*.md' 'docs/состояние-*.md'

Затем из `week_7/day_1/test/`:

1. `./запуск.sh окно` — открывает `myharness`. Вопрос задаётся так: `/help в какой я ветке?`
2. `./запуск.sh окно ollama/qwen3.5:9b-q4_K_M-32k` — то же на местной модели.
3. `./запуск.sh сценарий <модель>` — семь вопросов из `вопросы.txt` набираются сами.
4. `python3 ответы.py журнал-сценарий-<модель>.jsonl` — печатает вопросы, инструменты и ответы.

Серверы MCP песочницы записаны в `test/.mcp.json`: `rag`, `git`, `filesystem`. Разрешённые
инструменты записаны в `test/.claude/settings.json`. Серверы `git` и `filesystem` смотрят на
рабочую копию `~/challenge/main`.

## Подбор чисел поиска

Числа поиска подобраны заново на индексе помощника инструментом дня 23
(`rag/cli.py rerank-compare`), отчёт — `поиск.md`. Наборы вопросов прежние: 25 вопросов
`rag/control.jsonl` и 5 отрицательных на подбор, 10 вопросов `rag/answers.jsonl` и
5 отрицательных на проверку. Все вопросы наборов — по требованиям; вопросов по `README`
и `docs` в наборах нет.

| Число | День 28 | День 31 | Почему |
|---|---|---|---|
| `K₁` | 30 | 50 | у `heuristic` без переписывания запроса hit@5 на подборе 0,960 против 0,920 |
| `K₂` | 5 | 5 | `K₂` = 10 попаданий не прибавляет, а блок найденного вырастает вдвое |
| `τ` | 0,50 | 0,50 | наибольший порог без потерянных попаданий — 0,5048 |

- Итог режима `heuristic` на проверке: hit@1 0,500, hit@5 0,800, MRR 0,650.
- Близкие отрицательные вопросы порог не отсекает ни при каком значении без потери попаданий.
  В `docs` много текста о соседних темах, и косинус у таких вопросов 0,57–0,63. Их отсекает
  модель. Далёкие вопросы (косинус 0,36–0,41) порог отсекает.
- Режим `model` (перекрёстный кодировщик) даёт лучший порядок: MRR 0,900 против 0,795.
  Помощник его не использует: кодировщик занимает память рядом с местной моделью на Маке

- Вопрос о правах файла настроек подбор не починил. Причина измерена: кусок «Файл настроек
  защищён правами доступа» стоит по косинусу на 49-м месте из 674, и слияние с BM25 в первые
  пять его не поднимает. Выше стоят «Purpose» и «Каталог настроек» того же файла.

## Что найдено по ходу

- **Планы вытесняли документацию из выдачи.** На вопрос о настройках три места из пяти заняли
  куски «Карта файлов» из `docs/план-*.md`. Планы и файлы состояния исключены из индекса
  доводом `--exclude`. Индекс уменьшился с 1286 до 674 кусков.
- **Права файла настроек поиск не находит и после этого.** На индексе из одних требований
  (день 28) этот вопрос находился. Разбор — в разделе «Подбор чисел поиска».
- **Рекурсивные инструменты `filesystem` опасны для каталога с `.venv`.** В первом прогоне
  `directory_tree` на вопрос о каталоге `rag` стоил 737 739 токенов на DeepSeek и увёл местную
  модель от вопроса (108 с, ответ на английском). Во втором прогоне DeepSeek вызвал
  `search_files` с шаблоном `**/*`, сервер вернул 3,8 МБ, и API ответил ошибкой 400:
  1 297 956 токенов при окне 1 048 576. Оба инструмента убраны из разрешённых. Остались
  `list_directory` и `read_text_file`.
- **`myharness` не ограничивает размер ответа инструмента.** Предупреждение о переполнении
  окна печатается, но запрос уходит. Усечение большой вставки — отложенная задача 2.
- **Местная модель один раз написала «посмотрел», не вызвав инструмент** (первый прогон,
  вопрос о каталоге `mcp_servers`). Ответ она взяла из документации.
- **Пакетный режим инструменты MCP модели не отдаёт** (отложенная задача 17). Наряд
  `наряд-cloud.json` проверяет только поиск; вопросы о git идут в окне.

## Ограничения

- Помощник получает все инструменты MCP, которые разрешены в `.claude/settings.json` рабочего
  каталога. Если там разрешена запись, помощник её увидит. Инструкция запрещает ему менять
  что-либо; программного запрета нет.
- Содержимое `diff` уходит модели сеанса. С DeepSeek это облако.
- Индекс помощника сам не обновляется. Его пересобирает навык `/отчет`.
