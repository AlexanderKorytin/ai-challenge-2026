# FAQ пользователя myharness

Вопросы, с которыми пользователи приходят в поддержку. Каждый ответ опирается на требование
`openspec/specs`, оно названо строкой «Требование».

## Почему не работает авторизация: ключ не принят DeepSeek API

Сообщение «ключ не принят DeepSeek API (проверьте правильность)» значит, что DeepSeek отклонил
ключ: ключ отозван либо скопирован с ошибкой. Сеть при этом работает: при сбое сети
`myharness` пишет «не удалось проверить ключ: …», а не «ключ не принят».

1. Откройте кабинет DeepSeek и проверьте, что ключ не отозван.
2. Скопируйте ключ заново, без пробелов по краям.
3. Введите `/auth` и вставьте ключ. Команда работает и тогда, когда её нет в меню.
4. После строки «авторизация сохранена» ключ вводить заново не нужно.

Требование: `openspec/specs/api/spec.md` › «Проверка ключа отличает отказ от сбоя сети».
Требование: `openspec/specs/commands/spec.md` › «Меню показывает только применимые команды».

## Где хранится ключ DeepSeek и кто может его прочитать

Ключ хранится в файле `~/.config/myharness/config.json`. Каталог меняет переменная
`MYHARNESS_CONFIG_DIR`. `myharness` ставит файлу права `600` при каждой записи: читать его
может только владелец. Ключ не попадает ни в журнал прогонов, ни в профили, ни на экран.

Если ключ «пропал» после запуска с другой `MYHARNESS_CONFIG_DIR`, `myharness` читает другой
каталог. Уберите переменную или введите ключ заново через `/auth`.

Требование: `openspec/specs/config/spec.md` › «Файл настроек защищён правами доступа».
Требование: `openspec/specs/config/spec.md` › «Каталог настроек переопределяется переменной окружения».
Требование: `openspec/specs/config/spec.md` › «Секрет не покидает файл настроек».

## Почему в меню нет команд /model, /profile и /help

Пока ключ DeepSeek не задан, меню показывает только `/auth` и команды, которым ключ не нужен,
например `/info`. Введите ключ командой `/auth`, и остальные команды появятся.

Требование: `openspec/specs/commands/spec.md` › «Меню показывает только применимые команды».

## Ollama не отвечает: местная модель не подключается

Сообщение «Ollama не отвечает по адресу http://127.0.0.1:11434 — проверьте, что служба
запущена» значит, что по этому адресу никто не принимает соединений. Ключ и авторизация здесь
ни при чём: местной службе на своей машине токен не нужен.

1. Запустите службу Ollama: приложение Ollama или команду `ollama serve`.
2. Проверьте адрес. `myharness` берёт его из `OLLAMA_HOST`, а без переменной — `http://127.0.0.1:11434`.
3. Проверьте, что модель скачана: `ollama list`. Имя в `myharness` пишется с приставкой
   `ollama/`, например `ollama/qwen3.5:9b-q4_K_M-32k`.

Требование: `openspec/specs/api/spec.md` › «Поставщика называет имя модели».

## Как выбрать местную модель вместо DeepSeek

Введите `/model` и выберите модель из списка местных. Поставщика называет имя модели: имя с
приставкой `ollama/` уходит в службу Ollama, любое другое — в DeepSeek. Отдельной настройки
«поставщик» нет.

Требование: `openspec/specs/api/spec.md` › «Поставщика называет имя модели».

## Шлюз отвечает «нет токена либо токен неверен»

Служба Ollama на чужой машине стоит за шлюзом, и шлюз пускает только с токеном. `myharness`
отправляет токен из переменной `OLLAMA_API_KEY` заголовком `Authorization`. Без переменной
уходит заглушка, и шлюз отвечает отказом 401.

1. Получите токен у администратора шлюза.
2. Задайте `OLLAMA_API_KEY=<токен>` в окружении, из которого запускаете `myharness`.
3. Адрес шлюза в `OLLAMA_HOST` пишите полностью: с `https://` и портом, который назвал
   администратор шлюза. По открытому `http://` на чужую машину токен не уходит: `myharness`
   прерывает обмен и называет адрес.

Требование: `openspec/specs/api/spec.md` › «Поставщика называет имя модели» (токен службы Ollama).

## Ошибка «токен службы Ollama (OLLAMA_API_KEY) не уходит по открытому адресу»

Задан `OLLAMA_API_KEY`, а `OLLAMA_HOST` называет чужую машину по `http://`. Такой токен
прочёл бы любой узел на пути, поэтому `myharness` запрос не отправляет. Назовите адрес шлюза
с `https://` либо уберите токен, если служба своя. На петлевых адресах `127.0.0.1`,
`localhost`, `::1` ограничения нет.

Требование: `openspec/specs/api/spec.md` › «Поставщика называет имя модели» (токен службы Ollama).

## Сервер MCP «не ответил за 30 с»

`/mcp` опрашивает каждый сервер из `.mcp.json` с пределом `MCP_TIMEOUT`. Это миллисекунды,
по умолчанию 30 000. Сбой одного сервера соседям не мешает.

Местный сервер (запуск по stdio, в `.mcp.json` есть `command`):

1. Запустите команду сервера из `.mcp.json` вручную в терминале. Сервер на `npx` при первом
   запуске может ждать подтверждения установки.
2. Если сервер просто медленно стартует, увеличьте предел: `MCP_TIMEOUT=60000`.

Сервер на другой машине (`"type": "http"`, в `.mcp.json` есть `url`):

1. Проверьте адрес `url` и что сеть до сервера есть, в том числе через VPN.
2. Если сервер ответил кодом от 400, `/mcp` называет код и фразу, например «HTTP 401
   Unauthorized». Тогда дело в токене, а не в пределе ожидания.

В обоих случаях после правки введите `/mcp` снова и проверьте, что сервер показал версию
протокола и инструменты.

Требование: `openspec/specs/mcp/spec.md` › «Соединение и список инструментов».

## Сервер MCP подключён, но модель не зовёт его инструменты

Модель получает только инструменты, разрешённые списком `permissions.allow` в
`.claude/settings.json` либо `.claude/settings.local.json` рабочего каталога. Правило пишется как `mcp__<сервер>__<инструмент>`.
`/mcp` помечает разрешённые инструменты знаком «✓ модели».

Требование: `openspec/specs/mcp/spec.md` › «Разрешение модели».

## Предупреждение «запрос не влезет в окно модели»

`myharness` считает вес запроса до отправки. Если вес вместе с местом под ответ больше окна
модели, он предупреждает и называет оба числа. Запрос всё равно уходит.

1. Введите `/tokens`: команда покажет занятую долю окна и вес истории.
2. Очистите историю командой `/clear` либо сожмите её командой `/compact`.
3. Задайте вопрос короче или уберите большую вставку.

Требование: `openspec/specs/tokens/spec.md` › «О переполнении окна сказано до отправки».
Требование: `openspec/specs/commands/spec.md` › «Состав команд».

## Как ограничить расход токенов

`/budget <число>` задаёт предел веса запроса, `/budget` без числа показывает действующий.
`/tokens` показывает итог сеанса в токенах и деньгах.

Требование: `openspec/specs/tokens/spec.md` › «Предел веса запроса задаётся пользователем».
Требование: `openspec/specs/commands/spec.md` › «Состав команд».

## Как начать разговор заново

`/clear` чистит память агента главного экрана и открывает новую сессию.

Требование: `openspec/specs/commands/spec.md` › «Команда /clear чистит память агента главного экрана и открывает новую сессию».
