Сценарий: `./запуск.sh сценарий deepseek-v4-flash`, реплики — `реплики.txt`, между случаями `/clear`.

## 1. Тикет T-1001. Почему не работает авторизация?

Вызовы: `mcp__support__get_ticket`, `mcp__support__find_user`, `mcp__rag__search` — «ошибка «ключ не принят DeepSeek API (проверьте правильность)» — что делать, авторизация /auth, переменные окружения», `mcp__support__list_tickets`

```
В тикете T-1001 ошибка: «ключ не принят DeepSeek API (проверьте правильность)» — по документации это значит, что DeepSeek отклонил сам ключ (отозван или скопирован с ошибкой), а не сбой сети: при сбое сети сообщение было бы другим — «не удалось проверить ключ: …». Других тикетов у вас нет, так что дело именно в ключе.

Шаги решения:
1. Откройте кабинет DeepSeek и проверьте, что ключ не отозван.
2. Скопируйте ключ заново, без пробелов по краям.
3. Введите `/auth` и вставьте ключ — команда работает и тогда, когда её нет в меню.
4. После строки «авторизация сохранена» ключ вводить заново не нужно.
5. Если ключ «пропал» после запуска с другой `MYHARNESS_CONFIG_DIR`, myharness читает другой каталог настроек — уберите переменную или введите ключ заново через `/auth`.

Источники: week_7/day_3/FAQ.md › Почему не работает авторизация: ключ не принят DeepSeek API; week_7/day_3/FAQ.md › Где хранится ключ DeepSeek и кто может его прочитать; тикет T-1001, пользователь U-01.
```

## 2. Тикет T-1002. Почему не работает авторизация?

Вызовы: `mcp__support__get_ticket`, `mcp__support__find_user`, `mcp__support__list_tickets`, `mcp__rag__search` — «Ollama не отвечает по адресу http://127.0.0.1:11434 — проверьте, что служба запущена. OLLAMA_HOST не задан, авторизация местной модели»

```
Причина не в авторизации: в тикете ошибка «Ollama не отвечает по адресу http://127.0.0.1:11434 — проверьте, что служба запущена». Такой ответ значит, что по адресу никто не принимает соединений; токен и ключ тут ни при чём — местной службе на своей машине токен не нужен. У вас в окружении `OLLAMA_HOST` и `OLLAMA_API_KEY` не заданы, значит используется умолчание `http://127.0.0.1:11434`.

1. Запустите службу Ollama: приложение Ollama или команду `ollama serve`.
2. Убедитесь, что модель скачана: `ollama list`. Имя в myharness пишется с приставкой `ollama/`, например `ollama/qwen3.5:9b-q4_K_M-32k`.
3. Если служба стоит не на умолчании, задайте её адрес в `OLLAMA_HOST` (без схемы допишется `http://`); для своей службы на 127.0.0.1 токен не нужен.
4. Для чужой службы за шлюзом: адрес в `OLLAMA_HOST` целиком с `https://` и портом, а токен — в `OLLAMA_API_KEY` (по открытому `http://` на чужую машину токен не уходит).

Источники: week_7/day_3/FAQ.md › Ollama не отвечает: местная модель не подключается; openspec/specs/api/spec.md › Requirements › Requirement: Поставщика называет имя модели; тикет T-1002, пользователь U-02.
```

## 3. Я vera@example.com. Почему не работает авторизация?

Вызовы: `mcp__support__find_user`, `mcp__support__list_tickets`, `mcp__rag__search` — «авторизация Ollama через шлюз, ошибка "нет токена либо токен неверен", OLLAMA_API_KEY не задан», `mcp__rag__search` — «Ollama OLLAMA_HOST ключ доступа настройка переменных окружения myharness»

```
Причина: у вас в окружении `OLLAMA_API_KEY` не задан, а `OLLAMA_HOST` указывает на чужую машину за шлюзом (`https://gpu.example.com:443`). В прошлом тикете T-1003 («Шлюз не пускает к модели») была та же ошибка — «нет токена либо токен неверен»; тикет закрыт, потому что вы не ответили на уточняющий вопрос, выдал ли администратор шлюза токен. Шлюз пускает только с токеном, а `myharness` шлёт его из переменной `OLLAMA_API_KEY`; без переменной уходит заглушка, и шлюз отвечает 401.

Что делать:
1. Получите токен у администратора шлюза.
2. Задайте `OLLAMA_API_KEY=<токен>` в том окружении, из которого запускаете `myharness`.
3. Адрес в `OLLAMA_HOST` пишите полностью: `https://` и порт, который назвал администратор шлюза. По открытому `http://` на чужую машину токен не уходит — `myharness` прервёт обмен (на петлевых адресах 127.0.0.1, localhost, ::1 ограничения нет).
4. Если служба Ollama на самом деле ваша и стоит локально, токен не нужен — проверьте, что служба запущена (`ollama serve`) и модель скачана (`ollama list`).

Источники: week_7/day_3/FAQ.md › Шлюз отвечает «нет токена либо токен неверен»; week_7/day_3/FAQ.md › Ошибка «токен службы Ollama (OLLAMA_API_KEY) не уходит по открытому адресу»; week_7/day_3/FAQ.md › Ollama не отвечает: местная модель не подключается; openspec/specs/api/spec.md › Requirements › Requirement: Поставщика называет имя модели; тикеты T-1003, пользователь U-03.
```
