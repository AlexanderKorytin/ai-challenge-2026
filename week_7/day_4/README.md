# День 34. Ассистент с операциями над файлами

## Постановка

Ассистент сам читает и меняет файлы проекта. Человек ставит цель, а не называет файл. Нужно
минимум два сценария из пяти, работа с 2–3 файлами и больше, изменения на диске или в виде
`diff`, повторяемый прогон.

Видение пользователя: завести маленький проект с кодом и подключить к нему ассистента.
`myharness` работает с файлами **по умолчанию**, как Claude Code, без профиля и `.mcp.json`.

## Что сделано

**В `main` — встроенные файловые инструменты `myharness`** (`myharness/src/myharness/files_tools.py`,
`tool_output.py`). Модель получает `Read`, `Write`, `Edit`, `Glob`, `Grep` в любом рабочем
каталоге. Имена, доводы и пределы взяты у Claude Code:

- `Read` — 2000 строк, не больше 25 000 токенов, пометка `PARTIAL view`, файл больше 256 КБ — частями;
- `Grep` — три режима вывода, листание `head_limit`/`offset`, учёт `.gitignore`; идёт отдельным
  процессом, отмена его убивает;
- `Glob` — 100 путей, свежие первыми;
- `Edit` и `Write` — только после полного `Read`, ответ — `diff`;
- результат длиннее 50 000 знаков уходит в файл, модель дочитывает его `Read`. Правило действует и
  для инструментов MCP: беда дня 31 (3,8 МБ и отказ 400) закрыта целиком.

При первом запуске окна в папке `myharness` спрашивает о доверии (как Claude Code): «1» запоминает
папку в `trusted_dirs` файла настроек, и дальше модель читает и правит файлы без вопросов, как в
режимах `acceptEdits` и `auto`. Без доверия окно не открывается; наряд вопроса не задаёт и без
доверия только читает, если правило `allow: ["Edit"]` папки не открыло запись.
`.git`, `.claude`, `.mcp.json` и каталог настроек с ключом API закрыты. Сверка путей идёт по
тождеству файла: независимый просмотр нашёл обходы регистром букв, буквой `ſ` и символической
ссылкой — все закрыты. Требования — `openspec/specs/files/`, правки `mcp`, `batch`, `interface`.

**В этой папке — учебный проект и три сценария.**

```
test/
  исходник/   учебный проект «учёт задач»: tasks/{models,storage,report,cli}.py, тест, README, ПРАВИЛА.md
  после/      вторая версия cli.py — новая команда done
  сброс.sh    проект → test/проект/ со своим git: фиксация «начало», затем «команда done»
  прогон.sh   сброс → наряд сценария → git diff в итоги/<сценарий>-<прогон>.diff
  наряд-1..3.json   цели сценариев
  исходник/.claude/settings.json   allow Edit — наряд пишет в учебном проекте без доверия,
                    как `claude -p --allowedTools Edit`
  итоги/      diff, вывод наряда и журнал каждого прогона
```

В учебный проект заложены четыре нарушения `ПРАВИЛА.md`: функция без строки документации,
`print` в `storage.py`, путь `tasks.json` в `report.py`, голый `except:`. Документация не знает
команды `done`.

## Сценарии

| № | Цель (как её получает модель) | Сценарий из условия |
|---|---|---|
| 1 | «Найди все места, где проект обращается к хранилищу задач, и сохрани отчёт в ИСПОЛЬЗОВАНИЕ.md: файл:строка и что там делается» | места использования API + новый файл |
| 2 | «Проверь проект на соответствие правилам проекта и исправь все нарушения» | проверка правил + `diff` |
| 3 | «Документация отстала от кода. Сверь её с кодом, обнови и заведи CHANGELOG.md» | обновление документации + новый файл |

Модель `deepseek-v4-flash`, профиль по умолчанию, пакетный режим `--batch`. Каждый сценарий
прогнан дважды от сброса.

Повторяемость: набор найденных мест (сценарий 1), набор закрытых нарушений (сценарий 2) и набор
задетых документов (сценарий 3) совпали в обоих прогонах. Текст и способ правки различаются:
ответы `flash` дословно не повторяются (день 24).

Модель чаще переписывает файл целиком через `Write`, чем правит его `Edit`: из 5 записей
сценария 2 только одна — `Edit`. Правка от этого не теряется: `Write` поверх файла разрешён только
после полного `Read`.

Окно проверено вживую через псевдотерминал: вопрос о доверии, «1», просьба «добавь в README строку
о pytest» — на экране `⚙ Glob`, `⚙ Read: README.md`, `⚙ Edit: README.md` и под ним `diff` с
добавленной строкой.


## Известные ограничения

- Корень — домашний каталог: модель читает `~/.ssh`, как и у Claude Code; доверие дому — на сеанс.
- Чтение `.git/config` и `.env` разрешено; закрыть — правилом `deny`, а оно снимает весь `Read`.
- Модель может писать `profiles/*.json`, `Makefile`, `.githooks` рабочего каталога.
- Запретные признаки инвариантов и судья не видят текста, записанного `Write`/`Edit`.
- `diff` большого `Write` уходит на экран целиком.
