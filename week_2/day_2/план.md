## Как проверяем и почему так

- **Строгий цикл «тест → падение → код → проход»** — на весь `memory.py` и на разбор ответа
  архивариуса. Это чистые функции, и их края — испорченная строка, неизвестная роль, нечётный
  хвост, изменившийся отпечаток инструкции, потолок фактов — в живом прогоне не поймать.
- **Ручной прогон по сценарию** — на интерфейс: строка восстановления, `/memory`, объявление
  запомненного факта. Строгий цикл на отрисовку стоит дороже пользы.
- **Сквозная проверка** — на связку целиком: собрать состояние, провести обмены, выбросить
  состояние, собрать заново в том же каталоге и убедиться, что память на месте. Это и есть
  «перезапуск» без запуска второго процесса.

## Соглашение об именах (действует во всех шагах)

`state_dir`, `project_key`, `sessions_dir`, `profile_dir`, `SessionStore`, `Restored`,
`latest_session`, `new_session`, `fingerprint`, `load_facts`, `add_fact`, `remove_fact`, `facts_block`, `FACTS_MAX`,
`Agent(..., store=, facts=)`, `Agent.restore`, `Agent.set_store`, `Agent.remember(..., model=)`,
`ARCHIVIST_INSTRUCTION`, `archivist_profile`, `extract_request`, `parse_facts`, `EVERY_N`,
`State.store`, `State.since_archive`, `State.archivist_task`, `Config.remember`.

**Память — свойство самого инструмента, а не профиля.** Разговор сохраняется при любом
профиле, в том числе при встроенном `default`, и включать его нечем — он просто есть.
Сбор фактов тоже включён всегда; выключатель лежит в общих настройках инструмента, а не в
профиле. Причина: профиль отвечает на вопрос «кем сейчас работает модель», а память к
личности модели отношения не имеет — она про пользователя и его папку.

## Шаг 1. Каталог состояния и ключ рабочего каталога

**Файлы**: `src/myharness/memory.py` (новый), `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Хранилище лежит в каталоге состояния»
**Проверка**: переменная окружения уводит каталог; путь рабочего каталога кодируется в имя папки однозначно.

**Содержание**. Заголовок модуля: зачем каталог состояния, а не настроек — по соглашениям Unix
`~/.config` для того, что правят руками, `~/.cache` для того, что не жалко потерять,
`~/.local/state` для накопленного между запусками.

```python
def state_dir() -> Path        # $MYHARNESS_STATE_DIR либо ~/.local/state/myharness
def project_key(cwd: Path) -> str   # абсолютный путь: «/» и прочие разделители → «-»
def sessions_dir(cwd: Path) -> Path # state_dir() / "projects" / project_key(cwd)
def facts_dir() -> Path             # state_dir() / "memory"   (устройство — в шаге 6)
```

`project_key` кодирует **абсолютный** путь (`Path.resolve()`), иначе запуск из `./test` и из
`test` дал бы два разных разговора в одной папке.

Кодирование обязано быть **обратимым**, иначе разные пути склеиваются в одно имя и два каталога
делят один разговор. Правило: буквы и цифры любого алфавита и `_` остаются как есть; разделитель
пути `/` даёт `-` (так имя читается глазами, как в образце Claude Code); **всё остальное, включая
сам знак `-` и пробел, кодируется как `%XX`**. Тогда `/a/b c`, `/a/b:c`, `/a/b-c` и `/a/b/c` дают
четыре разных имени, а кириллица в имени остаётся читаемой.

Замена всего небезопасного на один `-` — та ошибка, которую нашёл проверяющий опытом: профили
`моя схема`, `моя/схема`, `моя.схема` и `моя-схема` получали один файл разговора, и один профиль
читал переписку другого.

**Тесты (пишутся первыми)**: переменная задана — путь внутри неё; не задана — под `~/.local/state`;
`project_key(Path("/a/b c"))` даёт `-a-b%20c`, а `/a/b-c`, `/a/b:c` и `/a/b/c` — три других имени; относительный и абсолютный пути одного каталога дают
один ключ.

## Шаг 2. Запись строки сессии

**Файлы**: `src/myharness/memory.py`, `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Разговор пишется дописыванием»
**Проверка**: строка дописывается, каталоги создаются, права файла `600`, недоступный каталог даёт текст ошибки, а не исключение.

**Содержание**.

```python
class SessionStore:
    def __init__(self, path: Path) -> None
    def append(self, role: str, content: str, meta: dict[str, Any] | None = None) -> str | None
```

`append` дописывает одну строку JSON: `ts` (UTC, ISO 8601), `role`, `content`, затем поля `meta`.
Создаёт родительские каталоги с правами `700` (имена папок сами по себе раскрывают рабочие каталоги
пользователя), файлу выставляет `600`. **Ошибку возвращает
текстом и не бросает** — ровно как запись журнала прогонов: вспомогательный механизм не имеет
права уронить обмен, который уже удался и уже оплачен.

**Тесты**: две записи дают две строки; права файла `0o600`, каталога `0o700`; **недоступный путь
задаётся через родителя-файл** (`tmp/файл/сессия.jsonl` даёт `ENOTDIR`), а не через несуществующий
корень: под root корень был бы создан, и проверка прошла бы вхолостую, оставив мусор в корне
файловой системы; `meta` попадает в строку и не затирает `role`.

## Шаг 3. Чтение сессии, отбраковка и окно

**Файлы**: `src/myharness/memory.py`, `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Испорченная запись не роняет восстановление»
**Проверка**: каждый краевой случай из дизайна воспроизведён проверкой и даёт предупреждение, а не падение.

**Содержание**.

```python
@dataclass
class Restored:
    pairs: list[tuple[str, str]]   # (вопрос, ответ) в порядке разговора
    saved_pairs: int               # сколько пар лежит в файле
    last_ts: str                   # отметка времени последней записи, "" — файла нет
    warnings: list[str]
    fingerprint_changed: bool

def read_session(path: Path, *, window: int, system_fp: str) -> Restored
```

Правила разбора, каждый — отказ, а не догадка:

- строка не разбирается как JSON → пропускается, предупреждение «строка N испорчена»;
- роль не `user` и не `assistant` → строка отбрасывается, предупреждение. Не угадываем: API
  требует строгого чередования, и угадывание упало бы позже и без видимой причины;
- записи собираются в пары «user, затем assistant»; нарушение порядка **не обрывает чтение**, а
  пересинхронизирует: повисший вопрос отбрасывается с предупреждением, ответ без вопроса
  отбрасывается с предупреждением, чтение продолжается со следующей строки.
  **Обрыв всего сбора недопустим.** В связке с пропуском испорченной строки он даёт катастрофу:
  строка ответа испорчена — вопрос повисает — следующий вопрос обрывает сбор — теряется весь
  разговор. Ровно то, ради сохранности чего и выбрано дописывание вместо перезаписи;
- нечётный хвост (вопрос без ответа) отбрасывается: память обязана идти парами, иначе сервер
  откажет в запросе;
- в память идут **последние `window` пар**; `saved_pairs` при этом равно полному числу пар в файле;
- `fingerprint_changed` истинно, если у последней записи с полем `system_fp` оно не совпало с
  переданным.

`window` равен нулю — окно выключено, берутся все пары.

**Тесты**: целый файл из трёх пар восстанавливается целиком; битая вторая строка даёт две пары и
предупреждение; **битая строка на месте ответа не уносит остаток разговора** — из четырёх пар
выживают три; **файл вида «user, user, assistant» читается**: первый вопрос отброшен с
предупреждением, пара из второго и ответа собрана; роль `system` в файле отбрасывается с
предупреждением, и её поле `system_fp` на `fingerprint_changed` не влияет; запись с `content`
не-строкой даёт предупреждение о содержимом, а не о роли; вопрос без ответа в конце отбрасывается
ровно одним предупреждением; при `window=1` возвращается последняя пара, а `saved_pairs` равно
трём; другой `system_fp` поднимает `fingerprint_changed`; отсутствующего файла достаточно для
пустого `Restored` без предупреждений; файл с не-UTF-8 байтами не роняет чтение; несериализуемое
значение в `meta` даёт текст ошибки, а не исключение.

## Шаг 4. Выбор сессии: последняя или новая

**Файлы**: `src/myharness/memory.py`, `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Разговор принадлежит паре каталог и профиль»
**Проверка**: последняя сессия пары находится по времени изменения; сессии разных профилей не смешиваются; новая сессия получает своё имя; посторонний файл выбор не уводит.

**Содержание**. Профиль — **уровень каталога**, имя файла — UUID:

```
$MYHARNESS_STATE_DIR/projects/<ключ рабочего каталога>/<профиль>/<uuid>.jsonl
```

```python
def profile_dir(cwd: Path, profile: str) -> Path
def latest_session(cwd: Path, profile: str) -> Path | None
def new_session(cwd: Path, profile: str) -> Path
```

**Почему UUID, а не время в имени.** Осмысленное имя тянет за собой целый класс бед, и все они
были воспроизведены проверяющим на первой версии: время в имени → две сессии в одну секунду →
счётчик → сдвиг момента вперёд → «следующий запуск вернул БОЛЕЕ СТАРЫЙ разговор» → сверка формы
имени, чтобы посторонний файл с кириллицей не побеждал цифры. Пять правок ради того, чтобы имя
что-то сообщало. UUID снимает всё разом: уникальность даром, часовые пояса ни при чём, счётчика
нет, вид имени жёсткий.

**Почему профиль каталогом, а не в имени файла.** Найти последнюю сессию пары «каталог + профиль»
надо, не читая файлы. Держать профиль в имени — снова разбирать имя; держать оглавление — снова
завести общее изменяемое состояние, ровно то, от чего мы ушли в фактах (шаг 6). Каталог решает
это без единой разборки имени: сессии профиля — просто содержимое его каталога.

**Почему порядок по времени изменения, а не по имени.** «Продолжить последний разговор» — это про
тот, с которым работали последним, а не про тот, который раньше начат. Вернулись вчера к старой
сессии — продолжать надо её. Имя со временем начала отвечает на этот вопрос неверно, и никакой
счётчик этого не чинит.

Правила:

- `latest_session` берёт `*.jsonl` из каталога профиля и возвращает самый свежий по `st_mtime`;
  каталоги и файлы с другим расширением пропускаются; нет каталога или он пуст — `None`;
- `new_session` возвращает путь `profile_dir(...) / f"{uuid4().hex}.jsonl"`; файла не заводит —
  он появится при первой записи, пустых сессий на диске не бывает;
- имя профиля кодируется тем же обратимым правилом, что и путь каталога (шаг 1): два разных
  профиля не имеют права попасть в один каталог. Пустой код имени заменяется на `-`:
  `Path("/a") / ""` даёт `/a`, и сессии легли бы в каталог проекта вперемешку с каталогами
  профилей;
- ничья по времени изменения разрешается по имени файла. Наносекундный `st_mtime` совпадает редко,
  но после копирования каталога состояния или `rsync` — запросто, и тогда «продолжить последний
  разговор» решалось бы жребием. В фактах ничья уже разрешена явно; в сессиях правило обязано быть
  таким же.

**Чем платим.** Имя файла больше не говорит, когда разговор начат. Восстанавливается из первой
записи самого файла — она несёт отметку времени; для показа в списке сессий этого достаточно.

**Тесты (пишутся первыми)**: два файла в каталоге профиля — берётся более свежий по времени
изменения (время правится явно, а не ожиданием); сессия другого профиля не видна; профили
`default` и `my-default` лежат в разных каталогах; профили `моя схема` и `моя-схема` лежат в
разных каталогах; посторонний файл с другим расширением и вложенный каталог выбор не уводят;
пустой каталог профиля и отсутствующий каталог дают `None`; `new_session` трижды подряд даёт три
разных пути и ни одного файла на диске; записанная сессия находится `latest_session`.

## Шаг 5. Отпечаток системной инструкции

**Файлы**: `src/myharness/memory.py`, `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Правка инструкции между запусками называется вслух»
**Проверка**: одинаковый текст даёт одинаковый отпечаток, изменённый — другой; отсутствие инструкции тоже имеет отпечаток.

**Содержание**. `def fingerprint(system: str | None) -> str` — первые 6 знаков шестнадцатеричного
`sha256` от текста в UTF-8; `None` и пустая строка дают отпечаток пустого текста, а не пустую
строку: иначе «инструкции не было» и «файл старого формата» стали бы неразличимы.

## Шаг 6. Глобальная память: файл на факт

**Файлы**: `src/myharness/memory.py`, `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Глобальные факты хранятся файлом на факт»
**Проверка**: факт добавляется отдельным файлом, повтор отбрасывается, потолки соблюдаются, две одновременные записи не теряют ничего, удаление убирает файл.

**Содержание**. Устройство выбрано по образцу памяти Claude Code и в одном месте строже его.

```
$MYHARNESS_STATE_DIR/memory/
  зовут-александр-a3f19c.md
  любимый-цвет-синий-7b2e04.md
```

**Общего изменяемого файла нет, поэтому нет и гонки.** Добавление факта — создание нового файла,
удаление — удаление файла; два запущенных инструмента пишут разные файлы и не встречаются.
Блокировка не нужна: её отсутствие здесь не упрощение, а следствие устройства.

У Claude Code рядом с файлами фактов лежит оглавление `MEMORY.md`, и оно остаётся единственным
местом, где две сессии всё-таки сталкиваются. Нам оглавление не нужно: факты короткие, читать весь
каталог при запуске дёшево, **каталог сам себе оглавление**.

Содержимое файла:

```markdown
---
добавлен: 2026-09-08T14:03:11Z
источник: человек
---

зовут Александр
```

Заголовок несёт происхождение факта: когда добавлен и кем — `человек` (через `/remember`) либо
`архивариус`. Через месяц при разборе памяти это единственный способ понять, откуда взялась строка.
Сам факт — тело файла. Формат не придётся ломать, когда факты вырастут из строк в записки с
обоснованием: место для разделов в файле уже есть.

```python
FACTS_MAX = 40          # штук
FACT_CHARS_MAX = 200    # знаков в одном факте

def facts_dir() -> Path                                   # state_dir() / "memory"
def load_facts() -> tuple[list[str], list[str]]           # (факты, предупреждения)
def add_fact(text: str, *, source: str = "человек") -> tuple[bool, str]
def remove_fact(index: int) -> tuple[bool, str]           # номер с единицы, как показан в /memory
```

Правила:

- **порядок фактов** — по полю `добавлен` по возрастанию, при совпадении по имени файла. Порядок
  обязан быть одинаков в двух запущенных копиях, иначе `/forget 2` в одной убирает не то, что
  видно в другой;
- **имя файла** — слаг из первых слов факта плюс шесть знаков отпечатка, чтобы имена не
  сталкивались. Кириллица в имени остаётся как есть, читается глазами. **Слаг обрезается по
  БАЙТАМ, не по знакам: потолок 80 байт.** Предел имени файла в ext4 — 255 байт, а знак кириллицы
  занимает два: факт из 200 законных знаков даёт имя в 410 байт и на сервере проекта не
  записывается вовсе. На макбуке (APFS считает знаки) это не проявляется — беда вылезла бы только
  на Ubuntu. Уникальность держит отпечаток, а не длина слага;
- **повтор** отбрасывается сравнением нормализованного текста (без учёта регистра, крайние пробелы
  срезаны, внутренние пробелы и переводы строк схлопнуты) со ВСЕМИ загруженными фактами, а не по
  имени файла: иначе правка факта руками ломала бы отбор повторов;
- **перевод строки внутри факта** схлопывается в пробел: факт — одна строка;
- **пустой и пробельный** текст отвергается; текст длиннее `FACT_CHARS_MAX` отвергается с
  указанием длины. Потолок в штуках от факта в двенадцать тысяч знаков не спасает, а факт уезжает
  в системную инструкцию каждого запроса — ровно то разбухание за деньги пользователя, ради
  которого потолок и заведён;
- **переполнение `FACTS_MAX`** — факт не добавляется, сообщается, что память полна и нужно
  `/forget`. Молча вытеснять старое нельзя: человек не узнает, что потерял;
- **запись** — во временный файл в том же каталоге, затем `os.replace`: читатель никогда не увидит
  недописанный файл. Каталог `700`, файлы `600`;
- **испорченный файл факта** пропускается с предупреждением, остальные читаются; исчезнувший во
  время чтения файл пропускается молча — его только что удалила вторая копия инструмента, и это
  не беда, а норма;
- **`remove_fact`** удаляет файл; неверный номер, ноль, отрицательное число и удаление из пустой
  памяти дают сообщение, а не исключение.

**Тесты (пишутся первыми)**: добавление создаёт один файл, чтение возвращает текст; происхождение
и время записаны в заголовок; повтор в другом регистре и с крайними пробелами отброшен; перевод
строки внутри факта схлопнут; пустой отброшен; факт длиннее 200 знаков отброшен с указанием длины;
сорок первый факт отброшен, старые не вытеснены; **факт из 200 знаков кириллицы записывается** —
имя файла не длиннее 255 байт; удаление по номеру убирает нужный файл и сдвигает нумерацию; номера 0, −1, 99 и удаление из пустой памяти дают сообщение; порядок фактов одинаков
при двух чтениях подряд; испорченный файл факта не мешает прочитать остальные; **две одновременные
записи разных фактов не теряют ни одного** (два процесса кладут по несколько фактов — в каталоге
оказываются все); права каталога `0o700` и файлов `0o600`; запись идёт через подмену (проверяется
тем, что прямая запись ломает проверку).

## Шаг 11. Восстановление при запуске

**Файлы**: `src/myharness/cli.py`, `src/myharness/ui.py`, `tests/check_app.py`
**Требование**: `openspec/specs/memory/spec.md` → «Разговор восстанавливается при запуске»
**Проверка**: второй запуск в том же каталоге с тем же профилем поднимает память; в ленте одна строка отчёта; реплики в ленту не печатаются.

Порядок: найти последнюю сессию пары «текущий каталог, имя профиля»; прочитать её с окном
`profile.history_window` и отпечатком текущей инструкции; отдать пары `agent.restore`; открыть
хранилище **на найденной сессии** (продолжаем её, а не заводим новую); напечатать отчёт.

```python
def restored_fragments(loaded: int, saved: int, last_ts: str) -> Fragments
```
даёт `· восстановлен разговор: 3 пары из 12 сохранённых, последняя 14:03`. Оба числа названы по
той же причине, по которой называется число выброшенных обрезкой: молча подставленный прошлый
разговор пользователь отлаживает как «модель отвечает не на то».

Предупреждения разбора печатаются `ui.error_fragments`, изменившийся отпечаток — отдельной строкой
`· инструкция профиля изменилась с прошлого запуска — прежние ответы получены под другой`.
Сессии нет — не печатается ничего: чистый запуск не должен ничего сообщать.

## Шаг 14. Архивариус: инструкция, профиль, запрос, разбор

**Файлы**: `src/myharness/archivist.py` (новый), `tests/check_units.py`
**Требование**: `openspec/specs/memory/spec.md` → «Факты извлекает отдельный агент»
**Проверка**: инструкция содержит слово «json» и пример; разбор достаёт список фактов; мусор в ответе даёт пустой список, а не исключение.

**Содержание**.

```python
EVERY_N = 5
ARCHIVIST_INSTRUCTION: str
def archivist_profile() -> Profile
def extract_request(pairs: list[tuple[str, str]]) -> str
def parse_facts(raw: str) -> list[str]
```

`ARCHIVIST_INSTRUCTION` — текст утверждён пользователем и пишется в код дословно:

```
Ты ведёшь память об одном человеке — пользователе инструмента.
Тебе дают кусок его разговора с моделью. Найди в нём факты О САМОМ ЧЕЛОВЕКЕ
и его работе, которые останутся верными и через месяц, в любом другом разговоре.

Записывай:
— как его зовут и как к нему обращаться;
— чем он занимается, какой опыт, на каких языках и в каком стеке работает;
— устойчивые предпочтения: язык общения, желаемый стиль ответов, что любит и не любит;
— обстановку работы: какие машины и серверы, где лежат проекты, чем собирает;
— решения о его проектах, принятые надолго.

НЕ записывай:
— содержание задачи, о которой шла речь, — это разговор, а не человек;
— сиюминутное: «сейчас спешит», «сегодня устал»;
— то, что сказала модель. Только то, что сказал сам человек;
— свои догадки. Не сказано прямо — не факт.

Каждый факт — одна короткая строка, понятная без разговора.
Плохо: «любит то, что мы обсуждали». Хорошо: «любимый цвет — синий».
Нечего записать — верни пустой список, это нормальный ответ.

Ответ строго json: {"факты": ["зовут Александр", "любимый цвет — синий"]}
```

Три ограничения в ней закрывают три конкретные беды: «только слова человека» — иначе в память
уедет то, что насочиняла модель; «без догадок» — иначе через месяц там окажется «предпочитает
краткие ответы», потому что человек однажды сказал «короче»; «самодостаточная строка» — иначе факт
«как договорились вчера» окажется бесполезен в папке, где никакого «вчера» нет.

Слово «json» и пример структуры обязаны стоять в самой инструкции: без них DeepSeek отклоняет
запрос с `response_format: json_object`.

`archivist_profile` — `deepseek-v4-flash`, `keep_history=False`, `thinking` выключен,
`temperature` 0.2, `response_format: json_object`, `max_tokens` 512.

`parse_facts` терпим к мусору: не JSON, не объект, нет поля, поле не список, элементы не строки —
всё это даёт пустой список, а не исключение. Пустые и слишком длинные (свыше 200 знаков) факты
отбрасываются: факт — короткая самодостаточная строка, а не абзац.

**Тесты**: инструкция содержит «json»; `{"факты":["зовут Александр"]}` даёт один факт; `{}`, `[]`,
`не json`, `{"факты":"строка"}`, `{"факты":[1,2]}` дают пустой список; факт из трёхсот знаков
отброшен; пробельный факт отброшен.

## Шаг 15. Архивариус: запуск в фоне раз в пять обменов

**Файлы**: `src/myharness/archivist.py`, `src/myharness/cli.py`, `src/myharness/ui.py`, `tests/check_app.py`
**Требование**: `openspec/specs/memory/spec.md` → «Архивариус работает в фоне и не молчит»
**Проверка**: после пяти обменов уходит один запрос архивариуса; ввод при этом не блокируется; новые факты объявлены в ленте; двух архивариусов разом не бывает.

**Содержание**.

```python
async def run(state) -> None    # один заход архивариуса
def due(state) -> bool          # пора ли: счётчик достиг EVERY_N и задача не идёт
```

В `State` — `since_archive: int = 0` и `archivist_task: asyncio.Task | None = None`.
Счётчик растёт в очереди запросов после каждого успешного обмена главного экрана. Достиг `EVERY_N`
— счётчик обнуляется, задача создаётся **отдельно** от задачи запроса, чтобы не блокировать ввод;
если задача уже идёт, новая не создаётся.

Архивариус получает последние `EVERY_N` пар памяти главного агента, ходит к модели без панели
(обработчик показа не передаётся — показывать нечего), каждый новый факт кладёт `add_fact` и
объявляет `ui.fact_added_fragments`. Пока работает — в строке состояния `· запоминаю…`
(`ui.status_fragments` получает признак).

При выходе (`/exit`, Ctrl+D) архивариус запускается последний раз, если с прошлого раза был хоть
один обмен, и приложение дожидается его не дольше пяти секунд: заставлять человека ждать выхода
дольше — хуже, чем потерять несколько фактов.

Сбор фактов включён всегда; выключить его можно `/memory off`, и тогда ничего этого не
происходит (шаг 16).

## Шаг 16. Выключатель сбора фактов в настройках инструмента

**Файлы**: `src/myharness/config.py`, `src/myharness/cli.py`, `tests/check_units.py`
**Требование**: `openspec/specs/config/spec.md` → «Настройки хранят выключатель сбора фактов»
**Проверка**: умолчание — включено; `/memory off` выключает и переживает перезапуск; при выключенном сборе архивариус не запускается ни разу.

**Содержание**. `Config.remember: bool = True` — поле рядом с ключом, моделью и именем профиля,
читается и пишется уже существующими функциями настроек. Умолчание **включено**: память — свойство
инструмента, а не то, что надо каждый раз включать.

Профиль этим не управляет намеренно. Профиль отвечает на вопрос «кем сейчас работает модель»;
память — про пользователя и его папку, к личности модели отношения не имеет. Заведи мы поле
профиля, память приходилось бы включать в каждом профиле заново, и в половине из них её бы забыли.

Испорченное значение в файле настроек даёт умолчание — как и у остальных полей: падение на старте
не оставляет пользователю выхода.

## Шаг 18. Проверки не трогают настоящий домашний каталог

**Файлы**: `tests/check_units.py`, `tests/check_app.py`
**Требование**: `openspec/specs/config/spec.md` → «Каталог настроек переопределяется переменной окружения»
**Проверка**: оба набора проверок задают `MYHARNESS_STATE_DIR` до импорта пакета; после прогона в `~/.local/state/myharness` ничего не появилось.

**Содержание**. В обоих файлах, в тот же блок, где уже задаются `MYHARNESS_PROFILES`,
`MYHARNESS_CONFIG_DIR` и `MYHARNESS_JOURNAL`, и обязательно **до** первого импорта `myharness`:
`os.environ["MYHARNESS_STATE_DIR"] = str(tmp / "state")`.

Забыть один файл — значит на первом же прогоне записать в настоящий домашний каталог. Это уже
случалось: проверки однажды затёрли рабочий ключ пользователя, и правило «всё, что пишет в
домашний каталог, обязано иметь переопределение пути» выведено именно оттуда.

Отдельная проверка сбоя записи: каталог состояния наведён на недоступный путь — обмен доходит до
конца, ответ цел, ошибка возвращена текстом.

Заодно чинится та же слабость в старой проверке журнала (`tests/check_units.py`, раздел 2):
недоступность там задана несуществующим корнем `/несуществующий/...`, а под root такой каталог
будет создан — проверка пройдёт вхолостую и оставит мусор в корне файловой системы. На сервере
проекта всё исполняется от root. Задавать недоступность надо родителем-файлом: под обычным файлом
каталог не создать никакими правами, ядро отдаёт `ENOTDIR` независимо от привилегий. Найдено
проверяющим при разборе блока 1–3.

## Шаг 19. Требования

**Файлы**: `openspec/specs/memory/spec.md` (новый), `openspec/specs/{agent,commands,interface,batch,profiles}/spec.md`
**Требование**: правило `CLAUDE.md` — спецификация, отставшая от кода, хуже её отсутствия
**Проверка**: `openspec validate --specs --strict` — 13 из 13.

**Содержание**. Новая способность `memory`: хранилище лежит в каталоге состояния; разговор
принадлежит паре «каталог и профиль»; разговор пишется дописыванием дословно; разговор
восстанавливается при запуске молча, с отчётом одной строкой; испорченная запись не роняет
восстановление; правка инструкции между запусками называется вслух; глобальные факты хранятся
отдельным файлом, читаемым человеком; факты подмешиваются в системную инструкцию только
разрешённым агентам; факты извлекает отдельный агент раз в пять обменов; каждый новый факт
объявляется; сбой хранилища не роняет обмен.

Правки существующих: `agent` — хранилище и факты приходят извне, восстановление идёт единственным
методом пополнения; `commands` — `/clear` открывает новую сессию, добавлены `/remember`, `/memory`,
`/forget`; `interface` — строка восстановления, строка архивариуса, объявление фактов; `batch` —
наряд не сохраняет и не восстанавливает разговор; `config` — выключатель сбора фактов.
