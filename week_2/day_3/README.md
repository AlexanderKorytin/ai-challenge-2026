# День 8 — работа с токенами

Ветка `w2d3`. Стадия: **Plan**.

## Постановка (условие задания)

Добавить в код агента подсчёт токенов:

- для текущего запроса;
- для всей истории диалога;
- для ответа модели.

Сравнить: короткий диалог, длинный диалог, диалог, превышающий лимит модели.

Показать: как растёт стоимость и расход токенов по ходу диалога; что ломается при переполнении.

Результат — код, который считает токены и показывает, как они влияют на поведение агента.

## Видение пользователя

Счётчики показываются так же, как в Claude Code: человек вводит запрос, и в строке ожидания
(«думаю…») слева видны стрелка вверх с числом исходящих токенов (зелёным), стрелка вниз с числом
входящих, включая токены размышлений (красным), и знак суммы с расходом за текущую сессию
(оранжевым). Размышления модели не заливают ленту: свёрнутая область, разворачивается клавишей.
Токены прошлых запусков в итог сессии не входят — считается только текущая.

## Ход работы по стадиям

### Research

Разведка на живом ключе, а не по документации:

| Что проверено | Итог |
|---|---|
| живой счёт выхода | кусок потока = токен: 180 кусков размышления против `reasoning_tokens` = 180, ответ разошёлся на один токен |
| когда приходит `usage` | одним событием в конце (на 5.69 с), для живого счётчика непригоден |
| предсказание входа | офлайн-токенизатор DeepSeek плюс надбавка 83 токена на запрос и ~1.5 на реплику — измерено на четырёх запросах |
| пределы модели | окно 1 000 000 токенов, выход 393 216 (сервер: `the valid range of max_tokens is [1, 393216]`) |
| тариф | flash $0.22/$0.66, pro $0.66/$1.98 за миллион (промах кэша / выход), попадание в кэш дешевле в 30 раз, часы пик вдвое дороже |
| переполнение окна | запрос отклоняется на входе, токены не списываются |

Опрошены профильные агенты: политика бюджета контекста и место учёта в архитектуре.
