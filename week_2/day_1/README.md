# День 6 — Первый агент

Ветка: `w2d1`. Стадия: **Validation**.

## Постановка

> Реализуйте простого агента, который принимает запрос пользователя, отправляет его в LLM через
> API, получает ответ, выводит результат в вашем интерфейсе.
>
> Важно: агент должен быть **отдельной сущностью**, а не просто одним вызовом API; логика запроса
> и ответа должна быть **инкапсулирована в агенте**.
>
> Результат: агент принимает запрос и корректно вызывает LLM через API. Формат: видео + код.

Уточнения из переписки с ментором:

* сущность держит системную инструкцию, параметры, **складывание стека сообщений** и пересылку в
  LLM; наружу отдаёт только результат;
* это «коробка» со своей политикой входа, политикой выхода и, если нужен, своим судьёй —
  изолированный модуль внутри приложения;
* устройство обязано выдерживать сто агентов с разными настройками: **один процесс приложения,
  сто экземпляров агента внутри**.

Дополнительно от пользователя: режим, в котором инструмент не ждёт человека в цикле, а сразу
исполняет то, что записано в конфигурации.

## Ход работы по стадиям

### Research — завершено

Классификация: архитектурная задача. Опрошены три профильных агента (устройство сущности,
управление памятью, путь перестройки), их расхождения разобраны и решены явно. Разведка по сети
о способах проверки агентов. Итог — [`дизайн.md`](дизайн.md), утверждён пользователем.

Ключевые решения: клиент API — аргумент вызова, а не поле агента; журнал пишет агент через
развязанный `journal.append`; составные режимы — оркестраторы над множеством агентов; потоковый
вывод через функцию обратного вызова, а не асинхронный генератор; память — скользящее окно с
блочной обрезкой, без пересказа.

### Plan — завершено

[`план.md`](план.md): 60 шагов, двенадцать блоков (А–М), ~7 ч 45 мин. Три рубежа: шаг 25 —
условие дня закрыто, шаг 39 — закрыта изоляция модуля, шаг 53 — закрыт режим без человека
в цикле. Разделение проверок записано в план: строгий цикл на логику, ручной прогон на
текстовый интерфейс.

Найдено при планировании: `__init__.py` — это `from .cli import main`, поэтому любой импорт
пакета тянет `prompt_toolkit`; пакетный режим без терминала требует отдельной лёгкой точки
входа (`args.py`).

### Executing — завершено

Двенадцать блоков плана, каждый — отдельный исполнитель, каждый закончен фиксацией с зелёными
проверками. Исходный слепок до правок: 147 утверждений — [`test/до.txt`](test/до.txt).

**Возможности сверх перестройки**: окно памяти со срезом блоками; режим `--batch` без человека
в цикле; список запущенных агентов по `/agents` со временем и токенами.

#### Поправки плана по ходу работы

План правился шесть раз, и каждый раз — потому что работа вскрывала то, чего не видела разведка.
Записаны прямо в [`план.md`](план.md), рядом с затронутым шагом:

1. **Шаг 4 перенесён к шагу 16.** Проверка, написанная за двенадцать шагов до своего кода,
   держала бы набор красным всё это время — то есть перестройка шла бы без страховки.
2. **Мест сборки сообщений оказалось четыре, а не три.** Разведка пропустила ветку рабочего
   экрана в `cli.worker`. Без правки рабочие экраны тихо перестали бы копить историю, **а все
   проверки остались бы зелёными**: они ходят по главному экрану.
3. **Переходник из шага 25 оказался неисполним.** Замысел «оставить старую функцию, а внутри
   создавать одноразового агента» не сходится с тем, как устроены вызывающие. Порядок блоков
   перестроен: агенты сначала заводятся на панелях, потом все вызовы переключаются разом.
4. **Шаг 46 перенесён в блок З.** Проверка изоляции агента неисполнима, пока `__init__.py` —
   это `from .cli import main`: любой импорт пакета тянет весь интерфейс.
5. **Критерий развязки уточнён.** «Ноль ленивых импортов по всему каталогу» противоречил
   шагу 46: в оркестраторах такой импорт разрывает круг, в точке входа — экономит вес.
6. **Добавлен блок Н** — список агентов, по просьбе пользователя посреди дня.

#### Находки, которых не ждали

- **Живой прогон наряда поймал настоящий сбой**: задание израсходовало весь `max_tokens` на
  рассуждения и не начало ответ — 1412 токенов заплачено, ответа нет. До сегодняшнего дня это
  был бы прогон со статусом «успех» и пустой строкой. Поймала политика выхода, заведённая утром.
- **Строгий цикл поймал ошибку в свежем коде**: на промежуточной версии `exchange` пара
  «вопрос — пустой ответ» оседала в памяти агента и уехала бы в следующий запрос.
- **Панели выбора не были кликабельными вовсе** — клик умели только вкладки. Починено попутно,
  мышью заработали `/profile`, `/params`, `/set`, `/model`.
- **Гипотеза дизайна не подтвердилась** — см. [`test/замер.md`](test/замер.md).
