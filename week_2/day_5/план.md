# План дня 10 — стратегии управления контекстом

## Основание

Утверждённый в чате дизайн из пяти разделов. Общая способность реализуется в `main`; после её проверки и фиксации от обновлённого `main` создаётся ветка `w2d5` и только в ней — `week_2/day_5/`.

## Договоры модулей

### `myharness/src/myharness/profiles.py`
**Владеет**: декларативными настройками стратегии профиля: `context_strategy`, `strategy_window`, `branch_prefills`.
**Отдаёт**: `Profile`; `load(name: str) -> tuple[Profile, list[str]]`; `save(profile: Profile) -> Path`; слепок и JSON с новыми полями.
**Обещает**: отсутствие поля означает `standard`; `sliding` и `facts` всегда имеют положительное `strategy_window`; неизвестные режимы и непригодные значения названы предупреждением и не применены молча.
**Не делает**: не выбирает сообщения, не ходит в сеть, не читает и не пишет разговоры.

### `myharness/src/myharness/context_strategy.py`
**Владеет**: закрытым перечислением `standard | sliding | facts | branching` и чистой политикой выбора истории.
**Отдаёт**: `ContextSelection(messages: list[dict[str, str]], selected_pairs: int, omitted_pairs: int)`; `select_history(history: list[dict[str, str]], strategy: str, window_pairs: int) -> ContextSelection`; `conversation_facts_block(values: Mapping[str, str]) -> str`.
**Обещает**: выбирает только целые пары; `sliding` и `facts` возвращают строгий хвост из `N` пар; `branching` получает уже выбранный путь и не обрезает его; входные списки не меняются.
**Не делает**: не знает о профиле, сети, диске, выжимке и интерфейсе.

### `myharness/src/myharness/sticky_facts.py`
**Владеет**: инструкцией извлекателя и разбором операций над фактами текущего разговора.
**Отдаёт**: `FactChanges(set_values: dict[str, str], forget_keys: tuple[str, ...])`; `extractor_profile(source: Profile) -> Profile`; `extract_request(values: Mapping[str, str], user_message: str) -> str`; `parse_changes(raw: str) -> FactChanges`; `apply_changes(values: Mapping[str, str], changes: FactChanges) -> dict[str, str]`.
**Обещает**: принимает только текстовые непустые ключи и значения; одна редакция ключа заменяет прежнюю; `forget` отсутствующего ключа безопасен; результат имеет устойчивый порядок.
**Не делает**: не вызывает API, не пишет на диск, не извлекает факты из ответа ассистента.

### `myharness/src/myharness/memory.py`
**Владеет**: защищёнными файлами полного линейного разговора, операций Sticky Facts и графа Branching.
**Отдаёт**: существующий `SessionStore` с новым `append_pair(user: str, assistant: str, meta: dict[str, Any] | None = None) -> str | None`; `PairStore`; `ConversationFacts`; `FactsStore.load() -> tuple[ConversationFacts, list[str]]`; `FactsStore.append(set_values: Mapping[str, str], forget_keys: Iterable[str], *, turn_id: str, source: str) -> str | None`; `BranchTurn`; `RestoredBranches.path(branch: str) -> list[tuple[str, str]]`; `BranchStore.load() -> RestoredBranches`; `BranchStore.append_turn(...) -> tuple[BranchTurn | None, str | None]`; `BranchStore.split(checkpoint_id: str | None, left: str, right: str) -> str | None`; функции поиска и создания сеанса по ключу `каталог + профиль + стратегия`.
**Обещает**: права файлов `600`, каталогов `700`; операции только дописываются; повреждённый хвост не уничтожает целую предшествующую запись; один узел Branching содержит завершённую пару целиком; стандартные сеансы остаются совместимыми.
**Не делает**: не выбирает контекст запроса, не вызывает модель, не рисует предупреждения.

### `myharness/src/myharness/agent.py`
**Владеет**: полной памятью одного собеседника, активной стратегией, редакцией фактов, активным путём ветви и всеми токенами его стратегии.
**Отдаёт**: прежние `build_messages()` и `exchange()`; расширенный `Turn` с `context_strategy`, `selected_pairs`, `omitted_pairs`, `branch`, `facts_revision`, `facts_usage`, `facts_error`; `conversation_facts() -> tuple[dict[str, str], int]`; `set_conversation_fact(key: str, value: str) -> str | None`; `forget_conversation_fact(key: str) -> str | None`; `split_branches(left: str, right: str) -> tuple[dict[str, Agent] | None, str | None]`.
**Обещает**: текущий вопрос не входит в `N`; запрос Sticky Facts видит прежнюю редакцию плюс текущую реплику, а следующая реплика ждёт обновления; основной запрос и извлечение выполняются одновременно; неуспешный основной обмен не создаёт пару; соседняя ветвь не попадает в путь.
**Не делает**: не выбирает экран, не хранит черновик ввода, не скрывает ошибку извлечения или записи.

### `myharness/src/myharness/screens.py`
**Владеет**: визуальной панелью, привязанным агентом, собственным черновиком и очередью заготовок панели.
**Отдаёт**: расширенный `Pane` с `draft`, `prefill_queue`, `prefill_initialized`; прежний `Screen`, `pane`, `pane_by_key()`.
**Обещает**: две панели никогда не разделяют изменяемый черновик или очередь заготовок; после разделения Branching на экране остаются ровно A и B.
**Не делает**: не выполняет сетевые запросы и не решает, какая стратегия выбирает сообщения.

### `myharness/src/myharness/cli.py`
**Владеет**: адресацией Enter, задачами и последовательной очередью каждой панели, переключением экранов, командами `/strategy`, `/facts`, `/branch`.
**Отдаёт**: `Request(content: str, pane: Pane, lead: Profile | None = None)`; `PaneWorker`; `switch_screen()`; `switch_pane()`; `apply_prefill(state: State, pane: Pane, profile: Profile, *, only_if_empty: bool = False) -> None`; `next_prefill(state: State, pane: Pane) -> None`; `cmd_strategy(state: State, arg: str) -> None`; `cmd_facts(state: State, arg: str) -> None`; `cmd_branch(state: State, arg: str) -> None`.
**Обещает**: Request захватывает точную панель при Enter; одна панель исполняет запросы строго последовательно, разные панели могут работать одновременно; переключение сохраняет и восстанавливает собственный черновик; `Ctrl+C` отменяет только активную панель.
**Не делает**: не собирает сообщения API и не разбирает ответ извлекателя.

### `myharness/src/myharness/output.py` и `ui.py`
**Владеет**: наблюдаемым отображением режима, исключённых пар, редакции фактов, ошибок вспомогательного обращения и расхода.
**Отдаёт**: прежний `run_turn()`; фрагменты для `/strategy`, `/facts`, `/branch`; дополненные команды, справку и метаданные ответа.
**Обещает**: исключённые, но сохранённые пары не называются забытыми; расход основного ответа и извлекателя различим; предупреждение о переполнении остаётся до отправки.
**Не делает**: не меняет память и не пересчитывает серверный расход из текста.

### `week_2/day_5/compare.py`
**Владеет**: сведением объективного расхода и явно размеченной проверки качества в сравнительную таблицу.
**Отдаёт**: `sum_usage(entries: list[dict[str, Any]]) -> UsageTotals`; `validate_assessment(raw: dict[str, Any], transcripts: Mapping[str, str]) -> Assessment`; `render_markdown(assessment: Assessment, usage: Mapping[str, UsageTotals]) -> str`.
**Обещает**: требует отметку по каждому пункту эталона и дословное свидетельство для найденного требования, ошибки или переноса; неизвестный расход не выдаёт за ноль; не складывает повторно вложенные поля токенов.
**Не делает**: не угадывает смысл ответа поиском ключевых слов, не вызывает модель-судью, не назначает весовые коэффициенты и не выставляет числовую оценку удобству.

После этого ведущий проходит настоящие 15 сообщений через DeepSeek: линейно для Sliding/Facts и по заданному маршруту для A/B. Любой сетевой, извлекательный или дисковый сбой помечает прогон неполным; скрытых повторов нет. Ведущий размечает каждый пункт эталона по реальным итогам с цитатой, отдельный проверяющий перечитывает оба итога каждой стратегии, а таблица сверяется с журналом и `Turn.request_messages`.
**Содержание**: программа считает только объективные токены и проверяет полноту доказательной разметки; пропуски, ложные утверждения, коррекция, перенос ветвей, нерешённые вопросы и полный успех оцениваются явно по рубрике, а не хрупким поиском слов; пользовательское удобство остаётся личной оценкой без числа.

## После исполнения

Разрешённый переход `Executing → Validation`: навык `/проверка` повторно запускает оба полных набора проверок один раз, строгую проверку OpenSpec, терминальный сценарий и независимый просмотр всех изменений дня. Только после пользовательского подтверждения результата возможен `Validation → Report` и навык `/отчет`.
