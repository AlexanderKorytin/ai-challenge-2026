# День 12. Персонализация ассистента

**Стадия: Done.** Пройдены `Research` → `Plan` → `Executing` → `Validation` → `Report`.
Результат подтверждён живым прогоном на настоящем DeepSeek и снят на видео.

## Условие

Добавить персонализацию поверх модели памяти: создать профиль пользователя, описать
предпочтения (стиль, формат, ограничения), подключить профиль к каждому запросу. Проверить
ответы для разных профилей и то, что ассистент учитывает профиль автоматически.

## Видение пользователя

Механизм создания профиля командой `/profile new`: человек одной репликой описывает занятие —
роль, стиль, формат, ограничения, ход работы, каких помощников вызывать. Описание уходит в
модель, она заполняет поля; чего в описании нет — доспрашивается опросом, ответ «неважно»
означает, что поля не будет. Профиль сохраняется, инструмент переходит в него.

## Что сделано

Дизайн — `docs/персонализация.md` в ветке `main`, план — `docs/план-персонализация.md` там же.
Код инструмента правится в `main`: команда `/profile new`, запись профиля парой файлов, поле
`overrides` с перекрытыми записями о человеке, пометка перекрытой записи в запросе.

## Демонстрация

Из песочницы `test/` заводятся два профиля занятия — `математика` и `писатель-философ`, —
затем третий профиль `ведущий`, который вызывает обоих. Один общий вопрос уходит сразу двум:
«Что такое бесконечность?». Созданные профили остаются в `profiles/`, ролик — в `test/`.

Каждый профиль рождён одной репликой описания и ровно одним вопросом опроса: у математика
спрошено про численный пример, у писателя-философа — про язык занятия (ответ «неважно» закрыл
вопрос без поля), у ведущего — про вид сводки.
