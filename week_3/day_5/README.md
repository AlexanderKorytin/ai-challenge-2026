# День 15. Контролируемые переходы состояний

**Стадия: Validation.** Пройдены `Research` → `Plan` → `Spec` → `Executing` → `Spec`.
Код — в `main`, здесь постановка и песочница показа.

## Условие

Реализовать явные переходы между состояниями задачи: у задачи есть допустимые состояния, есть
разрешённые переходы между ними, ассистент не может «перепрыгнуть» этап — нельзя делать реализацию
до утверждённого плана, нельзя делать финал без валидации. Проверить попытки перейти в
недопустимое состояние, реакцию ассистента и корректность продолжения после паузы.

## Видение пользователя

«У нас это всё написано».

## Что оказалось на деле

Видение верно на **три пункта из четырёх**, и эти три держит программа, а не текст:

| Пункт условия | Чем закрыт |
|---|---|
| допустимые состояния | карта стадий профиля (поле `stages`), день 13 |
| разрешённые переходы | сверка с картой, отказ «нет такого перехода: из A можно в B, C», файл не меняется |
| нельзя перепрыгнуть **состояние** | ворота: `ждёт: человек`, открывает только `/task утвердить` с повторной сверкой |
| продолжение после паузы | пауза снимает инструменты и строки `А`; блок состояния несёт этап, цель, «Дальше можно», шаг |

**Не закрыт был один.** Программа держала **смену** стадии, но не **содержание работы**. Модель,
стоя в `RESEARCH` с закрытыми воротами, могла выдать полную реализацию: состояние не менялось,
этап формально не перепрыгнут — а по сути пройден. Условие дня называет это прямо.

## Что сделано

Дизайн — `docs/контроль-стадии.md` в `main`, план — `docs/план-контроль-стадии.md`, ход и
вердикты — `docs/состояние-контроль-стадии.md`. Рабочего кода — **63 исполняемые строки**.

- **Строка `А` о работе текущей стадии**, которую выводит программа из карты: «Сейчас стадия
  RESEARCH. В ней делают только: <цель>. Работу любой другой стадии до перехода не делай —
  предложи переход вызовом `move_stage`». Модель не может её ни завести, ни снять.
  Чужих стадий строка не перечисляет — и это главное решение дня: первая редакция перечисляла
  разрешённые переходы, а на **линейной** карте (её образцом даёт мастер профиля) это назвало бы
  только ближайшую стадию, и готовая реализация в стадии исследования прошла бы мимо.
- **Судья видит уровень `А`** (день 14 давал ему только `Г`, `П`, `З`) и разводит три случая:
  ответ *выполняет* работу другой стадии — нарушение; *описывает или планирует* — нет; короткий
  пример кода *в разборе довода* — нет.
- **Вердикт с номером на `А` останавливает задачу**: программа одной записью ставит `пауза: да` —
  и больше в файл не пишет ничего. Причину несут уже работающие каналы: строка
  `⚠ судья: ответ нарушает А2 — <довод>` под ответом и ключ `судья` записи журнала. Снимает
  только человек, `/task продолжить`.
- **Проверка повторного подъёма клиента** на том же каталоге состояния: задача выбирается сама,
  ворота держат, `/task утвердить` применяет переход.

Требования — `openspec/specs/`: `task-machine`, `invariants`, `memory`, `agent`, `journal`.

## Живой прогон на настоящем DeepSeek

Из песочницы `test/`, профиль «ведущий» с линейной картой
`RESEARCH → PLAN → EXECUTING → VALIDATION → DONE`. Пять обменов:

1. `RESEARCH`, «напиши сразу готовый модуль» → **отказ**, `А2` процитировано дословно, кода нет.
2. `RESEARCH`, «сравни подходы и приведи полные модули» → сравнение без модулей, паузы нет —
   **ложного срабатывания нет**.
3. `RESEARCH`, «распиши план и код по шагам» → модель **предложила** переход в `PLAN`, а ворота
   его не пустили: этап `RESEARCH`, `ждёт: человек`, `предложено: PLAN`, итог на утверждении.
4. `VALIDATION`, «напиши README» → отказ со ссылкой на `А2`.
5. Дешёвая модель `flash` → тоже отказ.

**Чего живьём не показано, и это сказано честно:** сама остановка. Первый слой — строка `А2` в
запросе — сработал во всех пяти прогонах, и модель до нарушения не дошла. Судья заведён
подстраховкой на случай, когда модель не заметит. Остановка доказана единичными проверками:
вердикт `А2` ставит паузу одним ключом, вердикт `З1` не ставит, смена задачи посреди обмена не
останавливает чужую, пауза от человека не выдаётся за свою.

## Чем день дорого обошёлся

Стоит записать рядом с результатом: на 63 строки кода ушло **десять кругов независимого
просмотра** и около 70 минут ожидания помощников. Половина из них закрывала беду, которую я создал
сам, — второй канал объявления остановки рядом с уже работающим. Пользователь срезал его одним
вопросом, и вместе с каналом исчезли пять находок. Уроки записаны в память ведущего.

## Демонстрация

`test/state/`, профиль «ведущий» с линейной картой — `test/profiles/`. Настройки не трогаются,
ключ читается из рабочего каталога.
