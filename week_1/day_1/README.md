# День 1 (2026-08-31)

## Статус

`Done`

## Задание

Написать минимальный код, который отправляет запрос в LLM через API, получает ответ и
выводит его пользователю (CLI/Web). Провайдер — **DeepSeek API** (экономия).

Развёрнутая формулировка (получена в ходе постановки задачи): собрать минимальный
терминальный **harness** — `myharness`:

- запускается командой `myharness` в терминале, при старте — компактная минималистичная
  шапка (модель, статус авторизации, подсказка по командам);
- `/auth` — авторизация по API-ключу DeepSeek; проходит **один раз**, ключ запоминается
  между запусками (не вводить каждую сессию заново);
- `/model` — выбор модели (список + переключение);
- обычный текст — отправляется в DeepSeek, ответ стримится в консоль;
- если ответа ждём, а пользователь ввёл новый запрос — он встаёт в **очередь** и уходит в
  LLM сразу после того, как показан ответ на предыдущий;
- `Ctrl+C` во время ожидания ответа — отмена текущего запроса (не выход из harness);
- пока модель отвечает — анимированный индикатор «думает»; если модель поддерживает режим
  рассуждений (`reasoning_content`, DeepSeek thinking mode) — рассуждения тоже показываются
  пользователю по мере поступления;
- (дополнение по ходу работы) если пользователь отправляет запрос без авторизации —
  показать подсказку `/auth`, запрос не отправлять;
- (дополнение по ходу работы) любая ошибка при обращении к API (сеть, лимиты, невалидный
  ответ и т.п.) — показывается пользователю текстом, а не роняет harness;
- (дополнение после первой демонстрации) поле ввода — отдельная область снизу экрана,
  окаймлённая линиями сверху и снизу, а не просто строка приглашения;
- (дополнение после второй демонстрации) историю переписки можно прокручивать назад.

## Ход работы

### Research

Изучена актуальная документация DeepSeek API (`api-docs.deepseek.com`):

- базовый URL `https://api.deepseek.com`, OpenAI-совместимый формат;
- авторизация — заголовок `Authorization: Bearer <ключ>`;
- модели: `deepseek-v4-flash` (дешёвая, без рассуждений по умолчанию — выбрана моделью
  по умолчанию ради экономии), `deepseek-v4-pro` (поддерживает thinking mode),
  `deepseek-v4-flash-vision-exp`;
- `GET /models` — список моделей и одновременно способ проверить валидность ключа;
- потоковый ответ (SSE): поле `delta.content` — обычный текст, `delta.reasoning_content` —
  текст размышлений (на практике встречается и у `-flash`, не только у `-pro`).

Инструмент: пакет `openai` (клиент с указанием `base_url`, сам разбирает SSE и отдаёт
`reasoning_content` как есть) вместо ручного парсинга потока.

### Plan

Модули пакета `myharness` (`src/myharness/`):

| Модуль | Ответственность |
|---|---|
| `config.py` | Хранение ключа и модели по умолчанию в `~/.config/myharness/config.json` (`chmod 600`), **вне** репозитория — однократная авторизация между запусками |
| `api.py` | `DeepSeekClient` — обёртка над `AsyncOpenAI` с `base_url=https://api.deepseek.com`: `validate()` (проверка ключа), `list_models()`, `stream_chat()` (асинхронный генератор `StreamEvent(kind, text)`, `kind ∈ {reasoning, content}`) |
| `ui.py` | Цветовая схема (`prompt_toolkit.styles.Style`) и билдеры фрагментов текста для лога — шапка, подсказки, ошибки, справка |
| `cli.py` | Полноэкранное `prompt_toolkit.Application`: лог-панель + поле ввода, `asyncio.Queue` — очередь сообщений, отдельная `asyncio.Task` на каждый запрос — для точечной отмены по `Ctrl+C`, анимированный спиннер до первого токена |

### Executing

Первая версия: `uv`-проект (`pyproject.toml`, entry point `myharness = "myharness:main"`),
установлен как инструмент (`uv tool install --editable .`) — команда `myharness` доступна
в терминале без активации venv. Поле ввода — обычная строка `PromptSession` поверх
прокручивающегося терминала (`rich` для оформления, `patch_stdout` — чтобы стрим не ломал
строку ввода).

**Ревизия 1** (по итогам первой демонстрации — «раздели поле ввода линиями сверху и снизу
и сдвинь его вниз экрана»): переход на полноэкранное `prompt_toolkit.Application`
(`HSplit`: лог-панель, разделитель, `TextArea` для ввода, разделитель). `rich` убран из
зависимостей — вывод собирается напрямую как `prompt_toolkit`-фрагменты и `Style`; заодно
снят риск, что `[`/`]` в тексте ответа модели сломают markup-разметку (у фрагментов разметки
вообще нет, это просто текст).

Тогда же во время живого прогона поймана и исправлена реальная проблема устойчивости:
у клиента `openai` по умолчанию connect-timeout всего 5 секунд — на не идеальной сети (VPN)
это давало ложный `Request timed out` при живом и работающем сервисе. Таймаут увеличен
(`connect=20s, read=120s`) в `api.py`.

**Ревизия 2** (по итогам второй демонстрации — «при прокрутке назад пусто»): полноэкранный
режим переключает терминал на alt-screen buffer, у которого нет нативного скроллбэка —
это ограничение терминала, не баг конкретной реализации (то же самое у `vim`/`htop`/`less`).
Добавлена собственная прокрутка: `LogWindow` (подкласс `Window`) перехватывает колесо мыши;
`PageUp`/`PageDown` — то же с клавиатуры; флаг `autoscroll` отключается при ручной
прокрутке и включается заново по `Ctrl+End` или при отправке нового сообщения.

Учтены дополнения, поступившие по ходу работы:
- проверка авторизации **до** постановки сообщения в очередь — иначе подсказка `/auth`;
- любая ошибка стрима (сеть, API) ловится в `generate_response()`, harness не падает и
  остаётся готов принимать следующий ввод; сообщение пользователя, оставшееся без ответа,
  откатывается из истории диалога (чтобы не ломать контекст следующего запроса).

### Validation

Автоматически (без реального ключа DeepSeek, через поддельный клиент и headless-режим
`prompt_toolkit` — `create_pipe_input`/`DummyOutput`):

- `uv sync`, импорт всех модулей, `py_compile` — без ошибок;
- `config.py` — round-trip сохранения/чтения ключа, права файла `600` подтверждены;
- сценарии `generate_response`/`worker`: обычный ответ с рассуждениями; ошибка сети во
  время ответа (не роняет harness, история не засоряется недоответом); отмена запроса
  (`Ctrl+C`); два сообщения подряд через очередь — во всех случаях состояние и история
  корректны;
- полноэкранное приложение целиком: банер, `/auth` (переключение маскировки поля ввода),
  очередь, отмена, чистый выход — без исключений;
- прокрутка истории: колесо мыши отключает `autoscroll`, отправка нового сообщения
  включает обратно — проверено через прямой вызов обработчика мыши.

Вручную пользователем (реальный ключ, реальный терминал, экран записан на видео):
- запрос «привет» и вопрос про танталовый конденсатор на 40В/20мкФ получили настоящие
  ответы от DeepSeek (включая проговариваемые рассуждения у `-flash`-модели);
- по пути поймана и исправлена нестабильность сети (см. «Ревизия 1» выше);
- поле ввода снизу, окаймлённое линиями, — подтверждено;
- прокрутка истории колесом мыши — подтверждена.

## Результат

Рабочий каталог: `week_1/day_1/` (пакет `myharness`, `src/myharness/{__init__,config,api,ui,cli}.py`).
Песочница для живых прогонов и демонстраций: `week_1/day_1/test/` (видео там же, в
`.gitignore`, не коммитится — хранится на Google Диске).

**Быстрый старт:**

```bash
cd "week_1/day_1"
uv sync
uv tool install --editable .    # один раз — команда myharness появляется в PATH
myharness
```

**В самом harness:**

```
/auth                    — ввести API-ключ DeepSeek (ввод скрыт, сохраняется на диск)
/model                   — список моделей / /model <имя> — переключить
<текст>                  — отправить сообщение в DeepSeek
Ctrl+C                   — отменить текущий запрос
колесо мыши / PageUp/PageDown — прокрутка истории; Ctrl+End — вернуться к живому выводу
/help  /clear  /exit
```

Пользователю нужно вручную сделать только одно — ввести свой API-ключ DeepSeek через
`/auth` при первом запуске (это секрет, доступа к которому у Claude нет). Дальше harness
работает автономно.
