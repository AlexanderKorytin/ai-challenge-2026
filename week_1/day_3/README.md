# День 3 (2026-09-02)

## Статус

`Executing`

## Задание

Взять одну задачу (логическую, алгоритмическую или аналитическую) и решить её через API
четырьмя способами:

1. прямой ответ без дополнительных инструкций;
2. с инструкцией «решай пошагово»;
3. модель сначала составляет промпт для решения задачи, затем этим промптом задача решается;
4. в промпте заведена группа экспертов (например аналитик, инженер, критик), решение
   получается от каждого.

Сравнить: отличаются ли ответы и какой способ дал наиболее точный результат.

Результат — несколько решений одной задачи и их сравнение.

Наша постановка: задача не зашита в инструмент. Пользователь вводит любую загадку или задачу,
она уходит во все четыре способа сразу, и ответы ложатся рядом — по вкладке на способ. Кто прав,
решает человек: автоматического судьи здесь нет намеренно (см. Research).

## Ход работы

### Research

**Режим рассуждений DeepSeek включён по умолчанию.** Значит «прямой ответ без инструкций» на
самом деле уже пошаговый — модель разворачивает рассуждение внутри себя. Если ставить опыт на
умолчаниях, способы 1 и 2 сольются, и вывод «разницы нет» будет означать лишь то, что мерили
не то. Поэтому в профилях способов рассуждения выключены явно, а к способу 2 добавлена контрольная
клетка `chain_of_thought_nothinking` — та же инструкция без встроенных рассуждений. Тогда видно
раздельно: что даёт формулировка промпта, а что — рассуждения модели.

**Модель не может «поднять агентов» сама** — у неё нет доступа к API. Поэтому группа экспертов
сделана честно: harness шлёт независимые запросы, каждый со своей системной инструкцией, агенты
не видят ответов друг друга, и только потом ведущий получает все ответы разом.

**Задача должна быть по силам, но не решаться сходу.** Проверено на хрестоматийной загадке: на
ней модель отвечала верно двенадцать раз из двенадцати даже без единой инструкции — сравнивать
было бы нечего. Ни переформулировка, ни модель послабее не помогли: такие загадки известны ей
наизусть. Годится задача, где нужно сменить уровень рассмотрения: на ней голый вопрос
проваливается, а приёмы промптинга начинают различаться.

**Автоматического судьи не будет.** Сначала он был: отдельный дешёвый запрос сверял ответ с
эталоном и считал доли верных. Но судья требует эталона на каждую задачу, а задача здесь меняется
одной строкой; вдобавок на сводной таблице экспертов он оценивает не правильность разгадки, а
решительность формулировки. Задачи ставит человек — он же и читает ответы. Инструмент показывает
их рядом и считает то, чего глазами не видно: сколько запросов, токенов и секунд стоил способ.

### Plan

Способ — это профиль harness, и распознаётся он по самому профилю, а не по названию:

| Профиль | Способ | Что задаёт |
|---|---|---|
| `free` | 1 | ничего: голый вопрос, рассуждения выключены |
| `chain_of_thought_nothinking` | контроль | инструкция «решай пошагово», рассуждения выключены |
| `chain_of_thought` | 2 | та же инструкция при включённых рассуждениях |
| `meta_prompting` | 3 | цепочка из двух шагов: модель составляет промпт, затем решает им задачу |
| `multiprompting` | 4 | пять экспертов отвечают независимо, ведущий сводит ответы в таблицу |
| `task` | — | набор: один вопрос уходит во все четыре способа сразу |

Эксперты группы: `analyst` (формализует условие), `skeptic` (ищет невысказанные допущения),
`critic` (работает на опровержение очевидного ответа), `linguist` (разбирает условие как текст —
синонимы, формы, игра слов), `mathematician` (вводит обозначения, считает, проверяет
подстановкой). Роли подобраны так, чтобы задача любого рода — словесная или счётная — попадала
хотя бы под один подходящий взгляд.

Ведущий намеренно не выносит своего вердикта: он сводит ответы в таблицу
«эксперт — ответ — ключевой довод» и одной строкой называет, в чём эксперты разошлись. Задание
просит «решение от каждого», а выбор правильного остаётся за человеком.

### Executing

**Доработки harness (ветка `main`).** Задание потребовало от инструмента того, чего в нём не
было:

- **группа агентов** — профиль со списком `agents`: вопрос уходит каждому агенту со своей
  системной инструкцией, запросы идут одновременно, ответы экспертов лежат рядом панелями на
  одной вкладке, сводка ведущего — на соседней;
- **набор способов** — профиль со списком `methods`: вопрос из главного экрана уходит во все
  перечисленные способы сразу, каждый отвечает на своей вкладке;
- **панели внутри вкладки** — число колонок выбирается по ширине окна (пять экспертов в пять
  колонок нечитаемы), `Alt+←/→` переходят между панелями, `F3` разворачивает панель на весь экран
  и возвращает сетку;
- **цепочка шагов** — профиль со списком `screens`: ответ первого шага автоматически становится
  началом запроса второго. Так сделан способ 3: слева составленный моделью промпт, справа решение
  по нему, копировать руками ничего не нужно;
- **заготовка ввода** (`prefill`) — профиль может положить готовый текст в строку ввода;
- **мышь остаётся у терминала** — полноэкранный режим перехватывал её целиком, и текст в логе
  нельзя было выделить для копирования. Теперь выделение работает сразу, а клики по вкладкам и
  прокрутку колесом при надобности включает `F2`;
- попутно нашлась ошибка: подстановка `$переменных` в инструкции работала только с латинскими
  именами, `$слов` молча оставался в тексте.

**Как этим пользоваться.** Команда ветки дня — `myharnesslogic` (в `main` живёт чистый
`myharness`, они не вытесняют друг друга):

```bash
cd week_1/day_3
myharnesslogic --profile task   # внизу появятся вкладки способов
# задачу вводите в главном экране — она уйдёт во все способы сразу
# Alt+N или Shift+←/→ — вкладки, Alt+←/→ — панели внутри вкладки, F3 — развернуть панель
```

Замерная часть — на случай, когда одного ответа мало и нужен разброс на серии:

```bash
uv run python -m reasoning.series --runs 20   # прогнать способы серией
uv run python -m reasoning.web                # ответы рядом на 127.0.0.1:8766
```

Условие задачи для серии лежит в `data/task.txt` и в репозиторий не попадает: инструмент от
задачи не зависит, её меняют одним файлом.
