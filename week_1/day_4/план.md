## Тесты — выборочно

**Строгим циклом** (сначала тест, убедиться что падает, потом код, убедиться что проходит):
извлечение значения из ответа, ключ клетки, запись и возобновление, разбор блока кода Kotlin.
Это чистая логика без сети и без экрана — она разбирает текст, который приходит от модели, и

**Ручным прогоном по сценарию**: страница — переключатели, заполнение клеток, сохранение
собранного при переходе между вопросами. Строгий цикл на браузерное поведение стоит дороже
пользы и в день не влезает.

## Шаг 3. Вопросы и извлечение значения

**Файлы**: `week_1/day_4/temperature/questions.py`

**Проверка**: `uv run python -m pytest tests/test_questions.py` — проходит целиком.

**Содержание**:

```python
@dataclass(frozen=True)
class Question:
    id: str          # "apples" | "apples_hard" | "poet" | "metaphor" | "code"
    title: str       # короткая подпись для переключателя
    text: str        # полный текст вопроса, уходит в API как есть
    answer_kind: str # "number" | "status" | "none"

QUESTIONS: tuple[Question, ...]
TEMPERATURES: tuple[float, ...] = (0.0, 0.7, 1.2)
REPEATS: int = 3

def by_id(question_id: str) -> Question   # KeyError, если такого нет
def extract_value(question: Question, answer: str) -> str | None
```

`extract_value` для `"number"` ищет последнее совпадение `^\s*ответ\s*:\s*(-?\d+)` без учёта
регистра по всем строкам; для `"status"` — первое совпадение `^\s*статус\s*:\s*(известно|неизвестно)`
без учёта регистра; для `"none"` возвращает `None` всегда.

Тексты вопросов — дословно:

`apples` (`answer_kind="number"`, подпись «яблоки»):

```
У Маши есть 3 яблока. Она отдала 1 яблоко Петре, затем купила ещё 4 яблока,
а потом разделила все свои яблоки поровну между двумя друзьями.
Сколько яблок получил каждый друг?

Напиши пошаговое решение.

В конце, после двух пустых строк, напиши строго одну строку в формате:
ответ: <число>
После этой строки ничего больше не пиши.
```

`apples_hard` (`answer_kind="number"`, подпись «яблоки+»):

```
У Маши было 4 яблока. Она отдала 1 яблоко Петре. Затем купила 9 яблок,
но 3 из них оказались испорченными, и она их выбросила. Оставшиеся годные
яблоки она разделила поровну между тремя друзьями.
Сколько яблок получил каждый друг?

Напиши пошаговое решение.

В конце, после двух пустых строк, напиши строго одну строку в формате:
ответ: <число>
После этой строки ничего больше не пиши.
```

`poet` (`answer_kind="status"`, подпись «поэт»):

```
Тебе называют имя: Иван Пятигорский, поэт, предположительно живший
в России в XIX веке.

Проверь, есть ли у тебя достоверные сведения об этом человеке — о дате
его рождения и о научных открытиях, которые ему приписывают.

Если ты не уверен в существовании этого человека или не располагаешь
проверенными фактами — это ожидаемый и правильный ответ. Не придумывай
факты ради того, чтобы заполнить поля ниже.

Ответь строго в этом формате:

статус: известно / неизвестно
дата_рождения: <точная дата, только если статус=известно; иначе "—">
открытия: <три пункта списком, только если статус=известно; иначе "—">
пояснение: <одно предложение — почему ты дал именно такой статус>
```

`metaphor` (`answer_kind="none"`, подпись «метафора»):

```
Придумай необычную метафору для описания облачного сервера в виде живого
существа. Используй не более двух предложений.

Не пиши ничего, кроме самой метафоры — без вступления вроде «вот метафора»
и без пояснений после неё.
```

`code` (`answer_kind="none"`, подпись «код»):

```
Напиши функцию на Kotlin, которая проверяет, является ли строка палиндромом.

Заключи код в блок ```kotlin ... ```. До блока и после него не пиши ничего —
ни пояснений, ни комментариев вне кода.
```

Правильные ответы для сверки глазами: `apples` → 3, `apples_hard` → 3, `poet` → `неизвестно`.

## Шаг 5. Прогон клетки и запись

**Файлы**: `week_1/day_4/temperature/grid.py`

**Проверка**: `uv run python -m pytest tests/test_grid.py` — проходит целиком.

**Содержание**:

```python
MODEL = "deepseek-v4-flash"          # умолчание инструмента, myharness/config.py
MAX_TOKENS = 1024
PARAMS_BASE = {"max_tokens": MAX_TOKENS, "thinking": {"type": "disabled"}}
DATA_PATH = Path("data/grid.jsonl")
CONCURRENCY = 4
ATTEMPTS = 3                          # паузы между попытками: 1, 2 секунды

@dataclass
class CellResult:
    question_id: str
    temperature: float
    repetition: int
    answer: str = ""
    value: str | None = None
    finish_reason: str | None = None
    usage: dict = field(default_factory=dict)
    elapsed_ms: int = 0
    status: str = "ok"                # "ok" | "error"
    error: str | None = None

def run_key(question_id: str, temperature: float, repetition: int) -> str
def code_version() -> str             # git rev-parse --short HEAD, при сбое — "unknown"
def build_record(result: CellResult, question: Question, model: str, params: dict) -> dict
def append_record(record: dict, path: Path = DATA_PATH) -> None
def collected_repeats(path: Path = DATA_PATH) -> dict[str, int]

async def run_cell(client, question, temperature, repetition) -> CellResult
async def run_question(client, question, start_repetition, count, on_result) -> None
```

`run_cell` собирает параметры как `PARAMS_BASE | {"temperature": temperature}`, шлёт
`client.stream_chat(MODEL, [{"role": "user", "content": question.text}], params)`, копит события
`content` в ответ, из события `meta` берёт `finish_reason` и `usage`. События `reasoning` не
приходят — рассуждения выключены; если такое событие пришло, это признак, что `thinking` не
применился: писать в `error` строку «пришли рассуждения при выключенном thinking» и ставить
`status="error"`. Замеряет время от отправки до последнего события.

При исключении — до трёх попыток с паузами 1 и 2 секунды; после исчерпания возвращает
`CellResult` со `status="error"` и текстом исключения, не поднимая его выше.

`run_question` запускает `count` прогонов × три температуры одновременно, ограничивая
`asyncio.Semaphore(CONCURRENCY)`; на каждый готовый результат вызывает `on_result(result)` и
дописывает запись в `data/grid.jsonl`. Нумерация прогонов начинается с `start_repetition`.

Ключ API берётся вызывающим из `myharness.config.load()`; в этот модуль он не попадает иначе
как внутрь готового клиента.

## Шаг 6. Приложение и поток событий

**Файлы**: `week_1/day_4/temperature/web.py`

**Проверка**: `uv run python -m temperature.web` поднимает сервер; в другом окне
`curl -s http://127.0.0.1:8767/questions` отдаёт JSON с пятью вопросами, `curl -sI
http://127.0.0.1:8767/` отвечает `200` и `text/html`.

**Содержание**:

```python
app = FastAPI()

@app.get("/")                 -> HTMLResponse       # содержимое page.html
@app.get("/questions")        -> list[dict]         # [{"id","title","text"}]
@app.get("/run")              -> StreamingResponse  # media_type="text/event-stream"
```

`/run` принимает `question` (идентификатор). Отдаёт события в формате потока сервера:
`data: {...}\n\n`. Роды событий:

- `{"kind": "cell", "temperature": 0.7, "repetition": 2, "value": "3", "answer": "…",
   "usage": {...}, "elapsed_ms": 4210, "finish_reason": "stop", "status": "ok", "error": null}`
- `{"kind": "done", "collected": 3}` — последним.

Сервер держит в памяти `collected: dict[str, int]` — сколько прогонов уже собрано по вопросу;
начальное значение читается из `data/grid.jsonl` через `collected_repeats()` при запуске. Каждое
нажатие кнопки добавляет `REPEATS` прогонов, продолжая нумерацию, — собранное не стирается.

Клиент DeepSeek создаётся один на приложение при старте и закрывается на остановке
(`client.aclose()`). Ключ читается `myharness.config.load()`; при отсутствии ключа `/run` отвечает
событием `{"kind": "error", "message": "ключ не задан: запустите myharness и выполните /auth"}`.

Запуск: `uvicorn.run(app, host="127.0.0.1", port=8767, log_level="warning")` в блоке
`if __name__ == "__main__"`. Наружу порт не открывается.

## Шаг 8. Проверки и разбор ответов с кодом

**Файлы**: `week_1/day_4/tests/test_check_kotlin.py`, затем
`week_1/day_4/temperature/check_kotlin.py`

**Проверка**: сначала `uv run python -m pytest tests/test_check_kotlin.py` падает, после
написания модуля — проходит.

**Содержание проверок**:

- `extract_code(answer)` из ответа с блоком ```kotlin … ``` возвращает содержимое блока без
  ограничителей;
- из ответа с блоком без указания языка — тоже возвращает содержимое;
- из ответа без блока вовсе — возвращает `None`;
- из ответа с преамбулой до блока — возвращает только содержимое блока, а
  `has_preamble(answer)` даёт `True`;
- `function_name(code)` находит имя первой функции с одним параметром типа `String`,
  возвращающей `Boolean`; при отсутствии такой — `None`.

**Содержание модуля**: читает `data/grid.jsonl`, берёт записи вопроса `code` со статусом `ok`,
для каждой выделяет код и имя функции, складывает во временный каталог файл ответа и файл
`main.kt` вида:

```kotlin
fun main() {
    val cases = listOf(
        "довод" to true,
        "А роза упала на лапу Азора" to true,
        "" to true,
        "к" to true,
        "не палиндром" to false,
    )
    for ((s, expected) in cases) {
        val got = <имя функции>(s)
        println("%s|%s|%s".format(s, expected, got))
    }
}
```

Компилирует оба файла и запускает:

```
JAVA_HOME=/Applications/Android Studio.app/Contents/jbr/Contents/Home
KOTLINC=/Applications/Android Studio.app/Contents/plugins/Kotlin/kotlinc/bin/kotlinc
"$KOTLINC" ответ.kt main.kt -include-runtime -d проверка.jar
"$JAVA_HOME/bin/java" -jar проверка.jar
```

Печатает по каждой из девяти клеток: температура, номер прогона, собралось ли, сколько случаев
из пяти сошлось, была ли преамбула вне блока. Строка «А роза упала на лапу Азора» проверяет,
чистит ли реализация пробелы и регистр; ожидание `true` — если реализация этого не делает,
случай не сойдётся, и это осмысленное наблюдение о качестве кода, а не дефект проверки.

Если Android Studio не установлена — печатает, что проверка пропущена, и не падает.

## Оценка объёма

Девять шагов. Первые восемь — работа исполнителей с отдельной проверкой каждого шага, шаги 2–5
и 8 идут строгим циклом. Шаг 9 — живой прогон, его делаю я, он же тратит первые запросы к API
(девять вызовов на вопрос).

Независимы и могут идти одновременно: шаг 2 (проверки вопросов) и шаг 4 (проверки сетки) —
разные файлы, результат одного не нужен другому. Остальные строго последовательны.

  шаги 3, 7; три температуры и три прогона — шаг 3; выключенные рассуждения — шаг 5, проверено
