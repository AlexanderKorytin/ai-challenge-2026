# День 4. Температура

**Стадия:** Validation
**Ветка:** `day4-temperature`

## Постановка задания

Выполнить один и тот же запрос при `temperature` = 0, 0.7 и 1.2. Сравнить ответы по точности,
креативности и разнообразию. Сформулировать, для каких задач подходит каждая настройка.

Результат — примеры ответов с разной температурой и выводы по их использованию.
Формат сдачи — видео и код.

## Видение

Локальная страница: вверху переключатели вопросов, ниже текст выбранного вопроса, ниже таблица —
столбцы по температурам, строки по прогонам. Нажатие кнопки запускает прогон, таблица
заполняется по мере ответов. В видео: выбрали вопрос, нажали, дождались, перешли к следующему.
Собранные таблицы при переключении вопросов не стираются.

Вопросов пять: яблоки в простой и усложнённой версии, вымышленный поэт, метафора, код на Kotlin.

## Как запустить

```
cd week_1/day_4/test
PYTHONPATH=.. uv run --project .. python -m temperature.web
```

Страница — `http://127.0.0.1:8767/`. Порт слушается только на своей машине, наружу не
отдаётся: у страницы нет проверки, кто нажимает кнопку, а каждое нажатие — девять платных
вызовов к API.

Запуск идёт из песочницы `test/`, чтобы не давать работающей программе доступа к остальному
коду репозитория; `PYTHONPATH=..` нужен, потому что `uv run --project` выбирает окружение, но
каталог проекта в пути поиска модулей не добавляет.

Ключ доступа берётся из настроек `myharness` (`~/.config/myharness/config.json`); если ключа
нет, страница скажет об этом отдельным сообщением. В репозиторий ключ не попадает.

Разбор ответов с кодом на Kotlin — отдельно, после прогона:

```
cd week_1/day_4
uv run python -m temperature.check_kotlin            # разбирает data/grid.jsonl
uv run python -m temperature.check_kotlin путь.jsonl # или указанный журнал
```

Проверки: `cd week_1/day_4 && uv run pytest` — 84 штуки, все без сети и без экрана.

## Ход работы

### Research

Прочитаны требования затронутых способностей: `openspec/specs/params/`, `openspec/specs/api/`,
`openspec/specs/methods/`, `openspec/specs/profiles/`.

Две находки, определившие задание:

1. **Режим рассуждений DeepSeek включён по умолчанию и отключает влияние `temperature`.**
   Записано требованием в `openspec/specs/params/spec.md`. Без явного отключения рассуждений
   три температуры разошлись бы только случайным шумом, а вывод «температура ни на что
   не влияет» описывал бы режим рассуждений, а не температуру.
2. **Разнообразие — свойство набора ответов, а не одного ответа.** Параметра `seed` у DeepSeek
   нет, поэтому даже при `temperature = 0` повторяемость не гарантирована. Меньше чем
   несколькими прогонами на температуру разнообразие не измеряется в принципе.

Опрошены четыре профильных агента: по промптингу (формат ответа против измеряемого эффекта),
по обработке языка (метрики разнообразия на малой выборке), по эксплуатации (устройство
пакетного прогона), по архитектурам (механика температуры).

Дизайн — `дизайн.md`.

### Plan

Девять шагов, план — `план.md`. Тесты выборочно: строгий цикл на разбор текста и запись
журнала (ошибка там тихо портит всю таблицу, а проверяется без сети), ручной прогон по
сценарию — на страницу.

### Executing

Шаги выполнялись агентами-исполнителями, каждый шаг проверял отдельный агент. Что поймала
раздельная проверка и не поймали бы сами проверки:

- **`ответ: 3.5` превращался в `3`** — дробная часть отсекалась молча, и человеку показывалось
  неверное значение вместо пропуска. Пустая клетка заметна, подменённое число нет;
- **номер прогона мог выдаться дважды** — если последний прогон упал целиком, его номер не
  считался занятым, и в журнале появились бы две записи с одним ключом клетки;
- **упавшая доставка тратила бы деньги в никуда** — сборщик задач при исключении в одной клетке
  не отменял остальные, и те продолжали ходить в платный API уже никому;
- **путь к журналу зависел от места запуска** — из песочницы данные легли бы мимо.

### Validation

- `uv run pytest` — 84 проверки, все проходят;
- `openspec validate --specs --strict` — 10 спецификаций, чисто;
- живой пробный прогон на метафоре: девять вызовов, все успешны, 7,5 секунды на все девять;
  в записях `thinking: {"type": "disabled"}`, рассуждений в расходе токенов нет, ключи клеток
  уникальны, ключ доступа в журнал не попал;
- поведение страницы прогнано на заглушках вместо браузера — 20 проверок: клетки заполняются
  по мере прихода, собранное переживает переключение вопросов, повторное нажатие дописывает
  прогоны 4–6, пустое значение названо словами, ошибка видна в клетке;
- итоговый просмотр ветки отдельным проверяющим: связность слоёв подтверждена, найденные
  расхождения документов с кодом устранены.

**Наблюдение пробного прогона.** При `temperature = 0` три ответа на один вопрос **не совпали**:
два шли одинаково 128 символов и разошлись посреди фразы, третий оказался про другое существо.
Общее у всех трёх — только «Облачный сервер — это». Нулевая температура даёт жадный выбор,
а не воспроизводимость: `seed` у DeepSeek нет, а на стороне сервера в один пакет попадают
чужие запросы.
