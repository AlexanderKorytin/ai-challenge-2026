# /утр — правка текста по правилам письма

Правила лежат в соседнем файле `правила.md`. `CLAUDE.md` подключает его к каждому разговору,
поэтому в чате правила действуют без команды. Этот навык делает другое: правит названный файл.

Язык — русский, транслитерация запрещена.

## Вызов

- `/утр` без довода — напечатать `правила.md` и больше ничего не делать.
- `/утр <файл>` — править названный файл по порядку ниже.

## Порядок правки

1. Прочитать файл и `правила.md`.
2. Запустить счётчик: `python3 bin/утр.py <файл>`. Запомнить итоговую строку.
3. Править текст. Сначала закрыть строки счётчика, затем то, что программа не считает:
   залог, обороты, цепочки существительных, синонимы одного термина.
4. Запустить счётчик ещё раз.
5. Показать итог тремя строками: было, стало, оставлено намеренно и почему.

Правку не фиксировать в git. Пользователь видит её командой `git diff`.

## Что не трогать

- блоки кода и отрезки в обратных кавычках;
- цитаты, строки ошибок, вывод команд;
- числа, единицы и таблицы замеров;
- слова `SHALL`, `MUST`, `WHEN`, `THEN` и структурные заголовки в `openspec/specs/`;
- заголовок YAML файла навыка: по полю `description` среда выбирает навык.

## Форма, а не смысл

Навык меняет форму текста. Смысл, числа и порядок утверждений остаются прежними.

Иногда форму нельзя поправить без догадки о замысле автора. Пример: в длинном предложении
неясно, к чему относится «который». Такое место не править. Вынести его в список вопросов
под итогом, с номером строки.

Нулевой счёт не значит, что текст понятен. Счётчик ловит форму: длину предложения, длину абзаца
и запретные слова. После правки перечитать текст глазами читателя без контекста.

## Счётчик

`bin/утр.py` печатает по строке на нарушение: `путь:строка: правило: отрывок`.

| Правило | Условие |
|---|---|
| `длина N` | в предложении N слов, больше 20 |
| `абзац N` | в абзаце N предложений, больше шести; пункты списка не проверяются |
| `слово X` | слово начинается с запретного начала X из таблицы правил |

Заголовок YAML, блоки кода, таблицы и заголовки счётчик пропускает. Проверки счётчика:
`python3 bin/проверка_утр.py`.

Счёту нельзя верить больше, чем он стоит. Счётчик ошибается в четырёх случаях:

- Сокращение с точкой он узнаёт по своему списку. Сокращение вне списка рвёт предложение
  надвое. Тогда длинное предложение пропущено, а счёт предложений абзаца завышен. Так же рвёт
  многоточие посреди предложения и сокращение перед прописной буквой: «им. Ленина».
- Строку абзаца, начатую с `- `, `15. `, `|`, `@` или `# `, он считает началом списка, таблицы
  или заголовка. Предложение, перенесённое так, рвётся надвое.
- Запретное слово он ищет по началу слова, с приставкой или без. Начало «пуш» найдёт
  и «пушку». Каждую строку `слово` проверять глазами.
- Слово в «ёлочках» и в обратных кавычках он не проверяет: так запретное слово упоминают.

## Откуда правила

Источник — ГОСТ Р 58049-2017, раздел 8.2 «Общие требования к упрощённому техническому русскому
языку». Стандарт написан для документации авиационной техники. Английский прародитель —
ASD-STE100.

| Правило | Пункт |
|---|---|
| прямой порядок слов | 8.2.3.4 |
| действительный залог | 8.2.3.3, 8.2.3.13 |
| без метафор, сравнений и жаргона | 8.2.3.5 |
| русское слово вместо иностранного | 8.2.3.6 |
| один термин на понятие | 8.2.3.7 |
| глагол вместо отглагольного существительного, расшифровка сокращения | 8.2.3.10 |
| меньше причастных и деепричастных оборотов | 8.2.3.11 |
| союзы для порядка действий | 8.2.3.12 |
| простые предложения вместо сложного | 8.2.3.14 |
| слова не пропускать | 8.2.3.15 |
| вертикальный список | 8.2.3.16 |
| 20 слов и правила подсчёта | 8.2.5.1, 8.2.6.1 |
| одна команда на предложение | 8.2.5.2 |
| конкретные описания | 8.2.5.4 |
| абзац до шести предложений | 8.2.6.2 |
| предупреждение начинается с условия или команды | 8.2.7 |

Правила без пункта в таблице проект добавил сам:

- главное первым;
- без пустых вводных слов;
- объяснение нового понятия;
- имена как есть;
- число с единицей и источником;
- «не знаю» вместо догадки;
- схема вместо абзаца.

ГОСТ требует повелительное наклонение во множественном числе (8.2.3.9, 8.2.5.3). Проект этого
не берёт: процедуры в навыках написаны неопределённой формой.

Образец навыка — `https://github.com/tony-adamson/utr-skills`. Отличия: счёт ведёт программа,
иностранные слова заменяются русскими, режима «до конца сессии» и словаря мата нет.
