# /отчет — отчёт по заданию дня

Скилл только для рабочей директории `/Users/aleksandrkorytin/AI chellendge` (весь челлендж
AI SDLC). Запускается в самом конце задания дня, **после** того как пользователь подтвердил
результат — то есть на переходе `Validation → Report` из `CLAUDE.md`.

## Что делает

1. Тихо (без звука) записывает экран, пока пользователь показывает работу кода.
2. Выгружает ролик в общую папку на Google Диске.
3. Фиксирует и отправляет код дня в GitHub-репозиторий челленджа.
4. Дописывает в `README.md` папки дня ссылку на видео и на снимок кода (конкретную фиксацию).
5. Отдаёт пользователю обе ссылки в чате.

## Разовая предварительная настройка (уже сделана / проверить при первом запуске)

- **Разрешение на запись экрана.** `ffmpeg` захватывает экран через `avfoundation` от имени
  приложения-хозяина этой оболочки (обычно `Terminal.app` — проверяется деревом процессов через
  `ps -o pid,ppid,comm -p $$` вверх до первого GUI-приложения). Без разрешения
  «Экранная запись» (System Settings → Privacy & Security → Screen Recording) процесс `ffmpeg`
  **зависает без единой строки в stderr** — это и есть диагностический признак, а не баг.
  Если это произошло: остановить процесс (`pkill -9 -f "ffmpeg -f avfoundation"`), попросить
  пользователя выдать разрешение приложению-хозяину вручную в Системных настройках и **полностью
  перезапустить** это приложение (macOS не подхватывает разрешение на лету) — это тот самый
  редкий случай, когда действие может выполнить только пользователь.
- **GitHub.** `gh auth status` должен быть зелёным, `git remote -v` — указывать на репозиторий
  челленджа.
- **Google Диск.** Папка отчётов: `AI SDLC Challenge`,
  id `1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6`
  (https://drive.google.com/drive/folders/1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6).
  Доступ «по ссылке — просмотр» пользователь выставляет папке один раз вручную в веб-интерфейсе;
  файлы, созданные внутри нужного `parentId`, наследуют этот доступ автоматически.

## Ход работы

### 1. Определить день

Найти папку `week_<N>/day_<M>`, к которой относится текущая работа (по контексту разговора или
по последней изменённой папке в рабочей директории). Уточнить у пользователя, если неоднозначно.

### 2. Определить устройство захвата экрана

```bash
ffmpeg -f avfoundation -list_devices true -i "" 2>&1 | grep -i "capture screen"
```

Взять номер перед `Capture screen 0` (на момент настройки — `1`). Индекс может смениться при
подключении/отключении внешнего монитора — проверять каждый раз заново, не хардкодить.

### 3. Начать запись

Файл — во временную папку (scratchpad этой сессии), не в git-репозиторий (`*.mp4` в `.gitignore`).

```bash
ffmpeg -f avfoundation -i "<индекс>:none" -r 12 -pix_fmt yuv420p -vcodec libx264 \
  -preset veryfast -crf 26 -y "<scratchpad>/day_report.mp4"
```

Запускать через Bash с `run_in_background: true`. Сразу после запуска подтвердить, что в
выводе фонового процесса появились строки-баннер `ffmpeg version …` — если через 5–10 секунд
вывод пуст, это зависание из-за отсутствующего разрешения (см. раздел настройки выше), не ждать
дольше — останавливать и разбираться.

Сообщить пользователю: «Запись пошла, покажи работу кода. Как закончишь — напиши в чат».

### 4. Дождаться сигнала пользователя и остановить запись

Найти PID процесса `ffmpeg` (`pgrep -f "ffmpeg -f avfoundation"`) и остановить его
**мягко** — `kill -INT <pid>` (не `-9`), иначе файл `.mp4` останется без корректного финального
атома и может не открыться. Подождать 2–3 секунды, проверить файл:

```bash
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 "<файл>"
```

Если ролик длиннее ~2–3 минут или тяжелее ~25 МБ — предупредить пользователя и предложить
перезаписать короче/компактнее: следующий шаг (выгрузка через MCP base64) не рассчитан на
большие файлы.

### 5. Выгрузить видео на Google Диск

Прочитать файл, закодировать в base64 и вызвать
`mcp__claude_ai_Google_Drive__create_file`:

- `title`: `day_<M>_<YYYY-MM-DD>.mp4`
- `contentMimeType`: `video/mp4`
- `base64Content`: содержимое файла
- `parentId`: `1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6`
- `disableConversionToGoogleType`: `true`

Взять `viewUrl` из ответа — это и есть ссылка на видео.

### 6. Отправить код дня в GitHub

```bash
git add -A
git commit -m "week_<N>/day_<M>: <короткое описание>"
git push
git rev-parse HEAD
```

Собрать постоянную ссылку на снимок кода дня:
`https://github.com/<owner>/<repo>/tree/<sha>/week_<N>/day_<M>`

### 7. Обновить README дня и зафиксировать

В `week_<N>/day_<M>/README.md`, в разделе «Отчёт», заменить `_TODO_` на обе ссылки. Затем:

```bash
git add "week_<N>/day_<M>/README.md"
git commit -m "week_<N>/day_<M>: добавить ссылки на отчёт"
git push
```

### 8. Отдать результат пользователю

В чате — обе ссылки (видео и снимок кода) плюс подтверждение, что стадия `Report` завершена и
день переходит в `Done`.

## Ограничения, которые нужно держать в голове

- Выгрузка идёт как base64 одним вызовом инструмента — надёжна только для коротких (до пары
  минут) и сжатых роликов. Для длинной демонстрации сначала спросить пользователя, не разбить ли
  показ на несколько шагов/роликов.
- Доступ «по ссылке — любой» не выставляется через API этого MCP-подключения — он держится на
  разовой ручной настройке папки. Если папка когда-то будет пересоздана — предупредить
  пользователя, что нужно повторить настройку доступа вручную.
