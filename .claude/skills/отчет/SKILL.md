# /отчет — отчёт по заданию дня

Скилл только для рабочей директории челленджа AI SDLC —
`~/Library/Mobile Documents/com~apple~CloudDocs/AI chellendge` (проект переехал в iCloud;
прежний путь `~/AI chellendge` — резервная копия, из неё ничего не запускается). Запускается в самом конце задания дня, **после** того как пользователь подтвердил
результат — то есть на переходе `Validation → Report` из `CLAUDE.md`.

## Что делает

1. Уточняет у пользователя сценарий демонстрации, затем тихо (без звука) записывает экран, пока
   сценарий проигрывается (обычно — сам Claude ведёт ввод в терминале).
2. Выгружает ролик в общую папку на Google Диске.
3. Фиксирует и отправляет код дня в GitHub-репозиторий челленджа.
4. Дописывает в `README.md` папки дня ссылку на видео и на снимок кода (конкретную фиксацию).
5. Отдаёт пользователю обе ссылки в чате.

## Разовая предварительная настройка (уже сделана / проверить при первом запуске)

- **Разрешение на запись экрана.** `ffmpeg` захватывает экран через `avfoundation` от имени
  приложения-хозяина этой оболочки (обычно `Terminal.app` — проверяется деревом процессов через
  `ps -o pid,ppid,comm -p $$` вверх до первого GUI-приложения). Без разрешения
  «Экранная запись» (System Settings → Privacy & Security → Screen Recording) процесс `ffmpeg`
  **зависает без единой строки в stderr** — это и есть диагностический признак, а не баг.
  Если это произошло: остановить процесс (`pkill -9 -f "ffmpeg -f avfoundation"`), попросить
  пользователя выдать разрешение приложению-хозяину вручную в Системных настройках и **полностью
  перезапустить** это приложение (macOS не подхватывает разрешение на лету) — это тот самый
  редкий случай, когда действие может выполнить только пользователь.
- **GitHub.** `gh auth status` должен быть зелёным, `git remote -v` — указывать на репозиторий
  челленджа.
- **Google Диск.** Папка отчётов: `AI SDLC Challenge`,
  id `1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6`
  (https://drive.google.com/drive/folders/1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6).
  Доступ «по ссылке — просмотр» пользователь выставляет папке один раз вручную в веб-интерфейсе;
  файлы, созданные внутри нужного `parentId`, наследуют этот доступ автоматически.

## Ход работы

### 1. Определить день

Найти папку `week_<N>/day_<M>`, к которой относится текущая работа (по контексту разговора или
по последней изменённой папке в рабочей директории). Уточнить у пользователя, если неоднозначно.

### 2. Получить сценарий демонстрации у пользователя

Перед началом записи — спросить пользователя, какой сценарий показать: какие команды/сообщения
вводить, каких ответов дожидаться, каким действием завершить показ. Дождаться ответа и следовать
ему дословно — не импровизировать, не сокращать и не добавлять от себя лишние шаги.

Демонстрацию за терминалом ведёт сам Claude (набирает команды/сообщения), а не пользователь —
это часть общего принципа челленджа «юзер руками не пишет» (см. `CLAUDE.md`, раздел «Формат
работы»). Пользователь показывает сам, только если явно так попросил.

Если демонстрируемая программа — полноэкранная интерактивная TUI (нужен настоящий терминал,
например запущенный через `prompt_toolkit`) — ввод текста через обычный Bash-инструмент (пайп в
stdin) не подойдёт, потому что такой программе нужен реальный TTY. В этом случае вести ввод через
доступную GUI-автоматизацию терминала (desktop-модуль инструмента управления устройством/экраном),
а не через Bash.

### 3. Подготовить рабочую песочницу

Перед демонстрацией — перейти в `week_<N>/day_<M>/test/` (создать папку, если её ещё нет). Все
живые прогоны сервисов/агентов дня для записи — из этой песочницы, а не из корня папки дня: так
демонстрация не даёт запускаемой программе лишнего доступа к остальному коду и файлам репозитория.
Рабочие артефакты самого прогона (если появляются) в git не коммитить без необходимости.

### 4. Определить устройство захвата экрана

```bash
ffmpeg -f avfoundation -list_devices true -i "" 2>&1 | grep -i "capture screen"
```

Взять номер перед `Capture screen 0` (на момент настройки — `1`). Индекс может смениться при
подключении/отключении внешнего монитора — проверять каждый раз заново, не хардкодить.

### 5. Начать запись

Файл — во временную папку (scratchpad этой сессии), не в git-репозиторий (`*.mp4` в `.gitignore`).

```bash
ffmpeg -f avfoundation -i "<индекс>:none" -r 12 -pix_fmt yuv420p -vcodec libx264 \
  -preset veryfast -crf 26 -y "<scratchpad>/day_report.mp4"
```

Запускать через Bash с `run_in_background: true`. Сразу после запуска подтвердить, что в
выводе фонового процесса появились строки-баннер `ffmpeg version …` — если через 5–10 секунд
вывод пуст, это зависание из-за отсутствующего разрешения (см. раздел настройки выше), не ждать
дольше — останавливать и разбираться.

### 6. Провести сценарий и остановить запись

Выполнить сценарий из шага 2 дословно (если демонстрирует пользователь — дождаться от него
сигнала в чат об окончании). После последнего шага сценария — найти PID процесса `ffmpeg`
(`pgrep -f "ffmpeg -f avfoundation"`) и остановить его
**мягко** — `kill -INT <pid>` (не `-9`), иначе файл `.mp4` останется без корректного финального
атома и может не открыться. Подождать 2–3 секунды, проверить файл:

```bash
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 "<файл>"
```

Длина и вес ролика ограничены только здравым смыслом: выгрузка идёт через `rclone` и не зависит
от размера. Если нужно обрезать — резать **с пересжатием**, а не копированием потока: разрез по
опорным кадрам съезжает на секунды (при 12 кадрах в секунду опорный кадр примерно раз в 20 с).

```bash
ffmpeg -v error -ss <начало> -i <файл> -t <длительность> \
  -c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -movflags +faststart -y <обрезанный>
```

### 7. Выгрузить видео на Google Диск — через `rclone`

```bash
rclone copy "<файл>" challenge:week_<N>/day_<M>/ 2>&1 | grep -v NOTICE
rclone link challenge:week_<N>/day_<M>/<имя файла> 2>&1 | grep -v NOTICE
```

Вторая команда печатает ссылку на видео — её и отдаём пользователю.

Раскладка на Диске — по папкам дней (`week_1/day_3/…`), а не в одну кучу; `rclone copy` создаёт
недостающие папки сам. Имя файла — `day<M>_report.mp4`.

Подключение `challenge` уже настроено (полный доступ к Диску, корень — папка отчётов
`1z12ya5LX-V0fsnBFgqpdqA52DLuydiu6`), настройки лежат в `~/.config/rclone/rclone.conf` и в
репозиторий не входят. Проверить, что связь жива: `rclone lsf challenge:`.

**Инструментом `mcp__claude_ai_Google_Drive__create_file` видео выгружать нельзя.** Он принимает
содержимое только строкой внутри вызова, а ролик даже в полтора мегабайта — это миллионы знаков.
Проверено на дне 4: 20,6 МБ передать невозможно, а сжатие до проходимого размера убивает
читаемость таблицы в кадре. Инструмент годится для мелких файлов, не для записи экрана.

### 8. Отправить код дня в GitHub

```bash
git add -A
git commit -m "week_<N>/day_<M>: <короткое описание>"
git push
git rev-parse HEAD
```

Собрать постоянную ссылку на снимок кода дня:
`https://github.com/<owner>/<repo>/tree/<sha>/week_<N>/day_<M>`

### 9. Обновить README дня и зафиксировать

В `week_<N>/day_<M>/README.md`, в разделе «Отчёт», заменить `_TODO_` на обе ссылки. Затем:

```bash
git add "week_<N>/day_<M>/README.md"
git commit -m "week_<N>/day_<M>: добавить ссылки на отчёт"
git push
```

### 10. Отдать результат пользователю

В чате — обе ссылки (видео и снимок кода) плюс подтверждение, что стадия `Report` завершена и
день переходит в `Done`.

## Ограничения, которые нужно держать в голове

- **Общий ключ `rclone` к Google Диску выводится из обращения в течение 2026 года** — при
  выгрузке печатается предупреждение. Когда перестанет работать, завести собственный ключ
  приложения по инструкции https://rclone.org/drive/#making-your-own-client-id и прописать его
  в подключение `challenge`. Это разовая настройка в консоли Google, делает пользователь.
- Ссылка на снимок кода дня ведёт **на ветку дня**, а не на фиксацию по хэшу: фиксация не может
  содержать ссылку на саму себя, и снимок по хэшу показывает состояние на шаг раньше — со
  стадией `Report`, без ссылок и без выводов. Ветка дня после сдачи не меняется.
- Доступ «по ссылке — любой» не выставляется через API этого MCP-подключения — он держится на
  разовой ручной настройке папки. Если папка когда-то будет пересоздана — предупредить
  пользователя, что нужно повторить настройку доступа вручную.
