# /штурм — от условия к утверждённому дизайну

Стадия `Research` (по необходимости — переход в `Plan`). Кончается тем, что пользователь сказал
«да» на дизайн. **До этого «да» код не пишется** — ни строчки, ни «просто набросаю».

Язык всей работы — русский, транслитерация английских слов запрещена (см. `CLAUDE.md`).

## 1. Классифицировать задачу

Три рода, объём процедуры разный, необходимость утверждения — одинаковая:

| Род | Признак | Что делаем |
|---|---|---|
| **Проверка осуществимости** | «а можно ли вообще…» | Вопрос в 2–3 предложениях → разведка → рекомендация. Выход — ответ, а не код. |
| **Точечная правка** | флаг, параметр, поведение в одном месте | Разобраться в текущем ходе исполнения → уточняющие вопросы → короткий дизайн файлом → «да» → в `Plan`. |
| **Архитектурная** | новая способность, перестройка, смена соглашений | Полный процесс ниже, с дизайн-документом. |

Не занижать род. Соблазн «это же мелочь» — главный источник переделок. Сокращается длина
дизайна, а не необходимость утверждения.

## 2. Собрать контекст (всегда, до вопросов)

- Прочитать условие задачи и видение пользователя целиком, не додумывая.
- Прочитать требования затронутых способностей в `openspec/specs/` — там источник правды по
  действующему поведению `myharness`.
- Посмотреть код, который придётся тронуть. Широкий поиск по незнакомым местам поручается
  `Explore` в Claude Code либо `scout` на Luna в OMP: они читают много и быстро, но решений
  не принимают.

## 3. Уточняющие вопросы — по одному

Задавать по одному вопросу за раз и ждать ответа. Список из семи вопросов разом получает
односложные ответы на первый и молчание на остальные.

Спрашивать только то, что меняет работу. Всё, у чего есть очевидное умолчание, решать самому и
называть решение вслух.

## 4. Профильный разбор — когда задача незнакома

Профильный разбор берётся не каждый день, а когда **задача действительно незнакома**: в ней есть
предметная область, по которой ни код проекта, ни прошлые дни ответа не дают. Знакомая задача —
перестройка своего же кода, правка соглашений, повтор вчерашнего приёма — разбора не требует.

Цена названа прямо: один профильный помощник стоит 0,2–0,3 миллиона токенов, четверо — около
миллиона, то есть весь бюджет дня. В дне 9 разбор был взят по обряду, а все четыре настоящие
беды нашёл живой прогон, не он.

Берёте разбор — запускать **3–4 помощника одним вызовом** средства запуска, одним набором
поручений: по одному на ответ — это очередь, и штурм растянется вчетверо. Каждому — **одно
поручение и один ответ**, без долгого разговора.

Выбирать по существу задачи из единственного списка ниже:

| Имя | Область |
|---|---|
| `prompting-teacher` | инструкции модели, окно контекста, состояние разговора |
| `ai-agents-teacher` | устройство агентов, инструменты, память, остановка |
| `ai-security-teacher` | границы доверия, подмена указаний, права, утечки |
| `mcp-teacher` | протокол MCP, инструменты и ресурсы, способы передачи |
| `rag-teacher` | поиск по документам, происхождение утверждений в ответе |
| `mlops-teacher` | службы, версии, наблюдение, отказы, расход |
| `nlp-teacher` | разбор текста, разметка, меры качества |
| `transformers-teacher` | устройство моделей, внимание, пределы окна |
| `ai-ethics-teacher` | перекосы, объяснимость, ответственность, законы |
| `dev-env-guide` | сама среда разработки: инструменты, помощники, настройки, git |

Профильного имени в таблице нет — значит роли нет: выдумывать имя нельзя. Канонические
определения — в `.claude/agents/`, Claude Code запускает их на `opus`; для OMP команда
`python3 .omp/sync_agents.py --write` формирует зеркала в `.omp/agents/` с привязкой к Astra.

Широкий сбор фактов по коду и документации — не профильный разбор, а разведка: `Explore` в
Claude Code, `scout` на Luna в OMP. Она дешевле и решений не принимает.

Задание каждому помощнику:

- **узкое** — одна грань задачи, а не «подумай над заданием»;
- **самодостаточное** — весь нужный контекст внутри задания, помощник не видел этой беседы;
- **с явным выходом** — «дай 2 подхода и назови, чем каждый плох».

Обратно: выписать, **в чём помощники расходятся** — расхождение ценнее согласия. Мнение помощника
— материал, а не приговор: проверять по коду и документации. Помощники работают только чтением.

## 5. Подходы и компромиссы

Показать **2–3 подхода**, у каждого честно назвать цену: что усложняется, что станет труднее
менять, где ляжет техдолг. Дать рекомендацию, а не перечень.

Здесь же действует правило `CLAUDE.md`: если видение пользователя ведёт к костылю или техдолгу —
возразить и предложить альтернативу. Молчаливое согласие с плохим решением = ошибка.

## 6. Дизайн — файлом, изложение — коротко

Дизайн пишется **файлом всегда**: для задания дня `week_<N>/day_<M>/дизайн.md`, для общей задачи
и для задания дня без папки — `docs/<задача>.md`. Не ради порядка: разговор обрывается на рубежах очистки, и дизайн, оставшийся
в чате, исчезает вместе с ним.

```markdown
# Дизайн: <задача>
## Задача и видение
## Что решили и почему (включая отвергнутые подходы с причиной отказа)
## Затронутые способности   ← ссылки на openspec/specs/
## Границы: что делаем и чего НЕ делаем
## Риски и чем расплачиваемся
```

В разговор идёт **короткое изложение по разделам и один вопрос об утверждении**, а не полотно:
полный текст пользователь читает файлом. Раздел за разделом с вопросом после каждого — только
если пользователь этого просит: каждый такой круг стоит полного контекста разговора.

Самопроверка перед показом: каждое требование условия где-то в дизайне отражено; нет пунктов
«продумать позже»; названия файлов, помощников и способностей совпадают с настоящими.

## 7. Утверждение

(Слово «рубеж» в этом наборе навыков занято разрывом разговора — см. `/задание`.
Здесь речь об утверждении дизайна пользователем.)

Явно спросить утверждение дизайна. Получив «да» — объявить переход `Research → Plan` и вызвать
навык `/план`. Не получив — вернуться к нужному разделу.

**Ни при каком роде задачи не переходить к коду без произнесённого пользователем согласия.**
