# myharness

Терминальный клиент к DeepSeek API — общий инструмент челленджа AI SDLC. Появился в первый день
как «минимальный harness» (постановка — [`week_1/day_1/README.md`](../week_1/day_1/README.md)) и
с тех пор растёт от задания к заданию.

## Запуск

```bash
uv run myharness                 # из этого каталога
uv tool install --editable .     # поставить команду в систему
myharness                        # дальше просто так
```

Первый запуск попросит `/auth` — ключ DeepSeek запоминается и больше не спрашивается.

## Проверки

```bash
uv run python tests/check_units.py   # логика: без сети и без терминала
uv run python tests/check_app.py     # приложение целиком, с подставным клиентом
```

Обе не требуют ключа и настоящего терминала. Всё, что пишет в домашний каталог, в проверках
уводится во временный: `MYHARNESS_CONFIG_DIR`, `MYHARNESS_STATE_DIR`, `MYHARNESS_JOURNAL`,
`MYHARNESS_PROFILES`. Это не удобство, а требование: однажды проверки затёрли рабочий ключ.

## Что он умеет

**Источник правды о поведении — требования в [`../openspec/specs/`](../openspec/specs/), а не
этот файл.** Перед правкой поведения читать спецификацию задетой способности, после правки —
обновлять её же (`openspec validate --specs --strict`).

| Способность | О чём |
|---|---|
| `profiles` | профиль генерации: инструкция, параметры, заготовка ввода |
| `params` | семь ручек DeepSeek и их применимость при рассуждениях |
| `commands` | команды выбора модели и профиля, стратегий, памяти, расхода и управления разговором |
| `interface` | независимые экраны и панели со своими черновиками и очередями, список агентов, клавиши и мышь |
| `agent` | собеседник: память, сборка запроса, обмен, запись прогона |
| `team` | группа агентов и сводка ведущего |
| `methods` | набор способов: один вопрос разными приёмами |
| `work-screens` | диалоговые шаги по вкладкам |
| `memory` | разговор между запусками и глобальные факты о пользователе |
| `batch` | пакетный наряд без человека в цикле |
| `api` | обмен с DeepSeek: поток, пределы ожидания, список моделей |
| `journal` | журнал прогонов, строка JSON на обмен |
| `config` | настройки: ключ, модель, профиль, выключатель памяти |
| `context-strategies` | четыре режима контекста: Standard, Sliding Window, Sticky Facts и Branching |
| `tokens` | вес следующего запроса, расход активного Agent и общий расход сеанса |

### Стратегии контекста

`/strategy` открывает отдельный разговор одного из четырёх режимов. **Standard** сохраняет
прежнюю обрезку и выжимку. **Sliding Window** отправляет строго заданное число последних пар,
но хранит полный разговор. **Sticky Facts** добавляет к строгому хвосту редактируемый словарь
фактов текущей задачи; извлечение идёт отдельным обращением, поэтому его серверный расход
показывается отдельно. **Branching** создаёт две независимые ветви от общей контрольной точки.

Экраны стратегий не преобразуют и не очищают друг друга. Каждая интерактивная панель хранит
свой черновик и очередь заготовок; три панели могут выполнять запросы одновременно, а Enter
всегда адресует панель, активную в момент нажатия. `/facts` показывает и правит Sticky Facts,
`/branch` показывает контрольную точку и выбирает ветвь.

После обмена видны режим и фактически выбранные пары. Пары вне строгого окна называются
сохранёнными, но не отправленными: из полной записи они не исчезают. Для Sticky Facts также
видны редакции до и после, ошибка извлечения, отдельный расход основного обращения и
извлекателя и их сумма; отсутствующий серверный расход остаётся неизвестным. `/tokens`
разделяет расход активного Agent или стратегии и общий расход сеанса. В общий итог ровно один
раз входят извлекатели, ветви, группы, способы и уже завершённые Agent.

### Модули и слои

Таблица идёт снизу вверх по ввозам: каждый модуль ввозит только тех, кто выше него, — порядок
взят не на глаз, а разбором ввозов верхнего уровня (топологический, в 14 слоёв).

| Модуль | За что отвечает |
|---|---|
| `args` | ключи командной строки; из зависимостей только `argparse` |
| `config`, `params`, `picker` | настройки, ручки модели, панель выбора |
| `api`, `journal`, `tokens` | обмен с DeepSeek, запись прогонов, счёт токенов и денег |
| `memory`, `context_strategy`, `background` | разговор и факты на диске, режимы контекста, скелет фоновых служб |
| `agent` | собеседник: своя память, сборка запроса, обмен, запись прогона |
| `profiles`, `screens` | профили генерации, устройство экранов и панелей |
| `state` | состояние сеанса; терминала не тянет — это проверяется отдельным процессом |
| `batch` | пакетный режим без человека в цикле; интерфейса не знает вовсе |
| `ui`, `sticky_facts` | оформление лент и панелей, факты текущей задачи |
| `output` | вывод в ленту и отрисовка обмена |
| `archivist`, `compact` | фоновые службы: выписка фактов о человеке, сжатие истории |
| `conversation`, `commands_params`, `team` | подъём разговора с диска, команды ручек, группа исполнителей |
| `methods` | набор способов решения одной задачи |
| `workers` | очереди запросов: общая и своя у каждой интерактивной панели |
| `panes` | активный экран и панель, черновики ввода, заготовки |
| `strategies`, `agents_panel`, `commands_context` | режимы и ветви, список агентов, команды расхода |
| `commands_model`, `commands_memory`, `layout` | команды профиля и памяти, сборка окна |
| `commands` | разбор введённой строки: команда это или вопрос модели |
| `keys` | привязка клавиш |
| `cli` | точка входа интерфейса: сложить приложение, поднять разговор, отдать управление окну |

Проверками закреплена не вся эта раскладка, а три самых дорогих её утверждения: ни `agent`, ни
`batch`, ни `state` не тянут интерфейс (`tests/check_units.py`, проба в отдельном процессе).
Остальное — соглашение, и держится оно чтением, а не проверкой.

До 2026-09-13 треть этой таблицы была одним файлом `cli.py` на 2923 строки. Замысел разделения
и его границы — [`../docs/разделение-cli.md`](../docs/разделение-cli.md).

```

~/.local/state/myharness/memory/         глобальные факты, файл на факт
```
