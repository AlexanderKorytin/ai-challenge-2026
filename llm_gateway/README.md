# llm_gateway — шлюз перед службой Ollama

Шлюз даёт вход из сети для местной модели. Модель работает в Ollama на Маке. Вход —
`https://188.120.230.58`, пути `/v1/*` и `/api/*`. Дизайн — `docs/местная-служба.md`.

```
клиент ──HTTPS + токен──▶ Caddy :443 ──▶ шлюз 127.0.0.1:8780 ──▶ 127.0.0.1:11435 на VPS
                                                                    │ обратный туннель ssh
                                                                    ▼
                                                    Ollama 127.0.0.1:11434 на Маке
```

## Что делает шлюз

Проверки идут по порядку. Первая несработавшая даёт отказ.

| Проверка | Отказ |
|---|---|
| токен в заголовке `Authorization: Bearer` | 401 `invalid_api_key` |
| путь из списка | 404 `not_found` |
| модель из `LLM_MODELS` | 404 `model_not_found` |
| поля чата из списка известных шлюзу | 400 `unknown_field` |
| вид полей: реплика — объект, её текст — строка | 400 `invalid_request` |
| частота: ведро жетонов на клиента | 429 `rate_limit_exceeded`, заголовок `Retry-After` |
| окно: вход плюс `max_tokens` не больше `num_ctx` модели | 400 `context_length_exceeded` |
| служба принимает соединение | 503 `upstream_unavailable` |

Разрешённые пути: `POST /v1/chat/completions`, `GET /v1/models`, `GET /api/tags`,
`POST /api/show`, `GET /api/ps`. Жетон частоты тратит только чат.

Службе уходит не тело клиента, а тело, собранное заново из проверенных полей. Ollama читает
ключи JSON без учёта регистра: ключ `Model` рядом с `model` иначе обошёл бы список моделей.
Полей `options` и `keep_alive` в списке нет. Текст реплики списком частей шлюз взвешивает склейкой; часть-картинку он не принимает:
взвесить её он не умеет.

Окно шлюз проверяет сам, потому что Ollama молча обрезает длинный запрос. Замер 2026-10-09:
запрос в 12 000 слов к модели с окном 8192 вернул код 200 и `prompt_tokens: 4098`.

Вход шлюз считает словарём модели (`myharness.tokens`). Обёртку разговора он берёт по
умолчанию `myharness` и завышает вход примерно на 70 токенов: на запросе «Столица Франции?»
шлюз насчитал 90, служба — 19. Ошибка идёт в сторону отказа: запрос у самой кромки окна
шлюз отклонит, а не отдаст на обрезку.

Журнал — JSONL, строка на запрос: время, клиент, метод, путь, модель, код, длительность,
окно, вес входа, токены входа и выхода по ответу службы. Текста запросов и ответов в нём нет.

## Настройки

| Переменная | Значение |
|---|---|
| `OLLAMA_HOST` | адрес службы Ollama; на сервере — конец туннеля `http://127.0.0.1:11435` |
| `LLM_MODELS` | разрешённые модели через запятую |
| `LLM_RATE_PER_MINUTE` | запросов чата в минуту на клиента |
| `LLM_TOKEN_<имя>` | токен клиента `<имя>`; нужен хотя бы один |
| `LLM_GATEWAY_LOG` | файл журнала |

Без любой из четырёх последних шлюз не стартует и называет причину.

## Проверки

```
cd llm_gateway && uv run python tests/check_gateway.py
```

Сети и службы Ollama проверкам не нужно. Журнал пишется во временный каталог.

## Клиент

```
export OLLAMA_HOST=https://188.120.230.58:443
export OLLAMA_API_KEY=<токен клиента>
myharness --model ollama/qwen3.5:9b-q4_K_M-32k
```

Любой клиент OpenAI работает с адресом `https://188.120.230.58/v1` и токеном как ключом.
