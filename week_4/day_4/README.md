# День 19 — автоматический пайплайн из нескольких MCP-инструментов

## Постановка

Создать несколько MCP-инструментов (`search`, `summarize`, `saveToFile`) и выстроить из них
цепочку: первый получает данные, второй обрабатывает, третий сохраняет результат. Проверить
автоматическое выполнение цепочки и корректность передачи данных между инструментами.
Видение: искать в интернете — в Википедии; всё локально на Маке, без VPS.

## Как устроено

Местный MCP-сервер `pipeline` (код — `mcp_servers/pipeline/` в `main`). `myharness` запускает
его дочерним процессом по stdio из `test/.mcp.json`; разрешения на три инструмента — в
`test/.claude/settings.json`.

| Инструмент | Что делает | Что отдаёт модели |
|---|---|---|
| `search(query, lang="ru")` | один запрос к MediaWiki API: статьи и их вступления | `search_id`, заголовки и адреса; тексты остаются на сервере |
| `summarize(search_id, focus?)` | берёт тексты **на сервере** по `search_id`, сжимает моделью DeepSeek с пометками источников `[n]` | `summary_id`, текст выжимки, источники, расход токенов |
| `saveToFile(summary_id, filename)` | берёт выжимку **на сервере** по `summary_id`, пишет Markdown в `результаты/` | путь, размер, `sha256` |

**Данные передаются по ссылке.** Модель переносит между шагами только `search_id` и
`summary_id`, сами тексты идут внутри сервера. Если бы модель передавала текст доводом, она
могла бы его пересказать, обрезать или перепутать. Живой прогон это и показал: в ответе
человеку модель переформулировала выжимку, а в файле лежит дословный текст, который вернул
`summarize`.

**Автоматичность** — дело модели: описание каждого инструмента называет, откуда брать его вход
и что вызвать следом. Человек пишет одну просьбу — три вызова идут одним кругом инструментов.

**Выжимку делает сам сервер** запросом к DeepSeek (рассуждения выключены, предела длины нет;
ответ не `stop` — ошибка, а не обрезанный файл). Ключ — в своём файле сервера
`~/.config/pipeline-mcp/config.json` (права 600). Сначала замышлялся MCP sampling — сервер
просит модель клиента, — но протокол 2026-07-28 объявил его устаревшим (SEP-2577).

Существующий файл не перезаписывается; имя с каталогами, `..`, ведущей точкой или
управляющими знаками отвергается.

## Проверки

- `cd mcp_servers/pipeline && uv run python check_server.py` (в `main`) — 47 проверок без сети:
  настоящий клиент MCP, Википедия — образец, DeepSeek — подмена. В модель уходят ровно
  найденные вступления в порядке выдачи, в файл — ровно выжимка (`sha256`), отказы.
- Живой обмен из `test/`:

  ```
  uv run --project ~/challenge/main/myharness python живой_обмен.py "Найди в Википедии про Байкал, сожми и сохрани в файл baikal"
  ```

  Сервер не перезаписывает файлы, поэтому перед повтором удалите `test/результаты/baikal.md`
  или назовите в просьбе новое имя: иначе `saveToFile` откажет, модель сделает лишний вызов, и
  сверка порядка честно даст «ПРОВАЛ».

  Печатает вызовы и сверку: порядок `search → summarize → saveToFile`, id на входе каждого шага
  — из выхода предыдущего, `sha256` файла на диске, дословный текст и источники в файле.
