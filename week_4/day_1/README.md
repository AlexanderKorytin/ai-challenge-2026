# День 16. Подключение MCP

`Report`.
Код — в `main` (инструмент `myharness` общий на весь челлендж), здесь постановка, песочница показа
и видеоотчёт.

## Условие

Установить MCP SDK или клиент и написать минимальный код, который устанавливает MCP-соединение и
получает от сервера список доступных инструментов. Проверить, что соединение устанавливается и
список возвращается корректно. Результат — код, который подключается к MCP и выводит список
инструментов.

## Видение пользователя

Взять пару публичных серверов и показать. На неделе предстоит сравнение «MCP против навыка и
CLI» — выбор сделать сразу таким, чтобы код не переписывать.

## Что решили

Дизайн — `docs/подключение-mcp.md` в `main`, план — `docs/план-подключение-mcp.md`, ход и
вердикты — `docs/состояние-подключение-mcp.md`, требования — `openspec/specs/mcp/`.

- **Библиотека** — официальная `mcp` для Python, версия 2.x (`mcp>=2.2,<3`). Вторая версия
  разошлась почти со всеми примерами в сети: другие имена функций соединения, поля ответа,
  постраничная выдача, учебный сервер `MCPServer` вместо `FastMCP` — всё проверено пробой.
- **Серверы — GitHub и git**, потому что у обоих есть двойник в CLI (`gh` и `git`): сравнение
  недели честно только на задаче, решаемой обоими путями. Попутно они покрывают оба способа
  связи — удалённый HTTP и местный процесс через stdio. DeepWiki, Microsoft Learn и Context7 тоже
  отвечают без ключа, но сравнить их с CLI не с чем; добавить любой — одна команда.
- **Модуль внутри `myharness`, а не отдельный сценарий**: сравнение пойдёт через агента, у
  которого вызов инструментов DeepSeek уже есть с дня 13. Отдельный сценарий пришлось бы
  переносить через день.
- **`.mcp.json` рабочего каталога в формате Claude Code** — тот же файл читают оба инструмента.

## Что сделано

| Что | Где |
|---|---|
| соединение (stdio и HTTP), согласование `initialize`, список инструментов по всем страницам | `myharness/src/myharness/mcp_client.py` |
| `/mcp` — по каждому серверу имя, способ, версия протокола, инструменты `mcp__<сервер>__<инструмент>` | `myharness/src/myharness/commands_mcp.py` |
| `/mcp add` (HTTP или `-- <команда>`), `/mcp remove` — по образцу `claude mcp add` | там же |
| раздел справки `/help mcp` | `myharness/src/myharness/helpdoc.py` |
| проверки без сети на местном учебном сервере | `myharness/tests/check_units.py`, `mcp_учебный_сервер.py` |

Поведение при сбоях — у каждого сервера своя строка, остальные показываются:

| Случай | Что видно |
|---|---|
| нет `GITHUB_TOKEN` | «не задана переменная окружения GITHUB_TOKEN» |
| неверный токен | «… (HTTP 401 Unauthorized)» — библиотека прячет код ответа, достаём сами |
| сервер завис | «сервер не ответил за 30 с» — предел как у Claude Code, `MCP_TIMEOUT` в мс |
| запись SSE (законна у Claude Code) | причина у этой записи, прочие серверы опрошены |

**Тайны.** Токен в файле не хранится: `"Authorization": "Bearer ${GITHUB_TOKEN}"`, значение
подставляется из окружения при подключении. Буквальный токен в `Authorization` команда `add` не
принимает — репозиторий публичный. Значения заголовков и переменных не выводятся нигде, а если
библиотека процитирует подставленное значение в ошибке — на его месте `***`.
