# День 27. Местная языковая модель в приложении

**Стадия: Validation** — 2026-10-06.

## Постановка

Встроить местную языковую модель в настоящее приложение. Приложение отправляет запросы местной
модели, получает и показывает ответы, работает без облачных моделей.

## Что это

`калории` — утилита командной строки. Она называет калорийность и гликемический индекс (ГИ)
блюда. ГИ показывает, насколько быстро еда поднимает сахар в крови; у глюкозы он равен 100.

| пункт условия | чем закрыт |
|---|---|
| приложение шлёт запросы местной модели | `POST /api/chat` службе Ollama на этом компьютере, модель `qwen3.5:9b-q4_K_M-32k` |
| получает и показывает ответы | два направления: блюдо → числа, килокалории → блюда; разговор без доводов |
| работает без облачных моделей | на чужой адрес утилита запрос не шлёт; в песочнице без выхода в сеть она отвечает (`test/без-сети.sh`) |

## Как пользоваться

Нужна служба Ollama и модель дня 26 (`week_6/day_1/Modelfile`, ветка `w6d1`). Другую модель
называет переменная `CALORIES_MODEL`.

```
uv sync
uv run калории "борщ со свининой"     # блюдо → числа
uv run калории 450                    # килокалории → блюда
uv run калории 450 --блюд 3           # столько блюд назвать (умолчание 5)
uv run калории                        # разговор: строка за строкой
uv run калории --замер                # сверка модели с контрольным набором
```

Блюдо → числа, ответ за 2 с:

```
Борщ со свининой — оценка модели
  калорийность          65 ккал на 100 г
  порция                350 г → 228 ккал
  гликемический индекс  45 (низкий)
Числа назвала местная модель. Не для врачебных решений.
```

Килокалории → блюда, ответ около 50 с:

```
Блюда с порцией около 450 ккал — оценка модели
  Чизкейк классический     150 г    428 ккал (-22)  ГИ 45 (низкий)
  Котлета по-киевски       150 г    428 ккал (-22)  ГИ 45 (низкий)
  Салат Цезарь с курицей   250 г    412 ккал (-38)  ГИ 45 (низкий)
  Рыба в сливочном соусе   250 г    412 ккал (-38)  ГИ 35 (низкий)
  Творожная запеканка      250 г    412 ккал (-38)  ГИ 45 (низкий)
Числа назвала местная модель. Не для врачебных решений.
```

На слово «табуретка» утилита отвечает «Не знаю такого блюда».

## Устройство

```
человек ─► cli.py ─► core.py ─► ollama.py ─► служба Ollama (127.0.0.1:11434) ─► модель
           печать    числа,     один запрос
           разговор  проверка   по схеме JSON
```

- **`ollama.py`** шлёт один запрос. Довод `format` несёт схему JSON: служба не даёт модели выйти
  за схему. Довод `think: false` выключает рассуждения, без них ответ приходит за 2 с.
- **`core.py`** держит два направления. Модель называет три числа: килокалории на 100 г, вес
  порции и ГИ. Калорийность порции считает программа.
- **`cli.py`** разбирает ввод. Строка из числа («450», «450 ккал») идёт в подбор, прочие — в
  оценку блюда.
- **`measure.py`** сверяет модель с контрольным набором.

Программа отвергает невозможные числа: калорийность на 100 г выше 900 (столько даёт чистый жир)
и отрицательные значения. Разряд ГИ: низкий до 55, средний 56–69, высокий от 70.

### Подбор по килокалориям идёт в два этапа

Первая версия просила у модели блюдо и числа одним запросом. Живой прогон показал, что модель
подгоняет вес порции под число: 865 г яблока, литр чая, 1200 г супа. Теперь этапа два:

1. Модель называет только имена блюд, втрое больше просимого.
2. Каждое имя идёт отдельным запросом в оценку блюда. Этот запрос цели не знает.

Программа считает калорийность порции, сортирует блюда по отклонению от запроса и показывает
ближайшие. Порога отклонения нет: человек видит отклонение сам. Цена — 16 запросов и около 50 с
на пять блюд.

## Замер точности

Контрольный набор `контроль.jsonl` — 25 продуктов, у каждой строки назван источник:

- ГИ — Atkinson, Foster-Powell, Brand-Miller, Diabetes Care 2008;31(12):2281–2283, Table 1
  (средний ГИ 62 распространённых продуктов);
- калорийность — записи USDA, прочитаны на `nutritionvalue.org`. Сайт USDA с этой машины не
  открылся.

Все 50 чисел набора сверены с источниками программой. Прогон 2026-10-06, 67 с, вывод —
`test/замер.txt`:

| мера | значение |
|---|---|
| средняя ошибка калорийности | 8,1 % |
| средняя ошибка ГИ | 9,8 единиц |
| разряд ГИ верен | 64 % блюд (16 из 25) |
| блюд без оценки | 0 |

Что видно в строках:

- Калорийность модель знает хорошо: 19 блюд из 25 отклоняются не больше чем на 9 %. Худшая
  строка — картофель фри, +62 %.
- ГИ модель чаще занижает. Девять ошибок разряда, восемь из них — в сторону «ниже».
- Опасные для человека с диабетом строки: рисовое молоко (86 → 35), цельнозерновой хлеб
  (74 → 55), рисовые крекеры (87 → 65).

Границы замера. В наборе простые продукты из известной таблицы: модель могла видеть её при
обучении. Составные блюда («борщ со свининой») замер не покрывает: открытого источника ГИ для
них нет. Точность подбора по килокалориям не мерилась.

## Без облака

- У утилиты один адрес — служба Ollama на этом компьютере. Адрес другой машины в `OLLAMA_HOST`
  даёт отказ, запрос не уходит.
- Клиент не читает посредника из окружения (`HTTP_PROXY`): запрос не уйдёт через чужой сервер.
- `test/без-сети.sh` запускает утилиту в песочнице macOS, где разрешены соединения только на
  этот компьютер. Утилита отвечает. Запрос наружу под тем же запретом падает.

## Проверки

`uv run pytest` — 83 проверки, идут без службы: ответ службы подменяет `httpx.MockTransport`.

## Риски

- **Число модели — оценка, а не справка.** Утилита пишет это под каждым ответом. Решать по ней
  о дозе инсулина нельзя: в замере разряд ГИ неверен у 9 продуктов из 25.
- **Ответ модели не повторяется строго** от запуска к запуску.
- **Имя команды русское.** Переменные окружения с русским именем оболочка `zsh` не передаёт,
  поэтому переменная модели названа `CALORIES_MODEL`.
