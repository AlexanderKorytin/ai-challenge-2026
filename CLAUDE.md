## Development Workflow (STRICT)

Каждая задача ОБЯЗАНА проходить через стадии. Перескакивать или переходить по неразрешённым путям
ЗАПРЕЩЕНО.

### Стадии

1. **Research** — исследование задачи, документации, схемотехники, компонентной базы.
2. **Plan** — формирование плана реализации.
3. **Executing** — разработка схемы, платы, расчётов, конфигурации регистров.
4. **Validation** — проверка результата (ERC, DRC, сверка с документацией, расчёты).
5. **Report** — отчёт о проделанной работе.
6. **Done** — задача завершена.

### Разрешённые переходы

```
Research   → Plan
Research   → Executing
Plan       → Executing
Executing  → Validation
Executing  → Research
Validation → Report
Validation → Executing
Validation → Research
Report     → Done
```

Все остальные переходы ЗАПРЕЩЕНЫ. Перед сменой стадии — явно указывать текущую и следующую.

## Инструмент дня за днём — `myharness`

Терминальный клиент к DeepSeek API, общий для всего челленджа. Код: `week_1/day_1/src/myharness`,
проверки: `week_1/day_1/tests/` (запускаются без ключа и без терминала).

- **Профили генерации** — системная инструкция и параметры запроса одним объектом. Профиль это
  пара файлов: `<имя>.json` (параметры) и `<имя>.md` (текст инструкции; в JSON длинный текст
  превращается в нечитаемую строку с экранированными переносами). Числа из `vars` подставляются
  в инструкцию по `$имя` — так словесное ограничение и `max_tokens` не разъезжаются.
  Ищутся в `$MYHARNESS_PROFILES`, затем в `profiles/` рядом с местом запуска и выше по дереву,
  затем в `~/.config/myharness/profiles`. Имена переменных могут быть на любом языке —
  стандартный `string.Template` знает только латиницу и молча оставлял бы `$слов` в тексте.
- **Команды**: `/auth` (в меню виден только пока ключа нет), `/model`, `/profile`, `/params`,
  `/set`, `/system`, `/team`, `/clear`, `/help`, `/exit`. Ввод `/` открывает меню команд без
  Enter; списки и значения параметров выбираются стрелками во всплывающей панели
  (Enter — применить, Esc — отмена).
- **Группа агентов** — профиль со списком `agents` (имена других профилей) поднимает группу:
  вопрос уходит каждому агенту со своей системной инструкцией, запросы идут одновременно,
  ответ каждого приходит на свой экран, а профиль-ведущий получает все ответы разом и сводит
  их в главном экране. Экраны переключаются кликом по вкладке под строкой ввода, `Alt+N` или
  `Shift+←/→`; экраны агентов — только для чтения (постановка задачи, рассуждения, ответ).
  Разовый запуск из обычного профиля — `/team [профиль-ведущий] <вопрос>`. В журнал каждый
  ответ идёт со своим `agent` и общим `run_id` — так вся группа собирается обратно.
  Агент здесь не процесс: DeepSeek-API не хранит сессий, каждый запрос несёт свою системную
  инструкцию целиком, поэтому «поднять агента» — значит просто отправить запрос с его
  инструкцией.
- **Набор способов** — профиль со списком `methods` (имена других профилей): вопрос, заданный
  в главном экране, уходит **во все перечисленные способы разом**, и каждый отвечает на своей
  вкладке. Способ распознаётся по своему профилю: обычный — один запрос, со `screens` — цепочка
  (ответ шага автоматически становится началом запроса следующего, панели по шагам), с `agents`
  — группа (панели по экспертам, сводка ведущего отдельной вкладкой).
- **Панели внутри вкладки** — когда у способа несколько исполнителей, их ответы лежат рядом, а
  не подряд: сетка панелей (число колонок выбирается по ширине окна), `Alt+←/→` переходят между
  панелями, `F3` разворачивает панель на весь экран и возвращает сетку.
- **Рабочие экраны** — профиль со списком `screens` (имена других профилей) раскладывает приём
  в несколько шагов по вкладкам: у каждого экрана своя инструкция, своя заготовка ввода и своя
  ветка разговора, а ввод уходит в тот экран, который открыт. В отличие от `agents`, эти экраны
  диалоговые: шаги делает пользователь, а не оркестратор.
- **Заготовка ввода** — `prefill` / `prefill_file` в профиле: при выборе профиля текст
  подставляется в строку ввода (не отправляется — Enter жмёт пользователь). При переходе на
  рабочий экран заготовка встаёт только в пустую строку, чтобы не затирать набранное. Нужна
  там, где вопрос к модели сам является приёмом и всегда один и тот же.
- **Мышь по умолчанию у терминала** — текст выделяется и копируется сразу, без команд и клавиш.
  Полноэкранное приложение, перехватившее мышь, лишает терминал выделения, а копировать нужно
  чаще, чем кликать; экраны переключаются клавишами. `F2` или `/mouse` отдают мышь harness
  (клики по вкладкам, прокрутка колесом) и возвращают обратно — состояние видно в строке
  состояния.
- **Параметры, которые есть у DeepSeek**: `temperature`, `top_p`, `max_tokens`, `stop`,
  `response_format` (`text` | `json_object`), `thinking`, `reasoning_effort`. **Нет**: `seed`,
  `top_k`, `frequency_penalty`, `presence_penalty` — ручек для них не заводить.
  Режим рассуждений включён по умолчанию и **отключает** влияние `temperature` и `top_p`.
- **Журнал прогонов** — `myharness-journal.jsonl` рядом с местом запуска (или
  `$MYHARNESS_JOURNAL`): запрос, слепок профиля, ответ, причина остановки, токены. Ключ в журнал
  не пишется. Через журнал к harness подключаются внешние наблюдатели, не требуя правок в нём.
- **Настройки** — `~/.config/myharness/config.json` (права 600), переопределяются
  `$MYHARNESS_CONFIG_DIR`.

## Грабли рабочего окружения (проверено на своей шкуре)

- **Окружения в облачной папке.** iCloud помечает служебные `.pth`-файлы скрытыми, а Python
  начиная с 3.11 скрытые `.pth` игнорирует — установка пакета «editable» молча перестаёт
  работать, импорт падает с `ModuleNotFoundError`. Признак: файл на месте, путь верный, а
  `site.addsitedir` его не подхватывает (`ls -lO` покажет флаг `hidden`). Лечение на месте —
  `chflags nohidden`, правильное лечение — держать `.venv` вне облачной папки. Ещё iCloud
  плодит копии вида `myharness 2.pth` при конфликте синхронизации.
- **Проверки не должны трогать настоящие настройки.** Тесты harness писали в
  `~/.config/myharness/config.json` и затёрли рабочий ключ DeepSeek. Теперь каталог настроек
  берётся из `$MYHARNESS_CONFIG_DIR`, и проверки уводят его во временный каталог. Правило общее:
  всё, что пишет в домашний каталог, обязано иметь переопределение пути для проверок.
- **Установленная команда может смотреть в старый каталог.** После переезда проекта в iCloud
  команда `myharness` продолжала запускать код из прежней копии — правки шли мимо. Проверять,
  куда указывает установка: `cat ~/.local/share/uv/tools/<имя>/lib/python*/site-packages/*.pth`.
- **Автоматизация ввода в терминал и раскладка.** `System Events keystroke` шлёт коды клавиш, а
  не символы: при русской раскладке латиница превращается в кириллицу (`/profile` → `/ффффффф`).
  Для записи демонстраций текст надо класть в буфер обмена и вставлять Cmd+V.
